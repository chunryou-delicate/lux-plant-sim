쭉 병렬로 작업진행해 mcp로"*

## 무엇인가

**원화(2D)다. 게임에 바로 물리는 그림이 아니다.** 이 저장소의 흐름은
`원화(2D) → Meshy 3D(GLB) → tools/glb_thumb 로 납작하게 찍기 → 게임` 이다
(`docs/game_assets_first.md` · START-HERE §2.7). 그래서 여기 그림에 광택이 남아 있어도
최종 썸네일에는 안 남는다 — 썸네일은 GLB 에서 다시 찍는다.

## 어떻게 뽑았나 (재현할 수 있게 적어 둔다)

| | |
|---|---|
| 모델 | `recraft_v4_1` · `model_type: utility` · `resolution: 1k` · 1:1 |
| 값 | **1.25 크레딧/장** (Higgsfield) |
| 배경 | `background_color: "#FFFFFF"` — 이 저장소 썸네일 규약과 같다 |
| 팔레트 | 게임에서 **실측한 색**을 그대로 넘겼다 |

```
#BEB4A2 벽·용기   #D6CEBE 밝은 면   #5C4E42 흙
#92AC98 세이지    #E2C89C 나무      #5C625E 금속·어두운 면
#9EC484 잎        #84B26E 진한 잎
```

프롬프트 뼈대 — `Flat vector game asset. <물건 하나> … Three-quarter view slightly from
above. Soft muted pastel palette, no outlines, simple flat shading, no text, isolated on
pure white.`

⚠ **`no text` 를 꼭 넣는다.** 라벨·씨앗봉투처럼 글자가 들어갈 만한 물건은 안 넣으면
읽을 수 없는 가짜 글자가 찍힌다.

## ⚠ 한꺼번에 많이 던지면 절반이 실패한다

71장을 연달아 제출했더니 뒤로 갈수록 실패율이 올랐다(1묶음 2/12 → 4묶음 7/12 실패).
**프롬프트 탓이 아니다** — 실패한 12장을 그대로 다시 넣으니 **12/12 전부 성공했다.
던지는 속도가 원인이다.** 한 묶음(12장) 보내고 거둔 뒤 다음 묶음으로 가는 것이 맞다.
`submission_failed … 429 rate_limit_reached` 도 한 번 떴다.
