## 1. 크기 규약

| | 키 | 비고 |
|---|---|---|
| 여캐 4종 | **1.40 m** | |
| 남캐 4종 | **1.50 m** | |
| 몬이(마스코트) | **0.375 m** | 고정. 캐릭터 키에 연동하지 않음 |

- **1 GLB 유닛 = 1 미터**, **발바닥 y = 0**, XZ 는 바운딩 중심
- 크기가 GLB 에 이미 구워져 있음 — **엔진에서 추가 스케일 금지**

실사람 키(여 1.50 / 남 1.70)로 뒀더니 머리가 큰 3.5등신 치비라 방이 좁아 보였다.

그래서 캐릭터 뷰어(base)와 모션 뷰어(rigged)가 **서로 다른 크기**를 보여주고 있었다.

키를 바꾸려면 `tools/char/rescale_char_glb.py` 의 상수 두 개만 고쳐 다시 돌린다.
정점을 건드리지 않고 씬 최상단 `__scale_root` 래퍼에 scale/translation 만 얹으므로
**모션 클립 128개는 손대지 않아도 된다.** 래퍼가 이미 있으면 벗기고 재계산하므로
여러 번 돌려도 안전하다.

`jachwi_f` `yeoja_gajang` `yeoja_jubu` `yeoja_researcher`

### 경량본을 쓸 것

| | 삼각형 | 텍스처 | 용량 |
|---|---|---|---|
| 원본 | 평균 22.5만 | 2048² | 500 MB |
| **경량본 `lq/`** | **평균 2.2만** | 1024² (몬이 512²) | **74 MB** |

전체 840만 → 82만 삼각형(9.7%). 방 전체와 같이 돌리면 원본은 눈에 띄게 버벅인다.
게임 화면은 `lq/`, **초상화·클로즈업·재리깅에만 원본**을 쓴다.

감축은 meshoptimizer(gltf-transform)로 한다. **trimesh 계열은 스킨 웨이트를
파괴하므로 쓰면 안 된다.** 37개 전부 `JOINTS_0`/`WEIGHTS_0`·본 24개·애니 채널 수·
실스케일·노드 이름을 원본과 대조 검증했고, 형상 편차는 표면적 0.12%·외곽 0.8mm
이내다(몬이만 더 공격적으로 줄여 0.54%·1.8mm).

## 3. 모션 19종 · 클립 128개

| 경로 | 클립 |
|---|---|
| `3d/{id}_{k}.glb` | `idle` `walking` `walking_w`(여캐만) |
| `3d/anim/{id}_{k}.glb` | `inspect` `repot` `pickup` `harvest` `harvest_crouch` `opendoor` `sleep` `doze` `sit` `happyjump` `heart` `cheer` `wave` `nod` `listen` `scratch` |

Meshy 는 애니마다 스킨드 메시(≈15MB)를 통째로 재출력하지만 실제 애니 데이터는
68KB 뿐이다. `tools/char/strip_anim_glb.py` 로 메시·텍스처를 벗겨 **1.9GB → 16MB**
로 줄였다(99.5%). 144개 accessor 를 비트 단위로 대조해 동일함을 확인했다.

**클립은 캐릭터에 종속되지 않는다.** Meshy 리깅 8종의 본 이름·순서와 전체 노드
이름 집합이 동일하다(표준 24본). 클립은 노드 이름으로 바인딩되므로 어느 캐릭터에나,
원본·경량본 어느 쪽에나 붙는다. 128 × 2 = 256 조합 바인딩 검사 **실패 0건**.

> 캐릭터를 재생성하고 다시 리깅해도 **모션 384cr 을 다시 태우지 않아도 된다.**

### 알려진 결함 (수정 완료)

- 12개 클립(idle ×8, walking_w ×4)의 Hips 에 uniform scale 1.1765 가 들어 있어
  모션 전환 시 캐릭터가 17.65% 커졌다 → `normalize_anim_scale.py` 로 1.0 정규화
- 걷기 클립은 전진 모션이다. 제자리에서 보려면 Hips 의 XZ 를 매 프레임 고정한다

## 4. 색 커스터마이징 — 접음 (2026-07-26)

> ★ **2026-08-23 보탬 — 이 절을 「텍스처는 손 못 댄다」로 읽지 말 것.**
>
> 여기서 접은 것은 **런타임에 부위별로 색을 바꾸는 것**이다. 아틀라스 한 장에 다 구워져
> 있어서 「셔츠만」 골라낼 수가 없었다. 그 벽은 지금도 그대로다.
>
> **아틀라스를 통째로 다시 굽는 것은 다른 이야기고, 그건 된다.**
> `meshy_retexture` 의 `enable_original_uv: true` 는 **메시와 리그를 그대로 두고 텍스처만**
> 새로 낸다(10크레딧/벌). 옷을 「그려 입히는」 방식이라 **부피는 안 생기지만** 색·무늬·재질은
> 바뀐다. 캐릭터 베이스 새 구축(§8)이 이 길로 간다.
>
> ⚠ 내가 이 둘을 같은 것처럼 써 온 탓에, [Asset] 이 되는 길을 이 문서를 근거로
> 막을 뻔했다. **「부위별 마스크」와 「전체 재생성」은 다른 일이다.**


머리·눈썹·피부 색을 게임에서 바꾸려던 것. **접었다. 게임은 원본 색 그대로 간다.**
마스크 8종(`masks/`)과 도구는 남겨뒀으니 나중에 재시도할 때 처음부터 하지 않아도 된다.

### 전제부터 틀렸다

부위별 mesh/material 분리가 **경량화 때문에 깨진 게 아니라 애초에 없었다.**

| | 원본 8종 + 몬이 | 경량본 |
|---|---|---|
| mesh / primitive / **material** | 1 / 1 / **1** | 1 / 1 / **1** |
| **morph target** | **0** | **0** |

Meshy 는 머리·눈·옷·피부를 **2048² 아틀라스 한 장에 구워 단일 머티리얼**로 내보낸다.
감축 옵션에서 머티리얼 병합을 꺼도 달라지지 않는다. 블렌드셰이프도 없고, 리깅은
몸통 24본뿐이라 얼굴 본도 없다.

→ 자세한 제약은 `docs/character_material_constraint.md` (plan 소유)

### 우회로 — 마스크 텍스처

같은 UV 의 마스크로 텍셀 단위로 부위를 골라낸다. 명도비를 목표색에 곱해 음영을
보존하고, **로딩 시 캔버스에서 한 번만** 계산한다(셰이더 매 프레임 아님).

`tools/char/make_part_mask.py` → `masks/{char}_mask.png`
R 채널 인덱스 맵: 24 머리+눈썹 / 48 홍채 / 72 흰자·속눈썹 / 96 상징물 / 120 피부 /
144 상의 / 168 하의 / 192 신발 (G=B=0, A=255, 허용오차 ±10)

### 어디서 막혔나 — 다시 시도할 사람을 위해

큰 덩어리(머리·피부·옷·신발)는 잘 잡힌다. **눈 주변에서 끝내 안정되지 않았다.**
여성 3종(자취녀·여주부·여연구원)은 눈꼬리가 눈썹 쪽으로 올라간 형태라 눈 영역
모서리에 색 조각이 남는다.

가는 길에 밟은 함정들 — **같은 데서 막히지 말 것:**

| 함정 | 증상 | 해법 |
|---|---|---|
| **알파를 데이터 채널로 씀** | 하의만 색이 바뀜 | 캔버스는 프리멀티플라이드 알파라 `A=0` 텍셀의 RGB 가 0 으로 뭉개진다. A 는 255 고정, R 채널에 인덱스 |
| **UV 세로 반전** | 색과 위치가 전혀 안 맞음 | glTF 는 v 가 **아래로** 증가한다. `1-v` 로 뒤집으면 안 됨 |
| **정점 splat + 최근접 채우기** | 신발이 티셔츠로, 뒤통수가 눈으로 | UV 섬 경계를 넘어 번진다. **삼각형 래스터화**로 |
| **UV 공간 팽창** | 눈 라벨이 허리 높이에 나타남 / 눈썹엔 안 닿음 | 아틀라스는 섬이 빽빽하다. 섬을 건너뛰거나 못 건넌다. **3D 좌표로 판정** |
| **구(球)로 눈 영역** | 이마·앞머리까지 보호됨 | 반경 하나로 가로·세로가 같이 커진다. **축별 3D 상자**로 |
| **색만으로 분류** | 베이지 앞치마가 피부로 | 흰 신발↔흰 티셔츠, 검은 재킷↔검은 스커트는 색이 같다. **위치 우선, 색 보조** |
| **여백 미채움** | 이음매가 그물처럼 남음 | 섬 바깥 패딩에 라벨이 없으면 필터링이 원래 색을 물어온다. 최근접 라벨로 전부 메울 것 |
| **동어반복 검증** | "전수 통과"인데 실제론 틀림 | 높이로 라벨을 만들고 그 라벨의 높이를 확인하면 당연히 통과한다 |

**실측값 (재사용 가능):**
피부 R−G 는 24~48, 옷은 −20~+39 로 **겹친다** — 전역 임계값이 없다.
남주부의 베이지 셔츠는 그의 얼굴과 색도 거리 0.0247 로, 남연구원의 손(0.0374)보다
얼굴에 더 가깝다. 어떤 색공간으로도 안 갈린다.
눈: 흰자 반높이를 1 로 보면 **속눈썹 1.0~1.94 배 위, 눈썹 3.98~6.31 배 위.**

**검증은 반드시 렌더로.** 아틀라스 이미지는 UV 배치가 뒤섞여 있어 판단이 불가능하다.
`tools/char/preview_mask.py`(부위색) · `preview_recolor.py`(색 교체 결과) 가 브라우저
없이 3D 정사영으로 그려준다. 뷰어와 같은 알고리즘이라 여기서 맞으면 뷰어에서도 맞다.

### 7-4 표정 키는 [core] 소유다

`FACE_FILE`(`game.html`)은 **그림 목록이 아니라 「대사 키 → 파일 이름」 사전**이다.

### 8-1 「갈아끼우기」 — 되는 것과 안 되는 것

| 방식 | 되나 | 값 | 무엇에 |
|---|---|---|---|
| ㉮ 텍스처를 통째로 다시 굽는다 (`retexture` + `enable_original_uv`) | O | 10cr/벌 | **옷 색·무늬·재질.** 부피는 안 생긴다 |
| ㉯ 뼈에 딱 매단다 (three.js) | O | **0cr** | **머리카락 · 모자 · 안경 · 가방 · 눈알** |
| ㉰ 새 옷을 같은 뼈에 스키닝 | **X** | — | 셔츠·바지·치마 |

**㉰ 가 안 되는 이유** — Meshy 도구 목록에 **「이미 있는 스켈레톤에 새 메시를 스키닝한다」가
없다.** 있는 것은 `rig`(뼈를 새로 만든다) · `animate` · `retexture` 뿐이다. 옷을 따로 뽑으면
**자기만의 스켈레톤**을 가져서 몸 뼈에 못 붙는다. ([Asset] 이 전수로 확인)

> ⚠ **내가 여기서 틀렸다.** 나는 총괄에 *"㉰(덧씌우기) 이것뿐입니다"* 라고 올렸다.
> **도구가 그 동작을 제공하는지 확인도 않고** 설계를 권했다. [Asset] 이 잡았다.
> 같은 날 내가 [core] 에게 *"자를 알려진 것에 먼저 대 보라"* 고 해 놓고 나는 목록조차 안 봤다.

**대안** — 옷 껍데기를 절차적으로 만들고, **몸의 `JOINTS_0`·`WEIGHTS_0` 를 제일 가까운
정점에서 베껴** 스킨을 심는다. 0크레딧. [Asset] 안이고 아직 [추론]이다.
⚠ 그때 **겨드랑이·사타구니·팔 안쪽**을 조심할 것 — 유클리드 최근접이 **엉뚱한 팔뼈**를
물어 와서, 팔을 들면 옷이 한두 정점만 찢어지듯 늘어난다. 오류는 안 난다.
법선이 비슷한 것만 후보로 두면 걸러진다. (내가 마스크에서 같은 종류로 당했다)

### 8-3 ★ 눈 — **Meshy 는 구멍을 안 판다. 그런데 구멍이 필요 없다**
