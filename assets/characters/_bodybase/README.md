## ★ 이 판이 배운 것

1. **뷰는 «한 장 안에서» 뽑는다** — 따로 뽑으면 등신이 어긋나고, Meshy 는 그걸 «평균 내어» 뭉갠다.
   턴어라운드 시트 한 장 → `split_sheet.py` 로 가른다. 굽기 전에 키를 재어 8% 넘으면 막는다.
2. **리깅이 받는 것은 «포즈»가 아니라 «손»이다.**
   A포즈/T포즈 둘 다 422 였다. 손가락이 «갈라진» 원화로 구우니 그대로 통과했다.
   ⇒ 주걱 손(미튼)은 pose estimation 이 사람으로 못 읽는다 [셈].
3. **굽기를 다시 하면 «고친 것 말고 다른 것»이 흔들린다.**
   v8 은 가슴을 고쳤으나 얼굴을 잃었다. ⇒ 고칠 것이 하나면 **메시를 직접** 깎아라(크레딧 0).
4. **재질이 판정을 바꾼다.** `MeshToonMaterial` 이 굴곡을 뭉개 「귀·턱이 없다」로 잘못 물렸다.
   ⇒ `glb_shot.py` 는 재질 없이 «면의 기울기»만 칠한다. 그 자로 봐라.
5. **낼 파일 이름을 «짐작»하지 마라.** `g_front.png` 로 저장했다가 있던 파일 둘을 덮었다(67).

### 어떻게 나왔나 — 몸과 머리를 «갈라서» 만들었다
머리 크기와 몸 굵기가 프롬프트 한 낱말(chibi)에 묶여 있어 원화로는 사이가 안 나왔다.
  chibi 넣음 ⇒ 2.2등신·하체 굵음 / chibi 뺌 ⇒ 6등신 어른·하체 얇음·가슴 있음
⇒ 몸은 chibi «없이» 슬림하게 굽고(v14), 머리만 `tools/char/glb_head.py` 로 3D 에서 키웠다.
  리깅 «전»이라야 된다(뼈가 있으면 정점만 못 움직인다).

### 이 판에서 배운 것
· image_to_image 는 «크기»를 안 바꾼다 — 「머리를 훨씬 작게」 두 번(18cr) ⇒ 2.22→2.21
· 2D 로 머리를 잘라 붙이면 이음매가 각진다(shrink_head.py, 접음). 3D 라야 목에서 부드럽다
· glb_head 세 번 물림: 중심을 머리 한가운데 ⇒ 뒤통수로 밀림 / 목 아래만 blend ⇒ 어깨 접시 /
  목 위를 곧장 s배 ⇒ 머리 밑동 접시. 답: 목 아래는 «축 둘레만», 목 위는 «정수리까지 서서히»
· split_sheet 하체 관문은 «키»로 나눈다 — 어깨는 T포즈 팔 끝을 재고, 머리는 문제 그 자체다
· 시트 테두리를 «격자선 색»으로 칠하면 cut_bg_alpha 가 그것을 배경으로 삼는다(넷이 똑같은 %)
· 리깅은 로컬 GLB 를 못 받는다 ⇒ 푸시해 raw.githubusercontent.com URL 로 준다
