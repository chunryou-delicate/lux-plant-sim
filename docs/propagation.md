# 삽수(번식) — 정본

**2026-08-03 신설.** `story_arc.md` ④ *"삽수를 팔아 내 집 마련"* 의 실제 규칙이다.

> 정본은 `GAME_PLAN.md`. 이 문서는 그 §8(번식 — 킬러 콘텐츠)의 **미정 칸을 채운다.**
> 생장 규칙의 정본은 캐논(`monstera-growth-spec`)과 `docs/byeot_growth_chart_인계.md` 다.
> **여기서 캐논을 고치지 않는다.** 캐논에 이미 있는 개념만 쓴다.

## ★ 이 문서가 지킨 규칙

새 개념을 하나도 안 만들었다. 자르는 자리·모주 회복·삽수 공급 속도가 전부
**캐논의 마디 트리와 이미 확정된 값**에서 나온다. 새로 정한 것은
**물꽂이 기간·용기 슬롯 수·가격 공식·목표 금액** 넷뿐이고, 셋은 기존 값으로 검산했다.

| 이미 확정된 것 (뒤집지 않았다) | 어디 |
|---|---|
| 개체 소질 2층 — `base 0.10` × plain 0 / normal 1.0 / potential 2.5 / elite 6.0 | `plan-to-growth.md` 5차 §2 |
| `f_propagation` — batch `grade_mult 0.8` / individual `1.0` · `lineage_inherit 1.0` | 〃 §3 |
| 성숙 = 게이지 + 굴림(10~90%) · 중간잎 잠금 3% 환경 무관 | 〃 2026-08-03 |
| 삽수는 논문 표본이 못 된다 | `GAME_PLAN.md` §8 |
| 스토리 모드 전체가 초보 · 잎 손실 없음 | `story_arc.md` |

# 1. 어디를 자르나 — 캐논의 마디 트리 안에서

캐논 구조는 이렇다(`byeot_growth_chart_인계.md`).

```
node { id, up(위=생장점 방향), buds[], stem, isTip, isSeed }
stem ∈ { petiole, pink, thick, main }
bud  { stage(잎 0~4), side, special, childNode, probOverride }
```

## ★ 확정 — 자를 수 있는 것은 `stem`이 `pink` 이상인 마디다

| `stem` | 뜻(캐논) | 자를 수 있나 |
|---|---|---|
| `petiole` | 가는 잎자루. 아직 예비혹이 없다 | ❌ |
| **`pink`** | **분홍대기 — 혹이 날 가능성을 품음** | ✅ |
| **`thick`** | 눈이 활성. 여기서 가지가 남 | ✅ |
| **`main`** | 희귀(쌍혹) | ✅ |
| `bud` 만 | 잎 하나 | ❌ **잎꽂이는 안 된다** |

**왜 `pink` 가 경계인가.** 캐논이 `pink` 를 *"혹이 날 가능성을 품음"* 으로 정의했다.
그 가능성이 곧 **삽수가 새 생장점을 낼 수 있다는 것**이고, 그게 없으면 삽수는 자라지 못한다.
실제 몬스테라도 그렇다 — 마디(공기뿌리·눈이 있는 자리)가 없으면 물꽂이가 안 산다.
**잎만 떼면 절대 안 산다**는 것은 몬스테라에서 널리 알려진 사실이라,
플레이어가 한 번 해 보고 배우면 그 지식이 현실과 같다.

## ★ 자르면 무엇이 떨어져 나오나 — `up` 방향 전부

`up` 이 생장점 방향이므로, 자른 마디부터 `up` 을 따라 끝까지가 한 덩어리로 떨어진다.

```
      [isTip 생장점 · 잎 1장]  ┐
             |up               │
      [petiole]                ├─ 삽수 = 자른 마디 + 위 전부
             |up               │
      [pink]  ←★ 여기를 자른다 ┘
             |up
      [thick 눈 · 가지 1]  ┐
             |up            ├─ 모주로 남는다
      [pink]                │
             |up            │
      [isSeed 밑동]         ┘
```

## ★★ 그래서 트레이드오프가 저절로 생긴다

```
높이 자른다  →  삽수가 작다(잎 1장 · 12,000) · 모주는 거의 안 다친다
낮게 자른다  →  삽수가 크다(잎 3장 · 30,000 = 2.5배) · 모주가 크게 후퇴한다
```

**어느 마디를 고르느냐가 그대로 선택이다.** 규칙을 따로 만들 필요가 없고,
잘라낸 조각의 크기가 화면에 그대로 보인다.

## ★★ 가지(branch)를 자르는 것이 기본 경로다 — 캐논이 이미 그렇게 말했다

캐논 원문이 *"**가지를** 잘라 수경재배로 개체 수를 늘린다"* 이다. 구조상 정확한 표현이다.

```
잎이 중간잎이 되는 순간          (캐논 규칙 ④)
   → 예비혹(pink) 중 랜덤 하나가 눈(thick)이 된다
   → 그 눈에서 가는 잎자루가 나와 가지가 된다   (캐논 규칙 ②·③)
   → 그 가지가 자라 자기 pink 마디를 가지면 ★자를 수 있다
```

★ **가지를 자르면 모주 본체는 생장점을 하나도 안 잃는다.** 손실이 그 가지의 잎뿐이다.
그래서 *"가지가 날 때까지 기다렸다가 가지를 자른다"* 가 최적 전략이 되고,
그것이 실제 재배 방식과 같다.

★★ **삽수 공급 속도 = 중간잎 발생 속도.** 캐논 규칙 ④가 그렇게 묶어 놓았다.
그리고 중간잎 발생은 2026-08-03 에 확정된 **성숙 게이지**가 정한다 —
두 시스템이 새 배선 없이 이어진다. **빛을 관리하면 삽수도 빨리 나온다**가 저절로 성립한다.

# 2. 자른 뒤 모주 — 세 경우뿐이다

| | 무엇을 잘랐나 | 모주 |
|---|---|---|
| **①** | **가지** | 본체 무손실. 그 가지의 잎만 잃는다. **성장 안 멈춤** |
| **②** | 본체 윗동(생장점 포함) | 생장점을 잃는다 → 남은 예비혹 하나가 눈으로 승격 → 새 생장점 |
| **③** | 예비혹이 하나도 안 남게 | 새 생장점을 못 낸다 → **모주가 끝난다** |

## ★ ②의 회복 규칙 — 캐논 규칙 ④를 그대로 재사용한다

*"예비혹 후보 중 랜덤 딱 1개만 혹이 된다"* 를 그대로 쓴다. **새 규칙이 아니다.**

| | |
|---|---|
| 잎이 줄어드나 | **줄어든다.** 자른 조각이 품고 있던 잎만큼. 그 자리는 다시 안 난다 |
| 성장이 멈추나 | **새 생장점이 터질 때까지 멈춘다.** 기간은 캐논의 `bumpGrow` 그대로 |
| 되살아나나 | ② 는 되살아난다. **③ 은 안 된다** |
| 키 | **줄어든다.** 새 생장점이 아래 마디에서 나므로 |

★ 새 숫자를 하나도 안 만들었다. `bumpGrow` 는 이미 튜닝값에 있다.

## ★ 스토리 모드에서는 ③을 아예 막는다

`story_arc.md` 확정 — **스토리 모드 전체가 초보이고, 잎도 안 떨어진다.**
모주를 죽이는 조작은 잎 손실보다 큰 손실이라 그 방침과 어긋난다.

```
초보(스토리)   ③에 해당하는 마디는 「자를 수 없음」으로 표시된다. 실행 자체가 없다
자유·고수      열린다. 경고만 뜨고 플레이어가 정한다
```

`first_play.md` §4의 *"무엇을 숨기고 무엇을 말해 주나"* 와 같은 종류의 선이다.

# 3. 뿌리내리기 — 물꽂이

## ★ 확정 — 12 게임일. 스토리 모드에서는 실패하지 않는다

| | 값 | 왜 |
|---|---|---|
| 뿌리내리기 | **12 게임일** | 새 숫자를 안 만들었다 — 성숙 게이지 `gauge_days` 가 12 이고, 몬스테라 첫 잎 11일·콩나물 4턴과 같은 자릿수다. 관찰 리듬이 이미 있다 |
| 실패 | **없음 (스토리)** | 스토리는 초보다. 잎도 안 떨어지는데 삽수가 썩으면 방침이 어긋난다 |
| 빛 | **무관 (스토리)** | 물꽂이에는 `min 3.0` 이 필요 없다 |
| 물 | **면제** | 물속이라 마름 게이지가 없다 |

★ **12일은 실제와도 맞는다.** 몬스테라 물꽂이는 뿌리 2~3주, 심을 만큼 나오는 데 4~6주다.
게임일 12일이면 그 앞쪽이고, 초보 단계에서 기다림이 벌이 되지 않는 길이다.

## ★★ 물꽂이가 빛을 안 쓰는 것이 이 게임에서 중요하다

```
증식(물꽂이)  어두운 칸에서 된다   ← 시루와 같은 성격
육성(화분)    밝은 칸이라야 된다   ← min 3.0 · 무늬는 7.0~15.4
```

★ **슬롯 압박의 위치가 "증식"이 아니라 "육성"으로 옮겨간다.**
뿌리내리는 데는 자리가 안 아깝고, **뿌리 내린 뒤 밝은 칸으로 옮기는 순간** 압박이 온다.
`game_flow.md` §4의 *"등은 증식의 세금이다"* 가 그대로 유지된다 — 세금은 물꽂이가 아니라 등이다.

그리고 반지하·원룸의 어두운 칸이 **또 하나의 용도**를 갖는다. 시루(콩나물)와 물꽂이가
같은 칸을 놓고 다투게 되므로, 어두운 칸도 관리 대상이 된다.

## 자유·고수 모드에서 생기는 것 (스토리에는 없다)

| 실패 요인 | 근거 |
|---|---|
| 환수(물갈이)를 안 하면 썩는다 | 실제 물꽂이의 유일한 관리 행동 |
| 온도가 낮으면 뿌리가 안 난다 | `env_params.md` 온도 계수 |
| **잎이 없는 조각**은 거의 안 산다 | 광합성을 못 하면 뿌리 낼 에너지가 없다 |

★ 마지막 줄이 *"잎째 잘라야 한다"* 는 제약을 만든다. §1의 「잎꽂이 불가」와 같은 뿌리다.

## 화분 직삽(물꽂이 생략) — ⏸ 스토리 범위 밖이다

`GAME_PLAN.md` §8 미정 *"물꽂이 생략 페널티(바로 화분 → 진행 지연 며칠?)"* 에 대한 답이다.

**스토리 모드에서는 경로를 하나만 둔다 — 물꽂이뿐이다.**
직삽의 위험은 *"흙이 마르거나 과습이면 썩는다"* 인데 **스토리에는 물이 없어서 차이를 못 만든다.**
차이가 없는 선택지는 선택이 아니라 헷갈림이다.

→ **물 시스템이 들어오는 모드부터 직삽이 열린다.** 그때의 값은 `env_params.md` 와 같이 정한다.

# 4. 물꽂이 용기 슬롯 수 — ★ leaf 대기 항목의 답

`STATUS.md` plan 대기: *"leaf — 물꽂이 용기 슬롯 수(증식 단계가 슬롯을 얼마나 먹나)"*

## ★ 확정 — 용기가 둘이고, 그 차이가 곧 `f_propagation` 이다

| 용기 | 방 슬롯 | 삽수 칸 | 등급 계승 | 에셋 |
|---|---|---|---|---|
| **물꽂이 트레이** (batch) | **1칸** | **6칸** | **×0.8** | ⏸ 신규 — 재배트레이 재사용 검토 |
| **유리 수경병** (individual) | **1칸** | **1칸** | **×1.0** | ✅ `pot_glassjar.glb` (manifest id 116) |

★★ **`f_propagation` 의 batch/individual 이 이 한 줄이다.**
`plan-to-growth.md` 5차 §3이 *"individual 은 손이 더 가는 대신 손실이 없다"* 고 적었는데,
**그 「손」이 슬롯 6배**다. 값을 새로 안 만들고 확정값에 몸을 붙인 것이다.

## 왜 6칸인가

| 근거 | |
|---|---|
| 기하 | 유리 수경병 `real_max_m` **0.13m**. 병은 지름이 있어 칸당 **12cm** 는 필요하다 |
| 밀도 선례 | 시루 0.24m / **15칸**(칸 5cm · 콩나물) · 재배트레이-소 0.36m / **12칸**(칸 9cm · 모종) |
| 계산 | 0.36m 트레이에 12cm 간격 → **3 × 2 = 6칸** |
| 경제 | 몬스테라 모주는 마디 하나에 30~40일이라 삽수가 그 주기로 나온다. 6칸이면 **모주 6그루분** — 원룸 규모와 맞는다 |

★ 시루(15칸)만큼 주면 안 되는 이유 — 시루는 콩나물이 5cm 씩 서는 것이고,
삽수는 잎이 달린 줄기 조각이라 **물리적으로 그 밀도가 안 된다.** 밀도를 억지로 맞추면
*"방 슬롯 1칸이 15배"* 라는 시루의 값어치가 흐려진다.

## ⏸ 판단필요 — leaf·house 확인

- [ ] **물꽂이 트레이 GLB 가 없다.** `container_tray_s.glb`(0.36m·12칸)를 슬롯만 6으로 줄여
      재사용할 수 있는지, 아니면 새로 뽑아야 하는지 (leaf)
- [ ] 6칸의 실측 배치 좌표 (leaf)
- [ ] 트레이 `mount` — 시루가 `floor` 인데 물꽂이도 바닥인지, 선반 위인지 (house)

# 5. 무늬 유전 — 확정값을 어떻게 굴리나

## ★ 캐논의 "80%" 가 `grade_mult 0.8` 에서 정확히 나온다

캐논: *"모주가 무늬면 그 삽수는 훨씬 높은 확률(**80% 수준**)을 물려받는다."*
확정값: `f_propagation.batch.grade_mult = 0.8`.

**최적 관리**(무늬 최적 대역 DLI 7.0~15.4 → `f_light` 1.5 · CV<0.15 → `f_stable` 1.3)에서
잎 하나가 무늬일 확률은 `0.10 × 1.5 × 1.3 × mult = 0.195 × mult` 다.

| 소질 | 모주(0세대) | 삽수(1세대) | 비 |
|---|---|---|---|
| plain (0.0) | 0% | 0% | — |
| **normal (1.0)** | **19.5%** | **15.6%** | **0.80** ★ |
| potential (2.5) | 48.8% | 39.0% | 0.80 |
| elite (6.0) | 100%(상한) | 93.6% | 0.94 |

★ **normal 개체 기준으로 정확히 80%다.** 캐논 문장과 확정값이 어긋나지 않는다.
elite 는 상한에 걸려 있어 체감상 *"거의 그대로 물려받는다"* 가 되는데,
캐논이 말한 *"훨씬 높은 확률"* 과 같은 방향이다.

## ★★ 세대 감쇠 — 무한 복제를 물리가 막는다

`grade_mult 0.8` 은 **세대마다** 곱해진다. 규칙을 따로 안 만들어도 감쇠가 생긴다.

| 세대 | plain | normal | potential | **elite** |
|---|---|---|---|---|
| 0 (실생) | 0% | 19.5% | 48.8% | **100%** |
| 1 | 0% | 15.6% | 39.0% | **93.6%** |
| 2 | 0% | 12.5% | 31.2% | 74.9% |
| 3 | 0% | 10.0% | 25.0% | **59.9%** |
| 4 | 0% | 8.0% | 20.0% | 47.9% |
| 5 | 0% | 6.4% | 16.0% | 38.4% |

```
0.8ⁿ = 0.5  →  n = 3.1
★ 삽수 3세대마다 무늬가 반으로 준다
```

★ **외우기 쉽고 플레이어가 스스로 발견할 수 있다.** *"복제를 계속하면 흐려진다"* 가
잎에 그대로 보인다. `hidden_depth.md` §0의 「물리에서 나온 것만 숨긴다」에 맞는 재료다.

★ **plain 은 복제해도 영원히 0이다** (0 × 0.8 = 0). *"안 되는 그루는 아무리 복제해도 안 된다."*
이것이 §7의 씨앗 선발을 필수로 만든다.

## ★★ 그래서 individual(개별 처리)에 값이 붙는다

```
6그루를 batch    슬롯 1칸 · 등급 ×0.8
6그루를 individual 슬롯 6칸 · 등급 ×1.0   ← 감쇠가 없다
```

| | batch 4세대 | individual 4세대 |
|---|---|---|
| elite 등급 | 2.46 | **6.00** |
| 무늬율 | 47.9% | **100%** |

**초반에는 안 남는다** — 1세대 차이는 93.6% vs 100%, 6.4%p 에 슬롯 5칸이다.
**세대가 쌓이면 자릿수로 갈린다.**

★ **「복제를 이어갈 계통은 개별로, 팔 것은 일괄로」** 가 후반 플레이가 된다.
`GAME_PLAN.md` §8 미정의 *"개별 처리 보너스 — 수고 ↔ 확률 트레이드오프"* 가 여기서 성립한다.

## 계열(lineage)은 100% 동일 — 그래서 논문 표본이 못 된다

`lineage_inherit = 1.0` 확정. `GAME_PLAN.md` §8의 정합 논리가 이 값이다.
**삽수 = 증식 / 씨앗 = 논문.** 이 문서는 그 구분을 건드리지 않는다.

## ★ 중간잎 잠금(3%)의 계승 — 잎은 따라가고 형질은 안 따라간다

2026-08-03 확정: *"잎이 `mid` 에 들어서는 순간 딱 한 번, **환경 무관** 고정 3%."*
같은 절이 *"번식으로 물려주는 것도 여기서 성립한다"* 고 적었는데, 두 해석이 갈린다.

| | 판정 | 왜 |
|---|---|---|
| **잠긴 잎을 품은 조각을 자르면 그 잎은 삽수에서도 잠긴 채다** | ✅ **확정** | 유전이 아니라 **물리적으로 같은 잎**이 딸려간 것이다. 규칙이 필요 없다 |
| **잠금 형질 자체가 유전된다** (삽수의 새 잎도 3% 초과) | ❌ **안 한다** | 잠긴 그루를 복제해 잠긴 잎을 **양산**하는 농사가 성립한다. 3%가 환경 무관인 이유가 바로 그 농사를 막는 것이었다 |

★ **삽수의 새 잎도 3% 그대로다.** 확정 문구의 *"번식으로 물려주는 것"* 은 위 ✅ 쪽으로 읽는다.
어느 자리에서 키우든 어느 세대든 **똑같이 드물다** — 그래야 값이 운으로 남는다.

### ⏸ 판단필요 — 잠긴 중간잎의 값

잠긴 잎은 영원히 갈라지지 않는다. 갈라짐을 원하는 사람에겐 하자이고,
중간잎 형태를 모으는 사람(주부의 도감·컬렉션)에겐 값이다.

| 후보 | |
|---|---|
| **㉮ 판매가에 안 넣는다** | 잎 수에는 들어가되 프리미엄 없음. **가장 단순** |
| ㉯ 수집 축에서만 값 | 도감·정원 완성도(주부 트랙)에 항목 추가 |
| ㉰ 별도 가격 | 새 가격 항목이 는다. 반대 |

**판단 기준**: 주부의 「목표 제시」(도감·정원 완성도)가 설계되는 시점에 같이 정한다
(`game_flow.md` §6 미해결). 그 전까지는 ㉮로 둔다.

# 6. 파는 값 — 기존 가격표를 공식 하나로 설명한다

`sale_economy.md` §3의 가격표를 **바꾸지 않았다.** 그 표를 낳는 공식을 찾은 것이다.

## ★★ 확정 — 가격 공식

```
값 = 단위기본가 × 크기 × (1 + K·v²)          K = 60
      v = 그루의 무늬 잎 비율 (0~1)
```

| 종 | 삽수 기본가 (잎 1~2장) | 성체 단위기본가 (잎 3장~) |
|---|---|---|
| **몬스테라** | 12,000 / 잎 | 10,000 / 잎 |
| **포토스** | 3,000 / 마디 | 3,750 / 마디 |

★ **삽수와 성체는 크기로 갈린다** — 잎(마디) **1~2장이면 삽수 가격표**, **3장부터 성체 가격표**다.
삽수 단가가 조금 높은 것은 *"작아도 최소 이만큼은 받는다"* 는 소품 프리미엄이고,
경계에서 값이 뒤집히지 않는다(잎2 삽수 24,000 → 잎3 성체 30,000).

## 검산 — 기존 값이 **오차 0으로** 맞는다

`v = 0.307` 하나를 「알보 · 무늬」 라벨의 기준으로 두면 일곱 값이 동시에 떨어진다
(`1 + 60 × 0.307² = 6.667`).

| `sale_economy.md` 값 | 공식 | 오차 |
|---|---|---|
| 몬스테라 삽수(일반) 12,000 | 12,000 × 1 | **0%** |
| 몬스테라 삽수(알보) 80,000 | 12,000 × 6.667 | **0%** |
| 몬스테라 성체(잎 6장) 60,000 | 10,000 × 6 × 1 | **0%** |
| 몬스테라 알보 성체 400,000 | 10,000 × 6 × 6.667 | **0%** |
| 포토스 삽수(일반) 3,000 | 3,000 × 1 | **0%** |
| 포토스 성체(무늬, 마디 6) 150,000 | 3,750 × 6 × 6.667 | **0%** |
| 포토스 희귀무늬 성체 800,000 | 3,750 × 6 × (1+60·0.759²) | **0%** |

★★ **일곱 개의 서로 다른 가격이 계수 하나(K=60)와 무늬율 하나(v=0.307)로 전부 재현된다.**
손으로 맞춘 표가 아니라 **공식이 있던 표**였다. 그래서 이 공식을 채택한다.

★ **「알보」= v 0.307 · 「희귀무늬」= v 0.759** 가 저절로 나왔다.
라벨을 붙인 게 아니라 기존 가격이 그렇게 말하고 있었다.

★ 어긋나는 것 하나 — 포토스 삽수(무늬) 15,000 은 **v = 0.258** 이라야 맞는다.
**종마다 「무늬」 라벨의 기준 v 가 다르다**로 읽는다. 실제로도 포토스 마블퀸·골든은
몬스테라 알보보다 무늬가 옅다. **가격을 고치지 않는다.**

## ★★ 왜 v² 인가 — 이게 엔딩 경로를 성립시킨다

| 이유 | |
|---|---|
| **시장** | 실제 무늬 식물 값은 무늬 면적에 대해 **볼록**하다. 얼룩이 조금 있는 것은 값이 거의 안 붙고, 하이라이트는 자릿수가 뛴다 |
| ★ **게임** | 선형이면 *"무늬 잎을 조금씩 여러 그루"* 가 최적이 되어 **선발이 무의미해진다.** 볼록해야 **한 그루에 몰아주는 것**이 이득이고, 그래야 「elite 선발 → 복제 → 집중 육성」이라는 ④ 엔딩 경로가 성립한다 |

## ★ 값은 보이는 것으로만 매긴다

`v` 는 소질 등급이 아니라 **그 그루에 실제로 난 무늬 잎의 비율**이다.
소질 등급은 화면에 안 나온다. 플레이어는 **잎을 세어서** 값을 읽는다.

→ 정보 축(`GAME_PLAN.md` §3 — 초보 숫자 / 표준 막대 / 고수 없음)과 일관된다.
그리고 *"이 그루가 좋은 그루다"* 를 **관찰로** 알게 된다.

# 7. 엔딩까지 몇 그루인가

## ★ 먼저 — 일상 흑자로는 절대 못 간다

`game_flow.md` 부록의 자취생 흑자는 **선반 6개 · 관엽 29칸 · +2,348원/일** 이다.

```
1,000만원 ÷ 2,348원/일 = 4,259일     ← 불가능
```

★ **④ 엔딩도 「한 방」이다.** 일상 흑자는 버티는 장치일 뿐이다.
`sale_economy.md` §1의 *"자취생은 흑자 게임이 아니라 타임어택"* 이 ④까지 그대로 이어진다.
이건 밸런싱 실패가 아니라 **이 게임이 처음부터 그 모양**이었다.

## ★ 확정(후보) — 목표 금액 **1,000만원**

| 근거 | |
|---|---|
| 스케일 | 원룸 이사 150만의 **6.7배**. 단계가 하나 올라간 무게 |
| 서사 | 실제로 1,000만원은 *"계약금 / 보증금 일부"* 다. 게임은 **계약하는 순간**까지고 집값 전액이 아니다 — 월세 첫 달 유예와 같은 종류의 서사 장치다 |
| 역산 | 아래 표대로 **4~17그루**라는 손에 잡히는 수가 나온다 |

> ⏸ **금액은 후보다.** ③ 원룸의 슬롯 수·월세가 정해지면(`story_arc.md` §5 미확정)
> 재역산한다. **구조(4~17그루 · 관리 수준이 그 폭을 가른다)는 확정이다.**

## 몇 그루인가

최적 관리(DLI 7.0~15.4 · CV<0.15) 기준. 값은 §6 공식.

| 무엇을 파나 | v | 한 그루 값 | **1,000만원까지** |
|---|---|---|---|
| **elite 계통 성체(잎 6장)** | 0.936 | 3,213,960 | **★ 4그루** |
| elite 계통 성체(잎 3장) | 0.936 | 1,606,980 | 7그루 |
| **elite 계통 삽수(잎 1장)** | 0.936 | **642,790** | **16개** |
| potential 계통 성체(잎 6장) | 0.390 | 607,560 | 17그루 |
| normal 계통 성체(잎 6장) | 0.156 | 147,600 | 68그루 — 사실상 불가능 |
| (참고) 포토스 희귀무늬 성체 | 0.759 | 800,000 | 13그루 |

★★ **「성체 4그루냐 삽수 16개냐」가 마지막 선택이다.**
`sale_economy.md` §3이 만든 *"오늘 버티려고 파느냐, 탈출하려고 키우느냐"* 가
엔딩에서 한 번 더 나온다. 같은 구조를 두 번 쓰는 것이고, 두 번째는 플레이어가 이미 안다.

★ **종으로도 갈린다.** 몬스테라는 마디 30~40일이라 **느리고 비싸고**,
포토스는 마디 7~10일 등속이라 **빠르고 싸다**(`sale_economy.md` §3).
1,000만원은 몬스테라 4그루로도, 포토스 13그루로도 닿는다.
`story_arc.md` §2의 「세 경로가 다 유효해야 한다」와 같은 원칙을 종에도 적용한다.

## ★ elite 를 못 잡으면 어떻게 되나 — 막히지는 않는다

소질 분포는 plain 70% / normal 25% / potential 4% / elite 1% 다.
**70%의 확률로 첫 몬스테라는 plain 이고, plain 은 복제해도 영원히 0%다.**
그래서 ③ 원룸에서 **씨앗 선발**이 열려야 한다.

| 씨앗 | potential 이상 | elite |
|---|---|---|
| 20개 (1회전 11일) | 64% | 18% |
| **60개 (3회전 33일)** | **95%** | **45%** |

★ **3회전이면 potential 이상이 95% 나온다. elite 는 절반만 나온다.**

```
elite 를 잡았다    →  성체 4그루 · 짧게 끝난다
potential 뿐이다   →  성체 17그루 · 오래 걸린다
```

★★ **운이 결과를 가르되 막지는 않는다.** `sale_economy.md` §3의
*"희귀가 24일차 이전에 나와야 한다"* 와 같은 종류의 긴장이고,
이번엔 **실패가 파산이 아니라 지연**이라 마지막 단계에 어울린다.

## ★ 첫 플레이 몬스테라는 소질 **normal 고정**

**확정.** 이유:

- 첫 플레이는 **학습**이다. 70% 확률로 *"무늬가 영영 안 나는 개체"* 를 쥐여 주면
  플레이어는 자기가 뭘 잘못했는지 영영 모른다
- `first_play.md` 가 이미 **초기 진행도 143 을 고정**했다. 튜토 개체를 확정하는 선례가 있다
- normal 이면 최적 관리에서 19.5% — *"관리하면 가끔 나온다"* 라서 배움이 성립한다.
  그리고 **그것만으로는 엔딩에 못 가서**(68그루) 씨앗 선발의 이유가 생긴다

> ⚠ `first_play.md` 는 초기 진행도·슬롯까지만 고정했고 **소질은 아직 안 적혀 있다**
> (소질 2층 구조가 코드에 붙기 전이라 적을 자리가 없었다).
> **이 한 줄은 `first_play.md` §3에 옮겨져야 한다** — 그 파일은 이 창의 소유가 아니라 옮기지 않았다.

## ⏸ 시간은 여기서 못 낸다 — 넘겨짚지 않는다

그루 수는 위에서 나왔다. **며칠인지는 통합 시뮬 없이 못 낸다.**

★ **병목은 판매가 아니라 삽수 공급 속도다.**

```
모주 한 그루  →  삽수 하나 / 마디 하나   (몬스테라는 30~40일)
심은 삽수     →  자라서 다시 모주가 된다  → ★지수 증식
```

`game_flow.md` §4가 포토스로 실측한 바로 그 곡선이고(*"지수 증식은 시작이 느리다"*),
**몬스테라는 마디 주기가 3~4배라 더 느리다.** 그리고 `sale_economy.md` §0이
*"몬스테라는 뒤로 갈수록 마디가 느려진다"* 를 곡선으로 재 두었다.

세 값이 곱해져 결과가 갈리므로 손으로 못 짚는다:

| 축 | 폭 |
|---|---|
| 계통 등급 | elite(4그루) ↔ potential(17그루) |
| 종 | 몬스테라(느림·비쌈) ↔ 포토스(빠름·쌈) |
| 팔까 심을까 | 지금 팔면 증식이 멈춘다 |

→ **`sim.js` 시나리오에 「④ 엔딩까지 며칠」을 하나 추가해서 재는 것이 맞다.**
`game_flow.md` §4의 지렛대 실측이 이미 그 방식이고, 방 조립 없이 90일이 7ms 다(`STATUS` core).

**확실한 것만 적어 둔다** — 씨앗 선발 3회전은 **33 게임일**이고(회전 11일 × 3),
물꽂이는 **12 게임일**이다. 이 둘은 고정이라 어떤 시나리오에서도 바닥값으로 깔린다.

★ `story_arc.md` §5의 *"이사까지의 목표 플레이 시간은 빨리감기 실측 뒤에 나온다"* 와
같은 이유로, 실시간 환산도 여기서 정하지 않는다.

## ⏸ 판단필요 — ③ 원룸이 갖춰야 할 최소 슬롯

위 계산이 성립하려면 원룸에 이만큼이 필요하다. **story_arc.md §5 미확정 항목에 대한 요청**이다.

| 용도 | 칸 | |
|---|---|---|
| 모주 | 2~3 | 밝은 칸 |
| 씨앗 선발 | 20 | 밝은 칸 · 회전당 |
| 육성 | 4~17 | 밝은 칸 |
| 물꽂이 트레이 | 1~2 | **어두워도 된다** |
| 콩나물 시루 | 2~3 | 어두운 칸 |

★ 선발(20)과 육성(17)이 **동시에 필요하지 않다**(전반/후반이 갈린다) → 겹쳐 쓸 수 있다.
→ **밝은 칸 최소 20 · 어두운 칸 최소 4 · 방 슬롯 합계 최소 24칸.**
반지하(13칸 + 선반 6개 = 31칸)와 비슷하거나 조금 크면 된다.

      설계는 끝나 있다(`growth-multiplant-design.md`). **번식 구현은 그 리팩터 뒤다** (growth · core)
