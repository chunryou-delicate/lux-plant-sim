# 볕 에셋 스케일 규약 — 실제 미터계 (2026-07-23)

> 집(`data/house_rooms.json`)이 실제 미터로 확정되어, **모든 에셋을 같은 미터계에 맞춤**.
> 코드 창은 이 문서 + `assets/manifest.json` 만 보면 배치 가능.

## 1. 핵심 규칙

에셋 GLB는 **두 종류**이고, 다루는 법이 다르다.

| 종류 | 예 | GLB 원본 크기 | 로드 후 |
|---|---|---|---|
| **Meshy 생성물** | 잎·화분·조명·아이템·집모듈 | **정규화됨(최대축 1.0 또는 2.0)** — 실제 크기 아님 | **`scale_to_real` 을 균등 곱해야 함** |
| **절차적 생성물** | 가구·선반 7종 (`source:"procedural"`) | **이미 실제 미터** | `scale_to_real = 1.0` (그대로) |

```js
// 배치 코드 예
const e = manifestItem;                 // is_glb:true 항목
const gltf = await loader.loadAsync(`assets/${e.path}`);
gltf.scene.scale.setScalar(e.scale_to_real);   // ← 이 한 줄이면 실제 크기
```

**GLB 파일 자체는 리스케일하지 않았다.** 저장소가 2GB라 158개를 다시 구우면 블롭이 통째로 쌓여 푸시가 크게 느려지기 때문. 배율은 manifest 필드로만 관리한다(값 조정도 즉시 가능).

## 2. manifest 필드

모든 `is_glb:true` 항목(158개)과 연결된 2D 항목에 부여됨:

| 필드 | 뜻 |
|---|---|
| `scale_to_real` | 로드 후 곱할 균등 배율 |
| `real_max_m` | 실제 세계에서 **가장 긴 축**의 길이(m) |
| `glb_raw_max` | 원본 GLB의 최대축(정규화값) |
| `size_basis_cat` | 치수 기준이 된 분류(성장단계 우선) |

manifest 최상위 `_scale_convention` 에도 같은 규약이 기록되어 있다.

## 4. 선반 = 배치 슬롯을 가진 유일한 에셋

가구·선반 7종은 화분을 올릴 **슬롯 좌표를 직접 들고 있다**(총 37개). 좌표는 GLB 로컬 기준 미터.

```json
"slots": [{"x":-0.31,"y":0.074,"z":0.0}, ...],
"tier_heights": [0.074, 0.434, 0.794],
"size_m": {"w":0.72,"d":0.28,"h":0.794},
"kind":"etagere", "tiers":3, "mount":"floor"
```

- `mount`: `wall`(벽걸이) · `floor`(바닥) · `floor-mobile`(카트, 이동 가능) · `lean-wall`(사다리) · `window`(창턱)
- `tier_heights` → **단이 높을수록 조도 유리**. 조도 계산 입력으로 쓸 것.
- `has_light:true`(그로우랙)는 `light_bars[].y` 에 식물등 높이가 있음 → 자체 광원.

**화분을 슬롯에 놓는 법**: 화분 GLB에 `scale_to_real`을 곱한 뒤, 바운딩박스 **바닥면(y_min)** 을 슬롯 `y` 에 맞추고 x·z 를 슬롯에 맞춘다.

## 5. 주의 — 집 모듈 GLB는 사실상 대체됨

`assets/house/house_mod_*.glb`(창호·문 프레임 4종)는 Meshy 산출물이라 배율이 필요하지만, 코드 창이 **`data/window_presets.json` 의 코드 생성 창틀 30종**으로 전환했다. 실사용은 코드 프리셋 쪽이고, GLB는 참고용으로 남긴다.
