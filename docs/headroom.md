## 1. 머리공간(headroom)이란

**그 자리 위로 비어 있는 높이[m]** 다. 화분 밑면(= 슬롯 y)부터 위쪽 첫 장애물 밑면까지.

```
머리공간 = min( 천장, 내 위 차폐체의 밑면, 내가 앉은 가구의 윗단 밑면 ) − 내 y
```

세 가지를 본다. **셋 다 실제 조립 결과에서 읽는다** — 지어낸 값이 없다.

| 무엇 | 어디서 | 반지하 예 |
|---|---|---|
| 천장 | `built.size.h` | 2.30m (반지하) |
| 차폐체 | `built.occluders[]` 의 `y0` (내 y 보다 **위에서 시작하는 것만**) | 창턱 받침 `y0 1.55` |
| 선반 윗단 | `room.slots` 를 uid 로 묶어 얻은 **단 높이** − 판 두께 | 에타제르 0.03 / 0.412 / 0.794 |

### 왜 선반 단은 차폐체로 못 보나 — 실제로 확인했다

`house.js` 는 가구 하나를 **통짜 상자 하나**로만 차폐체에 등록한다
(`house.js` 740행: `occluders.push({x, z, w, d, h:fsz.h, y0:yBase, ...})`).
반지하를 조립해 `built.occluders` 를 그대로 찍어 보면 6개뿐이고, 3단 선반은 그중 하나다:

```
0 {x:-0.18, z:-2.07, w:0.36, d:0.24, h:0.035, y0:1.55, src:'furniture'}   창턱 받침
1 {x:-2.10, z:-1.50, w:1.10, d:2.00, h:0.94,  y0:0,    src:'furniture'}   침대
2 {x: 0.70, z:-1.80, w:1.20, d:0.60, h:0.74,  y0:0,    src:'furniture'}   책상
3 {x: 1.08, z:-1.07, w:0.44, d:0.44, h:0.89,  y0:0,    src:'furniture'}   의자
4 {x: 1.25, z: 1.075,w:0.90, d:0.45, h:0.80,  y0:0,    src:'furniture'}   서랍장
5 {x:-0.71, z:-1.86, w:0.72, d:0.28, h:0.794, y0:0,    src:'furniture'}   에타제르 3단  ← 판이 안 보인다
```

5번은 바닥(y0 0)부터 0.794 까지의 **한 덩어리**다. 아래 칸에 놓인 화분의 천장인
"둘째 단 밑면(0.382)"은 이 목록 어디에도 없다. 그래서 **단 높이는 슬롯에서 되뽑는다** —
`slotId` 가 `{가구 uid}:{단}` 이므로 같은 uid 의 슬롯 y 를 모으면 그게 단 목록이다
(에타제르: 0.03 · 0.412 · 0.794).

판 두께는 슬롯에 안 실린다. `furniture_pastel.js` 의 실제 값(`shelf_etagere` t=0.03 ·
`shelf_wall` t=0.035)을 읽어 `SHELF_BOARD_M = 0.03` 으로 뒀다. **지어낸 값이 아니라
읽어 온 값**이고, house 가 슬롯에 판 두께를 실어 주면 그날 이 상수를 지운다.

### 못 재면 null

방 치수를 모르면(정적 프로파일 경로 `room_profile.createProfileLight` 의 `room` 에는
`size` 도 `built` 도 없다) `headroomAt` 은 **null** 을 낸다. 0 으로 메꾸면 모든 자리가
막힌 자리가 되고, 무한대로 메꾸면 규칙이 없는 것이 된다. **못 쟀으면 막지 않는다.**

## 2. 키 — 화분 밑면부터 잎 꼭대기까지

### 어떻게 쟀나 (추정 아님)

`plant_grow.html` 의 형태는 `buildPlant()` 가 마디·잎을 실제로 쌓아 만든다 —
높이를 내는 식이 따로 없다. 그래서 **방에 실제로 놓이는 그루를 그대로 만들어 쟀다**:

```
plant_assemble.assemble({ growthDays: d, seed: 92158, potD: 0.20 })   ← room_view 가 부르는 그 함수
new THREE.Box3().setFromObject(g).max.y                               ← 화분 밑면(y=0) 기준 꼭대기
d = 0 … 1095 (1일 간격) · 헤드리스 크롬(tools/test_cdp.mjs) · 2026-08-03
```

* `seed 92158` 은 **게임이 실제로 쓰는 값**이다 — `room_view` 가 `spec.seed` 를 안 주면
  `plant_assemble` 이 `(o.seed ?? 92158)` 로 떨어진다.
* `potD 0.20` 은 `room_view.MONSTERA_POT_D`. 반지하 슬롯은 전부 한도가 0.20 이상이라
  이 방에서는 항상 0.20 이다.
* **화분 지름에 선형**이다 — `plant_assemble` 이 그루 전체를 `potD/원본지름` 배율로 줄인다.
  그래서 표 하나로 모든 화분 지름을 낸다.

### 실측 곡선

| 유효 생장일 | 총 키[m] | 무엇 |
|---|---|---|
| 0 | **0.133** | 화분만 (= 화분 높이) |
| 45 | 0.319 | 새싹 끝 |
| 100 | 0.413 | |
| **143** | **0.540** | ★ 도착 개체 |
| 146 | 0.543 | 말린 새순 |
| 300 | 0.614 | |
| 453 | 0.653 | |
| **454** | **0.717** | ★ 잎 한 장이 펴지며 6cm 가 한 번에 오른다 |
| 730 | 0.808 | 2년 |
| 1095 | 1.027 | 3년(GMAX) |

곡선은 **계단**이다. 잎이 펴질 때 키가 한 번에 오르고 그 사이는 평평하다 —
"어느 날 갑자기 막힌다"가 그래서 생긴다(그래서 경고 띠가 필요하다, §4).

`headroom.js` 는 이 곡선을 세로 오차 **0.006m** 안에서 줄인 35점 꺾은선으로 갖는다.
유효 143일 모델값 0.5399 / 실측 0.5403 — 차이 0.4mm.

씨앗을 바꾸면 값이 달라진다: 143일에서 **±7%**(0.504~0.540), 1095일에서 **±37%**
(1.007~1.380). 지금 게임은 씨앗이 하나라 문제가 아니지만, 개체마다 씨앗을 다르게 주는
날이 오면 §7 의 room_view 제안(실제 bbox 를 받는 길)이 필요해진다.

## 3. 막혔을 때 무엇이 일어나나

**즉시 정지다. 서서히 느려지지 않는다. 그리고 죽지 않는다.**

| | 일어나나 |
|---|---|
| 유효 생장일이 오른다 | **아니오** — `loop.js` 가 `io.growth.advanceTo` 를 안 부른다 |
| 달력(코어 날짜)이 간다 | 예 |
| 돌본 날(`daysPlanted`)이 는다 | 예 |
| 오늘 DLI 가 growth 이력에 남는다 | 예 — `setDailyLight` 은 막힌 날에도 부른다 |
| 잎이 시든다·떨어진다 | 아니오 |
| 화분이 사라진다·개체가 죽는다 | **아니오** |
| 옮기면 다음 날부터 다시 오른다 | 예 |

빛이 넉넉한데 위가 막히면 **형태만 정확히 정지**한다. 되돌릴 수 있는 규칙이고,
그래서 벌이 아니라 **선택**이다 — 옮기거나, 삽수하거나, 그냥 그 크기로 두거나.

### 빛 부족 정지와 반드시 구분한다

두 정지는 **처방이 정반대**다.

| | 사유 | 플레이어가 할 일 |
|---|---|---|
| 빛 부족 | `turn.growthBlocked` (growth 소유 문구) | 등을 켜라 · 밝은 자리로 |
| 머리공간 | `turn.headroomBlocked` (core 소유 문구) | **위가 트인 자리로 · 삽수** |

한 칸에 섞으면 화면이 "빛이 모자랍니다"라고 말하고 플레이어는 등을 하나 더 산다.
그래서 `turn` 에 칸을 따로 두고, 기록 문구에 **'빛'이라는 말을 넣지 않는다**
(`test_headroom.mjs` F 가 이걸 검사한다).

### 경고가 먼저

남은 여유가 `WARN_MARGIN_M = 0.10m` 이하로 내려가면 정지 전에 한 번 알린다.

```
📏 천장까지 0.06m 남았습니다 — 곧 더 못 자랍니다        ← 유효 335일
📏 위가 막혔습니다 — 이 자리 머리공간 0.71m 인데 키가 0.72m 입니다.
   위가 트인 자리로 옮기거나 삽수를 하세요                ← 유효 454일
```

기록은 **바뀔 때만** 남긴다(매일 찍으면 같은 줄로 도배된다).

방 5×4×**2.30m**. 슬롯 14칸. 아래는 전부 실제 조립 결과에서 잰 값이다
(`tools/test_headroom.mjs` A·E 가 이 표를 못 박는다).

|---|---|---|---|---|
| **창턱** `banjiha-sill:0` | 1.585 | **0.715** | 천장 | **453** |
| 책상 `desk:0·1` | 0.74 | 1.560 | 천장 | 안 막힘 |
| 서랍장 `dresser:0·1` | 0.80 | 1.500 | 천장 | 안 막힘 |
| 에타제르 1단 `:0~2` | 0.03 | **0.352** | 윗단 밑면 | **52** |
| 에타제르 2단 `:3~5` | 0.412 | **0.352** | 윗단 밑면 | **52** |

**바닥이 제일 크고, 선반 아래 칸이 위 칸보다 작다.** 규칙이 기하와 맞는다.

### 이 규칙이 실제로 무는 자리는 둘

**① 에타제르 아래 두 단 — 도착 즉시 막힌다.**
머리공간 0.352m 인데 도착 개체가 0.540m 다. **처음부터 안 들어간다.**
Day 4 에 선물을 받자마자 눈에 보이는 규칙이라, 가르치는 값이 크다.

**② 창턱 — 유효 454일에 막힌다.**
도착 0.540m → 여유 0.175m. 유효 **454일**에 키가 0.717m 가 되어 0.715m 를 넘는다.
도착에서 **311 유효일** 뒤다.

### 창턱을 떠나면 조도가 얼마나 떨어지나

여름 7일평균 기댓값 DLI (맑음 .55 / 흐림 .30 / 비 .15 가중). 자라는 문턱은 **3.0**.

| 자리 | 등 0 | 등 1 | 등 2 | 머리공간 |
|---|---|---|---|---|
| **창턱** | 2.42 ✗ | **4.26 ✓** | 4.41 ✓ | 0.715 |
| 에타제르 3단 `:7` | 0.24 ✗ | **12.07 ✓** | 12.17 ✓ | 1.506 |
| 에타제르 1단 `:1` | 0.07 ✗ | 0.88 ✗ | 0.97 ✗ | 0.352 |
| 책상 `:0` | 0.31 ✗ | 0.80 ✗ | 1.56 ✗ | 1.560 |
| 서랍장 `:1` | 0.03 ✗ | 0.08 ✗ | 0.10 ✗ | 1.500 |

| 바닥 한가운데 | 0.13 ✗ | 0.32 ✗ | 0.38 ✗ | 2.300 |

**창턱 → 바닥은 DLI 4.26 → 0.61 (−86%)이고, 문턱 3.0 아래다.**

### ★ 결론 — 절반만 성립한다. 보고한다.

**성립하는 것**
* 제일 밝은 자리(창턱 4.26)가 머리공간이 제일 빠듯한 자리(0.715m)라는 긴장은 **실재한다.**
* 에타제르 아래 두 단은 도착 개체가 **아예 못 들어간다** — 규칙이 첫날부터 보인다.
* 바닥은 위가 완전히 트여 3년(1095일) 내내 안 막힌다.

**성립하지 않는 것 — ⑴ 반지하 바닥은 대안이 아니다**
바닥은 어느 등 개수로도 **0.72 를 못 넘는다**(문턱 3.0). 창턱에서 막혀 바닥으로 내리면
이번엔 **빛 부족으로 멈춘다.** "위가 뚫린 방바닥으로 가면 자란다"가 반지하에서는 거짓이다.
반지하에서 실제로 갈 수 있는 자리는 **에타제르 맨 윗단** 하나뿐이고, 그 자리는
등 1개에서 **12.07 로 창턱(4.26)보다 훨씬 밝다.**
⇒ 반지하에서 이 규칙이 가르치는 것은 "밝은 자리를 떠나라"가 아니라
**"낮은 자리를 떠나라"** 다. 그 자체로 좋은 교훈이지만 문서의 말과 다르므로 적어 둔다.

**성립하지 않는 것 — ⑵ 311 유효일은 튜토리얼 밖이다**
창턱 정지는 유효 454일이다. 반지하 튜토리얼은 원룸 이사로 끝나므로(`story_arc.md`)
**창턱 정지는 튜토 안에서 거의 안 일어난다.** 지금 반지하에서 이 규칙을 실제로 만나는
경로는 ①(에타제르 아래 칸에 놓는 실수) 뿐이다.

### 조정 제안 (plan 판단)

| | 제안 | 결과 |
|---|---|---|
| **가** | **그대로 둔다.** 반지하에서는 ①만 물게 하고, 창턱 정지는 장기 플레이·다음 방의 규칙으로 남긴다 | 손댈 것이 없다. 튜토는 지금 그대로 |
| **나** | **식물등을 머리공간 장애물로 넣는다** (§6 한계 ②). 반지하 식물등 바는 에타제르 맨 윗단 **0.226m 위**(y 1.02)에 있다 | 제일 밝은 자리(12.07)가 **유효 26일**에 막힌다. "등을 위로 올려라"가 새 선택이 된다. 실제 식물등 바가 높이 조절식이라 자연스럽다. **이걸 권한다** |
| **다** | 창턱 받침을 조금 낮춘다(y 1.55 → 1.40) | 머리공간 0.865 로 **늘어** 더 늦게 막힌다. 반대 방향이다 — 하려면 반대로 올려야 하는데 그러면 창(1.495~2.045)과 부딪친다 |
| **라** | 키 곡선을 빠르게 한다(`growAmt`·`growSpan`) | **growth 소유 값**이다. 형태 전체가 바뀌므로 여기서 건드릴 값이 아니다 |

**가 + 나** 를 권한다. 규칙 자체는 지금 그대로 두고, 등을 장애물 목록에 넣는 것만
house 에 요청하면 반지하 안에서도 규칙이 산다.

```
SHELF_BOARD_M 0.03 · WARN_MARGIN_M 0.10 · PLANT_POT_D_REF 0.20 · HEADROOM_BLOCK 'headroom'
```

차폐체 OBB 규약은 `daylight_lux.isShadowed` 와 **같은 것 하나**를 쓴다
(중심 = `x+w/2, z+d/2` · `rot` 은 중심 기준). 두 곳이 다른 규약을 쓰면
"그림자는 지는데 머리는 안 걸리는" 상자가 생긴다.

### `src/game/loop.js` (최소 수정)

```js
const headroom = headroomOfTurn(S, io, p);          // advanceTo 앞
const headBlocked = !!(headroom && headroom.blocked);
...
io.growth.setDailyLight(dli);                        // 막힌 날에도 반드시
if (!headBlocked) step = io.growth.advanceTo(calBefore + 1);   // 막혔으면 안 부른다
```

`turn.headroom`(판정 전체)과 `turn.headroomBlocked`(사유 문자열)이 새로 실린다.
기존 `turn.growthBlocked`(빛)는 **건드리지 않았다.**

**⚠ 알려진 대가** — 막힌 날은 `advanceTo` 를 안 부르므로 growth 의 달력(`CAL_DAY`)이
코어 날짜보다 뒤처진다. 지금은 아무 데도 두 값이 같기를 요구하지 않아 문제가 없지만,
깔끔한 해법은 growth 쪽에 **"달력만 하루 보내기"** 창구가 생기는 것이다
(`advanceTo(day, { hold:true })` — core-to-growth 요청감).

그대로 두되, house 가 개구부 위 벽을 차폐체로 넣는 날 **반드시 다시 밸런싱해야 한다.**

## 7. room_view 에 필요한 API (제안만 · 구현 안 함)

`src/game/room_view.js` 는 다른 작업자 몫이라 손대지 않았다. 필요한 것은 셋이다.

**① 놓기 전에 막아 준다 — `surfaceAt` 에 머리공간을 얹는다**
```js
surfaceAt(px, py, { potD, plantTopM })
  → { ..., headroomM, headroomOk, headroomReason }
```
지금은 화분이 **지름**으로만 걸러진다(`maxPotD`). 도착 개체를 에타제르 아래 칸에 놓으면
놓이기는 하고 그날부터 안 자란다 — 놓는 순간 "이 칸은 0.35m 라 안 들어갑니다"가 나와야 한다.
계산은 `headroom.headroomCheck` 를 그대로 부르면 되고, 방뷰는 `built` 를 이미 들고 있다.

**② 막힌 자리 표시 — `showSlotRings` 에 사유를 하나 더**
지금 링은 "지름이 안 맞는 자리"를 어둡게 칠한다. 여기에 **"키가 안 맞는 자리"** 를
다른 색으로 더한다. 지름과 키는 다른 제약이므로 같은 색으로 합치면 안 된다.

**③ ★ 실제 키를 알려 준다 — 표를 없앨 수 있는 유일한 길**
```js
plants()  → [{ slotId, potD, days, heightM }]      // heightM = Box3(그룹).max.y
```
방뷰는 그루를 **이미 조립해 놓고 있다.** 그 bbox 를 한 줄 실어 주면 `headroom.plantTopM`
의 실측 표가 통째로 필요 없어지고, 씨앗별 차이(§6 ④)도 저절로 맞는다.
그때 `headroom.js` 는 `blockedBy(실제키, 머리공간)` 만 남는다.
