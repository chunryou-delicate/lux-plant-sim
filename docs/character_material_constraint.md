# 캐릭터 머티리얼 제약 — Meshy는 아틀라스 한 장으로 굽는다

작성 2026-07-25 · 대상 `assets/characters/3d/`

## 요지

Meshy `multi_image_to_3d`는 머리·눈·옷·피부를 **2048² 아틀라스 한 장에 전부 구워
단일 머티리얼**로 내보낸다. 부위별 mesh/material 분리가 없다.

| 항목 | 원본 8종 + 몬이 | 경량본 lq |
|---|---|---|
| mesh | 1 | 1 |
| primitive | 1 | 1 |
| **material** | **1** | **1** |
| image(texture) | 1 (2048²) | 1 (1024², 몬이 512²) |
| **morph target** | **0** | **0** |

원본과 경량본이 동일하다. **경량화가 머티리얼을 병합한 것이 아니라 처음부터 하나였다.**
감축 옵션에서 머티리얼 병합을 꺼도 달라지지 않는다.

## 이것이 막는 것

- **부위별 머티리얼 교체 불가** — "머리 material만 골라 색 바꾸기"가 성립하지 않는다.
- **블렌드셰이프(모프 타겟) 불가** — 표정을 모프로 만들 수 없다.
- Meshy 리깅은 **몸통 24본**이고 얼굴 본이 없다. 3D 얼굴 애니메이션도 불가.

## 우회 — 마스크 텍스처

같은 UV를 쓰는 마스크 텍스처를 만들어 셰이더나 캔버스에서 **텍셀 단위로 부위를
골라낸다.** 머티리얼 분리와 같은 결과를 얻는다.

도구: `tools/make_part_mask.py` → `assets/characters/masks/{char}_mask.png`

분류 방법 (두 단계가 모두 필요하다)

1. **색** — 저폴리 클레이 팔레트라 색 덩어리가 뚜렷하다. 기준색과의 거리로 1차 분류.
   진갈색=머리·눈, 살구=피부, 흰색=상의, 청색=하의.
2. **3D 위치** — 머리카락과 눈·눈썹은 **같은 진갈색이라 색만으로는 못 가른다.**
   정점의 UV와 3D 좌표를 UV 공간에 뿌리고 채워 텍셀마다 3D 위치를 얻은 뒤,
   머리 높이 + 얼굴 앞면 여부로 눈·눈썹을 갈라낸다.

마스크 채널 규약 — **R 채널 인덱스 맵**

| R 값 | 부위 |
|---|---|
| 0 | 기타 |
| 40 | 머리카락 |
| 80 | 눈·눈썹 |
| 120 | 피부 |
| 160 | 상의 |
| 200 | 하의 |

`G=B=0`, **`A`는 항상 255**.

> **알파를 데이터 채널로 쓰지 말 것.** 캔버스는 픽셀을 프리멀티플라이드 알파로
> 저장하므로 `A=0` 인 텍셀은 RGB가 통째로 0 으로 뭉개진다. 부위를 RGBA 네 채널에
> 나눠 담았다가 A 채널에 넣은 하의만 색이 바뀌는 문제를 실제로 겪었다(2026-07-25).
> 그래서 A 는 불투명으로 고정하고 R 하나에 코드를 넣는다. 코드 간격 40 은
> 확대·축소 시 보간이 섞여도 최근접 코드로 복구되게 하기 위한 여유다.

적용은 **로딩 시 캔버스에서 한 번만** 계산한다(`assets/characters/color_shift.html`).
셰이더로 매 프레임 도는 방식이 아니라 스키닝과 충돌하지 않고, 게임에서도 캐릭터
생성·변경 시점에만 실행하면 되는 성격의 작업이다. 명도는 원본을 유지해 음영과
옷 주름이 살아남는다.

같은 마스크 파이프라인으로 **얼굴 영역을 뽑아 표정(눈·입) 텍스처 교체**도 할 수 있다.
게임 화면에서 얼굴은 24~48px이라 이 방식으로 충분히 읽힌다.

### 함정

- 아틀라스는 **여백 비중이 크다.** 마스크의 부위별 텍셀 퍼센트는 실제 표면적 비율이
  아니다. 분류 품질은 반드시 3D에 올려서 확인해야 한다.
- UV 배치가 뒤섞여 있어 텍스처 이미지만 봐서는 어느 덩어리가 어느 부위인지 알 수 없다.
- 마스크는 텍스처 UV에 종속된다. **캐릭터를 재생성하면 마스크도 다시 만들어야 한다**
  (도구 재실행이라 비용은 낮다).

## 리깅은 캐릭터에 종속되지 않는다

Meshy 리깅은 8종 전부 **본 이름·순서와 전체 노드 이름 집합이 동일**하다(표준 24본).

```
Hips, LeftUpLeg, LeftLeg, LeftFoot, LeftToeBase, RightUpLeg, RightLeg, ... (24개)
```

`assets/characters/3d/anim/` 의 스트립된 클립은 **노드 이름으로 바인딩**되므로
어느 캐릭터에나 붙는다. 따라서 **캐릭터를 재생성하고 다시 리깅해도 모션 128개는
그대로 재사용된다.** 재작업 비용에서 모션 생성비(384cr)는 빠진다.

재작업 시 실제로 드는 것

| 항목 | 비용 |
|---|---|
| 원화 재생성 | Higgsfield |
| 3D 변환 | Meshy 30cr × 8 = 240cr |
| 리깅 | Meshy 5cr × 8 = 40cr |
| **모션 128개** | **0 — 기존 클립 재사용** |
| 실스케일·경량화·마스크 | 0 — 스크립트 재실행 |
