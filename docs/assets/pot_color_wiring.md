⛔ **코드가 아니다.** 붙일 코드는 `docs/handoff/pots-to-plan.md §5` 에 **이미 있다**(2026-08-08 · [Asset]).
이 문서는 총괄이 물은 둘만 답한다 — **「어느 칸이 색을 갖나」 · 「누가 읽나」**.
그것이 그때 인계문에 **안 적혀 있던 것**이고, 그래서 붙이는 쪽이 안 집었을 수 있다.


# ① 어느 칸이 «색»을 갖나 — **단 하나. `potAsset` 이다**

```
pot.potAsset : string        예) 'pots/pot_concrete_round_c1.glb'
```

★ **색은 «따로 된 칸»이 아니다.** 에셋 «경로»가 곧 종류이자 색이다.
⇒ 그래서 색을 더해도 **세이브에 새 칸이 안 는다.** `save.js §packPot` 이 이미 `potAsset` 을 왕복시킨다.

## ⇒ ★★ 그 하나가 왜 «충분»한가 — **되짚는 표가 이미 있다**

```
potKindOfAsset(asset)   → 종류 (concrete_round …)
potColorOfAsset(asset)  → 색   (base / mint / pink)
potDiameterOf(asset)    → ★ 지름. «자리 판정이 쓰는 유일한 창구». 모르면 «던진다»
knowsPotAsset(asset)    → 아나 (매 프레임 그리는 데가 먼저 물어본다)
```
⇒ `POT_ASSET_INDEX` 가 `colors` 까지 통째로 싣는다 — **민트 화분도 제 종류를 안다.**

## ⇒ ★★★ 그리고 **색은 지름을 안 바꾼다** — 이것이 이 일을 «싸게» 만든다

```
diameterM 은 «갈래»에만 있다  — nursery 0.1314 · concrete_round 0.1801 · terracotta 0.2010
                              ceramic 0.2020 · concrete_square 0.2755
colors[] 안에는 diameterM 이 «없다»   ⇐ 재서 확인했다
```
> ⇒ ★ **색만 바꾸는 것은 «언제나 된다».** 자리를 한 칸도 못 잃는다.
> ⇒ ⇒ 그러니 색 배선은 **밸런스를 한 톨도 안 건드린다.** 모양(갈래)을 바꾸는 것과 «다른 일»이다.

# ② 누가 읽나 — **네 자리. 그중 «하나»가 끊겨 있다**

| # | 누가 | 무엇을 | 지금 |
|---|---|---|---|
| ㉠ | `state.js:477` | 화분을 만들 때 `potAsset: potKind.asset` 을 심는다 | ⛔ **늘 «기본» 에셋이다.** 색이 여기서 안 들어간다 |
| ㉡ | `save.js §packPot` | `potAsset` 을 세이브에 싣고 되싣는다 | ✔ 이미 왕복한다 |
| ㉢ | `room_view.js:2019·2256` | 방을 조립할 때 `spec.potAsset` 을 보고 `swapPotMesh` | ✔ 색 GLB 를 «그릴 줄 안다» |
| ㉣ | `shop.js potKindList()` | 표를 화면에 내준다(색 포함) | ⛔ **게임이 «안 부른다».** 검사(`tools/test_pots.mjs`)만 부른다 |

> ## ⇒ ★★★ **끊긴 것은 ㉠·㉣ 둘이고, 사실은 «한 자리»다 — 「사람이 색을 고르는 화면」이 없다.**
> ⇒ ㉡㉢ 은 **이미 돈다.** 색을 심어 주기만 하면 세이브도 화면도 따라온다.

⚠ 그리고 **㉢ 은 「조립할 때」 한 번만 돈다.** 상태만 바꾸고 다시 그리면 «안 갈린다» —
  내가 그것으로 판을 세 번 버렸다(2026-08-29). ⇒ 색을 바꾸면 **방을 다시 조립해야** 한다
  (`roomView.setRoom(id)` 이 그 문이다).
