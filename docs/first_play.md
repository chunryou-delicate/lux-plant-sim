## ★ [정정 2026-08-02] Day 4의 **순서가 고정**이다

> **이전**: *"첫 수확 ↳ 식물신 메시지 ↳ 몬스테라 도착"* — 식비 결과가 어디 끼는지 없었다
> **정정**: **수확 → 식비 절감 결과 표시 → 몬스테라 도착.** 몬스테라는 **정산 뒤에** 온다.

식비 결과를 몬스테라보다 먼저 보여주는 이유는, 그게 **첫 자리 선택의 답안지**이기 때문이다.
답안지를 보기 전에 다음 문제가 오면 첫 문제가 무엇이었는지 흐려진다.

## ★ [추가·확정 2026-08-02] 몬스테라 최초 도착 자리는 **정답이 아니다**

```
도착 자리   ✕ banjiha-sill:0 (정답 창턱)
            ○ 그 방에서 화분이 들어가는 어두운 자리
플레이어    도착을 보고 banjiha-sill:0 으로 **직접 옮긴다**
```

**두 번째 학습이 "옮기기"** 라서 그렇다. 처음부터 정답 자리에 놓아 주면
플레이어는 **[다음 날]만 누르고** 몬스테라 구간에서 아무것도 배우지 않는다.

# 3. 몬스테라 — 식물등이 아니라 **창가 높은 자리**

## ★ [정정] 식물등은 첫 플레이의 통과 조건이 아니다

> **이전**: 튜토 체크리스트 *"☐ 등을 켜고 갈라진 잎 1장"*
> **정정**: *"☐ 몬스테라를 창가 높은 자리에 두어 새순이 나온다"*

**식물등은 이후의 비싼 성장 가속·안정화 선택지로 내린다.**
첫 플레이에서 배울 것은 **"자리"** 하나다.

| | 첫 플레이 | 이후 |
|---|---|---|
| 몬스테라를 자라게 하는 법 | **높은 창가 자리** (자연광) | + 식물등(가속·안정화) |
| 보상 | **말린 새순 (`spear_furled`)** | 갈라짐 · 무늬 |

## ★ 보상은 **갈라짐이 아니라 말린 새순**

갈라짐(`fenestrate` 6.0)은 반지하 자연광으로 **닿지 않는다.**
첫 플레이 보상은 **화면에서 눈으로 보이는 변화**여야 한다 — 말린 새순이 서는 것.

**도착 후 3~7턴을 목표 구간으로 둔다.**

### ★ [정정 2026-08-02] *"새순 전개 / 새잎"* → **`spear_furled` 하나**

> **이전**: *"새순 전개 / 새잎"*, *"화면상 새순 변화가 시작"* — 범위가 열려 있었다
> **정정**: **`spear_furled` 가 관측된 순간**이 보상이자 종료다(§0).

*"새순 전개"* 는 `spear_opening`이고 **그 다음 단계**다. *"새잎"* 은 `leaf_*` 로 더 뒤다.
셋을 묶어 두면 **어느 화면이 보상인지** 사람마다 다르게 읽고, 판정도 넓어진다.

> 얇은 통합에서는 도착 다음 날부터 3턴, **Day 7에 `spear_furled`** 가 나왔다
> (근거: `handoff/core-to-plan.md` 2026-08-02). **도착한 날은 돌본 날로 세지 않는다.**
> 목표 구간 3~7턴은 그대로 두고, **수치는 실플레이 뒤에 다시 본다.**

```
growth 판정 = 최근 DLI 이력의 평균 (dli7)

```

## ⚠ real 모드에서는 보장되지 않는다 — **첫 플레이는 novice 전용**

**슬롯 `banjiha-sill:0` 기준** (§5) — `space`가 아니라 `slots` 실측이다:

| 라벨 | 값 | 판정 |
|---|---|---|
| `banjiha.slots.peak_summer` = **novice 판정값** | **3.77** | `min` 3.0 초과 → **성장** |
| `banjiha.slots.avg7_summer` (real) | **2.42** | **`min` 3.0 미만 → 정체** |

**real 모드의 자연광만으로는 형태 진행이 보장되지 않는다.**
날씨·계절이 굴러가면 평균이 2.42로 내려가기 때문이다.

→ **첫 플레이는 novice 전용으로 명시한다.** real 모드는 식물등이 필요하고,
그게 §3의 *"식물등은 이후의 선택지"* 와 맞는다.

### ★ [정정 2026-08-02] *"성장 재개"* 라고 쓰지 않는다

> **이전**: *"자연광만으로는 **성장 재개**가 보장되지 않는다"*
> **정정**: *"**형태 진행**이 보장되지 않는다"*

*"재개"* 는 **한 번 멈췄다가 다시 도는 것**을 뜻하는데, 첫 플레이의 몬스테라는
**도착 시점에 형태 진행이 시작된 적이 없다** — `spear_ready` **0%** 로 도착한다(§2·§9).
어두운 자리에 있는 동안은 *"멈춘 것"* 이 아니라 **아직 안 오른 것**이고,
창턱으로 옮기면 *"다시 도는 것"* 이 아니라 **처음 오르기 시작하는 것**이다.

**§9의 두 축 규칙과 같은 말이다** — 형태 진행도는 **오르거나 멈추거나**이고 **줄지 않는다.**

> ⚠ 이 절의 3.77 · 2.42는 **house 기존 실측값**이다. house의 반지하 정적 프로필 결과가
> 아직 통합되지 않았으므로, **여기서 숫자를 새로 추정하거나 갱신하지 않는다.**
> 프로필이 들어오면 그때 house 값으로 한 번에 맞춘다.

# 4. 학습 통과 기준 — [정정]

> **이전**: *"아무도 시키지 않았는데 다시 옮긴다"*
> **정정**: 아래 한 줄

```
정답 슬롯을 집어 주지 않았을 때
플레이어가 콩나물은 어두운 자리, 몬스테라는 높은 창가 자리에 배치한다.
```

**두 작물의 요구가 정반대**라는 게 핵심이다 — 하나는 어두울수록 좋고 하나는 밝을수록 좋다.
같은 방 안에서 **자리를 나눠 쓰는 법**을 배우는 것이 첫 플레이의 학습 내용이다.

## ★ [정정 2026-08-02] 무엇을 숨기고 무엇을 말해 주나 — **선이 그어졌다**

> **이전**: *"정답 위치를 직접 알려주지 않았을 때"* — 방향까지 숨기는 것처럼 읽혔다
> **정정**: **숨기는 것은 DLI 숫자와 정답순**이다. **방향은 말해 준다.**

| 기본(수동) UI가 **숨기는 것** | 기본 UI가 **말해 주는 것** |
|---|---|
| 슬롯별 **DLI 숫자** | *"어두운 자리에 놓아 보세요"* |
| **밝기순 정렬**(고르면 정답이 되는 순서) | *"높은 창가 자리로 옮겨 보세요"* |
| 어느 슬롯이 `banjiha-sill:0`인지 | |

**목표를 숨기면 학습이 아니라 술래잡기**가 된다. 반대로 *"3번 슬롯에 두세요"* 는 지시라서
플레이어가 방을 볼 이유가 없어진다. 그래서 **방향은 말해 주고, 어느 자리인지는 방을 보고 고르게** 한다.
자리 목록의 순서는 **밝기와 무관하게** 둔다 — 순서가 정답이면 목록이 답을 흘린다.

> ⚠ **자동 시나리오는 이 기준이 아니다.** 자동 시뮬이 *"가장 어두운 자리"*·`banjiha-sill:0`을
> 골라 넣는 것은 **검증 하네스 편의**이고, 학습 통과 기준과 무관하다.
> 자동 경로가 통과했다고 **§4가 통과한 것이 아니다** — §4는 사람이 플레이해야 판정된다.

## 보조 관찰 — 통과 기준이 아니다

*"한 번 더 옮겨본다"* 는 **보조 관찰로만 유지**한다.
옮겨보는 행위 자체는 학습의 증거가 될 수 있지만, **통과 조건은 최종 배치**다.
(시루 이동은 수확 전까지 자유다 — §1)


**식물등은 필수 구매품이 아니다.** 선택이 생긴다 —
*"식물등을 사서 지금 방을 보완할까, 그 돈을 이사 자금으로 모을까?"*

| | |
|---|---|
| 빠르게 이사한 플레이어 | 반지하에서 식물등을 **안 사도 된다** |
| 진행이 늦어 겨울을 맞는 플레이어 | 식물등이 **안전장치**가 된다 |

상세는 **`time_modes.md` §9**.

## 첫 통합 시뮬레이션에서 비교할 세 경로

| 경로 | |
|---|---|
| **A** | 식물등 없이 **겨울 전에 원룸 이사** |
| **B** | 반지하에 남아 **식물등 구매** |
| **C** | 이사도 식물등도 늦어져 **겨울 진입** |

### 각 경로에서 확인할 것

- 튜토리얼이 **지나치게 길어지지 않는가**
- **콩나물 반복이 단순 노동이 되지 않는가**
- **식물등 구매가 사실상 강제가 되지 않는가**
- **이사 자금이 단순 시간 대기가 되지 않는가**
- 계절 변화가 **화면과 성장 결과로 읽히는가**
- 겨울이 **억울한 실패가 아니라 예고된 압력**으로 느껴지는가
- **식물등과 이사 모두 의미 있는 선택으로 남는가**

> ★ 이 일곱 줄은 `balance_decisions.md`의 **"시뮬이 못 잡는 것"** 에 가깝다.
> 숫자로는 앞의 넷만 잡히고, **뒤의 셋은 실플레이로만 보인다.**

## 아직 확정하지 않는 것

정확한 시작 날짜 / 계절 진행 속도 / 스토리 외부광 계수·월별 곡선 /
가을·겨울의 실제 DLI / 식물등 가격·출력·전기료·해금 시점 /

겨울에 생장을 정지시킬지 위험 구간만 만들지

## 현재 작업에 미치는 영향 — **없다**

house 창턱·광량 불변 / 외부광·날씨·계절 수치 불변 / 식물등을 첫 플레이에 연결 안 함 /
**첫 플레이 종료 조건은 계속 "몬스테라 말린 새순 등장"**

# 9. [추가·확정] 형태 진행도와 활력은 **별도 축** (2026-08-02)

## 확정

```
형태 진행도 (growthDays)   잎 수 · 새순 단계 · 형태.  빛이 충분하면 오르고, 부족하면 멈춘다
활력       (vigor)        개체의 건강.              환경이 나쁘면 깎인다
```

**둘을 하나로 합치지 않는다.** 합치면 *"안 자란다"* 와 *"죽어간다"* 가 구분되지 않는다.

## novice 첫 플레이에서의 규칙

| | novice |
|---|---|
| **형태 진행도 게이지** | **보인다** |
| **형태 진행도 값** | **상승 또는 정지만.** ★**감소하지 않는다** |
| **활력** | **숨긴다.** ★**감소하지 않는다** |

> **왜 형태는 안 줄어드나** — 첫 플레이가 가르치는 건 *"빛이 부족하면 **멈춘다**"* 이지
> *"되돌아간다"* 가 아니다. 되돌아가면 플레이어가 **자기 실수를 복구할 수 없다고** 느낀다.
>
> **왜 활력을 숨기나** — 관리 변수를 하나 더 얹으면 첫 플레이의 학습 내용
> (*"콩나물은 어두운 자리, 몬스테라는 높은 창가"*)이 흐려진다.
> **정보 축**(초보 숫자 / 표준 막대 / 고수 없음)과도 맞물린다.

## 미래 — 고수 모드에서 활력이 살아난다

환경 악화가 **활력을 깎고**, 그게 눈에 보이는 단계로 이어진다:

```
처짐 → 변색 → 새순 손상 → 잎 손실 → 고사
```

**형태 진행도는 그때도 안 줄어든다.** 줄어드는 건 활력이고,
**활력이 바닥나면 형태가 손실**된다(잎이 떨어진다). 인과가 한 방향이다.

**세부 임계값과 고사 기간은 첫 플레이 이후 결정한다.**

## ✅ [확정 2026-08-02] 게이지 표시 사상 = **A. 단계 원비율**

> **이전**: 3안(A 원비율 / B 바닥값 15% / C 앞단계 꼬리 ~60%) **체감 결정 대기**
> **확정**: **A — `growthPhase().progress01` 원비율**

## 표시 계약

```
① spear_ready 진입 시            →  0%
② 단계 내부 진행을 그대로          →  0 → 100%
③ 저광에서는                     →  정지. ★감소하지 않는다
④ 단계가 완료되면                 →  다음 phase로 전환. 새 단계는 0%부터
```

**게이지는 `progress01`을 그대로 그린다.** 바닥값도, 앞 단계 꼬리도 넣지 않는다.

## 사상 근거가 **아닌** 것 — 셋

| 쓰지 않는다 | 왜 |
|---|---|
| **생존 여유** | 활력 축이 담당한다(§9 본문). 두 축을 섞으면 §9가 무너진다 |
| **`daysPlanted`** | *"돌본 날"* 표시에만 쓴다 |
| **절대 `growthDays`** | 143은 **유효 진행도이지 비율이 아니다.** 임의 환산 금지 |

## ③이 §9 본문과 같은 규칙이다

*"저광에서 정지하고 감소하지 않는다"* 는 **형태 진행도 규칙 그대로**다.
게이지는 그 값을 비추는 창일 뿐이라 **따로 정할 게 없다.**

> ### 알아둘 것 — 도착 직후엔 화면이 조용하다
>
> `spear_ready`는 **겉보기 변화가 없는 단계**이고, A는 **0%에서 시작**한다.
> → 도착 직후 플레이어가 보는 것은 **0%인 게이지 하나**다.
>
> **게이지가 움직이기 시작하는 것 자체가 첫 피드백**이 된다.
> 그래서 **하루 넘길 때 눈에 띄게 움직여야** 한다 — 3턴에 새순이 나오는
> 목표 구간(§3)이면 **한 턴당 30% 안팎**이라 충분히 읽힌다.

## ★ [추가 2026-08-02] 구현이 A안에 닿는 지점 — 두 곳뿐이다

```
게이지    growthPhase().progress01 을 그대로 그린다        ← 환산·보정 없음
종료      growthPhase().phaseId === 'spear_furled'        ← 문자열 정확 일치(§0)
```

**게이지와 종료 판정이 같은 한 객체에서 나온다.** 둘이 다른 출처를 보면
*"게이지는 100%인데 안 끝났다"* 가 생기고, 그건 플레이어가 고칠 수 없는 종류의 어긋남이다.

**첫 플레이 밖의 값은 섞지 않는다** — 생존 여유·`daysPlanted`·절대 `growthDays`(143) 셋 다.
`daysPlanted`와 유효 `growthDays`는 **표시만** 한다(§3의 두 축).

> ✅ **구현 완료 (`ae3b070`).** `markMonsteraPhase()`는
> `FIRST_PLAY_COMPLETE_PHASE_ID === 'spear_furled'`의 정확 일치만 완료로 인정한다.
> `spear_opening`·`leaf_mid`를 거부하는 회귀 테스트도 함께 통과했다.
