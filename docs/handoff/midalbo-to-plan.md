## 1. 무엇을 어떻게 쟀나 — 자 이야기부터

### 자를 고른 근거
커밋 `4b280f6`(차콜)이 쓴 자를 먼저 **재현했다.** 그 커밋은 무엇을 쟀는지 안 적어 놨는데,
텍스처(`_base_color.png`)가 아니라 **섬네일**(`assets/monstera/skins/thumbs/*.png`)이었다.

| | 그 커밋이 적은 값 | 내가 잰 값 |
|---|---|---|
| 차콜 으뜸색 · 색가짓수 | (21,25,25) · 1,480 | **(21,25,25) · 1,480** ✅ |
| 모브 | (100,61,95) · 9,880 | **(100,61,95) · 9,880** ✅ |
| 스페클-그린크림 | (19,83,48) · 31,294 | **(19,83,48) · 31,294** ✅ |
| 하프문-그린흰 | (9,34,17) · **5,420** | (9,34,17) · **5,436** ⚠ |

⚠ **하프문 한 줄이 16 차이 난다.** 값 판단에 안 쓰인 숫자라 결론은 안 흔들리지만,
「문서에 적힌 숫자도 재는 자다」(§2.9 ⑤)의 사례를 하나 더 보탠다.
⇒ 나머지 셋이 한 톨도 안 다르므로 **잰 대상은 섬네일이 맞다.**

### 자에 더 넣은 것 넷 — 「으뜸 색·색 가짓수」만으로는 못 가른다
박사님 정의가 **모양** 이야기(점박이가 흩어졌나 · 반반으로 갈렸나 · 통째로 한 색인가)라
색 두 개로는 안 잡힌다. 그래서 넷을 더 쟀다.

| | 무엇 | 무엇을 가르나 |
|---|---|---|
| ③ **초록비** | 잎 속살 중 「초록」 화소의 비율 | 완전 특수색인가 |
| ④ **갈림거리** | 초록 무리와 특수색 무리의 **무게중심 거리** ÷ 잎 반지름 | 한쪽에 몰렸나 |
| ⑤ **덩어리도** | 적은 쪽 화소 중 8-이웃이 전부 같은 편인 것의 비율 | 점인가 덩어리인가 |
| ⑥ **최대조각** | 적은 쪽이 **몇 조각**인가(제일 큰 조각의 몫) | 한 덩어리인가 |

★ **재는 자가 한 번 거짓말했다. 적어 둔다.**
처음엔 생 RGB 로 `G − max(R,B) ≥ 10` 을 초록 판정에 썼다. 섬네일은 한쪽에서 빛을 받아
**그늘진 초록의 차가 좁아진다.** 그래서 멀쩡한 잎이 「반쪽만 초록」으로 잡혀 하프문이 됐다.
⇒ **색도**(`g/(r+g+b)`)로 바꿨다. 밝기가 곱해져도 색도는 안 변한다. 정답률 53% → 68%.

★ 그리고 가장자리 안티앨리어싱 고리를 **2겹 깎아** 잰다. 안 깎으면 흰 배경과 잎 사이의
회색 띠가 통째로 「특수색 고리」로 잡힌다.

### 문턱은 어디서 왔나 — **눈으로 안 정했다**
성숙잎 19갈래는 **이미 등급이 있다**(`varie_grades.json` · 박사님 확정문).
그걸 정답지로 놓고 문턱을 맞췄다. `node tools/probe_midalbo.mjs --mat` 이 채점표를 낸다.

```
적은쪽 < 15%                       → 한 색짜리 잎 → 초록이면 산반 · 아니면 풀문
갈림 ≥ 0.35 이고 덩어리 ≥ 0.55     → 하프문 (두 색이 한쪽으로 몰렸다)
적은쪽 ≥ 35% 이고 덩어리 ≥ 0.85    → 하프문 (통짜로 나눠 가졌다)
그 밖                              → 산반 (흩어져 있다)
```

★ **갈래 단위로 정한다.** 에셋은 한 갈래가 세 판(기본·쨍·차분)이고 **같은 무늬를 색만 달리
구운 것**이라 등급이 갈리면 안 된다. 실제로 갈렸다 — 하프문-크림민트가 기본·쨍은 하프문인데
차분판만 산반으로 떨어졌다(차분판이 크림 쪽까지 초록으로 눌러서다).
⇒ 세 판을 다 재고 **많은 쪽**으로 정한다. 비기면 기본판을 따른다.

## 4. 붙인 것 — 잎이 날 때 **둘을 같이 정한다**

### ㉠ 표가 정본이다 (`data/balance/varie_grades.json`)
`grades[].midAssets` 를 새로 넣었다. 성숙잎의 `assets`(matNum) 과 같은 결이다.

```json
{ "id": "heart_halfmoon_v2_stem", "ko": "하프문-크림민트", "midNums": [29, 30, 31] }
```

⚠ **성숙잎처럼 「대표 + 1 + 2」로 못 접는다.** `midNums` 가 연속이 아닌 갈래가 있다
(알보-흰연두 = 42·4·5 — 기본판이 나중에 붙어서다). 그래서 **세 번호를 다 적는다.**
코드에 이름을 안 박았다 — `shop.js` 밑값은 파일을 못 읽었을 때만 사는 사본이고,
`test_variegrade` A-2 가 둘이 갈리는 것을 막는다.

### ㉡ 같은 자리에서 그림 두 벌이 나온다 (`src/game/shop.js`)
`assignPotLeafGrades` 가 등급을 적는 그 줄에서 `leafSkinsFor()` 를 부른다.
`assigned[]` 와 `events[]` 에 `midSkin`·`matSkin` 이 실려 나온다.

```js
{ leafBirth: 45, leafNo: 3, grade: 'halfmoon',
  midSkin: 'leaf_mid_albo30', matSkin: 'leaf_mat21' }
```

★★ **적지 않고 되뽑는다.** 왜 그렇게 했는지가 이 배선의 핵심이라 적어 둔다:
- 확정문 §5 가 *"두 벌이 되면 반드시 어긋난다"* 고 못 박았다. 그림을 따로 적으면 두 벌이 된다.
- 그리고 **적어도 안 남는다.** `save.js §화분 한 칸` 은 적을 칸을 **이름으로 골라** 적는다
  (흰 목록). `pot.leafSkins` 같은 새 칸은 **저장 한 번에 조용히 사라진다.**
  적으려면 `save.js` 를 같이 고쳐야 하는데 그 파일은 내 것이 아니다.
⇒ 그림은 **`등급 + 시드 + 화분id + leafBirth` 의 순수 함수**다.
  · 두 벌이 안 생긴다 · 저장·불러오기를 건너도 같은 답 · **옛 세이브에도 저절로 선다**
- 굴림은 **`assignPotLeafGrades` 가 쓰는 `marketHash` 그대로**다. 소금만 다르다
  (21=등급 · 23=중간잎 · 29=성숙잎).
- ⚠ **표를 고치면 그림이 바뀐다**(등급은 그대로). 한 판 안에서는 표가 안 바뀌니
  「한 번 정해지면 안 바뀐다」는 성립한다.

**옛 세이브**: `potLeafSkinsOf(S, pot, { varieLeafBirths })` 가 등급 없는 무늬 잎을
`legacyGradeId`(산반)로 떨어뜨리고 **`fromLegacy: true` 로 표시한다.** 조용히 안 한다.

새로 난 창구:
`midSkinKeysOfGrade(id)` · `gradeOfMidNum(n)` · `leafSkinsFor(gradeId, seed, potId, leafBirth)` ·
`potLeafSkinsOf(S, pot, opt)` · `LEAF_SKIN_SALT`

## 9. ★ 판단필요 — 박사님

⇒ 「이름으로 묶은 것」을 그대로 둘지, **모양대로 옮길지.**
