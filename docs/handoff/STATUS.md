# STATUS — 창별 상태판

**한 파일만 열면 전체가 보이게 하는 것이 목적이다.**
박사님이 창 5~6개를 돌며 복붙해 전달하지 않도록, 각 창이 **자기 섹션만** 갱신한다.

---

## 쓰는 법

작업이 끝나거나 중요한 결과가 나오면 **자기 섹션만** 이 형식으로 갱신한다.

```markdown
## {내창}
갱신: 2026-08-01 (커밋 abc1234)
완료: (이번에 한 것 2~4줄)
발견: (★다른 창이 알아야 할 것 — 없으면 생략)
대기: (누구의 무엇을 기다리나)
판단필요: (★사용자·plan이 정해야 할 것)
```

### 규칙

| | |
|---|---|
| **★ 커밋·푸시까지** | 안 하면 박사님이 못 읽는다. 푸시가 빠지면 안 쓴 것과 같다 |
| **자기 섹션만 수정** | 남의 섹션은 **절대** 건드리지 않는다. 섹션이 나뉘어 있으면 git이 자동 병합한다 |
| **요약만** | 상세는 기존 `{내창}-to-{상대}.md` 에. 여기는 **2~4줄** |
| 대화 요약 | 그대로 해도 된다. **파일에도** 남기라는 것 |

### ★ "발견"과 "판단필요"를 꼭 써라

**창을 가로질러 보는 사람에게 제일 중요한 정보다.**
"완료"는 커밋 로그에도 있지만, 저 둘은 **여기 없으면 어디에도 없다.**

| 항목 | 무엇을 쓰나 |
|---|---|
| **발견** | 예상과 달랐던 것 · 남의 전제를 깨는 값 · 인터페이스 변경 · 버그 |
| **판단필요** | plan/박사님이 정해야 할 것. **선택지와 근거를 같이** 적을 것 |

> 판단이 필요한데 안 적으면 **아무도 모른 채 몇 주가 간다.**
> 반대로 적어두면 박사님이 이 파일 하나로 결정할 수 있다.

  char 소비 약 145cr이 그래서 안 보였음 → **`manifest._credit_log` 기록 규칙 신설.
  전 창이 유료 API 쓸 때 한 줄씩 남겨 주세요.** 없으면 충전 시점을 못 잡습니다

- **시루·재배트레이 슬롯이 관엽 선반과 완전 동일 규격** → 가구·작물용기를 한 배치 로직으로 처리 가능
- GLB 내보낼 때 **`vertex_normals` 를 미리 계산해야 NORMAL 이 들어간다.** 안 하면 three.js가
  flat shading만 켜고 **잎 두께 조절이 통째로 무효**가 됨(실제로 겪음)
- house 실측 대입: **반지하 0.55~0.48 짜리 4칸은 저광작물(새싹채소·상추) 자리**
