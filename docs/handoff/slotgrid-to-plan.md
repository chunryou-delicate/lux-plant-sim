## 1. 무엇이 문제였는지 — 「자리가 둘」은 상판의 성질이 아니었다

책상 상판은 1.20 × 0.60 m 다. 거기에 노란 네모가 **둘**이었다. 왜 둘인가를 끝까지 따라가면
`src/render3d/furniture_pastel.js` 의 한 줄에서 끝난다.

```js
/* :123 */ return addSlots(g, tierSlots(w, h, w>1.4?3:2, d*0.15), [h]);   // 책상
/* :85  */ function tierSlots(w, y, n, z=0, margin=0.09){ … }             // 가로 한 줄만 깐다
```

- `tierSlots` 는 **가로 한 줄**만 깐다. 깊이(`d`)를 아예 안 쓰고 `z` 가 상수다
- 개수 `n` 은 빌더에 **박힌 상수**다 — 책상 `w>1.4?3:2` · 서랍장 `2` · 선반단 `3`
- 그래서 0.72 ㎡ 짜리 상판에 자리가 둘이고, 그 둘은 상판 **양 끝**(면 중심에서 ±0.51 m)이다

즉 **「자리가 둘」은 방 데이터도 상판 크기도 아닌, 빌더의 상수였다.** 화면은 그 상수를
「여기 둘뿐입니다」로 읽어 주고 있었고, 그게 박사님이 보신 그림이다.

★ 그런데 **놓는 길은 이미 상판 전체를 받고 있었다.** 2026-08-07 에 `surfaceAt → snapOnSurface`
가 상판 격자를 깔았고(`docs/handoff/placegrid-to-plan.md` §3), 책상 상판에서 자유 좌표가
21곳 나온다. **없던 것은 「놓을 수 있다」는 표시뿐**이었다.

`room_view.js` 에 층을 하나 더 얹었다. 이름은 `guideCells` 다.

| 층 | 뜻 | 색·모양 | 개수 |
|---|---|---|---|
| 추천 자리 `guideRings` | **「여기가 좋다」** | 녹색 투명면 + 테두리 | **14 — 예전 그대로** |
| 가구 윗면 칸 `cellRings` | **「여기 놓을 수 있다」** | 테두리만 (녹색 면 없음) | 새로 생긴 것 |

`span` 칸짜리는 그 묶음의 **한가운데**에 앉는다.

| 끌고 있는 것 | 지름 | 칸 수 | 반지하에 나는 칸 | 그중 올라가는 칸 |

절반이라 둘 다 격자 위에 있다. 그래서 `span` 을 받아 묶음 한가운데를 낸다.

## 3. ★★ 세이브 — **한 글자도 안 바뀐다**

인계 지시가 「기존 번호를 고정하고 새 칸을 뒤에 덧붙이는 것」을 권했다.
**그보다 안전한 길이 있어서 그쪽으로 갔다: 슬롯을 아예 안 늘렸다.**

### 왜 슬롯을 안 늘렸나

슬롯을 늘리면 `slotId = uid + ':' + i` 의 **번호 뜻**이 움직인다. 「뒤에 덧붙이기」로 뜻을
지켜도 다음이 남는다 — 그리고 이 넷은 덧붙이기로 안 풀린다.

| | 덧붙이기로도 남는 문제 |
|---|---|
| **격자가 안 맞는다** | 지금 책상 슬롯은 면 중심에서 **±0.51 m** 다. 0.25 칸 한가운데는 ±0.125·±0.375 다. 두 자리를 그대로 두고 칸을 덧붙이면 **칸에서 0.135 m 벗어난 네모 둘**이 남는다 — 상판이 더 지저분해진다 |
| **드롭다운** | `game.html` 의 `fillSlots`·`fillMusunSlots` 가 자리마다 `<option>` 한 줄이다. 14 → 31 이면 목록이 못 쓸 물건이 되고 `slotLabel` 이 「책상 9번 칸」이 된다 |
| **얼린 프로파일** | `data/profiles/room_profile.*.json` 을 다시 뽑아야 한다 |
| **검사 9개** | 아래 §5 표 |

⇒ **자리(계약)와 칸(화면)은 뜻이 다른 것**이고, 뜻이 다른 것을 한 이름으로 부르려던 것이
문제였다. 갈라 놓으면 셋 다 안 건드리고 지시가 이뤄진다.

### 그래서 지금 이렇게 된다

- 추천 자리에 놓으면 → 예전 그대로 `banjiha-desk:0` 으로 저장된다
- 새 칸에 놓으면 → **`free:pot_01`** 로 저장된다. 이건 2026-08-03 부터 있던 규약이고
  `save.js` · `light_adapter.js` · `state.setPotAt` 이 이미 다 안다
- 옛 세이브는 **아무 영향이 없다** — 슬롯 이름도 개수도 좌표도 그대로다

## 6. `game.html` 에 붙일 것 — ★ 이건 **꼭 붙여야 한다**

`game.html` 은 지시대로 안 건드렸다. 그런데 **재서 확인한 사고가 하나 있고, 그게 이번 일의
목적(가구 위 아무 칸에나 놓기)을 정면으로 막는다.**

### 6-1. 사고 — 자유 좌표 화분의 `slotId` 를 `fillSlots` 가 조용히 갈아 끼운다

**재현했다.** 재현 방법(임시 탐침은 규칙대로 지웠다) — 반지하에서
① `S.pots[0].at` 을 책상 자유 칸으로 두고 `slotId = 'free:pot_01'` 로 놓는다
② `#lamps` 에 `change` 를 쏜다(= `fillSlots` 를 부르는 길 하나. `loadSave` 도 같은 길이다)

```
before  slotId = "free:pot_01"          at = (0.415, 0.74, -1.5)   ← 책상 위
after   slotId = "banjiha-etagere:0"    at = (0.415, 0.74, -1.5)   ← 이름만 바뀌었다
그다음   io.light.daily(...) 가 던진다:
  [조도] pot_01 의 자리가 어긋납니다 — slotId=banjiha-etagere:0 는 (-0.62, 0.03, -1.72) 인데
  at 은 (0.415, 0.74, -1.5) 입니다. 자유 좌표로 옮겼다면 slotId 가 free:pot_01 여야 합니다.
```

원인 — `fillSlots` 의 목록(`list`)에는 **추천 자리만** 들어간다. 그래서 `free:pot_01` 은
언제나 「목록에 없는 자리」로 보이고, 아래 줄이 그것을 갈아 끼운다:

```js
  const p = pot0(S);
  if (p && (pick || !list.some(s => s.slotId === p.slotId)))
    p.slotId = list[0] ? list[0].slotId : null;
```

⚠ **이건 이번 변경이 만든 것이 아니다.** 자유 배치는 2026-08-03 부터 있었으므로 지금도 나는
사고다. 다만 새 칸이 보이기 시작하면 **플레이어가 실제로 그 길로 간다.**

### 6-2. 붙일 두 줄 (그대로 붙여넣기)

`function fillSlots(pick)` 안, `const p = pot0(S);` 아래 두 줄을 이렇게 바꾼다.

```js
  const p = pot0(S);
  /* ★ 자유 좌표로 놓인 화분은 **건드리지 않는다** (2026-08-11 · 재현해서 잡았다).
     이 목록은 추천 자리뿐이라 `free:pot_01` 이 늘 "목록에 없는 자리"로 보인다.
     갈아 끼우면 slotId 만 바뀌고 at 은 그대로라 light_adapter 가 다음 호출에서
     「자리가 어긋납니다」로 던진다 — 화면이 통째로 멎는다. */
  if (p && !isFreeSlotId(p.slotId) && (pick || !list.some(s => s.slotId === p.slotId)))
    p.slotId = list[0] ? list[0].slotId : null;
  $('slot').value = (p && !isFreeSlotId(p.slotId) && p.slotId) || (list[0] ? list[0].slotId : '');
```

- `isFreeSlotId` 는 `game.html` 이 **이미 import 해 쓰고 있다**(`slotLabel`). 새 import 없다
- ⚠ 셋째 줄은 **화장**이다. 자유 좌표 화분일 때 드롭다운이 「몬스테라 자리」로 엉뚱한 자리를
  가리키는 것은 남는다 — 목록에 그 자리가 없으니까. 「방 안 자유 자리」 같은 항목을 하나
  넣을지는 §7 판단필요다. **급한 것은 첫째 조건 하나뿐이다**(안 넣으면 던진다)

### 6-3. 드롭다운은 **안 늘어난다**

지시가 걱정하신 「14 → 60 이면 목록이 못 쓸 물건이 된다」는 **이 길에서는 안 일어난다.**
`fillSlots`·`fillCropSlots`·`fillMusunSlots` 가 읽는 `io.light.room.slots` 는 여전히 14칸이고
`slotLabel` 도 「책상 1번 칸/2번 칸」 그대로다. 늘어난 것은 **화면의 네모뿐**이다.

## 7. 판단필요 (박사님)

1. **추천 자리 둘이 칸에서 벗어나 있다.** 책상의 `banjiha-desk:0/:1` 은 상판 양 끝
   (면 중심 ±0.51 m)이라 0.25 칸 한가운데(±0.125·±0.375)에서 **0.135 m 벗어나 있다.**
   지금은 「초록 면이 깔린 추천 네모 2개 + 격자에 물린 칸 8개」가 같이 뜬다.
   ㉮ 그대로 둔다(추천은 원래 격자와 무관한 안내다) ·
   ㉯ 슬롯 좌표를 칸 한가운데로 옮긴다 ← **이건 DLI 가 바뀐다. 사고다** ·
   ㉰ 추천 네모를 **제일 가까운 칸으로 옮겨 그리기만** 한다(계약 좌표는 그대로, 표시만)
   ⇒ 지금은 ㉮ 로 뒀다. ㉰ 는 「표시가 실제 앉는 자리와 다르다」가 되어 권하지 않는다.
2. **가구 위에 물건이 서 있는 칸**(반지하 책상의 집게등 자리). 지금은 네모가 그려지지만
   실제로는 못 겨눈다. ㉮ 그대로 · ㉯ 어둡게(못 놓는 색) · ㉰ 안 그린다.
   판정하려면 「그 칸 위에 무엇이 서 있나」를 새로 재야 한다 — **안 했다.**
3. **드롭다운에 「방 안 자유 자리」 항목을 둘지** (§6-2 셋째 줄). 지금은 자유 좌표 화분일 때
   「몬스테라 자리」가 엉뚱한 자리를 가리킨다.
4. **칸을 0.25 보다 잘게 할지.** 지금 반지하 책상은 4×2 = 8칸이다. 0.20 으로 하면 6×3 = 18칸,
   0.15 면 8×4 = 32칸이 된다. 사진으로 보시고 정하시면 `place.GRID_CELL` 한 줄이 아니라
   `room_view.cellsOfRect` 의 눈금 하나다(바닥·창턱과 갈라진다 — 그러면 그건 그것대로 빚이다).
5. **`maxPotD` 를 「한 칸 한도」로 쓰는 것.** 서랍장 `maxPotD` 0.42 는 **단 깊이 0.45 − 0.03**
   이다. 새싹 재배판은 실제로 0.36 × 0.24 인데 **회전무관 지름 0.4327** 로 재기 때문에
   서랍장에 못 올라간다(0.4327 > 0.42). 실제 판때기는 들어간다.
   ⇒ 「지름 하나」가 아니라 「가로×세로 칸 수」로 재면 풀린다. 다만 그건 `potFits`·`fitCheck`·
   `slotFitsDiameter` 를 다 같이 옮기는 일이고 **검사 여러 개의 얼린 답**을 건드린다.
   **이번엔 안 했다.** 할지 말지 정해 주시면 그때 한 벌로 옮긴다.

## 8. 못 한 것

- **`game.html` 은 안 고쳤다** — §6 의 두 줄이 붙어야 자유 칸 배치가 안 멎는다
- **집게등 아래 칸 하나**를 못 겨눈다(§4-②). 등을 치우고 다시 재 보지 않았다 — **못 쟀다**
- **`maxPotD` 를 칸 수로 바꾸는 일**(§7-5). 검사 여러 개의 얼린 답을 건드려서 안 건드렸다
- **`furniture_pastel.js` · `house.js` · `place.js` · `data/profiles/*.json` 은 한 줄도 안 고쳤다.**
  고칠 이유가 없었다 — 이번 일은 계약이 아니라 화면이었다
- **폰 실기(game.html) 화면으로는 안 찍었다.** `game.html` 을 다른 창이 동시에 잡고 있어
  드래그 상태를 만들어 찍는 길을 안 열었다. 사진은 `room_view_demo.html` 것이다
