## 1. 무엇을 만들었나 (설명 먼저)

박사님 말씀:
> *"식물 탭에서 **버튼 누르면 빛 분포** 볼 수 있게 해줘. **그리드 살리면서** 약간 그
> **일전에 시뮬레이터 결과처럼** 보이게. 버튼 누르면. **그리드 수치도 작은 숫자로** 보이고."*

방바닥에 **두 겹**을 얹는다.

| 겹 | 무엇 | 어디에 |
|---|---|---|
| ① 색 | 칸마다 조도 색(파랑→시안→초록→노랑→빨강) | 3D · `src/render3d/lighting_viz.js` |
| ② 숫자 | 칸 한가운데의 작은 숫자 + 아래 머리글 | HTML 겹쳐 그리기 · `src/render3d/light_grid_labels.js` |

그 위에 **원래 있던 배치 격자 눈금이 그대로 남는다.** 히트맵을 격자 **아래**에 깔았다
(히트맵 y=0.0022 · 막힌 칸 0.003 · 눈금선 0.004). 사진으로 확인했다(§4-⑦).

### 「시뮬레이터 결과처럼」을 어떻게 옮겼나 — 한 군데를 일부러 바꿨다

시뮬레이터(`index.html`)의 판때기는 **정점색으로 번지는** 부드러운 그림이다. 그 화면에는
숫자가 없으니 그래도 됐다. 게임에는 **칸마다 숫자**를 얹어야 하는데, 번진 색 위에 숫자를
얹으면 **「이 숫자가 이 색인가」가 반 칸 어긋난다**(정점은 칸 *모서리*, 숫자는 칸 *한가운데*).

⇒ 게임 쪽은 **칸마다 납작한 네모 한 장**으로 칠했다. **한 칸 = 한 색 = 한 숫자**다.
색 눈금(제트)·반투명·상대 밝기는 시뮬레이터 그대로라 첫인상은 같다.

### 격자를 22칸이 아니라 **0.25m 배치 격자**에 맞췄다

조도 엔진의 `GRID` 는 22 지만, 방바닥에는 이미 **0.25m 배치 격자**가 깔려 있다
(`room_view §gridSpan` · 반지하 19×15 = 285칸). 조도를 22칸으로 따로 깔면 **선이 두 벌**
겹쳐 보이고, 그건 「그리드 살리면서」와 정면으로 어긋난다.
⇒ 히트맵 칸 = 배치 칸. 재서 확인했다 — **19×15 로 같다**(§4-⑦).

### 값은 지어내지 않는다 — `io.light.dliAt` 그대로

화면이 내는 숫자는 **DLI(mol/m²·d)** 다. 게임이 「여기 놓으면 어떤가」를 판정할 때 부르는
**바로 그 함수**(`light_adapter.dliAt`)에 바닥 좌표를 넣어 얻는다. 그래서 §4-④ 는
「같은 함수를 두 번 부르면 같은 값이 나오나」가 아니라 **「화면에 실린 숫자가 그 함수 값 그대로인가」**
를 잰 것이고, 결과는 **한 톨도 안 다르다**.

머리글이 무슨 값인지·색의 양 끝이 얼마인지·무슨 조건인지를 같이 적는다:
`DLI mol/m²·d · 바닥 · ■0.00 → ■0.32 · clear·summer·등 0개`

## 2. 숫자를 왜 HTML 로 그렸나 — **재서 골랐다**

3D 안에 글자를 얹는 길이 셋이었다. **폰 390px 에서 읽히나**를 기준으로 골랐다.

| 길 | 폰 390px 에서 글자 높이 | 값 | 판정 |
|---|---|---|---|
| ㉮ 바닥에 눕힌 캔버스 텍스처 | 칸이 12px 인데 시점이 30~40° 라 세로가 60% 로 눌린다 ⇒ **6~9px** | 드로우콜 +1 | **안 읽힌다** |
| ㉯ 스프라이트(빌보드) | 안 눌린다 | 라벨마다 **드로우콜·텍스처 +1** (35개면 +35) | 폰에서 아깝다 |
| ㉰ **HTML 겹쳐 그리기** | **11px 고정**(어디서나 11px) | WebGL 드로우콜 **0** | ⇐ 골랐다 |

⇒ ㉰. 대신 **그린 뒤마다 좌표를 다시 잡아야 한다** — `renderer.render` 를 한 겹 감싸서
자동으로 돌게 했다(되돌릴 수 있게 원본을 들고 있고 `dispose` 에서 정확히 되돌린다).

### 몇 칸마다 적나 — 사람이 안 정한다, **화면이 정한다**

285칸을 다 적으면 폰에서 뭉갠다. 그래서 **화면에서 한 칸이 몇 px 인지**를 재서
`ceil(30px / 칸px)` 칸마다 적는다. 줌을 당기면 저절로 촘촘해진다(실측 §4-⑧).

| | 칸 간격 | 몇 칸마다 | 그린 숫자 |
|---|---|---|---|
| 기본 시점 | 12.04px | 3칸 | 35개 / 285칸 |
| 14칸 당긴 뒤 | 17.36px | 2칸 | 75개 |

### 자리 수도 격자가 정한다

반지하 **바닥**은 DLI 0.00~0.32 다. 한 자리로 적으면 **서른다섯 칸이 전부 「0.0」** 이 되어
아무것도 안 말한다(첫 판이 실제로 그랬다). 격자 최대값을 보고 자리 수를 고른다 —
1 미만이면 두 자리, 10 미만이면 한 자리, 1000 넘으면 `k`. 엔진이 DLI 를 소수 둘째 자리까지
내므로 **거기서 멈춘다**(없는 정밀도를 지어내지 않는다).

## 5. `room_view.js` 에 붙일 코드 (⚠ 내가 못 붙였다 — 그때 다른 창이 들고 있었다)

다섯 군데다. **어디에 · 무엇을 · 왜**를 같이 적는다.

### ㉮ 들여오기 — 다른 `import` 옆 (지금 55줄 언저리)

```js
import { attachLightHeatmap } from '../render3d/light_grid_labels.js';
```

### ㉯ 창구 본체 — `function disposeFurnGhost() {` **바로 앞**(지금 6070줄 언저리 · `showGrid` 다음)

`showGrid` 옆에 두는 이유: **같은 격자를 쓰는 두 그림**이라 한자리에 있어야 나중에
누가 격자를 손댈 때 둘 다 눈에 들어온다.

```js
  /* ── ★ 빛 분포 겹쳐 보기 (2026-08-16 · 박사님 "버튼 누르면 빛 분포 볼 수 있게") ──
     배치 격자와 **같은 칸**에 조도(DLI)를 칠하고 칸마다 작은 숫자를 얹는다.
     ⚠ **끈 상태가 기본이고, 켤 때만 잰다.** 켜 놓고 매 프레임 다시 재면 폰이 죽는다.
     ⚠ 값은 여기서 지어내지 않는다 — `lightEngine.dliAt` 이 낸다. 게임이 화분 자리를
       판정할 때 부르는 그 함수 그대로다(그래서 화면과 판정이 못 갈린다).
     ⚠ 조건(날씨·계절·등 개수)은 **호출부가 준다.** 여기서 기본값을 지어내면 화면이
       「맑은 여름」이라 적어 놓고 실제로는 다른 날을 그리는 일이 생긴다 — 안 주면 그 사실을
       머리글에 그대로 적는다. */
  let heatView = null, heatWant = false, heatOpt = {};
  function setLightHeatmap(on, opt = {}) {
    heatWant = !!on;
    heatOpt = opt;
    if (!heatWant) { if (heatView) heatView.set(false); return false; }
    if (!built) throw new Error('[빛분포] 방이 아직 안 지어졌습니다');
    if (!O.lightEngine || typeof O.lightEngine.dliAt !== 'function')
      throw new Error('[빛분포] 조도 엔진이 없습니다 — createRoomView 에 lightEngine 을 넘기십시오');
    const c = { weather: opt.weather || 'clear', season: opt.season || 'summer',
                lampCount: opt.lampCount | 0,
                litHours: opt.litHours == null ? 12 : opt.litHours };
    const y = opt.y == null ? 0 : opt.y;                  // 재는 높이[m] — 기본은 바닥
    const valueAt = (x, z) => O.lightEngine.dliAt({ x, y, z }, c).dli;
    const unit = opt.unit || `DLI mol/m²·d · ${y ? y.toFixed(2) + 'm' : '바닥'}`;
    const extra = opt.extra || `${c.weather}·${c.season}·등 ${c.lampCount}개`;
    if (!heatView) heatView = attachLightHeatmap(view, {
      canvas, valueAt, unit, extra,
      /* 벽 속 칸은 안 칠한다 — 배치 격자가 안 그리는 그 칸이다(§gridSpan) */
      keep: (i, j) => gridSpan().at(i, j),
      captionPos: opt.captionPos, fontPx: opt.fontPx, minGapPx: opt.minGapPx
    });
    else heatView.refresh({ valueAt, unit, extra });
    heatView.set(true);
    return true;
  }
```

### ㉰ 공개 API — 돌려주는 객체 안, `grid() { … },` **바로 다음**(지금 8668줄 언저리)

```js
    /* ── ★ 빛 분포 (2026-08-16) ──
       roomView.setLightHeatmap(true, { weather, season, lampCount, litHours })
       roomView.setLightHeatmap(false)
       roomView.lightHeatmap()        지금 상태·잰 값·라벨 수 (검증용)
       ⚠ 버튼은 game.html 몫이다. 여기는 켜고 끄는 창구만 낸다. */
    setLightHeatmap(on, opt) {
      try { return setLightHeatmap(!!on, opt || {}); } catch (e) { throw fail(e); }
    },
    lightHeatmap() { return heatView ? heatView.stats() : { on: false, cells: 0, labels: null }; },
```

### ㉱ 방을 다시 지으면 다시 잰다 — `assemble()` 끝, `applyDaylight(); needsRender = true;` **바로 다음**(지금 1133~1134줄)

```js
    /* 방을 갈아탔거나 가구를 옮겼다 → 차폐가 달라져 **값이 바뀐다.** 켜 둔 채였으면 다시 잰다.
       ⚠ 안 하면 화면이 옛 방의 밝기를 그대로 보여 준다 — 조용히 틀리는 유형이다. */
    if (heatView) { try { heatView.rebuild(); } catch (e) { console.warn('[빛분포] 다시 재기 실패 —', e.message); } }
```

### ㉲ 치우기 — `dispose()` 안, `clearGrid();` **바로 앞**(지금 9317줄 언저리)

```js
      if (heatView) { heatView.dispose(); heatView = null; }
```

⚠ `heatView.dispose()` 는 감쌌던 `renderer.render` 를 **원래대로 되돌리고**, 숫자 `<div>` 를
DOM 에서 걷고, 부모의 `position` 을 원래 값으로 되돌린다.

## 6. `game.html` 이 부를 창구 (마스터 창 몫)

[식물] 탭 버튼에 이렇게 물리면 된다.

```js
/* 켜기 — 조건은 **지금 게임의 것**을 준다. 안 주면 화면이 「맑은 여름」이라 적어 놓고
   딴 날을 그리게 된다(setLightHeatmap 의 ⚠ 참고). */
const sky = io.light.skyFor(S.day, S.sim);
roomView.setLightHeatmap(true, {
  weather: sky.weather, season: sky.season,
  lampCount: S.lamps.count, litHours: S.lamps.litHours
});

/* 끄기 */
roomView.setLightHeatmap(false);

/* 날이 가거나 등을 켜거나 가구를 옮겼으면 — 같은 줄을 다시 부르면 된다(켜져 있으면 다시 잰다) */
```

- **끈 상태가 기본**이다. 켤 때만 285칸을 잰다(12~60ms).
- 버튼 상태는 `roomView.lightHeatmap().on` 으로 읽으면 된다.
- 머리글을 게임 UI 가 직접 그리고 싶으면 `{ captionPos: 'none' }` 을 주면 된다 —
  ⚠ **그때는 무슨 값인지·단위가 무엇인지를 그쪽이 반드시 적어야 한다.**
- `weather`/`season` 을 한글로 보이고 싶으면 `{ extra: '맑음·여름·등 0개' }` 로 통째로 넘기면 된다
  (지금 화면에는 엔진이 쓰는 `clear·summer` 가 그대로 나온다 — §7).

## 7. 못 한 것 · 판단이 필요한 것 (짐작으로 안 적는다)

1. **`room_view.js` 에 안 붙였다.** 다른 창이 들고 있었다(`git status` 에 걸려 있었다).
   §5 코드를 붙여야 게임 버튼이 돈다. **지금은 검사 도구가 공개 API 로만 밖에서 붙여 잰 것이다** —
   그래서 §5 의 코드도 「이렇게 하면 된다」가 아니라 **실제로 도는 것과 같은 배선**이다.
2. **머리글의 날씨·계절이 영문이다**(`clear·summer`). 엔진이 내는 문자열을 **그대로** 적었다 —
   여기서 한글로 바꾸면 화면이 엔진 값과 다른 말을 하게 된다. 한글은 `extra` 로 호출부가 주면 된다.
   ⇒ **판단 필요**: 마스터가 `extra` 로 넘길지, 코어가 `ko` 표를 낼지.
3. **바닥 값이 거의 다 0 근처다.** 반지하 바닥은 DLI **0.00~0.32** 다(맑음·여름·등 0개).
   틀린 게 아니라 **반지하가 실제로 그렇다** — 창턱(1.6m)이 4.80 인 방이다.
   ⇒ **판단 필요**: 「빛 분포」를 **바닥**에서 볼지 **화분 높이**에서 볼지.
   높이는 이미 손잡이가 있다(`setLightHeatmap(true, { y: 0.75 })`) — 시뮬레이터도 0.75m 로 본다.
   박사님께 여쭙고 정할 일이라 **기본은 바닥(y=0)** 으로 두었다. 그게 「그 칸에 놓으면」과
   글자 그대로 같은 값이기 때문이다.
4. **가구에 가린 칸은 안 보인다**(285칸 중 61칸). 바닥에 칠하는 그림이라 침대·책상 밑이 가린다.
   배치 격자도 똑같이 가리므로 **일부러 맞췄다**(`depthTest: true`).
   시뮬레이터는 반대로 `depthTest:false` 로 가구를 뚫고 보여 준다 — 그건 진단 화면이라 맞는 선택이다.
   ⇒ **판단 필요**: 게임에서도 뚫어서 보여 줄지. 한 줄이면 바꾼다(`{ depthTest: false }`).
5. **원룸·다른 방에서는 안 재 봤다.** 반지하만 찍었다. 격자 크기는 방마다 다르므로
   칸 수가 크게 늘면(온실 같은 방) 재는 시간이 285칸 기준보다 는다 — 칸 수에 정비례한다.
6. **`?fast=1` 로 재고 대사를 건너뛴 상태**의 숫자다. 실제 플레이 중(캐릭터가 걸어다니고
   말풍선이 뜨는 동안)의 프레임 비용은 안 쟀다.
