## 5. ★권하는 것 하나 — `slow 1.5 · best 2.0` (㉠a3)

`data/growth_tuning.json` 의 `growth_speed.by_band` 를 이렇게:

```json
"slow": 1.5, "best": 2, "good": 2, "over": 1
```

**진짜 `test_balance_routes` 로 확인했다 — FAIL 2건 → FAIL 1건.**

```
A 등 없이 — 이사 24/24 (100%) · 중앙값 튜토 126일 · 계절 autumn:20 winter:4 · 유효생장 249 · 잎 4장
B 등 1개  — 이사 24/24 (100%) · 중앙값 튜토 106일 · 계절 autumn:20 winter:4 · 유효생장 249 · 잎 4장
PASS ①-1   PASS ①-2   FAIL ③-b(151일)
```

### 왜 이것인가 — 세 가지

1. **`①-2` 를 고치는 가장 작은 값이다.** `slow 1.25`(㉠a1)는 152일이라 아직 겨울이고,
   `slow 1.5` 에서 126일 = 가을로 넘어간다(가을은 튜토 45~134일).
2. **이득비가 안 줄어든다.** `best` 를 천장(2.0)까지 같이 올렸기 때문에
   등의 이득이 ×1.17 → **×1.19** 로 **오히려 커진다.** 같은 126일인 ㉠a2(best 1.75)는
   ×1.10 으로 준다 — ⇒ **`slow` 를 올릴 때는 `best` 도 같이 올려야 한다.**
3. **A 가 죽지 않는다.** 83% → 100% 로 오히려 산다.

### ★대가 — 정직하게 두 가지

**① 어두운 자리가 50% 빨라진다.** 「자리가 결과를 바꾼다」의 크기는
**이득비 ×1.19**(A 126일 vs B 106일)로 남는다. 지금은 ×1.17(189 vs 161)이다.
**비율은 커지고 절대 일수는 28일 → 20일로 줄어든다.** 어느 쪽으로 읽을지가 판단입니다.

**② ★등이 「안전장치」 역할을 잃는다.** 지금은 A 83% · B 100% 라
식물등이 사는 것이 **"나갈 수 있느냐"** 자체다. ㉠a3 에서는 둘 다 100%라
등이 사는 것은 **"20일 빨리"** 로 바뀐다.
`story_arc §2` 가 C 경로를 *"식물등이 안전장치"* 라고 부르는데 **그 문장이 약해진다.**
— 값의 문제가 아니라 서사의 문제라 박사님 판단입니다.

### 깨지는 검사 세 개 — 하나만 진짜다

| 검사 | 무슨 말인가 | 진짜 고장인가 |
|---|---|---|

이건 밸런스 값이 아니라 **하네스가 무엇을 재고 있는가**의 문제라 이 창이 못 정합니다.

속도를 올려도 겨울에 빛이 `min` 아래로 떨어져 정지하는 것은 그대로다.
**속도 손잡이로 못 고치는 별개 문제**다.

### ③ `good` · `over` 계수는 여전히 못 잰다

반지하 튜토가 그 밴드를 한 번도 안 지난다(growthspeed 창 §8② 그대로).
㉠a3 의 `good: 2` 는 `best` 와 맞춘 값이지 **잰 값이 아니다.**

### ④ 안 재 본 것

- **첫 플레이 30일**(게임일 = 튜토일 + 30)을 줄이는 길 — `first_play` 소유라 안 건드렸다
- `shop.priceOf` 사다리 자체 · 생장 곡선의 총 길이 — 각각 shop · plant_grow 소유
- 시루 2개 · 무순 병행 등 다른 플레이 방식 — 시루 3개만 재 봤다(−5일)
- 원룸·아파트 방에서의 같은 표 — 반지하만 쟀다
- `잎2 exit + slow 1.7`(게임 80일이 될 값) — 어차피 `①-1` 이 깨지는 구간이라 안 쟀다

### ⑤ ★이 창의 워크트리는 `main` 보다 20+ 커밋 뒤에 있었습니다

이 워크트리에는 `growth_speed` 자체가 없었다(`data/growth_tuning.json` 에 그 절이 없다).
동기화가 권한에 막혀서, **공유 체크아웃의 내용을 임시 폴더에 복사해 거기서만 쟀다.**
진짜 `src/**` · `data/**` · `game.html` 은 **읽기만** 했다 — `git status` 가 그 증거다.
기준값이 박사님이 말씀하신 것과 **정확히 일치**하는 것으로 재현을 확인했다
(A 189일 · 유효생장 249 · 잎 4장 · 게임 219일 · FAIL 2건).

⇒ **`node tools/probe_tutorial_length.mjs` 를 이 워크트리에서 돌리면 안 됩니다.**
`main` 위에서 돌려야 위 숫자가 나옵니다. 도구는 스스로 사본을 만들어 값을 갈아 끼우므로
`main` 에 합쳐진 뒤에는 그냥 돌아갑니다.

## 도구 사용법

```
node tools/probe_tutorial_length.mjs             후보 30벌 + 딸린 검사 (10분 넘게 걸린다)
node tools/probe_tutorial_length.mjs --quick     세 경로만 (딸린 검사 생략 · 5분쯤)
node tools/probe_tutorial_length.mjs --only=㉠a3 후보 하나만 (쉼표로 여러 개)
```

★ 이 도구는 **저장소를 한 글자도 안 고친다.** 임시 폴더에 사본을 만들고 거기서만
`growth_tuning.json` · `tutorial.js` · `characters.json` 을 갈아 끼운 뒤, 끝나면 지운다.
후보마다 **새 프로세스**인 이유는 `loop.js` 가 계수를 모듈 최상단에서 한 번만 읽기 때문이다.
딸린 검사(`test_save` 등)도 같은 사본에서 돌린다 — 그래야 "그 값일 때" 깨지는지가 재진다.
