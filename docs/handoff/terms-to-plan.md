### ★★ 세고 나서 알게 된 것 둘

**㉠ ① 은 말하는데 — 첫 플레이 단계일 때만이다.**
`#quest` 는 「퀘스트 > 살림목표 > 첫플레이 단계」 순으로 이긴다(`drawJourney`).
첫 플레이가 끝나면 **퀘스트가 그 줄을 가져간다.** 실측:

```
첫 플레이가 끝난 판 (Day 4)
  ① #quest : 무순을 길러 콩나물과 한 상에 올리세요     ← 「수확까지 1일」이 사라졌다
  시트 시루 줄 : 4/5칸 · 1일 남음                      ← 시트를 열어야 보인다
```

⇒ **살림이 시작되면 방 화면에서 「며칠 남았나」가 통째로 사라진다.**

**㉡ [다음 날]은 화면에서 제일 크고 매일 누르는 단추인데 아무 말도 안 한다.**
물주기 단추는 「(2개 대기)」를, 거두기 단추는 「(익은 것 3개)」를 이미 제 글자로 말한다.
[다음 날]만 늘 「다음 날 ▸」이었다.

### 그래서 얹은 것 — **새 통로를 안 만들었다. 단추가 스스로 말한다**

```
자라는 중  →  다음 날 ▸ · 수확까지 3일     (길게 누르면 「하루씩 넘기면 3일 뒤에 거둡니다」)
할 일 있음 →  다음 날 ▸                     (말풍선·손가락이 이미 말한다 — 안 겹친다)
```

| 왜 이 자리인가 | |
|---|---|
| ① | 「계속 눌러라」를 말할 자리는 **그 단추**다. 다른 데 적으면 읽고 나서 눈을 옮겨야 한다 |
| ② | 늘 보인다(방 화면 아래 띠). **시트를 안 열어도 된다** |
| ③ | **손가락을 되살리지 않는다** — 2026-08-06 에 박사님이 *"자꾸 다음 날에 쓰잘데기없이 계속 가이드 손가락 유지된다"* 며 물리신 길을 안 되밟는다 |
| ④ | 물주기·거두기 단추가 이미 같은 결이다. **배울 것이 하나도 안 는다** |

⚠ **오늘 손이 갈 일이 있으면 아무 말도 안 얹는다.** 거둘 것이 익었는데 「수확까지」를
  적으면 두 안내가 서로 다른 곳을 가리킨다 — 이 저장소가 제일 자주 앓는 병이다.
⚠ **수를 문구에 안 박았다.** `cropPotList` 가 낸 `daysLeft` 를 읽는다(주기가 바뀌어도 안 낡는다).

## 2. G-11 — 수확 `+OOOg` 뜨는 글자

- **없던 것을 새로 만들었다.** 거둔 순간 화면에 뜨는 것은 배너 하나뿐이었고 그것은
  **화면 위쪽**에 뜬다 — 어느 시루가 얼마를 냈는지는 아무 데도 안 적혔다.
- 붙인 것 — `#floats` 한 칸(`.float`) + `floatUp(열쇠, 글자)`.
  **자리는 말풍선과 같은 자**를 쓴다: `roomView.screenPosOf(열쇠)` 를 **프레임마다** 다시 묻는다
  (`§markTick` 이 「시점을 돌리면 미끄러진다」로 이미 겪은 그것).
- **부르는 자리는 `noteHarvest` 하나다.** 거두는 길이 둘(방의 말풍선 · 아래 [거두기] 단추)인데
  둘 다 이 함수를 지난다. 두 곳에 붙이면 언젠가 한쪽만 고쳐진다.
- **시루마다 하나씩** 뜬다(`r.perPot[].grams`). 합쳐 적으면 「어느 시루가 얼마를 냈나」가
  사라지는데, 그것이 이 게임에서 자리를 고르는 근거다.
- ⚠ 수를 안 지어냈다 — 코어가 낸 g 을 `formatGram` 에 그대로 넘긴다(400g · 1kg 은 그 함수가 정한다).

| 거둔 뒤 시루 위에 뜨는 글자 | **없다** | **`+1kg 수확`** (실측 `+1kg 수확@179,448` — 시루 자리 `banjiha-dresser:1` 위) |

**「분류」는 이미 돼 있다.** 밥상 창은 작물을 갈라 말한다:

```
부제      보유 채소 1kg 가운데 300g이 오늘 상에 오릅니다
꾸러미    콩나물 700g · 무순 300g            ← 갈래로 합쳐 적는다(lotsBriefKo)
몫 줄     첫 몫 · 콩나물 300g      2,500원
          둘째 몫 · 무순 200g      2,500원
```

**없는 것은 「선택」이다** — 손잡이가 **g 한 줄**(− / 300g / ＋ / 최대 / 0g)뿐이고,
작물마다 따로 고르는 칸(`[data-mealkind]`)은 **0개**다.

### ★★ 왜 화면만으로는 못 만드나 — **재서 확인했다**

고른 값이 실제로 쓰이는 길이 이렇다:

```
화면  planMeal(S, g)  →  fp.food.mealPlanWon = (그 g 의 물건 값)   ← **수 하나**
하루가 갈 때  eatFromPantry(fp)
    → cropMealPlan(fp, { grams: gramsOfWon(mealPlanWon) })         ← **총 g 만** 받는다
    → 몫 규칙이 **어느 작물을 먹을지 스스로 고른다**
```

⇒ 채널이 **수 하나**다. 「콩나물 300g · 무순 0g」을 적어 보낼 칸이 없다.
⇒ 그리고 총 g 으로는 **그 뜻을 흉내 낼 수 없다.** 실제 표로 확인했다 —
  보유 콩나물 400g + 무순 300g 판에서

| 총 g 을 이렇게 주면 | 몫 규칙이 고르는 것 |
|---|---|
| 500g (최대) | 콩나물 300g + 무순 200g |
| 300g | 콩나물 300g **또는** 무순 200g — 둘 다 2,500원이라 **먼저 거둔 쪽**이 이긴다(FIFO) |
| 200g | **무순 200g** (2,500원) — 콩나물 200g(1,667원)보다 값이 커서 |

  즉 「콩나물만 300g」을 사람이 고르려 해도 **총 g 으로는 그 말이 전달되지 않는다.**
  화면에 손잡이만 붙이면 **고른 것과 먹은 것이 다른 판**이 난다 — 그게 이 저장소가
  제일 싫어하는 「화면이 거짓말하는」 자리다.

### ⇒ 안 만들었다. **필요한 것은 화면이 아니라 창구 하나다**

`first_play.js` 에 **작물별 상한을 받는 칸** 하나면 끝난다(셈은 안 바뀐다):

```
① cropMealPlan(fp, { grams, gramsByKind })   — 후보 고르는 자리에서 `left[k]` 를 그 상한으로 깎는다
② fp.food.mealPlanKinds                      — 고른 값을 적어 둘 칸 (save.js 한 줄)
③ eatFromPantry                              — 그 칸을 ① 에 그대로 넘긴다
```

⚠ **그 파일은 내 몫에서 ⛔ 「읽기만」이다**(지시문 §3). 그래서 **손대지 않았다.**
  화면 쪽(밥상 창의 칸·손잡이)은 창구가 서면 반나절이면 붙는다.
☐ **판단필요** — 이 창구를 누가 낼 것인가. `first_play.js` 를 잡은 창이 ①②③ 을 내주면
  화면은 그 위에 바로 얹는다.

⚠ 밥상 창에 **줄을 더 붙이지도 않았다.** `test_questui W-360/390/430` 이
  *"밥상 창이 화면 안이고 · **안 구르고** · 가로로 안 넘친다"* 를 못 박고 있는데,
  콩나물+무순 판이 이미 제일 긴 판이다. 고를 수도 없는 줄을 더 넣어 그것을 깨면
  **얻는 것 없이 잃기만 한다.**
