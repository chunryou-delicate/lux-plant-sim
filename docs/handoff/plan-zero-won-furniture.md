## ⓑ 정한 글 — 갈래 키는 «프리셋이 `resale_won: 0` 으로 정한 것»(shop.js:328 「0 이면 «치우기만»」)
```

② 단추(첫 탭)       「0원에 팔까요?」  → 「치울까요?」
                    (자리를 잃는 가구면 → 「자리 15→13 · 치울까요?」 — 쓰레기봉투는 자리가 없어 지금은 안 난다)
③ 배너 제목         → 「쓰레기봉투·폐지를 치웠습니다」
   배너 아랫줄       → «없음». ⛔ 「0원이 들어왔습니다」를 쓰지 않는다 (banner(title) 만 — 빈 sub 는 game.html:16472 가 이미 안 그린다)
④ 로그              → 「🪑 쓰레기봉투·폐지를 치웠습니다」  ( 「— 0원」을 뺀다)
   사건 ko          → 「…를 치웠습니다」 · ⚠ id 'furniture_sold' 는 «그대로» 둔다
```

⚠ id 를 안 바꿔도 되는 까닭 — [잰 것] `furniture_sold` · `furnitureSold` 를 «세는» 곳이 없다(save.js 저장 · light_adapter 조립뿐). 퀘스트·통계가 「가구를 판 적」으로 세지 않으니, 치운 것이 «판 것»으로 잘못 세어질 자리가 없다.

## ⓒ 왜 「팔았다」가 아니라 「치웠다」인가
```
① 박사님 결정 「팔리는데 쓰봉은 0원으로」는 ⇒ «값»(0원)과 «되는가»(방에서 걷어낼 수 있다)다. 그 둘은 그대로다
   ⇒ 낱말은 [plan] 몫이다. 값을 안 건드리고 말만 고친다
② 「팔았습니다 — 0원」은 ⇒ 거래가 «없는데» 거래라고 말한다 ⇒ 사람은 그것을 «값이 깨졌나»로 읽는다
③ ★ 「한 낱말이 방마다 다른 것을 가리키면 그 낱말로 규칙을 세우지 마라」(2026-09-06) 그대로다 —
   「팔기」가 다른 가구에서는 «돈이 들어온다»를, 쓰레기봉투에서는 «방에서 걷는다»를 가리킨다 ⇒ 낱말을 갈라야 한다
④ 0원을 말하는 것은 «소음»이다 — [core] 가 이미 적어 둔 규칙(game.html:15155 「15→15 는 소음이고, 안 바뀐 것을 말하면 바뀐 것이 묻힌다」)과 같다
⑤ 「치우기」는 «이미 있는» 낱말이다 — [core] 가 shop.js:328 에 「0 이면 «치우기만»」으로 적어 뒀다. 새 낱말을 짓지 않았다
```
⇒ 「버리기」가 아니라 「치우기」인 까닭 — 이 가구는 「쓰레기봉투·폐지」다. 폐지는 버리는 것이 아니라 «내놓는» 것이라 「치우다」가 둘을 다 덮는다.
