## 2-3. ★★ 「보이는 대로 판다」 ↔ 「무늬를 모아 키운다」 — **같은 씨앗 짝짓기**

2. **A 에서는 아무 일도 안 일어난다** — 삽수 잎이 **1장 그대로**다.

3. **B 에서는 키우면 9판을 잃는다** — 그 9판은 무늬 마디를 자르긴 했는데(자른 횟수 합 9)
   **못 팔고 파산**했다. ⇒ **무늬 삽수를 뿌리내리자마자 파는 그 80,000원이 파산을 막고 있었다.**
   「키운다」는 곧 **현금 흐름을 끊는다**는 뜻이다.

⇒ 정리하면 **키우는 길은 「돈이 버티는 판」에서만 쓸 수 있는 수**다. 지금 판에서 그 조건을
만족하는 것은 C 하나뿐이다. 이건 값의 물음이라 §4-③ 에 넘긴다.

## 3-2. `G-4` — **지키던 말이 뒤집혔다**

이 검사가 지키던 것: 「민무늬 삽수를 팔아 버는 **꾸준수입**이 탈출의 전제조건이다」.
재는 자를 고치자 **부등호가 뒤집혔다**:

```
자르며 감(민무늬도 판다)      9/20
안 자르고 기다림(무늬만 자른다) 15/20   ← 안 파는 쪽이 더 잘 나간다
```

★ 셈이 말한다 — 민무늬 삽수는 12,000원인데 병이 7,000원이라 **순 5,000원**,
한 바퀴에 14일(`§P-3`: 하루 56원 = 하루 지출의 **0.3%**). 그런데 그 자르기가
**모주의 잎 예산을 쓴다**(`cutBudgetOf`). ⇒ **5,000원 벌자고 무늬가 붙을 자리를 없앤다.**

⚠ 통과하게 부등호를 뒤집지 않았다. 뒤집으면 「꾸준수입이 손해다」가 **정상으로 못 박힌다.**
값의 물음이므로 §4-④ 로 넘긴다.

# 4. 판단필요 (★ 박사님이 정하실 것 — 값은 제가 안 건드렸습니다)

## ① ★★ 경로 A(등 없이) 38% — **못 나간 25판이 전부 파산이다**

재는 자로는 더 못 올린다. 물음은 하나다:
**「식물등을 안 사고 반지하를 나갈 수 있어야 하는가?」**

* 그래야 한다면 → 값을 움직여야 한다(하루 지출 16,667원 / 이사비 2,000,000원 / 창턱 DLI).
* 안 그래도 된다면 → **A 는 「등을 사야 한다는 것을 배우는 길」**이고, `G-2b` 의 문턱(50%)을
  A 에는 안 걸어야 맞다. 그때는 검사의 뜻을 다시 쓰는 일이라 제가 정할 것이 아니다.

## ② ★★ 프롤로그 무늬 두 장이 **출구를 안 바꾼다** (§2-2)

성공률 0판 차이. 바뀌는 것은 **가장 빠른 판 24일**과 이야기뿐이다.
「두 장이면 한 장은 자르고 한 장은 남긴다」는 몬이의 말이 **실제로는 안 쓰이고 있다** —
튜토 확정 무늬(가을 45일)가 그 자리를 먼저 채우기 때문이다.
⇒ 이야기용으로 충분한가, 아니면 확정 무늬 게이트를 늦춰 프롤로그 두 장이 실제로 쓰이게 할 것인가.

## ③ ★★ 「무늬를 모아 키운다」가 **C 에서만 성립한다** (§2-3)

* C 에서 삽수 값 **9.1배**(80,000 → 731,111원), 대가는 3일.
* A 에서는 **모주 하나가 이미 2,133,333원**이라 키울 틈이 없다.
* B 에서는 **8만원을 안 받으면 9판이 파산**한다.

⇒ 새 삽수 규칙이 값을 내려면 **모주 값이 이사비보다 낮거나**, **버티는 돈이 더 있어야** 한다.
지금 판에서는 「키우는 길」이 사실상 잠겨 있다.

## ④ 민무늬 삽수의 **꾸준수입이 손해다** (§3-2)

순 5,000원 / 14일 = **하루 지출의 0.3%**, 그 대가로 모주 잎 예산을 쓴다.
값(민무늬 삽수 12,000원 · 병 7,000원)이 움직이지 않으면 이 길은 안 쓰는 게 맞다.

## ⑤ 코어에 고칠 것 하나 — **`takeCutting` 이 자리를 안 잡아 준다** (코드째로 적는다)

⛔ `src/` 를 안 건드렸으므로 여기 적는다.

`takeCutting(S, opt)` 은 `opt.at` 이 없으면 `c.slotId` 를 비워 둔다. 그러면
`loop.cuttingLightOf` 가 첫 줄에서 null 을 돌려주어 **그 삽수는 영영 빛을 못 받는다**
(무늬 소질 미정 · 새 잎 0장). 화면(`game.html`)이 자리를 안 주면 같은 일이 난다.
⇒ 자리를 안 준 삽수를 **조용히 두지 말고**, 화면이 「이 삽수를 어디에 둘까요」를 묻게 하거나
   기본 자리(가장 밝은 빈 칸)로 떨어뜨리는 편이 낫다. 제안:

```js
/* propagation.takeCutting 끝 부분 — 자리가 없으면 '어디에도 없는' 삽수가 된다 */
if (!c.slotId && !c.at && opt.slots && opt.slots.length) {
  /* state.rehomePot 과 같은 규칙: 슬롯 목록의 첫 자리(=가장 밝은 자리) */
  setCuttingAt(S, c, atFromSlot(opt.slots[0]), opt);
}
```

⚠ 이건 **제안이지 결정이 아니다.** 「자리를 안 정하고 자를 수 있어야 하는가」가 먼저다.
