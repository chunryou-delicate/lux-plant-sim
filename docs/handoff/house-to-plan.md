## 3. `homes.json` — 실측값을 빼서 `house_rooms.json` 으로 옮겼습니다

사용자 지시대로 **한 파일을 나눠 쓰지 않고 완전히 분리**했습니다.
(`data/balance/README.md` 에는 "한 파일을 둘이 나눠 쓴다"로 돼 있는데, 그 뒤 지시가 바뀌었습니다)

```
data/house_rooms.json     house — rooms.{id}.measured 블록에 실측
data/balance/homes.json   plan  — rent · deposit · moveCost · utility 만
```

### 붙여 넣을 것 ①: `data/balance/homes.json` 에서 제거

각 집 항목의 **`peakDLI`·`slots` 필드를 지워 주세요.** 이제 여기서 읽습니다:

```js
const rooms = (await fetch('./data/house_rooms.json').then(r=>r.json())).rooms;
const m = rooms[home.room].measured;
// m.peakDLI · m.minDLI · m.slots · m.n3 · m.n6 · m.dark · m.winterPeak
```

### 붙여 넣을 것 ②: `data/balance/README.md` 의 경계 표 수정

````markdown
- `data/` (상위) = **house 소유**. 구조·에셋 정의(`house_rooms.json`·프리셋류)
````

## 5. ★ 정정 — "그림자 버그 때문에 DLI가 전부 틀렸다"는 아닙니다

사용자가 그렇게 우려하셨는데, **확인 결과 조도 숫자는 영향을 안 받았습니다.**

| | 쓰는 것 | 그림자 버그 영향 |
|---|---|---|
| **조도 엔진** (DLI) | `built.occluders` — 방 데이터에서 계산한 OBB 목록 | **없음** |
| **화면 그림자** | three.js 그림자맵 — 렌더 기하 | 있었음 |

`_dli_probe.html` 은 `updateShellVisibility` 를 **한 번도 부르지 않습니다**(grep 0회).
컷어웨이는 렌더 전용이고 `occluders` 를 건드리지 않습니다.

**다만 숫자는 실제로 바뀌었습니다** — 다른 두 버그 때문입니다:
1. 근거리 샘플링(창 중심 거리 → 최근접점): 참값 대비 +76~286% 과대 → ±2%
2. 가구가 벽에 7cm 박혀 있던 것: 안쪽면(±4.9) 기준으로 재배치

그래서 아파트가 **8.04 → 6.02** 가 됐습니다. 그림자 때문이 아닙니다.
