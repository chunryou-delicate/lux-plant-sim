### 답 — 반지하는 **9칸**

목표 대역(5~8)보다 **1칸 많습니다.** 판단은 그쪽에 맡깁니다:

- **9칸 그대로 두기** — 콩나물 3개 쓰고도 6칸이 남습니다. 남는 칸에 관엽을 놓아도
  전부 고사권이라 "어두운 자리는 콩나물 말곤 쓸 데가 없다"가 분명해집니다
- **7칸으로 줄이기** — 서랍장(2칸, DLI 0.06/0.04)을 창 쪽으로 0.5m 옮기면 됩니다.
  그러면 콩나물 3 + 여유 4가 되어 경쟁이 생깁니다

**학원교실은 8칸** — 가장이 시루 11개 필요하다면 **3개 모자랍니다.**
교실 뒤편에 낮은 수납장을 하나 더 놓으면 3~4칸이 늘어납니다. 필요하면 말씀 주세요.

## 2. [처리됨] `daily_light.js` 무늬종 계수 — 확인했습니다. **되돌리지 않습니다**

`isVariegated` / `variegatedThresholds` / `thresholdsFor(…, explicitVarie)` 확인.
`buildDailyLight` 슬롯 출력의 `variegated` 필드도 그대로 둡니다.

**설계가 맞다고 봅니다** — 특히 `max`에 곱하지 않은 판단이 정확합니다.
흰 조직은 보호 색소가 없어 더 잘 타는 게 맞습니다.

한 가지만 확인해 주세요: **무늬 몬스테라의 `fenestrate`가 8.4** 인데,
현재 아파트 최고가 **6.02**(전에 6.26이었다가 벽 관통 수정으로 내려감)라
**아파트에서도 무늬종은 안 갈라집니다.** 온실(12.42)에서만 갈라집니다.
"무늬종엔 온실이 필요하다"가 의도라면 그대로 두면 되고,
아파트에서도 보이게 하려면 발코니 선반 조정이 필요합니다.

> 앞으로 `src/engine/` 은 handoff로 요청 주시면 제가 고치겠습니다. 이번 건은 그대로 갑니다.

## 인터페이스 — 슬롯 ID가 생겼습니다

그쪽 `setDailyLight(c, slotId)` 에 맞춰 **안정 ID**를 넣었습니다.

```js
// buildDailyLight() 슬롯 출력
{ "slotId": "apartment-shelf_ladder_4tier-20:0", ... }
//           └ 가구 uid ──────────────────────┘ └단
```

- 가구를 **옮겨도** 안 바뀝니다(좌표가 아니라 가구 uid에 붙음)
- 가구를 **지워서 배열이 밀려도** 안 바뀝니다
- **세이브/로드에 유지**됩니다 (uid가 `house_rooms.json`과 집꾸미기 내보내기 JSON에 저장)

검증: 아파트 83슬롯 전부 고유(83/83).

자세한 계약 스펙은 **`docs/handoff/house-to-core.md`** 에 있습니다.
