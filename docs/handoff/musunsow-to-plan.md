# 2026-08-11 · musunsow → plan (재배판을 **놓고 나서** 심는다)

## 요청

> "왜 가방에서 무순 심기를 해야 돼? **재배판 배치 후 무순 심기**를 해야지?"

```
예전 : 가방에서 [🌱 무순 심기] → 다 자란 판을 방으로 끌기 → 물
지금 : 방으로 끌기(빈 재배판이 선다) → 놓인 판에 [🌱 심기] → [💧 물 주기] → 7칸이 돈다
```

콩나물은 **그대로다.** 시루는 「놓기 = 심기」다(`state.placeSiru`). 재배판은 씨앗을 뿌리는
판이고 시루는 콩을 앉히는 용기라 결이 다르다 — 박사님이 그렇게 정하셨다.

고친 파일은 다섯이다: `game.html` · `src/game/first_play.js` · `src/game/state.js` ·
`src/game/save.js`. **`loop.js` 는 한 글자도 안 고쳤다**(왜인지는 §4). 검사 파일은 하나도 안 건드렸다.

---

## 1. 「안 심은 판」을 상태에 어떻게 적었나 — **유도가 안 된다**

지시대로 **새 칸을 만들기 전에 유도가 되는지부터** 봤다. 시루 한 칸이 가진 것 전부:

| 칸 | 뜻 |
|---|---|
| `slotId` · `at` | 놓였나 |
| `startedOnDay` | 물을 줬나(회전을 시작했나) |
| `ageDays` · `dliHist` | 얼마나 자랐나 · 받은 빛 |
| `harvested` · `cycle` · `harvestCount` | 몇 번 돌았나 |
| `idleSinceDay` | 언제부터 기다리나 |

그런데 이 둘이 **저 칸 전부에서 한 톨도 안 다르다**:

```
A. 놓았고 · 씨앗을 뿌렸고 · 아직 물은 안 줬다   → started=null · age=0 · dliHist=[] · harvested=false
B. 놓았고 · 씨앗을 안 뿌렸다                     → started=null · age=0 · dliHist=[] · harvested=false
```

그리고 **A 와 B 가 같이 있어야 하는 것이 이번 지시의 뼈대**다(뿌린 뒤에 물을 준다).
⇒ 유도가 성립하지 않는다. **칸 하나를 새로 만들었다.**

```js
// first_play.makeCropPot
sown: opt.sown !== false      // ★ 없으면 심은 것이다
```

★ **없으면 심은 것**으로 잡은 것이 이 칸의 전부다. 옛 세이브·옛 코드가 만든 칸에는 이 칸이
없는데, 그때는 「놓기 = 심기」였으므로 **없는 것이 곧 심은 것**이다. 반대로 잡으면
(없으면 안 심음) 돌아가던 판의 콩나물이 통째로 「안 심은 시루」가 되어 물을 못 준다.

읽는 창구는 `cropPotSown(p)` 하나다. 화면은 `cropPotList` 가 낸 `sown` · `needsSow` 만 읽는다 —
판정을 화면에 또 만들지 않는다.

## 2. 세이브에 실었다 — 안 실으면 껐다 켜면 심긴 판이 된다

`save.packCropPot` 에 한 줄:

```js
sown: o.sown !== false,
```

⚠ 이 칸은 **화이트리스트**다. 안 적으면 저장 한 번에 사라지고, 안 심은 재배판이 **씨앗 한
봉지를 안 쓰고 회전이 도는 판**이 된다. START-HERE §5 의 `arrivalSlotId` 와 같은 종류의 사고다.

**실측**(브라우저에서 새로고침 왕복):

```
껐다 켜기 전 : [{crop_02_01, sown:true}, {crop_02_02, sown:false}]
껐다 켠 뒤   : [{crop_02_01, sown:true}, {crop_02_02, sown:false}]   ← 같다
```

옛 세이브(=`sown` 칸이 아예 없는 판)를 만들어 열어 보니 `sown:true` 로 열린다(= 심긴 것).

## 3. 안 심은 판에 물을 주면 — **단추가 아예 안 뜬다**

정한 것: **[💧 물 주기]를 안 그린다.** 그리고 **눌러도 아무 일이 안 나게** 규칙도 같이 막았다.
화면만 막으면 재현·자동조작·다른 화면이 그대로 새어 나간다(bagone §4 와 같은 판단).

```js
// first_play.idlePots — 물을 기다리는 용기
placedCropPots(b).filter(p => !p.harvested && p.startedOnDay == null && cropPotSown(p))
```

이 한 줄이 `waterCrop`·`beansproutWaterStatus`·`advanceBeansproutDay` 의 `idle` ·
`firstPlayNextEvent` 를 **한꺼번에** 고친다 — 다섯 곳이 전부 이 함수 하나를 본다.

**실측**: 안 심은 판만 놓고 `waterCrop(S,{kind:'musun'})` → `{watered:false, already:true}`
(던지지 않는다 — 두 번 눌러도 안전하다는 이 파일의 규약 그대로).

## 4. 하루 넘김 — `loop.js` 는 안 고쳐도 된다

`advanceBeansproutDay` 의 시루 고리가 이렇게 되어 있다:

```js
if (p.harvested || p.startedOnDay == null || p.ageDays >= hd) continue;
```

안 심은 판은 `startedOnDay` 가 null 이라 **이미 건너뛴다.** 그래서 코어에 손댈 것이 없었다.
`loop.js` 쪽 문지기(`anyCropPlaced`)는 「방에 선 시루가 하나라도 있나」라 안 심은 판도 통과하는데,
그건 맞다 — 그 방에는 콩나물이 자라고 있을 수 있다.

**실측**(화면에서): 안 심은 판을 놓고 [다음 날] → 칸 `0/7` 그대로 · [심기] 단추 그대로.

## 5. 안 심은 판과 물 안 준 판이 **화면에서 갈리나** — 갈린다

| | 게이지 | 옆줄 | 단추 | 줄 색 |
|---|---|---|---|---|
| **안 심음** | 7칸 **맨 빈 칸**(`.cells` 만) | 「아직 안 심었습니다 — 씨앗을 뿌려야 7칸이 생깁니다」 | **[🌱 심기]** | 초록(`.siru.unsown`) |
| **물 안 줌** | 7칸 **물빛 테두리**(`.cells.dry`) | 「물을 주면 7칸이 하루에 하나씩 찹니다」 | **[💧 물 주기]** | 물빛(`.siru.thirsty`) |

`.cells.dry` 는 `test_bagcell` 의 W 절이 콩나물에서 지키는 그 옷 그대로이고, 여기서 한 글자도 안 무르게 했다.

## 6. 화면이 어떻게 바뀌었나

### ① 가방 카드의 [🌱 무순 심기] 단추 — **없앴다**

`#sowMusun` 을 통째로 걷었다(마크업·`drawMusun` 배선·`onclick` 셋 다).
그 단추가 하던 `resowCrop(S,{kind:'musun',sirus:1})` 은 **가방에서 개체를 만들어 버리는** 길이었다.

### ② [두기] 드롭다운도 화면에서 걷었다

`$('placeMusun').onclick` 이 `placeCrop` 을 `potId` 없이 불렀다 — **그 자리의 판이 전부 함께
움직인다.** 판이 하나뿐이던 시절에는 안 드러났는데, 이제 끌 때마다 빈 판이 하나씩 서므로
단추 한 번에 판들이 한 자리로 뭉친다.
⇒ 놓기는 **끌기 하나**, 옮기기는 줄의 **[📍 자리] 하나**다(콩나물이 08-10 에 간 그 길).
⚠ `#musunSlot` 은 **남겼다.** 화면에 안 보이는 자료 칸이다 — `drag.slotsFor('musun')` 이 그
`<option>` 목록에서 빛나는 원과 되돌림 경로를 읽는다(`#cropSlot` 과 같은 이유).
그리고 **늘 채운다** — 예전에는 `if (pots)` 라 첫 판을 끌 때 목록이 비어 아무 자리도 안 빛났다.

### ③ [🌱 심기]는 **시루 줄**에 붙는다 — 새 UI 틀을 안 지었다

`#siruList` 의 줄이 `data-siru`/`data-act` 로 단추를 그리던 그 자리·그 방식이다.
`data-act="plant"` 한 종류가 늘었다. 단추마다 `data-kind` 를 같이 싣는다 — 한 상자에
콩나물과 무순이 같이 서므로 id 만으로는 어느 작물인지 모르고, 화면이 짐작하면 무순에
콩 씨앗이 나간다.

그러려면 `#siruBox` 가 **무순도 그려야** 한다. 예전에는 `kind === 'beansprout'` 로 걸렀다.
그 필터를 걷었다. 부수로 얻은 것 셋:

- 방에 선 재배판이 **판마다 제 줄**을 갖는다(예전엔 줄이 아예 없었다 — 물주기는 화면 위쪽
  공용 단추가 종류를 골라 주는 길뿐이었다)
- 제목이 서 있는 것을 말한다(`#siruBoxTitle` — 한 종류면 그 이름, 섞이면 「재배 중」)
- 줄 머리가 `${containerKo} ${ord}` 다 — 「시루 1」 · 「새싹 재배판 2」

### ④ 무순 카드는 **가방 카드 하나**가 됐다

`holdCard` 조건이 「방에 놓였나」였다. 그러면 첫 판을 놓는 순간 카드가 [식물] 로 가서
**둘째 판을 끌 손잡이가 사라진다** — 재배판을 두 개 산 사람이 하나만 놓을 수 있었다.
⇒ 카드는 늘 [가방] 에 살고, **가방이 비고 판이 전부 방에 서 있으면 통째로 걷는다**
(콩나물 칸이 0개에서 사라지는 것과 같은 규칙). 그러지 않으면 같은 물건이 화면 두 곳에 뜬다.

### ⑤ 걷어낸 안내 하나

`commitPlace` 의 「아직 안 심었습니다 — 가방에서 [🌱 무순 심기]를 먼저 눌러 주세요」를 걷었다.
그 단추가 없어졌고, **이제는 안 심은 판이야말로 놓을 수 있는 것**이라 그 자리에서 그 말은
정반대의 거짓말이 된다. 무엇이 모자란지는 `placeSiru` 가 던지는 재고 부족 문구가 그대로
배너로 나온다(§placeFailed 가 08-11 에 배너를 붙여 뒀다).

그 아래 있던 `setCropAt` 한 벌도 같이 걷었다 — 콩나물도 무순도 그 위에서 반드시 돌아가므로
**닿을 수 없는 자리**였고, 조용히 「자리 옮기기」로 새면 각개가 무너진다.

### ⑥ 3D 도 판마다 선다 (같이 고친 것)

무순만 자리 사본(`ms.at`) 하나로 그리고 있었다. 판이 여럿 서면 **첫 판만 보이고**, 열쇠도
`crop_02`(자리 이름)라 줄의 [📍 자리]·[💧 물 주기]가 찾는 열쇠(용기 id)와 어긋나
**걸어가는 연출이 통째로 빠졌다.** 콩나물 고리에 합쳐 종류를 안 가리게 했다.

발밑 초록(`syncPlantGlow`)도 같은 병이었다 — `crop_01`·`crop_02` 라는 **없는 열쇠**에 칠하고
있었다(방뷰는 08-09 부터 용기 id 로 세운다). 이건 **콩나물에도 있던 옛 버그**다. 같이 고쳤다.

## 8. ★ 판단이 필요한 것

1. **[🌱 심기]에 체력을 물릴지.** 지금은 **안 문다.**
   근거: 콩나물은 「놓기 = 심기」인데 그 길(`placeSiru`)이 체력을 안 쓴다. 여기서 물리면
   같은 결과를 내는 데 무순만 손이 하나 더 드는 셈이라 두 작물의 셈이 갈린다.
   ⚠ 다만 **[🌱 다시 심기](`resowCrop`)는 체력을 문다.** 그래서 지금은
   「처음 심기는 공짜 · 다시 심기는 손 하나」라는 비대칭이 있다. 물리게 하려면
   `state.sowCrop` 에 `canActStamina(S,'sow')` 한 줄이면 되고, 그건 밸런스 창과 같이 정할 일이다.

2. **무순을 여러 판 세울 수 있게 됐다.** 예전에는 `canSow = !pots` 로 **한 판**이었는데,
   끌기가 첫 걸음이 되면서 재고만큼 설 수 있다. 이번 지시의 자연스러운 결과라 안 막았다 —
   `bagone-to-plan.md §6` 의 「무순 다판 재배는 코어 결정 대기」가 이렇게 풀린 셈이다.
   막아야 하면 `commitPlace` 의 무순 갈래 한 줄이다.

3. **`#siruBox` 가 이제 무순도 담는다.** 제목이 「콩나물 시루」에서 서 있는 것에 따라
