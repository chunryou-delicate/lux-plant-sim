# branchcut → plan — **모주에서 자란 그 가지를 그대로 떼어내는 창구**를 냈다

> 2026-08-16 · 창 `branchcut`
> 고친 파일 **둘**: `plant_grow.html` · `src/render3d/plant_assemble.js`
> 새 파일 **둘**: `tools/probe_branchcut.mjs` · 이 문서
> `src/game/room_view.js` · `game.html` 은 **한 글자도 안 건드렸다**(다른 창이 쓰는 중이다).
> ⇒ **배선은 안 했다.** 병 안에 그 가지가 서 있는 화면은 **아직 아무도 못 봤다**(§5).

## 0. 설명 먼저 — 무엇이 없어서 지어내고 있었나

박사님 원문(두 번 말씀하셨다):

> *"삽수 시, **기존에 자랐던 거 가지 그대로 잘라서 넣어줄래?** 안 그러면 이상한 듯."*
> *"저렇게 하지 말라니까. **줄기 기존 자랐던 거 그대로 쓰라고. 그게 어렵나.**"*

지금 병 속의 줄기는 **원기둥 하나**(`room_view §addCutStem` — `CylinderGeometry`)이고
잎은 **등급으로 고른 GLB 한 장**이다. 등급은 맞지만 **그 가지가 아니다.**
그래서 「자른 그 가지」가 아니라 **비슷하게 생긴 다른 가지**가 병에 들어 있었다.

까닭은 하나다. 방에 선 몬스테라는 `plant_assemble` 이 `plant_grow §buildPlant` 을 그대로
돌려서 만드는데, **그 결과물에 「이 메시가 어느 축·어느 마디의 것인가」가 하나도 안 적혀
있었다.** 표가 없으니 떼어낼 수가 없고, 떼어낼 수가 없으니 지어낼 수밖에 없었다.

★ **지어낼 것은 원래 하나도 없었다.** 같은 씨앗·같은 생장일이면 같은 형태가 나온다
(그것이 `plant_assemble` 이 존재하는 이유다). 그러니 **자를 때의 씨앗·생장일로 모주를 다시
지어, 그 마디에서 위로 딸려 나가는 것만 떼어내면** 줄기 굵기·잎 무늬·휘어진 각도가 전부
**자란 그대로** 나온다.

이 창이 한 일은 셋이다.
① `plant_grow` 이 메시에 **표를 적게** 했다(그리기는 한 글자도 안 바꿨다) ·
② `plant_assemble` 에 **`branchOf` 창구 하나**를 냈다 ·
③ 그것이 정말 「그대로」인지 **브라우저에서 재는 자**를 만들었다.

**생장 알고리즘·확률·캐논 숫자·난수 스트림은 한 개도 안 바꿨다.**

## 1. 무엇이 바뀌었나

### 1-1. `plant_grow.html` — 메시에 **표**가 붙는다 (그리기는 그대로)

`buildPlant` 이 그리면서 `plantGroup` 의 자식마다 이렇게 적어 둔다.

| 칸 | 무엇 | 붙는 곳 |
|---|---|---|
| `axisKey` | 그 축의 경로 — `n0` · `n0.1` · `n0.1:1` | 줄기·혹·잎 전부 |
| `part` | `'stem'` \| `'bump'` \| `'leaf'` | 〃 |
| `segIndex` | 그 혹이 앉은 마디 번호 | 혹만 |
| `leafBirth` | 그 잎의 `leafBirth` | 잎만 |
| `segT[]` | 마디 경계의 t (`segT[0]=0` … 마지막=1) | 줄기만 |
| `tubSeg`·`radSeg` | 그 튜브의 격자 | 줄기만 |

- **이름은 `axisPathsOf(axes)` 하나가 짓는다.** `cuttableNodes()` 안에 있던 그 줄을 밖으로
  뺀 것이고, 지금은 `cuttableNodes` 와 `buildPlant` 이 **같은 자리에서 나온 같은 이름**을 쓴다.
  ⇒ `nodeId` 가 `n0.1#3` 이면 `axisKey`= `n0.1` · 마디 3 이다. **두 벌로 안 짓는다.**
- `addStemTube` 이 만든 메시를 **돌려준다**(예전엔 아무것도 안 돌려줬고 아무도 안 읽었다).
  튜브 격자 두 값(`Math.max(12, pts.length*10)` · `10`)은 **인자 자리에 그대로 있던 식**을
  상수로 뽑기만 했다 — 값은 그대로다.
- `nodeTs` 는 `segT.slice(1,-1)` 이 됐다. **같은 나눗셈이라 한 비트도 안 바뀐다.**
- ⚠ 표는 `userData` 를 **복사해서** 얹는다. `stretchGLB`(혹)이 `g.userData = proto.userData`
  라 **에셋 원본과 한 칸을 나눠 쓰기 때문**이다 — 거기에 그냥 쓰면 혹 전부가 같은 축
  이름을 갖게 된다.

### 1-2. `plant_assemble.js` — **`branchOf`** 창구 하나

```js
asm.branchOf({ nodeId, growthDays, seed, leafState, potD, lightAz, photo })
   → THREE.Group | null
```

하는 일은 넷이다.
① 그 씨앗·그 날로 **모주를 다시 짓는다**(`assemble` 을 그대로 부른다 — 길이 두 벌이 안 된다) ·
② 정본 `cuttableNodes()` 에 **그 마디가 있는지 묻는다**(없으면 `null`) ·
③ 표를 보고 딸려 나갈 것만 **골라 옮긴다** · ④ **남은 모주는 버린다**.

딸려 나가는 것의 규칙은 `cuttableNodes §carried` 와 **같다**:

- 그 축의 **잎**
- 그 축의 **`segIndex ≥ i` 인 혹**
- 그 축의 마디 `i` 이상에서 난 **가지 전부**(그 아래로 통째로)
  ⇒ 트리를 다시 안 탄다. 가지의 경로가 `<부모>.<난 마디 번호>` 라서 **이름만 봐도 안다**
- 그 축의 **줄기 튜브 중 마디 `i` 위쪽**

★ **줄기는 정점을 새로 안 만든다.** 튜브는 링 (tubSeg+1)개 × (radSeg+1)점짜리 규칙적인
격자라, 자를 링부터 끝까지를 **그대로 베껴 오면** 좌표가 한 비트도 안 바뀐다.
새로 나는 점은 **잘린 자리를 막는 뚜껑 하나**뿐이다(안 막으면 줄기 속이 들여다보인다).

⚠ **자른 면은 링 자리에 앉는다** — 마디 경계와 최대 반 링(마디 길이의 약 5%) 어긋난다.
정점을 옮겨 딱 맞추는 길도 있지만, 옮기는 순간 「자란 그대로」가 아니게 되므로 안 옮겼다.

## 2. ★ `room_view.js` 가 붙일 최종 계약

### 2-1. 부르는 법

```js
const asm = await getPlantAssembler({});
const branch = asm.branchOf({
  nodeId:     spec.nodeId,        // 'n0.1#3' — cuttableNodes 가 낸 그 이름
  growthDays: spec.motherGrowthDays,  // ★ 자를 때 **모주의 유효 생장일** (§2-3 을 먼저 읽어라)
  seed:       spec.seed,          // 모주를 그릴 때 쓰는 그 씨앗(지금 게임은 안 넘겨서 기본 92158 이다)
  leafState:  spec.leafState,     // 자를 때의 잎별 상태. 안 주면 무늬가 안 난다(§2-4)
  potD:       0.20                // ★ **모주를 그린 그 값**을 준다. 크기가 모주와 같아진다
});
if (!branch) { /* 예전 길(addCutStem)로 내려앉는다. 잎을 지어내지 마라 */ }
```

### 2-2. 무엇이 나오나

| | |
|---|---|
| **반환** | `THREE.Group` — **밑동(자른 면 한가운데)이 원점**이다. 병 아가리에 그대로 앉힌다 |
| | **`null`** — 모르는 마디 · 아직 안 난 마디 · 씨앗 단계 · 조립 실패. **0 도 빈 그룹도 아니다** |
| `userData.kind` | `'cutting'` |
| `userData.nodeId`·`axisKey`·`segIndex` | 어느 마디를 잘랐나 |
| `userData.leafCount` | 실제로 딸려 온 **잎 수** |
| `userData.node` | 정본 `cuttableNodes()` 의 그 줄 — `stem`·`leaves`·`variegatedLeaves`·`leafBirths`·`leafKeys`·`growthDays` |
| `userData.varieLeafKeys` | 딸려 온 무늬 잎 열쇠(`leaf_mid_albo22` 등) |
| `userData.sizeM` | `{h, d}` — 떼어낸 뒤의 실제 높이·회전무관 지름[m]. **병에 맞춰 줄일 때 이 값을 봐라** |
| `userData.cutDir` | 자른 자리에서 줄기가 뻗는 방향(단위벡터) |
| `userData.scale` | 모주에 걸렸던 배율(사진을 원래 크기로 되돌릴 때 쓴다) |
| `userData.leaves` | `[]` — 모주와 **같은 규약**이다(`applyLook` 이 색만 얹는다. 처짐은 못 준다) |
| `userData.skinsPending` | 아직 못 받은 무늬 장수. **0 이 아니면 도착 뒤 다시 지어야 한다** (`asm.onSkinChange`) |

**병에 세우는 세 줄** (`addCutStem` 이 원기둥을 세우는 자리에 그대로 들어간다):

```js
/* 밑동이 원점이므로 «물에 잠기는 깊이»만큼 내려 꽂으면 된다 */
branch.position.set(0, surfaceY - soak, 0);
/* 자란 그대로는 옆으로 뻗어 있다 — 병에는 세워 꽂는 것이 맞다면 이 한 줄이 세운다 */
const d = branch.userData.cutDir;
branch.quaternion.setFromUnitVectors(new THREE.Vector3(d.x, d.y, d.z), new THREE.Vector3(0, 1, 0));
/* 병보다 크면 줄인다. 조각이 20~52cm 라 0.13m 병에는 반드시 줄여야 한다(§3 표) */
const want = (rimY + CUT_STEM_UP) * 1.6;
if (branch.userData.sizeM.h > want) branch.scale.setScalar(want / branch.userData.sizeM.h);
g.add(branch);
g.userData.potPart = jar;           // ⚠ 그대로 못 박아라 — 안 그러면 가지를 병으로 읽는다
```

⚠ **`potPart` 를 반드시 병으로 못 박아라.** 「잎이 아닌 첫 자식」 규칙이 가지를 병으로
읽으면 자리 한도가 엉뚱해진다(`buildCutJar` 주석이 이미 그렇게 적어 두었다).

### 2-3. ⚠⚠ **먼저 채워야 할 칸 하나 — 「자를 때 모주의 유효 생장일」이 세이브에 없다**

`branchOf` 는 **그 날의 그 모주**를 다시 지어야 하는데, 지금 코어가 저장하는 것은

- `c.source.growthDays` — **그 조각이 자란 날**이다(모주의 날이 아니다). `day − dayOfAge(마디생일)`
- `c.cutOnDay` — **달력 날**이다. 빛 게이트 때문에 유효 생장일과 다르다

둘 다 **모주의 유효 생장일이 아니다.** 되짚을 수도 없다(마디 생일이 없으면 역산이 안 된다).

⇒ **자를 때 한 칸을 적어 두어야 한다.** `propagation §takeCutting` 의 `source` 블록에 한 줄이다:

```js
source: { …, motherGrowthDays: <자를 때 io.growth.growthDays()>, seed: (S.sim && S.sim.seed) }
```

그리고 `game.html §syncRoom` 의 삽수 `spec` 에 `nodeId`·`motherGrowthDays`·`seed`·`leafState` 를
같이 넘기면 된다. **그 칸이 없으면 `branchOf` 를 부르지 마라** — 모주의 날을 어림잡아 넣으면
「자란 그대로」가 그 순간 거짓말이 된다. 없는 동안은 예전 길(원기둥)이 그대로 맞다.

⚠ 옛 세이브에는 그 칸이 영원히 없다. **`null` 이면 예전 길로 내려앉는 것**이 정직하다.

### 2-4. ⚠ 무늬는 **`leafState` 를 줘야** 난다 · 그리고 **늦게 온다**

이 인스턴스는 빛 이력이 없어서 스스로는 무늬가 **절대 안 난다**(`plant_assemble §한계`).
`game.html` 이 화분에 이미 넘기고 있는 `leafStateForRoom(p)` 를 삽수에도 그대로 주면 된다.

무늬 텍스처는 **그 잎이 실제로 쓸 때 한 장씩** 받는다(`§ensureSkin`). 그래서 **첫 판은
기본잎으로 선다** — 실측 1초쯤 뒤에 도착한다. `asm.onSkinChange(cb)` 로 알림을 받아 그
가지만 다시 지으면 된다(화분이 이미 그렇게 하고 있다).

③ `fitCam()` 은 **그루용 자**라 하한(FRUSTUM 1.5)이 삽수 한 토막에 너무 넓고 **늘 원점을 본다** —
   밑동이 원점인 가지는 화면 밖으로 뻗어 나갔다. 그래서 상자 한가운데를 담게 바꿨다.

⚠ **색 가짓수의 바를 500 으로 내렸다**(§2.9-③ 의 3,000 이 아니다). 까닭을 적어 둔다 —
**잎 한 장짜리 삽수를 당겨 찍으면 화면이 거의 한 색의 잎**이라 2,400색쯤 나온다.
사진을 눈으로 확인한 뒤 내린 바이고, 까만 사진(3색)·빈 사진(1색)은 이 바로도 그대로 걸린다
(둘 다 실제로 걸렸다).

## 5. 못 한 것 · 안 한 것 (있는 그대로)

- ★★ **배선은 안 했다.** 지시대로 `room_view.js` · `game.html` 을 안 건드렸다.
  ⇒ **「병 안에 그 가지가 서 있다」는 아직 화면으로 확인되지 않았다.** 확인된 것은
  **가지 자체**까지다(§3-2 의 사진 다섯 장). 그래서 여기 「고쳤다」로 안 적는다
  (START-HERE §2 — 「고쳤다」를 화면 확인 없이 쓰지 않는다).
- ★ **「자를 때 모주의 유효 생장일」이 세이브에 없다**(§2-3). 이 칸이 없으면 배선을 해도
  옳은 가지가 안 나온다. **코어(`propagation`)가 한 줄을 적어야 하고, 그건 이 창 범위 밖이다.**
- **자른 면이 마디 경계에서 최대 반 링 어긋난다**(마디 길이의 약 5%). 정점을 옮겨 딱 맞출 수는
  있지만 그러면 「자란 그대로」가 깨진다. **재서 적어만 뒀다.**
- **처짐(`userData.leaves`)은 빈 배열이다.** 모주와 같은 규약이다 — 원본이 잎을 pivot 으로
  안 묶고 마디 트리로 두므로 그룹째 처지게 할 수가 없다. 색(밴드·시듦)은 얹힌다.
- **뿌리는 안 만든다.** 물에서 난 흰 뿌리는 모주에 없던 것이라 **떼어낼 것이 없다** —
  그건 `room_view` 가 지금처럼 그리는 것이 맞다(지어내는 것이 아니라 새로 난 것이다).
- **삽수를 다시 모주로 자르는 길**(`cuttableNodesOfCutting`)은 growth 트리에 없는 마디라
  `branchOf` 가 `null` 을 낸다. **화분 모주에만 쓴다.**
- **세이브는 안 봤다.** `branchOf` 는 부를 때마다 다시 짓는 값이라 저장할 것이 없다.
