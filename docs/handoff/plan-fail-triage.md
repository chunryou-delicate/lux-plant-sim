> **숫자를 정하러 갔다가 재는 식이 틀린 것을 찾았다.** 그래서 숫자를 안 정한다.

## 7-1 자가 무엇이라 말하나

```
FAIL G-2c → ★이사한 판 96개 중 3개가 아직 여름에 끝납니다 (가장 빠른 것 튜토 354일)
             — 그 판은 계절 전환도 식물등 해금도 못 봅니다
```
식은 `assert.equal(summer.length, 0)` — **여유 0**이다.
뜻은 이렇게 적혀 있다(2026-08-03):
> *"여기가 빨개지면 **가을·식물등·겨울 콘텐츠를 아무도 못 보는** 상태로 돌아간 것이다."*

## 7-2 ★ 그런데 그 세 판은 **다 보고 나갔다**

계절은 **90일씩 · 한 바퀴 360일**이고 게임 0일은 연중 **135일**(여름 45일째)이다
(`weather.js §DAYS_PER_SEASON` · `tutorial.js §yearDay0Of`).

| 튜토일 | `yearDay` | 계절 |
|---|---|---|
| 57 | 192 | 가을 |
| 189 | 324 | 겨울 |
| 314 | 89 | 봄 |
| **315** | 90 | **여름** ← 여기서 되돌아온다 |
| **354** | **129** | **여름** (두 번째 · 39일째) |

⇒ **세 판은 전부 튜토 354일에 끝났다.** 가을(45)·겨울(135)·봄(225)을 **다 지나고** 두 번째 여름이다.
⇒ 자가 찍은 내역이 스스로 그것을 증명한다 — **`확정무늬 45일`**. 확정 무늬는 **가을 게이트**라
  가을에 닿아야 온다(`varieGrantOpensDay`). **가을을 봤다는 증거가 같은 줄에 있다.**

## 7-3 ⇒ 판정: **㉠ 자가 낡음.** 합격선이 아니다

`r.season === 'summer'` 를 「계절을 못 봤다」로 읽는 등식은 **판이 튜토 315일 안에 끝날 때만 참**이다.
2026-08-03 에는 그게 참이었다(그때 판은 57~189일에 끝났다). **지금은 꼬리가 315일을 넘는다.**
⇒ **한 바퀴 돌아온 판을 「한 바퀴도 못 돈 판」으로 읽고 있다.** 정반대다.

### 고칠 식 — **새 숫자를 안 만든다**

```js
// 지금: 끝날 때 계절이 여름인가
const summer = all.filter(r => r.season === 'summer');
// 이렇게: 가을에 닿기 전에 끝났나 — 바로 아래 줄이 이미 쓰는 값이다
const OPEN = varieGrantOpensDay(A.ok[0].S.tutorial);   // = 45 (가을 진입)
const tooEarly = all.filter(r => r.lastDay < OPEN);
```
★ `OPEN` 은 **이 검사가 바로 다음 줄에서 이미 쓰는 값**이다. 문턱을 새로 짓지 않는다.
★ 그리고 **여유 0 을 그대로 둔다.** 「가을 전에 끝난 판」은 한 판도 있으면 안 되는 것이 맞다 —
  느슨하게 할 이유가 없다. **내가 정할 숫자가 없다는 것이 이 건의 결론이다.**

## 7-4 ⚠ 다만 **따로 볼 것 하나** — 꼬리가 354일까지 간다

G-2c 가 잘못 잡았을 뿐, **그 세 판 자체는 눈에 띈다.**

| | |
|---|---|
| 중앙값 | A 89일 · C 175일 |
| 이 세 판 | **튜토 354일** — 중앙값의 두 배 |
| 그 판의 모습 | 잎 7장(무늬 2) · 삽수 **2개**만 팜 · 그루로 3,762,500원 |

⇒ **삽수를 거의 안 팔고 모주를 키워서 통째로 판 길**이다. 되긴 되는데 **두 배 넘게 걸린다.**
⇒ 이게 **의도된 느린 길인지, 아니면 막다른 길에 가까운지**는 밸런스 판단이고,
  **재현이 그 길을 제대로 못 잰다**고 이 파일 자신이 §1320 에 적어 두었다:
  > *"모주 하나가 이미 2,133,333원이라 그 문턱이 삽수가 자라기 전에 먼저 걸린다. (…)
  >  **재는 자를 고쳐야 재진다.** 고치는 곳은 §④ 한 줄이고 (…) **plan 몫이다.**"*

⇒ **그것이 진짜 내 몫이다.** G-2c 합격선이 아니라 **§④ 의 「사람이 어떻게 파나」**다.
  아직 안 정했다 — 정하려면 「모주를 통째로 파는 것을 정상 경로로 볼 것인가」부터 정해야 하고,
  그건 박사님 판단이 필요해 보인다. **근거만 모아 올린다.**

# 8. **못 가른 셋을 마저 갈랐다 — 셋 다 ㉣ 이었다** (2026-08-23)

## 8-1 ★★ `first_play_attacks` · `pots E-6` — **한 뿌리다. 그리고 박사님 결정이다**

앞에서 *"수확 g 이 정확히 2배 — 못 갈랐다"* 로 두었다. **재서 찾았다.**

```
first_play.js:680   const harvestMultOf = (rules) => …
first_play.js:679   CROP_HARVEST_MULT = { banjiha: 2.0, oneroom: 1.3 }
first_play.js:694   base × cropTiredMultiplier × harvestMultOf(rules)   ← 여기서 2배가 붙는다
```

**박사님 원문**(`first_play.js:665`):
> *"**2배로 하고 난이도 올라갈수록 줄이는 건 어때?**"* · *"어쨌든 **게임오버는 되면 안 되니까**"*

까닭도 적혀 있다 — 체력 5 로는 **「열심히 하면 되는 구간」이 아예 없었다.**

실측:
```
콩나물  1끼 4,000 / 2끼  7,000 / 3끼 10,000     savedWonPerCycle 3,500
무순    1끼 2,000 / 2끼  5,000 / 3끼  8,000     savedWonPerCycle 2,500
```
⇒ 두 자가 붙들고 있는 것은 **배수가 붙기 전 값**이다. `pots E-6` 의 `500/5000`·`600/4000` 도,

### ⚠⚠ 그리고 내가 총괄에 올린 경보가 **틀렸다**

내가 이렇게 적었다:
> *"**하루 식비 절감이 통째로 2배가 되는 자리**라 아무나 고치면 안 됩니다"*

**아니다.** 같은 절이 바로 그것을 막아 두었다(`first_play.js:673`):
> ⚠ **밥으로 아끼는 것은 안 늘어난다** — 하루 몫 상한이라 g 이 늘어도 그대로다.
>   늘어난 것은 **전부 팔린다.** 그래서 배수의 효과는 **판매 수입에만** 온다.
> ⚠ `savedWonPerCycle` 은 **안 건드린다.** 같이 올리면 하루 몫이 흔들린다.

⇒ ★ **식비는 한 푼도 안 움직인다.** 움직이는 것은 **파는 쪽**이다.
⇒ 내가 「2배」만 보고 **어디에 붙는 2배인지를 안 읽었다.** 경보의 방향이 반대였다.

★ 그리고 이 사실은 **§7 의 물음과 붙는다** — 수확량 2배가 **판매 수입에만** 온다면,
  채소로 버는 돈이 그만큼 늘고 **이사비에 닿는 길이 하나 더 있다**는 뜻이다.
  `plan-questions-moveout.md` 의 물음 ①(모주가 열쇠 하나) 을 볼 때 같이 봐야 한다.
