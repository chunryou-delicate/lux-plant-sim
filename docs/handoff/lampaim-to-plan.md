# 식물등 겨누기 · 꼬리 — 인계

**2026-08-06.** `docs/growlight_aim.md` §2 §3 §6-1~3 을 구현했다.
정본은 그 문서다. 여기는 **잰 것**과 **화면이 붙일 자리**, 그리고 **판단이 필요한 것** 하나다.

범위: 물리(겨누기·꼬리) · 데이터(겨누기 범위) · 상태·세이브 · 검사.
값·전기세는 안 건드렸다(§4 는 다른 창 몫).

---

## 0. 세 줄 요약

- **겨눌 수 있다.** 집게·스탠드 등은 머리를 돌린다. 바 등은 못 돌린다(던진다)
- **안 겨눈 등은 한 톨도 안 바뀌었다.** 6개 방 전 슬롯 696개 값이 **비트 단위로** 같다
- ⚠ **판단 하나 필요하다** — 「뒤쪽을 안 비춘다」를 안 겨눈 등에까지 걸면
  창턱 DLI 가 6.64 → 4.80 으로 내려앉는다. 지금은 **겨눈 등에만** 걸어 뒀다. §6 을 봐 달라

## 1. 화면이 부를 정확한 시그니처

`game.html` 은 한 글자도 안 건드렸다. 아래를 붙이면 된다.

### 읽기

```js
io.light.lampList()
// → [{ uid, preset, idx, pos:{x,y,z},
//      aimable: boolean,                       // false 면 손잡이를 아예 그리지 마라
//      range: { yaw, tiltMin, tiltMax } | null, // 도(°). null = 못 겨눔
//      aim:   { yaw, tilt } | null }]           // null = 안 겨눔(기본)

io.light.aimRangeOf(uid)   // { yaw, tiltMin, tiltMax } | null — 모르는 uid 면 던진다
io.light.lampAims()        // { [uid]: {yaw, tilt} } — 겨눈 등만 실린다
```

### 쓰기 — **두 곳에 적는다**

```js
import { setLampAim, clearLampAim } from './src/game/state.js';

io.light.setLampAim(uid, { yaw, tilt });   // ① 물리 적용 + 범위 검사(밖이면 던진다)
setLampAim(S, uid, { yaw, tilt });         // ② 세이브에 남긴다

io.light.clearLampAim(uid);                // 겨누기 풀기
clearLampAim(S, uid);
```

★ **①을 먼저 부른다.** 범위 밖이면 ①이 던지므로 세이브에 못 들어간다.
  반대로 하면 못 쓰는 값이 세이브에 남는다.

| | 뜻 | 범위 |
|---|---|---|
| `yaw` | 좌우 회전(도). 위에서 내려다본 방위각 | 등마다 다름 (지금은 전부 ±180) |
| `tilt` | **똑바로 아래(0)에서 꺾어 올린 각**(도) | 집게 0~75 · 스탠드 0~60 |

⚠ `tilt` 는 하늘에서 재는 각이 아니라 **바닥에서 재는 각**이다. `0 = 수직 아래`.
  기본값이 0 이어야 「안 건드린 등 = 옛 동작」이 성립해서 이렇게 맞췄다.

**yaw 가 어느 쪽인가** (손짓을 거꾸로 붙이지 않으려면 필요하다).
`aim = ( sin(tilt)·sin(yaw),  −cos(tilt),  sin(tilt)·cos(yaw) )` 이므로:

| yaw | 머리가 향하는 쪽 |
|---|---|
| `0°` | **+z** |
| `90°` | **+x** |
| `180°` / `−180°` | **−z** |
| `−90°` | **−x** |

`tilt = 0` 이면 yaw 가 무엇이든 `(0,−1,0)` 이다(수직 아래라 방위가 뜻이 없다).
그래서 화면은 **tilt 를 먼저 세우고 yaw 를 돌리는** 순서가 자연스럽다.

### 겨누는 동안 실시간 미리보기 (§5 의 조준경)

```js
io.light.setLampAim(uid, { yaw, tilt });     // 캐시는 여기서 스스로 비운다
const d = io.light.dliOfSlot(slotId, { weather, season, lampCount, litHours });
// 임의 좌표는 io.light.dliAt({x,y,z}, {...}) — 기존 배치 미리보기와 같은 함수
```

★ `clearCache()` 를 따로 부를 필요 없다 — `setLampAim`·`clearLampAim`·`setLampAims` 가
  각각 안에서 비운다. 자리 하이라이트를 그대로 다시 그리면 그게 조준경이다.

### 세이브

세이브·복원은 **자동**이다. `S.lamps.aim` 에 `{uid: {yaw,tilt}}` 로 실리고,
`deserialize(raw, { light })` 가 방을 조립한 뒤 `io.light.setLampAims()` 로 얹는다.
화면이 따로 할 일은 없다.

### 왜 저절로 같은가 — 분기가 아니라 식이다

`aim` 이 없거나 `(0,-1,0)` 이면 일반식이 옛 두 줄로 **그대로 떨어진다.**

```
a = (0,-1,0),  v = 잰 점 − 등
along = v·a = −vy
perp  = v − (v·a)a = (vx, vy+along, vz),   vy+along = vy+(−vy) = 0   ← IEEE754 에서 정확히 0
off   = |perp| = hypot(vx, 0, vz)  =  옛 hypot(dx, dz)
dist  = hypot(along, off)          =  옛 hypot(dy, off)              ← hypot 은 부호에 무관
```

⚠ 함정 하나 — `dist` 를 `hypot(vx,vy,vz)` 로 구하면 **안 된다.** 수학은 같아도
연산 순서가 달라 마지막 자리가 갈린다. 직교 성분 둘로 `hypot(along, off)` 을 써야
옛 식과 **같은 순서**가 된다. `aimVector(0,0)` 이 `sin(0)=0`·`cos(0)=1` 로
**정확히** `(0,-1,0)` 이 되는 것도 같은 이유로 중요하다.

## 3. 꼬리 — 고른 것과 탈락시킨 것

옛 곡선은 `t>1` 에서 `(1.15−t)·0.5` 로 꺾여 `t=1.15` 에 0 이 됐다. 문제가 둘이었다:
**① `t=1` 에서 0.55 → 0.075 로 뚝 떨어진다**(불연속) **② `t>1.15` 는 0 이다.**

`t ≤ 1` 은 **글자 그대로 그대로** 뒀다 — 「거의 같다」의 폭을 **0** 으로 잡았다.
근거: §2 의 회귀를 「거의」가 아니라 **비트 단위**로 지킬 수 있고, 원뿔 안은
문서 §3 표대로 이미 잘 돌고 있어 손댈 이유가 없다.

### 후보 — `f(t)` 값

| 후보 | t=0 | 0.5 | 1 | **1.15** | 1.5 | 2 | 3 | 5 | 10 | 20 | f′(1⁺) | 판정 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| A 옛것 `(1.15−t)·0.5` | 1.0000 | 0.8875 | 0.5500 | **0.0000** | 0 | 0 | 0 | 0 | 0 | 0 | −∞(계단) | ✗ t>1.15 가 0 · t=1 에서 불연속 |
| **B 멱 `0.55·t^−1.636`** | 1.0000 | 0.8875 | 0.5500 | **0.4376** | 0.2833 | 0.1769 | 0.0911 | 0.0395 | 0.0127 | 0.0041 | **−0.90** | **채택** |
| C 지수 `0.55·e^−1.636(t−1)` | 1.0000 | 0.8875 | 0.5500 | 0.4303 | 0.2427 | 0.1071 | 0.0208 | 0.0008 | 0.0000 | 0.0000 | −0.90 | ✗ 너무 빨리 죽는다(t=5 에 0.0008) |
| D 급한 멱 `0.55·t^−3` | 1.0000 | 0.8875 | 0.5500 | 0.3616 | 0.1630 | 0.0688 | 0.0204 | 0.0044 | 0.0006 | 0.0001 | −1.65 | ✗ t=1 에서 기울기가 꺾인다 |
| E 유리식 `0.55/(1+(t−1)²)` | 1.0000 | 0.8875 | 0.5500 | 0.5379 | 0.4400 | 0.2750 | 0.1100 | 0.0324 | 0.0067 | 0.0015 | −0.00 | ✗ 기울기 0 — 원뿔 경계가 평평해 보인다 |

왼쪽 기울기는 `f′(1⁻) = −0.9` 다. **B 를 고른 이유**:

- 값도 기울기도 이어진다(C¹). `K` 는 지어낸 값이 아니라 `−0.55K = −0.9` 를 푼 **해**다 → `K = 0.9/0.55 = 1.6363…`
- `t=1.15` 에서 **0.4376** — 0 이 아니다
- 멱함수라 꼬리가 **길되 얇다**. `t=20` 에 0.00409, `t=50` 에 0.00091, `t=100` 에 0.00029 → 결국 0 으로 간다
- C 는 같은 C¹ 이지만 지수라 `t=5` 에서 이미 0.0008 이다. 「조금씩 차등으로」라기엔 너무 일찍 끊긴다

### ⚠ 그런데 — 이 꼬리는 **지금 게임에서 한 번도 안 불린다**

재고 나서야 알았고, 이게 이번에 가장 중요한 발견이다.

`spread = r·d/ref` 이고 `off ≤ dist` 는 피타고라스라 **항상** 성립한다. 그래서

```
t = off/spread = (ref/r)·(off/dist) ≤ ref/r
```

**`t` 의 상한이 `ref/r` 로 못 박혀 있다.** 기구별로:

| 기구 | ref/r | = t 상한 |
|---|---|---|
| growlight_clip | 0.3/0.35 | **0.857** |
| growlight_bar | 0.3/0.5 | **0.600** |
| growlight_stand | 0.4/0.7 | **0.571** |
| lamp_ceiling · floor · pendant · wall · string · desk | — | 0.429 ~ 0.833 |

**게임에 있는 아홉 기구 전부 1 미만이다.** 겨눠도 마찬가지다 — `off ≤ dist` 는
겨누기와 무관하기 때문이다. 실제로 집게 등을 `yaw −180~180 × tilt 0~75` 전수로 돌리며
14칸을 다 재 봤고 **최대 `t` 는 0.8571**, 곧 이론 상한 `ref/r` 과 정확히 같았다.

⇒ **후보 A~E 중 무엇을 골라도 자리별 DLI 는 전부 같다.** `t>1` 가지가 안 불리므로
  표를 따로 낼 것이 없다. 옛 `1.15` 절벽도 **도달 불가능한 죽은 코드**였다 —
  문서 §3 이 "절벽처럼 끊긴다"고 본 것은 곡선의 모양이지 실제로 겪는 값이 아니었다.

★ 이것은 문서 §1 의 결론과 **어긋나지 않고 오히려 같은 말**이다 —
  「범인은 감쇠 곡선이 아니라 거리다」. 곡선 밖이 끊겨서 어두웠던 게 아니라,
  역제곱이 이미 다 한 것이었다. 그래서 꼬리는 지금 **잠재적**이고,
  실제로 빛을 옮기는 것은 §4 의 겨누기다.

꼬리를 정말로 켜려면 `spread` 식을 바꿔야 하는데, 그건 `t ≤ 1` 값을 바꿔서
**회귀를 깬다.** 그래서 손대지 않았다 — §6 의 판단거리로 남긴다.

## 5. 바 등은 안 돌아간다 — **던지기**를 골랐다

`io.light.setLampAim('banjiha-growlight-bar', …)` 는 **던진다.**

무시가 아니라 던지기를 고른 이유: 무시하면 화면은 손잡이를 보여 주는데 빛이 안 움직이고,
세이브에는 값이 남아 「겨눴는데 안 먹는」 상태가 조용히 굳는다.
바 등이 붙박이인 것은 버그가 아니라 **설계**(§2)라 크게 말해야 한다.

★ 화면은 `lampList()` 의 `aimable:false` 를 보고 **손잡이를 아예 안 그리면** 된다.
  던지기는 배선이 틀렸을 때의 안전망이지 평소 경로가 아니다.

범위는 새로 짓지 않았다. `data/lighting_presets.json` 에 `aim` 블록을 넣고
**`adjustable_height` 와 갈라지지 않는지 검사가 못 박는다**(`test_lampaim ④-b`).

| 등 | `adjustable_height` | `aim` |
|---|---|---|
| `growlight_clip` | true | `{yaw:180, tilt_max:75}` |
| `growlight_bar` | false | **없음** |
| `growlight_stand` | true | `{yaw:180, tilt_max:60}` |

## 6. ★ 판단이 필요한 것 하나 — 「뒤쪽을 안 비춘다」의 범위

지시와 문서 §2 는 `along ≤ 0` 이면 0 이라고 했다. 그대로 넣으면 **합격선이 깨진다.**

### 왜 — 창턱이 등보다 **위**에 있다

잰 값이다:

| | y | 비고 |
|---|---|---|
| `banjiha-sill:0` | **1.585** | 창턱 |
| `growlight_bar` 발광점 | 1.066 | 창턱보다 **0.52m 아래** |
| `growlight_clip` 발광점 | 1.136 | 창턱보다 **0.45m 아래** |

옛 식은 `dy = Math.abs(p.y − pt.y)` 였다. **절댓값이라 등 위쪽도 아래쪽과 똑같이 비췄다.**
창턱의 등 PPFD 42.62 는 **전부 거기서 나온다.**

문서 §2 는 "`aim` 이 아래면 `along = dy`" 라고 적었는데, 옛 `dy` 는 **절댓값**이고
새 `along` 은 **부호가 있다.** 반지하 14칸 중 등보다 위인 칸이 정확히 이 한 칸이라,
하필 합격선이 걸린 자리에서만 갈린다.

### 그대로 넣으면

| | 지금 | 뒤쪽 차단을 안 겨눈 등에도 걸면 |
|---|---|---|
| `banjiha-sill:0` 등 1개 PPFD | 42.62 | **0** |
| `banjiha-sill:0` 등 1개 DLI | **6.64** | **4.80** |
| 갈라짐 문턱 6.0 | 넘는다 | **못 넘는다** |

⇒ 「등을 사는 경로」와 「안 사는 경로」가 다시 바이트 단위로 같아진다
  (`test_balance_routes ①-1` 이 막으려던 그 상태). 창 tau 0.70 결정의 근거가 사라진다.

### 그래서 지금 어떻게 해 뒀나

**축이 있는 등만 원뿔이다.**

- `aim` 이 안 실린 등(= 안 겨눔) → 옛 대칭 모형 그대로. 뒤쪽 차단 **안 건다**
- `aim` 이 실린 등(= 플레이어가 겨눔) → 원뿔. 뒤쪽 **0**

읽는 방식: *겨누지 않은 등은 광축이 없다. 축이 없으면 「뒤」도 없다.*
겨누는 순간 축이 생기고 그때부터 앞뒤가 갈린다.

이러면 회귀가 비트 단위로 지켜지고(§2), 겨눈 등은 뒤를 안 비춘다(`test_lampaim ⑤`).
다만 §4 표의 `y0/t0` 열처럼 **「똑바로 아래로 겨누기」가 「안 겨눔」과 다르다**
(창턱 6.78 → 6.64). 그 한 칸이 이 선택의 값이다.

### 박사님께 여쭐 것

세 갈래다. **숫자만 놓고 고르시면 그대로 맞춘다.**

| | 무엇 | 창턱 등1 DLI | 잃는 것 |
|---|---|---|---|
| **가 (지금)** | 겨눈 등만 원뿔 | **6.64** | "아래로 겨누기 = 안 겨눔" 이 안 성립(한 칸, 6.78→6.64) |
| 나 | 전부 원뿔(문서 §2 그대로) | **4.80** | 합격선·tau 0.70 근거가 무효 |
| 다 | 나 + 창턱 밝기의 근거를 다시 잡는다 | 다시 재야 한다 | 반지하 밸런스를 처음부터 다시 뜬다 |

**다 를 고르실 경우 미리 재 둔 것** — 창턱을 등으로 밝히려면 **겨눌 수 있는 등**이 있어야 한다.
집게 등을 창턱 쪽으로 돌리면(`yaw −90 · tilt 60`) 창턱이 **6.81** 로 문턱을 넘는다(§4 표).
⚠ 그런데 튜토가 처음 주는 등은 **바 등**이고 그건 못 돌린다. 즉 **다** 를 고르면
튜토 구간의 창턱은 4.80 에 머물고, 「등을 사면 갈라진다」가 **집게 등을 산 뒤로 밀린다.**
그게 §2 가 말한 두 단계 배움과 오히려 맞을 수도 있다 — 다만 `test_balance_routes` 의
세 경로를 전부 다시 떠야 한다.

★ 참고로 바 등 발광점이 `yBase + 높이×0.92` 로 mount 보다 **4.6cm 위**에 잡혀 있다
(`house.js` — 바닥 스탠드용 식이 선반 밑 부착에도 쓰인다). 물리로는 아래여야 맞지만,
창턱은 그보다 **0.52m 위**라 이걸 고쳐도 위 판단은 안 바뀐다. 별건으로 남긴다.

## 8. 검사

새로 만든 것: `tools/test_lampaim.mjs` — 14항목.

```
① 회귀 (14칸 × 등 0/1/2, 허용 오차 없음)   ①-b 합격선 4.80/6.64
② 항등 (aim 명시해도 옛 식과 비트 단위 동일)  ③ 겨누면 밝은 자리가 옮겨 간다
④ 바 등은 던진다   ④-b 범위가 adjustable_height 와 안 갈린다
④-c NaN·문자열 각도를 0 으로 삼키지 않고 던진다
④-d 표를 통째로 얹다 실패하면 아무것도 안 바뀐다(전부 아니면 전무)
⑤ 뒤쪽 0          ⑥ 꼬리 (t≤1 완전 동일 · t>1.15 ≠ 0 · 멀면 0 · C¹)
⑦ 세이브 왕복   ⑦-b 옛 세이브 = 안 겨눔   ⑦-c 직전 판 각도가 안 남는다
⑧ 겨눈 상태에선 프로파일 안 뽑는다
```

★ ④-c·④-d 는 **스스로 낸 버그**를 잡고 나서 넣은 것이다.
  ④-c — 처음에 `Number(x) || 0` 로 짰더니 `NaN` 이 조용히 0 이 되어
    「겨눴는데 아래를 본다」가 됐다. 지금은 **안 준 것만 0** 이고 준 것이 숫자가 아니면
    던진다(`light_adapter` · `state` 양쪽).
  ④-d — `setLampAims` 가 표를 먼저 비우고 한 칸씩 얹어서, 중간에 실패하면
    「세이브는 못 읽었는데 등은 일부 돌아간」 상태가 남았다. 지금은 **전부 검사한 뒤에**
    한 번에 바꾼다.

`node tools/test_*.mjs` 전체 **29개 전부 통과**(기존 28 + 새것 1).
`test_balance_routes` 의 내부 2건(`①-2`·`③-b`)은 **작업 전과 똑같이** 실패한다 —
밸런스가 아직 안 맞는다는 뜻이고 이 작업이 건드린 것이 아니다.
