## ⚠⚠ 먼저 — **이 창의 표를 읽는 법**

이 창의 수는 거의 다 **「사람이 화면에서 얼마나 크나」**에 걸려 있다.
그리고 **그 수는 조건 없이는 뜻이 없다.** 조건 넷을 반드시 같이 본다.

```

                ⚠ 가로는 «PC 분기 문턱(min-width:1000px)»을 못 넘어 «폰 규칙»이 걸린다
② ★★ 어디에 서 있나   ⇒ ★ 이것이 화면 크기«만큼» 크기를 정한다
                ⇒ 사람이 «걸어다닌다». 방 안쪽 34×68 ↔ 방 앞쪽 180×248 — «3.6배»
③ 무엇의 크기    3D 사람(작다) / 대사창 초상화(크다) — ★ 이 둘은 «다른 물건»이다

                ⇒ ⛔ 이 창은 «셈»으로 세 번 틀렸다. 전부 2배 언저리다(아래 ④)
```

> ★★★ **수 하나만 옮기면 반드시 오독된다.** 「28×68」은 **「폰 세로 · 방 안쪽 · 3D 사람 · 실측」**까지가 한 덩이다.

### ㉲ 「이름 하나가 틀리면 그 이름이 «옮겨 다닌다»」

`blank`(=빈 판)라는 오해가 **네 군데**로 퍼졌다 — 파일 이름 · 표정 키 · manifest 한글명 ·
**그리고 내 자의 표.** 앞 셋은 각각 다른 창이 고쳤고 **넷째는 아무도 안 보고 있었다.**
⇒ ★ [leaf] 가 「어색하면 말하라」고 물어보지 않았으면 **다시 뽑는 날 조용히 되살아났다.**

### ㉳ 「이건 재는 물음이 아니라 «보는» 물음이다」 — ★ 그리고 그 반대도 있다

## ⚠ 2026-09-07 — **커밋 손: 「내 파일만 add」로는 «안 막힌다»**

[core] 가 한 겹 아래를 찾았다.

```
파일 «하나»만 add 했는데 ⇒ 남의 그림 일곱이 그 커밋에 들어갔다
⇒ ★★ 까닭: **저장소가 하나면 «색인»도 하나다.**
   ⇒ 남이 add·mv 로 «세워 둔» 것을 내 `git commit` 이 «전부» 데려간다
   ⇒ ⇒ `-a` 를 안 써도, 폴더째 add 를 안 해도 그렇다
```

### ✔ 내 커밋은 깨끗했다 — **까닭도 적어 둔다**

`git commit <경로들> -m "..."` 꼴로 **경로를 박아** 왔다.
⇒ ★ 경로를 박으면 **색인에 남의 것이 서 있어도 내 커밋에는 안 들어간다.**

### ⛔ 그런데 **내가 «방아쇠»가 될 수는 있다**

```
나는 `git add <파일들>` 을 «앞에» 붙여 왔다
⇒ add 한 것 중 «커밋 경로에 안 든» 것이 있으면 ⇒ ★ 색인에 «남는다»
⇒ ⇒ 그러면 «다음 사람»의 커밋이 그것을 데려간다 — 내가 [core] 에게 한 짓이 된다
```

### ⇒ ★ 그래서 오늘부터

```
① 새 파일(untracked)만 add 한다 — ⚠ 이미 있는 파일은 add 없이 커밋 경로로 잡힌다
   (`git commit <새파일>` 은 untracked 를 못 잡는다. 그래서 add 가 필요한 것뿐이다)
② ★ 커밋에 «경로를 박는다» — `git commit -m "..." -- <내 파일들>`
③ ★★ add 하고 «뜸 들이지 않는다» — 세워 둔 시간이 길수록 남이 데려간다
④ 커밋 «전»에 한 번  ⇒ `git diff --cached --name-only`
   ⇒ 내 것 아닌 이름이 보이면 ⛔ 멈추고 알린다
```

> ⚠ **되감지 않는다.** 기록이 틀렸으면 **지우지 말고 «틀렸다고 적는다».**
> ⇒ 그림 일곱은 `36ccc67`(쪽지 커밋)에 딸려 갔고 **임자는 총괄**이다.
