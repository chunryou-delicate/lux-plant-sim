# growth → plan

**2026-07-26 · 보고 + 판단 요청**

`plan-to-growth.md` 요청분(최소 루프 v0)을 반영하고 조도를 실제로 연결해 돌렸다.
결과와, 문서와 어긋난 값 하나를 보고한다.

## 0. 복구본 확인 — 커밋했다

`dli7` · `dliCV` · `fLight` · `fStable` · `setDailyLightSteady` 다섯 개, 새 이름에 맞춰 복구한 것
그대로 살렸다. 내용이 맞았고 `calcMatureProb`에 갈라짐 문턱(fenestrate 미만이면 0)을 넣은 건
"자연광만으로는 갈라진 잎을 못 본다"를 실제로 성립시킨다.

다만 **같은 파일을 두 창이 고치면 파일 지정 커밋으로도 못 막는다**는 게 이번에 확인됐다.
소유 규칙이 확정됐으니 앞으로 `plant_grow.html` 수정은 이 파일에 "붙일 수 있는 코드"로 주면 반영한다.

## 1. ★ 조용히 죽는 버그를 하나 더 잡았다

빛을 넣고 8개 시나리오 260일치를 돌린 결과다.
지난 사고(함수 소실)가 `PLANT_DLI=null`이라 안 보였던 종류라, 연결 상태 검증이 유일한 확인이었다.

```
함수 정의 24/24 전부 있음
끔·고정 0.3·6.5·20 · 0↔13 요동 · 0→18 점증 · 개별 번식   → 이상 없음
음수·NaN 섞기                                          → ★ 오류
```

**NaN·음수 DLI가 확률을 NaN으로 만든다.** 이게 함수 소실보다 나쁘다 —
`rng() < NaN` 은 항상 `false`라 **오류도 안 나면서 무늬도 갈라짐도 영영 안 나온다.**
터지기라도 하면 고치는데, 이건 "왜 안 나오지" 하면서 밸런스를 의심하게 된다.

`setDailyLight`에서 값을 막고(경고 후 끔 처리) 확률 함수에도 방어를 뒀다.
**계약 객체에서 dli가 null/누락으로 오는 경우가 있으면 알려달라** — 지금은 끔으로 처리한다.

## 2. 시나리오 결과 — 반지하 · 몬스테라 · 360일

날씨는 날짜를 시드로 굴렸다(되감아도 같은 날씨). 확률은 그날의 7일 평균으로 계산했다.

| 등 | DLI 범위 | 7일평균 밴드 | 무늬 확률 | 갈라짐 확률 | 첫 갈라짐 |
|---|---|---|---|---|---|
| **0개** | 0.02~0.55 | **고사 100%** | 0.0% | 0.0% | 없음 |
| **1개** | 6.50~7.03 | **최적 100%** | **13.0%** | **12.6%** | 1일차 |
| **2개** | 12.98~13.51 | 성장 100% | **38.8%** | 22.0% | 1일차 |

**등 하나가 고사에서 최적으로 뒤집는다.** 예상표(§3)와 거의 일치한다 —
무늬 13% / 39%는 예상 그대로고, DLI도 6.7 예상에 6.50~7.03이 나왔다.

## 3. ★ 판단 요청 — 아파트가 자연광만으로는 안 갈라진다

문서에 "자연광만으로는 **아파트에 가야** 갈라진 잎을 본다"(`balance_decisions.md` §②)로 돼 있는데,
실제로는 아파트도 안 갈라진다.

| 방 (등 0개) | DLI 범위 | 주 밴드 | 갈라짐 |
|---|---|---|---|
| 원룸 | 0.21~4.77 | 정체 | 0% |
| **아파트** | 0.28~6.26 | **정체** | **0%** |
| 온실 | 0.58~13.01 | 최적 | 5.7% |

**원인은 재는 대상이 다른 것이다.** 아파트 6.26은 *맑음·여름 최고치*(peak)인데,
갈라짐 판정은 *7일 평균*으로 한다. 날씨 계수(맑음 .55 / 흐림 .25 / 비 .12)와 계절을 곱하면
평균이 문턱 6.0을 못 넘는다. house는 peak를, 생장 창은 이동평균을 재고 있었다.

셋 중 하나를 골라야 한다.

| | 방법 | 결과 |
|---|---|---|
| ⑴ | 갈라짐 문턱을 6.0 → 4.5 | 아파트에서 갈라짐. 대신 원룸(4.77)도 걸쳐서 구분이 흐려진다 |
| ⑵ | 아파트 peak를 올린다 | 실측을 흔드는 것이라 권하지 않는다 |
| ⑶ | **"아파트도 등이 필요하다"로 문서를 고친다** | 등 하나로 뒤집히는 지금 구조가 그대로 살아난다 |

**⑶을 권한다.** 등 하나가 고사↔최적을 가르는 게 선명하고, "아파트면 그냥 되는" 것보다
플레이어의 선택이 살아난다. 반지하도 등만 있으면 아파트보다 잘 자라는 게
"어두운 방이 빛을 통제할 수 있는 방"(`sale_economy.md` §2)과도 맞물린다.

문턱을 바꾸실 거면 `data/growth_tuning.json`의 `thresholds.fenestrate`만 고치면 된다.

## 5. ★ 체력(vigor) 모델 — 설계 기록함. 검산에서 두 가지가 걸린다

박사님 결정대로 고사 판정을 이동평균이 아니라 체력으로 간다. **구현은 v1**,
지금은 `data/growth_tuning.json`의 `vigor` 절과 `growth-to-core.md`에 기록만 했다.
`dliAvg(7)`은 `fStable` 등에 쓰이므로 그대로 두고, "고사 판정에 쓴다"는 계획만 폐기했다.

주신 수치로 돌려보니 두 군데가 문구와 어긋난다. **plan 판단 요청.**

### ① 시작값 80 vs 문구의 "33일 / 100일 이상"

| | 시작 80 | 시작 100 |
|---|---|---|
| 몬스테라 ×1.0 (암흑 −3.0/일) | **27일** | 33일 |
| 산세 ×0.3 (−0.9/일) | **89일** | 111일 |

**문구의 33일·100일은 시작 100 기준이다.** 시작 80으로 두면 27일·89일이 된다.
어느 쪽이 의도인가. 시작 80은 "처음 데려온 화분이 이미 완벽하진 않다"는 뜻으로 읽히는데,
그렇다면 문구를 27일·89일로 고치는 게 맞다.

### ② 종별 계수를 회복에도 곱하면 산세가 167일 걸린다

`species_mult`를 증감 양쪽에 곱하면 이렇게 된다.

| | 암흑 생존 | 최적에서 0→100 회복 |
|---|---|---|
| 몬스테라 | 27일 | 50일 |
| 산세 (양쪽 적용) | 89일 | **167일** |
| 산세 (감소에만 적용) | 89일 | 50일 |

저광 내성은 **"버티는" 능력이지 "회복이 느린" 능력이 아니다.**
양쪽에 곱하면 산세가 한 번 상하면 반년을 못 돌아온다 — 초보용 식물인데 회복이 제일 어려워진다.

→ **감소에만 곱하는 쪽을 권한다.** JSON에 `decay_only: true`로 넣어뒀다.
다르게 가려면 `false`로 바꾸면 된다.

## 6. 밴드 이름 개칭 — 동의. house에 요청했다

`die → critical` · `weak → poor` · `survive → stagnant`.
체력 모델로 가면 밴드는 "죽는다"가 아니라 오늘 상태 라벨이 되므로 개칭이 맞다.

`growth-to-house.md`로 요청했다. **house가 적용하는 시점에 growth도 같이 바꾼다** —
한쪽만 바꾸면 계약 객체의 `band`와 생장 창의 `bandOf()`가 갈린다.
core 창이 밴드 이름을 쓰기 시작하기 **전에** 바꾸는 게 싸다.

`light_thresholds.json`의 **필드명(`die`/`survive`/`min`)은 그대로 둔다** — 그건 임계값 이름이지
밴드 키가 아니고, 바꾸면 `growth_tuning.json`까지 연쇄된다.

## 7. 체력 표시 수준 — 별개 토글에 동의. 다만 전제가 하나 있다

"온도는 켜고 싶은데 체력 숫자는 보고 싶다" 같은 조합이 있으니 시뮬 깊이 축과 분리하는 게 맞다.
`growth_tuning.json`의 `vigor.display`에 `number` / `bar` / `none` 세 단계로 넣어뒀다(기본 `bar`).

**전제**: 지금 잎의 시각 표현이 4단계(die/survive/best/over)뿐이라 **0~100을 눈으로 못 읽는다.**
이대로 숨기면 고수 모드가 실력이 아니라 찍기가 된다 — 주신 지적 그대로다.

그래서 `vigor.visual`에 연속 연동값을 넣어뒀다. 계단이 아니라 보간이다.

```
droop_deg   0 → 38°   잎자루가 아래로 꺾이는 각
sat         1.0 → 0.35 채도
light       1.0 → 0.8  밝기
yellow      체력 40 미만부터, 아래 잎에 더 세게 (최대 0.55)
gloss       1.0 → 0.15 광택
```

**구현 순서는 시각 연동이 먼저다.** 체력 숫자만 만들고 표시를 숨기면 그 순간 게임이 망가진다.
v1에서 vigor를 만들 때 시각 연동을 같은 커밋에 넣겠다.

### 하나 더 — 잎 손실은 되돌릴 수 없게 두는 게 맞다

`vigor.leaf_loss`: 체력 30 미만이면 4일마다 아래 잎부터 **영구** 손실.
회복해도 잃은 잎은 안 돌아온다. 이게 이동평균과의 핵심 차이이자,
"살아났지만 아래 잎 두 장은 잃었다"를 성립시키는 부분이다.
암흑에서 시작 80이면 몬스테라는 **17일째부터**, 산세는 **56일째부터** 잎을 잃기 시작한다.
