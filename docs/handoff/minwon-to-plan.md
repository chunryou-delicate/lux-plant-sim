## 1. ① 가만히 두면 하루가 안 간다

### 1-1 무엇이 어긋나 있었나 — **같은 하루를 두 벌로 세고 있었다**(§2.8)

- 시루 게이지 `dayFrac()` 은 하루치를 다 흐르면 **0.995 에서 멈춘다.** 까닭까지 적혀 있다 —
  *"꽉 찬 게이지는 '다 됐다'는 뜻인데 하루가 넘어가지도 않았는데 그렇게 보이면 거짓말이다."*
- 그런데 시계 `dayPhase` 는 `% 1` 로 **그냥 감아 돌았다.**

실측(2026-08-19 · `tools/probe_dayhold.mjs` · 가만히 두고 10분):

```
   0초  06:01   Day 0        450초  00:46   Day 0
 150초  12:16   Day 0        550초  04:56   Day 0
 300초  18:31   Day 0        600초  05:53   Day 0   ← 한 바퀴(576초)를 다 돌았다
```

**한 바퀴가 576초(9분 36초)다.** 가만히 두면 자정을 넘어 다시 새벽이 되고, 또 돌고, 또 돈다.
**날짜만 그대로다.** 화면이 「하루가 몇 번이나 지났다」고 말하면서 `Day` 는 안 움직였다.

### 1-2 ★ 박사님 확정 — **넘긴다. 실시간 진행이다**

값이 얼마나 움직이는지를 같이 놓고 여쭈었다:

| | |
|---|---|
| 하루 | **576초**(9분 36초) |
| 시간당 | 6.25일 |
| 하루 지출 | 16,667원(월세 몫 포함) |
| ⇒ **시간당 약 104,000원** · 시작돈 150만이면 손 놓고 **약 14시간에 파산** |

박사님: **"넘긴다 — 실시간 진행"**. ⇒ **되묻지 말 것.**

### 1-3 고친 것

- 하루 안에서 흐른 몫을 `dayElapsed01` 로 따로 든다. 한 바퀴를 다 돌면
  **`autoNextDay()` 가 [다음 날] 과 같은 길(`goNextDay`)로** 하루를 넘긴다.
  ⚠ 셈을 여기서 따로 하지 않는다 — 그러면 손으로 넘긴 하루와 저절로 간 하루가 갈린다.
- **밥상 창은 안 연다.** 고른 것이 없으면 `planMeal(null)` 과 같은 뜻이고 그것은
  *"최선껏 먹는다"* 다(`first_play §planMealGrams`) — 가만히 두었다고 굶기지 않는다.
  창을 띄우면 자리를 비운 사람 앞에서 게임이 멈춘다.
- **못 넘기는 때는 서서 까닭을 적는다.** 첫 시루를 놓기 전([다음 날]이 잠긴 때) ·
  연출 중 · 게임오버가 그렇다. 그때는 `DAY_HOLD01`(0.995) 에서 서고 시각 옆에
  **「· 하루가 저물었습니다」**가 붙는다. **조용히 안 넘어가는 것이 제일 나쁘다.**
- 막는 문은 **[다음 날] 이 쓰는 그 문 그대로**다. 새 조건을 지어내면 단추와 시계가
  서로 다른 판단을 한다.

⚠ **탭을 떠나 있으면 안 간다** — `clockPaused()` 가 `document.hidden` 을 본다.
  켜 놓고 잠들어도 뒤에서 파산하지는 않는다. 그 창이 **앞에 있어야** 흐른다.
⚠ 대사·안내판을 펴 놓은 동안도 안 흐른다(예전 그대로 · 박사님 2026-08-06 확정).

### 1-4 실측 — 셋을 갈라서 쟀다 (`tools/probe_dayauto.mjs`)

```
① 시루를 놓기 전     elapsed 0.999 · held 예 · 「새벽 05:53 · 하루가 저물었습니다」 · Day 0
   ⇒ 안 넘어간다. 서고 까닭을 적는다 ✔
② 시루를 놓은 뒤      Day 1 → +5초 → Day 2 · 「새벽 06:06」
   ⇒ 저절로 넘어간다 ✔
③ 넘어간 뒤           elapsed 0.004 · 시계가 6시로 되돌아간다 ✔
```

한 바퀴를 실제로 기다린 실측도 남긴다(`tools/probe_dayhold.mjs` · 603초):
`0초 06:06 → 302초 18:29 → 552초 04:03 → 603초 05:53`.

⚠ **재다가 거짓말 하나를 더 잡았다.** 넘어가는 연출이 도는 동안에도 「하루가 저물었습니다」가
  붙어 **「아침 06:17 · 하루가 저물었습니다」**라는 앞뒤 안 맞는 줄이 나왔다.
  **서 있는 것과 가고 있는 것은 다른 말**이다 — `dayClockHeld()` 가 `dayAnimRunning` 을 보게 했다.

⚠⚠ **되돌리는 자리를 하나로 묶었다**(`resetDayClock`). `runDayAnim` 의 연출-끄기 지름길이
  `dayPhase` 만 되돌리고 `dayElapsed01` 을 두고 있었다 — 그대로 두면 다음 프레임이 다시
  「하루가 다 갔다」로 읽어 **저절로 넘기기가 무한히 돈다**(검사·`?fast=1` 이 그 길로 간다).

★ 새 손잡이 둘
| 이름 | 무엇 |
|---|---|
| `window.__dayClock()` | 시계가 어디까지 갔고 섰나 — **읽기 전용** |
| `window.__dayClockSkip(v)` | 하루치 끝자락으로 밀어 놓는다 — **재는 자만 쓴다.** 한 바퀴가 576초라 이게 없으면 실측 한 번에 10분이 든다. ⚠ **0.999 를 안 넘긴다** — 경계를 자가 넘어 버리면 제가 만든 결과를 보는 것이라 아무것도 안 잰 것이 된다 |

## 2. ② 해상도에 따라 [다음 날] 이 안 눌린다

### 2-1 재현 — **대사가 떠 있으면 1600 아래로는 전부 안 눌린다**

`tools/probe_nextcover.mjs` — 대사를 **일부러 띄워 놓고** 잰다. 앞선 자는 「그때 마침
대사가 떠 있었나」에 따라 답이 달라져서, 그걸 안 가르면 해상도 탓으로 읽힌다.

| 화면 | 대사 상자 | [다음 날] | 덮은 것 |
|---|---|---|---|
| 1920×1080 | 1000×168 @(280,890) | **눌린다** | — |
| 1440×900 | 1000×168 @(40,710) | ✘ | `dlgNext` |
| 1366×768 · 1280×800 · 1152×864 · 1024×768 | … | ✘ | `dlgBox` |
| 390×844 (폰) | 370×102 | ✘ | `dlgText` |

왼쪽 아래 셋(`waterCrop`·`harvestCrop`·`waterPot`)도 **같이** 막혔다.

### 2-2 까닭 — 2026-08-17 에 단추를 띄우면서 규칙 밖으로 나갔다

`#dlg` 는 `z-index:34`, 모서리 단추는 `z-index:26` 이다. 원래는 단추가 `#bottom` 안에 있었고
그 띠에 *"대화 중에는 하단 액션이 눌리면 안 된다 — 대사를 넘기려다 하루가 지나간다"* 는
규칙이 걸려 있었다. 2026-08-17 에 넷을 **`#stage` 안으로** 옮겨 모서리에 띄우면서
(`offsetParent` 때문에 `#stage` 안이라야 했다) **그 규칙 밖으로 나갔다.**

⇒ 단추는 **밝게 켜져 있는데** 손가락은 대사 상자로 갔다.

### 2-3 고친 것 — 넷도 같은 규칙을 받는다

```css
#stage.talking #next, #waterCrop, #harvestCrop, #waterPot, #resow { opacity:.35; pointer-events:none }
```

셋이 한꺼번에 풀린다: ① 어느 해상도에서나 **같게** 군다 ② 화면이 거짓말을 안 한다
(흐리면 못 누르는 것이다) ③ *대사를 넘기려다 하루가 지나가지 않는다* 가 되살아난다.

⚠ **`z-index` 로 단추를 대사 위에 올리는 길은 안 골랐다.** 눌리기는 하는데 위 규칙이 깨진다.
⚠⚠ 선택자를 `#stage.talking ~ #bottom #next` 로 먼저 썼다가 **한 군데도 안 먹었다** —
  넷은 `#bottom` 이 아니라 `#stage` 안에 있다. **옮긴 자리를 기억으로 짚지 말 것.**

## 3. ③ 캐릭 이동 튜토가 없다

### 3-1 **없던 게 아니다** — 있는데 한 번도 안 떴다

`COACH_NOTES.walkTip`(「사람을 눌러 보세요」)은 **2026-08-17 에 같은 지시로 이미 들어와 있었다.**
그러니 물음은 「없다」가 아니라 **「왜 안 보이나」**다. 까닭이 둘이고 둘 다 재서 잡았다:

1. **화면이 바쁘면 그 자리에서 버린다.** `coach()` 는 `coachClear()` 가 거짓이면 그냥 돌아간다.
   그런데 `walkTip` 을 부르는 자리는 **첫 시루를 놓은 직후**(+900ms)라 그때 몬이의 대사가
   떠 있다 — `talking` 이면 무조건 거짓이다.
2. **부르는 자리가 한 길에만 있었다.** [확인] 바는 **누르기 길**에서만 뜬다.
   **끌어서 놓으면** `drag.end → commitPlace` 로 끝나 `placeConfirmOk` 를 아예 안 지난다
   (실측: 끌어 놓은 뒤 `confirming:false`). 안내문은 *"끌거나 눌러서"* 라고 두 길을 다
   말하는데 쪽지는 한 길에만 걸려 있었다.

### 3-2 고친 것

- **`coachLater(id)`** — 지금 못 뜨면 **버리지 않고 기억해 두고** 화면이 조용해질 때 뜬다.
  기다리는 것은 하나뿐이다(§coach ⓐ 한 번에 하나와 같은 규율). `coachTick()` 이 띄운다.
- 부르는 자리를 **끌기·누르기 두 길 다**에 놓았다.
- 「한 번 보면 끝」(ⓓ)은 그대로다 — `coachSeen` 이 지킨다.

**실측(고친 뒤 · 끌어서 놓는 길)**

```
+600ms  쪽지떴나: true · 본것: ["walkTip"] · 「사람을 눌러 보세요」
```
