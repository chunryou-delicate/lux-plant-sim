# 1. ⚠⚠ 먼저 — 「시작 첫날」이 어디인지가 **이 창 밖**에 있다

박사님: *"바로 시작날이 바로 30일기준 마지막날인거야. **다음날 누르면** 월세 30만원이 쓱 빠지게"*

넣은 것은 **튜토 1일차 청구**다. 그런데 **튜토 시계는 첫 플레이가 끝나야 돈다**:

```js
export function tutorialDay(ts, opt = {}) {
  …
  if (!firstPlayDone) return { skipped: '첫 플레이 진행 중' };   // ← 돈도 계절도 안 움직인다
```

첫 플레이는 **돈이 멈춘 16일**이다(`docs/first_play.md §0` — novice·맑음·여름 고정).
⇒ **지금 구현에서 「1일차」는 게임 17일쯤이다.** 게임을 켜고 처음 누르는 [다음 날]이 아니다.

| 후보 | 무엇 | 누가 고쳐야 하나 |
|---|---|---|
| ㉠ | **그대로 둔다** — 첫 플레이(배우는 16일)는 돈이 안 도는 「연습」이고, 살림은 그 뒤부터 | 아무도. 지금 상태 |
| ㉡ | 첫 플레이 **첫날부터** 살림이 돈다 | `first_play.js` · `loop.js` — **코어 소유. 이 창이 못 한다** |

⇒ ★ **박사님이 고르셔야 합니다.** ㉡ 이면 코어 창에 넘겨야 하고, 그때 「석 달 빠듯」 대사도
   첫 플레이 안으로 들어갑니다.

# 2. 유예 폐지 — 예고(`rent_soon`)를 살렸다

예전 조건은 `ts.rent.paidCount === 0 && ts.day === nextDueDay − 7` 이었다.
첫 청구가 1일로 당겨지면 그 조건은 **튜토 −6일**을 가리켜 **한 번도 안 터진다.**

죽은 코드로 남기지 않고 **매달** 뜨게 바꿨다. 첫 달은 예고할 여지가 없으니(첫날 청구) 저절로 빠진다.
⇒ 뜻도 바뀐다: 예전은 「봐 주던 것이 끝난다」, 지금은 **「또 돌아온다」** 다.

대사도 그래서 갈랐다(`dialogue.js`, 이 창 소유):

- **`rentFirst`(튜토 1일차)** — 이 게임의 **「돈 설명」 자리**가 됐다.
  *"삼십만 원. 들어오자마자 한 번에 빠져나갔다." / "…남은 걸로 세 달은 될까." /
  "아니. 이대로면 두 달이야." / "밥값을 얘들이 대신 내 주면 그때 세 달. 그것도 빠듯하고."*
  ⇒ 「두 달 / 밥값을 아끼면 세 달」은 **실측값**이다(아래 §3 — 61일 / 80일).
- **`rentSoon`(매달 이레 전)** — 짧게. `REPEATABLE` 에 넣었다(안 넣으면 대화 상자가 두 번째를 막는다).

## ⚠⚠ 정정 — 아래 표는 **2026-08-09 에 한 번 갈아 끼웠다**

처음 낸 표는 **「시루를 30개로 늘려도 −19,740 → −17,569 밖에 안 간다, 천장에 막혔다」** 였다.
**그 표가 틀렸다.** 지금 이 문서의 표가 맞다. 왜 틀렸는지를 남긴다 —

`probe_econ.mjs` 가 **달력 90일**을 돌리고 그 90으로 나눴다. 그런데 살림은 **튜토 시계가 돌 때만**
나가고, 튜토 시계는 첫 플레이가 끝나야 시작한다. **시루가 많을수록 첫 플레이가 길어져서
같은 달력 90일 안의 튜토일이 시루 1개면 90일, 30개면 68일**이었다 — 분모가 후보마다 달랐던 것이다.
그래서 시루를 늘릴수록 이득이 짧은 기간에 눌려 담겨 **곡선이 납작해 보였다.**

⇒ ★★ **결론이 뒤집힌다.** 천장에 막힌 것이 아니라 **기울기가 완만한 것**이다. 처방이 정반대다:
  「천장」이면 상한을 풀어야 하고, 「기울기」면 **회전분·판매가율·주기를 올려야** 한다(§9).
  잰 자가 틀려서 처방이 뒤집힐 뻔했다. 도구는 고쳤다(`play({ tutorialDays })`).

**왜 상한이 안 먹나.** 곳간 상한은 `min(한 회전분 합계 5,000, 끼니상한 × 2,500)` 인데

**식비절감이 시루 3개부터 40개까지 108,000원(=하루 1,200원)에 완전히 고정**된다.

하루로 펴면 1,200원이다. 곳간에서 꺼내는 상한 5,000원/일은 **한 번도 안 닿는다**
(쉬어서 버린 몫 `spoiledWon` 이 모든 후보에서 0원 — 곳간이 넘친 적이 없다는 뜻이다).

## ③ 역산 — 「유지」가 되려면 시루가 몇 개여야 하나

```
하루 벌이 = [ 곳간 6,000 + (N−3) × 회전분 × 판매가율 − N × 씨앗값 ] ÷ 5
```

| 회전분 | 씨앗값 | 판매가율 | **필요 시루** | 방 자리(14칸) |
|---|---|---|---|---|
| 3,000원 | 700원 | 70% | **72개** | ✕ |
| 3,000원 | 700원 | 85% | 55개 | ✕ |
| 3,000원 | 700원 | 99% | 46개 | ✕ |
| 3,000원 | **300원** | 85% | 46개 | ✕ |
| **6,000원** | 700원 | 85% | 25개 | ✕ |
| **10,000원** | 700원 | 85% | 16개 | ✕ |
| **10,000원** | 700원 | 99% | **14개** | ○ (딱) |

⇒ ★★ **「월세+식대 유지」를 그대로 두면 방에 안 들어간다.** 반지하는 **14칸**이고
  몬스테라·가구가 그중 몇을 쓴다. 회전분을 3,000 → 10,000원으로 **세 배 넘게** 올려야 겨우 닿는다.

⚠ 이 표는 **시루값(자본)을 뺀** 정상운영 셈이라 72개이고, ① 의 실측(시루값을 90일에 나눠 넣음)은
  **77개**다. 둘은 어긋난 것이 아니라 시루값을 넣느냐 빼느냐의 차이다 — 같은 답이다.

⚠⚠ **시루 N개 = 방 자리 N칸이다.** 시루를 「무리」에서 「하나하나」로 바꾸는 작업이 끝나면
  시루 하나가 한 칸을 먹는다(지금은 한 칸에 여러 개가 뭉쳐 있다). 「20개면 닿는다」는
  **20칸이 필요하다**는 뜻이고, 방은 14칸이다.

# 9. 못 한 것과 그 이유

| | 왜 |
|---|---|
| 회전분 표를 `data/balance` 로 옮기기 | `first_play.js` 는 **다른 워커 소유**. §7 에 붙일 코드로 적었다 |
| 첫 플레이 첫날부터 살림 돌리기 | 같은 이유. §1-㉡ |
| 가구(선반) 값·칸수를 정하기 | 가구 자리는 **house 소유**. 회수일(시루 7,000원 = 5회전)이 그 값의 상한을 준다 |
| `startCashWon`·`dailySpendWon` 을 `data/balance` 로 | `banjihaRulesFrom(homes, {dailyFoodWon})` 를 만들어 **월세·하루지출은 정본에서 유도**하게 했다. 시작돈은 아직 코드에 있다 — `characters.json` 의 `startCash` 칸이 캐릭터별이라 반지하 튜토와 어떻게 잇는지가 미정이다 |
| 무순(2종째)을 실제로 돌려 재기 | 하네스가 콩나물 한 종만 돌린다. 2종이면 회전분 합이 5,000원이 되는데 그건 이미 곳간 상한과 같아 **결론이 안 바뀐다**(§4-②) |
| 시루 40개 이상 | 방 자리가 14칸이라 그 위는 실측 의미가 없다(§4-③ 역산으로 대신했다) |
| 수확 주기(㉢)를 **실측**하기 | `CROP_KINDS` 에 얼어 있어 규칙 사본으로 못 바꾼다. §7.5 ㉢ 은 유도값이라 그렇게 표시했다 |
| 「월세+식대 유지」를 성립시키는 값 찾기 | 현실감 안에 답이 없다는 것까지가 측정의 몫이다. 목표를 낮출지 세계관을 바꿀지는 기획 결정(§8 ㉠) |
