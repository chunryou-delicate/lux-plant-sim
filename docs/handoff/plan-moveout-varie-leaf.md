# 이사 둘째 조건 — 「무늬 잎을 낸 적」의 뜻 셋

2026-08-24 · [Plan] · 박사님 확정(*"「판 적」 대신 「무늬 잎을 낸 적」 및 돈으로"*)의 뜻을 정한다.
⛔ **값은 안 건드렸다.** ㉠ 의 수는 **권고**이고 정하는 것은 박사님이다.

---

# ㉢ **「낸 적」이다. 「지금 있나」가 아니다.** ★ 코드가 이 답을 «강제»한다

## ⓐ 쓸 수 있어 보이는 칸이 이미 있다 — ⚠ **그런데 못 쓴다**
```js
quest.js:198   motherVarieLeaves   «그중 무늬 잎 수»
game.html:7702 motherVarieLeaves = st2.variegatedLeaves      ← ★ «지금 달고 있는» 수다
```

## ⓑ ★★★ 그리고 **잎은 준다**
```js
growth_adapter.js:312
  "삽수를 자르면 코어 장부에서는 «잎이 준다»(propagation §motherLeafStats 가 lostLeaves …)"
```
⇒ ★★★★ **「지금 있나」로 하면 — 무늬 잎을 잘라 삽수를 만드는 «순간» 이사 문이 닫힌다.**
⇒ ⇒ ⚠ **옛 병이 돌아온다.** 게다가 **더 나쁘다** —
```
옛 병   무늬 삽수를 «팔면»   문이 닫힌다
새 병   무늬 잎을 «자르면»   문이 닫힌다     ← ★ 한 걸음 «앞»으로 당겨진다
```
  ⇒ **팔기 전에 이미 닫힌다.** 플레이어는 **판 적도 없는데** 문이 닫힌 것을 본다.

## ⓒ ⇒ ★★ 그리고 더 깊은 까닭 — **두 조건은 성격이 달라야 한다**
```
돈 2,000,000       「지금 있나」   ← 쓰면 준다. 그래야 «모으는 것»이 뜻을 갖는다
무늬 잎을 낸 적     ★「했나」       ← 배움은 «되돌아가지 않는다»
```
⇒ ★★★ **문이 「돈이 있고 + 할 줄 안다」를 묻는다.**
  둘 다 「지금 있나」면 **문이 한 가지만 묻는 것**이 되고, 둘 다 「했나」면 **문이 안 닫힌다.**

## ⓓ ⚠ **지금 «안» 물려도 「낸 적」이라야 한다**
박사님 ③으로 삽수 버튼이 원룸으로 가면, **반지하에는 자를 수단이 없어** 잎이 안 준다.
⇒ ⚠ **그래서 지금은 「지금 있나」로 해도 안 걸린다.**
⇒ ★★ **그래도 「낸 적」이라야 한다** — ★ **이사 조건이 «삽수를 어디서 배우나»에 의존하면 안 된다.**
  삽수가 반지하로 돌아오는 날 **조용히 물린다.** ⇒ **㉞ 의 모양이다: 지금 답이 맞으니 안 본다.**

## ⇒ **[core] 에 필요한 것**
```
새 칸 하나   varieLeafEver (또는 varieLeafEverCount) — 한 번 참이면 계속 참
⚠ motherVarieLeaves 를 «재사용하면 안 된다». 그것은 지금 수이지 이력이 아니다
★ 다만 «이름»은 같은 결로 — 두 칸이 헷갈리면 다음 사람이 잘못 읽는다
```

# ㉠ 몇 장인가 — ★ **한 장을 권한다** (⛔ 정하는 것은 박사님)

```
① ★ 그 수를 쓰는 줄이 «이미» 있다
     quest.js:633   opens: num(s.motherVarieLeaves) >= 1
   ⇒ 새 문턱을 안 만든다. ㉰(같은 것을 두 곳에 짓지 않는다)와 같은 결이다
   ⇒ ★★ 그리고 «한 사건»이 문을 열고 다음 줄을 동시에 연다 — 깨끗하다

② 두 장은 «같은 것을 두 번» 하는 것이다
   ⇒ 배움이 안 늘고 «시간»만 는다. 계율 ⑦(힘은 드묾에서 온다)의 반대다

③ ⚠ 「2」는 이미 «다른 뜻»으로 쓰이고 있다
     quest.js:420  done: motherLeaves >= 2      (몬스테라가 자리를 잡았다)
     quest.js:586  opens: motherLeaves >= 2     (자를 수 있게 됐다)
   ⇒ 이사도 2 면 «같은 수가 세 가지 뜻»을 갖는다
```
⇒ ★ 그리고 **무늬 잎 한 장을 내는 것 자체가 이미 어렵다** — 등을 사고 · 자리를 고르고 · 기다린다.
  **그 셋을 다 해낸 것이 「할 줄 안다」의 증거로 충분하다.**

---

# ㉡ 어느 잎인가 — ★ **어디서 났든**. 가르지 않는다

```
반지하   삽수가 원룸으로 가므로 ⇒ 모주밖에 없다. «저절로» 한정된다
나중     방이 늘어도 규칙을 안 고쳐도 된다
```
⇒ ★★ **지금 안 갈리는 것을 미리 가르지 않는다.**
  갈라 두면 **그 가름이 왜 있는지 아무도 모르는 날**이 온다(이 저장소가 오늘 여러 번 본 병이다).
⇒ ⚠ **다만 「무늬」의 판정은 하나여야 한다** — 모주 잎과 삽수 잎을 **다른 자로 재고 있지 않은지**
  [core]·[growth] 가 한 번 봐 주면 좋겠다. **거기가 갈려 있으면 그때는 갈라야 한다.**

---

# ⇒ ★★ 그리고 이것이 **반지하와 원룸을 깨끗하게 가른다**

```
반지하   빛을 사고 · 자리를 고르고 → 무늬 잎을 «낸다»   → 나간다
원룸     그 무늬를 «불린다»(삽수)  → 판다
```
⇒ ★ 어젯밤 §8(*"반지하는 살리는 것 · 원룸은 값을 정하는 것"*)과 **한 줄로 이어진다.**
⇒ ★★ **그리고 어젯밤 「민무늬만 막자」로 푼 매듭이 «필요 없어진다»** —
  삽수를 통째로 원룸으로 옮겨도 **문이 안 잠기기 때문**이다.
  ⇒ ⚠ **내 처방이 폐기된 것이 아니라 «문제 자체가 없어진» 것**이다. 더 나은 결말이다.

## ⚠ 원룸 퀘스트라인에 걸리는 것
```
· 「삽수 배우기」가 원룸 «확정» — 어젯밤 밑그림 그대로 쓴다
· ⚠ 다만 원룸 첫 줄이 「삽수를 배운다」면, ★ 반지하에서 «무늬 잎 하나»를 이미 냈다는 전제다
  ⇒ 원룸 첫 대사가 그것을 «받아» 주어야 한다 — "그 잎, 하나 더 만들어 볼까요"
· ⚠ 그리고 이사할 때 그 무늬 잎이 «따라와야» 한다. 안 따라오면 원룸 첫 줄이 공중에 뜬다
  ⇒ [core] 확인 요청 대상이다
```
