# ★★★ 원룸을 헤드리스로 «못 잰다» — 프로파일 다섯이 낡았다

2026-08-23 밤 · [Plan] · **파일은 안 건드렸다**(`--write` 안 붙임). 값 변경 0.

---

## 0. 어쩌다 봤나

「열여섯이 살림의 본전」인데 반지하에 **시루가 오르는 칸이 6개뿐**이라는 것이 나왔다.
⇒ 그래서 물었다 — **「열여섯」이 애초에 원룸 수인가?**
⇒ 세러 갔다가 **다른 것**이 나왔다.

## 1. ★★ 방 프로파일 여섯 중 **반지하 하나만 치수를 갖고 있다**

```
data/profiles/room_profile.*.json  —  slots[].maxPotD

  banjiha      15칸 · 치수 있음 15 · ★시루(≥0.24) 6칸
  oneroom      11칸 · 치수 «없음» 11        ← 전부 null
  apartment    83칸 · 치수 «없음» 83
  classroom   128칸 · 치수 «없음» 128
  greenhouse   64칸 · 치수 «없음» 64
  tworoom      20칸 · 치수 «없음» 20
```

## 2. ⇒ **치수가 없으면 「못 받는다」로 판정된다** — 조용한 폴백이 «아니라» 계약이다

```js
place.js:319       isNum(slot.maxPotD) && potD <= slot.maxPotD     ← 숫자가 아니면 false
first_play.js:526  Number.isFinite(slot.maxPotD) && slot.maxPotD >= diameterM
first_play.js:523  "maxPotD == null 을 통과시키면 치수를 모르는 자리에 화분이 올라간다"
loop.js:1382       throw "지름 …m 화분이 올라가는 자리가 이 방에 없습니다 (…0칸)"
```
⇒ ★ **fail-loud 로 잘 설계돼 있다.** 문제는 설계가 아니라 **데이터가 낡은 것**이다.

## 3. ⚠ **그런데 게임 본편은 안 아프다** — 여기가 갈림이다

```
게임 화면    light_adapter.build 로 방을 «실시간으로 짓는다»   → 치수가 살아 있다
헤드리스     room_profile.createProfileLight(프로파일 JSON)    → ★ 치수가 null 이다
             ↑ sim.js:157 · probe_econ · probe_economy_chase … 밸런스 도구 전부
```
⇒ ★★ **손으로 놀면 멀쩡하고, 재려고 하면 안 된다.**
⇒ ⚠ **그래서 아무도 안 걸렸다** — **원룸을 헤드리스로 재 본 사람이 없었으니까.**

## 4. ★★★ 낡은 정도가 「값이 틀림」이 아니라 **「자리 이름이 통째로 다름」**이다

```
$ node tools/gen_room_profile.mjs --rooms=oneroom      (대조만 · 안 씀)

oneroom: DIFF (15칸)
  + oneroom-nightstand:0  새 자리        + oneroom-shelf:0..7   새 자리 (여덟)
  + oneroom-desk:0, :1    새 자리        + oneroom-sill:0..3    새 자리 (넷)
```
⇒ ★ **열다섯 칸이 «전부» 「새 자리」다.** 저장된 11칸은 **옛 uid 체계**다.
⇒ ⇒ **부분이 낡은 게 아니라 통째로 딴 방이다.**

## 5. ⇒ 재는 김에 나온 것 — **원룸 빛은 반지하와 «급»이 다르다**

```
등 0개 · 맑음 · 여름 (LIVE)
  oneroom-sill:0..3      6.66 · 6.69 · 6.58 · 6.27      ← ★ 창턱 넷이 전부 6 위
  oneroom-shelf:5 / :7   4.91 · 4.51
  oneroom-desk:0         2.72
  oneroom-nightstand:0   0.00                            ← ⚠ 완전 어둠
비교: 반지하 창턱 peak 3.68 (제일 밝은 자리)
```
⇒ ★★ **원룸 창턱은 반지하 «최고» 자리의 거의 두 배다. 등 없이.**
⇒ ★★★ 이것이 **§8 「빛의 뜻이 방마다 다르다」를 숫자로 받쳐 준다** —
  **반지하는 살리는 것 · 원룸은 값을 정하는 것.** 원룸에서 빛은 **더 이상 문제가 아니다.**
⇒ ⚠ 그리고 **원룸에도 완전 어둠(협탁 0.00)이 있다.** 삽수 가르치기에 쓸 자리다.

## 6. ⇒ **「열여섯이 원룸 수인가」에 대한 답 — 아직 «모른다»**


⚠ **위 줄은 추정이다. 단정하지 않는다.** ⇒ **프로파일을 다시 뽑아야 answer 가 나온다.**
⇒ ★ 다만 **「열여섯」이 어느 방에서도 쉽지 않다는 것**은 15칸이라는 사실만으로 보인다.

## 7. ⇒ 해야 할 일 — **내 몫이 아니다**

```

```
⇒ ⛔ **[Plan] 은 안 한다.** `data/profiles/` 는 내 소유가 아니고 **밸런스 값에 닿는다.**
⇒ ★ **[House] 또는 [core] 몫이다.** 아파트·교실·온실·투룸도 같은 상태다.
⇒ ⚠ 뽑고 나면 **반지하 프로파일도 바이트가 같은지** 대조해야 한다(`gen_room_profile` §17 이 그 계약을 적어 뒀다).

## 9. ⚠ 오늘의 계율로 읽으면

**㉞ 「답이 맞으니 셈을 안 본다」**의 **한 겹 앞**이다.

```
㉞     답이 맞으니 «셈»을 안 본다
이것   손으로 되니 «재 볼 생각» 자체를 안 한다
```
⇒ ★ ㉞ 는 **셈을 안 보는 것**이고, 이건 **재는 일 자체를 안 하는 것**이다. **더 앞이다.**
⇒ ⚠ 아직 계율로 안 박는다. **박을 자리만 적어 둔다**(총괄 판단 — 하룻밤 자고 박는다).

⛔ **정정** — 처음 이 자리에 **「㉜ 의 뒤집힌 판」**이라 적었다. **㉜ 는 「계측기가 대상을 바꾼다」**이고,
내가 인용한 *"안 읽히는 값은 틀려도 아무도 안 아프다"* 는 **㉞ 쪽 문장**이다. 총괄이 잡았다.
⇒ ★ **번호를 안 보고 «내가 쓴 말»만 보고 갖다 붙였다.** ㉞ 를 세운 밤에 ㉞ 를 잘못 부른 것이다.
