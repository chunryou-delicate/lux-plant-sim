## 1. 왜 콩나물이 첫 주자인가 (확정된 배경)

- → *반지하에서 콩나물 팔아 원룸으로 이사* 루프가 자연 발생. **이사 가면 오히려 못 키운다.**

## 2. 실제 재배 방식 (설계 근거)

```
콩 불리기(반나절) → 시루에 안치기 → 어둡게 덮기
→ ★자주 물주기★ → 3~5일 → 수확
```

**핵심은 물 요구가 극단적으로 높다는 것.** 마르면 죽는다.

### 관엽과 리듬이 정반대다 (이게 설계 가치)

| | 관엽(몬스테라) | **콩나물** |
|---|---|---|
| 물 | 드물게 | **매우 자주** |
| 빛 | 관리가 핵심(많이/적당히) | **차단이 핵심(0이어야 함)** |
| 주기 | 몇 달 | **3~5일** |
| 실패 | 과습·과광 | **마름 · 빛 샘** |

→ 관엽만 있으면 **며칠씩 아무 일도 안 일어난다.** 콩나물이 초반 공백을 메운다.

**→ "수분 게이지"로 통일하는 것을 제안합니다.**
횟수가 아니라 **게이지가 떨어지면 채우는 방식**이면 모드와 무관하게 돌아갑니다.
**콩나물은 게이지가 유난히 빨리 떨어지는 작물**로 두면 "손이 자주 간다"는 성격이 그대로 살아납니다.

### ② 물은 콩나물 전용이 아니라 **공통 시스템**이어야 합니다

- 관엽도 물이 필요하고, 로드맵이 **1빛 → 2물 → 3경제** 입니다.
- 콩나물만 따로 만들면 나중에 합칠 때 꼬입니다.
- **→ 물을 공통 시스템으로 설계하고, 콩나물은 "물 요구가 극단적인 작물"로 두는 것**을 제안합니다.

이 둘은 **plan 이 확정** → growth/core 가 구현하는 순서가 맞다고 봅니다.

## 5. 인터페이스 (에셋 쪽 계약)

```js
// 시루 — 관엽 선반과 완전 동일한 슬롯 규격(검증 완료)
item.slots        // [{x,y,z}] 15칸, 로컬 미터, y = 심는 바닥 높이
item.slot_count   // 15
item.blocks_light // true — 뚜껑 닫으면 DLI 0
item.lid_state    // 'open' | 'closed'
item.scale_to_real// 1.0 (절차적 = 이미 실제 미터)

// 뚜껑 토글 2가지 방법
//  (a) 파일 스왑: container_siru_open.glb  ↔  container_siru_closed.glb
//  (b) 노드 토글: _closed.glb 만 로드하고 그 안의 'lid' 노드를 show/hide  ← 가벼움

// 콩나물 인스턴싱 — 슬롯마다 바운딩박스 바닥면을 슬롯 y에 맞춘다
for (const s of siru.slots) {
  const m = beansprout[stage].clone()
  m.position.set(s.x, s.y - bbox.min.y, s.z)
  m.rotation.y = rand() * Math.PI * 2   // ★ 없으면 15개가 전부 같은 방향으로 휨
}
```

**헤드룸 확인 완료** — 뚜껑을 닫은 채로 **전 단계(씨앗~대형 12.8cm)가 들어갑니다**(헤드룸 16.2cm).
초기엔 11.7cm라 대형이 뚫고 나왔는데, 썸네일 점검 중 발견해 뚜껑을 높였습니다.

## 6. 참고 — 에셋 제작 방침

- **콩나물은 절차적(코드) 생성**이 맞았습니다. 형태가 단순해 Meshy로는 오히려 뭉개지고,
  크기·굵기·휨을 파라미터로 조절할 수 있으며 15개 인스턴싱이라 하나만 잘 만들면 됩니다. 크레딧 0.
- **★ 상추부터는 Meshy 로 갑니다.** 잎이 겹치고 주름지고 곱슬거리는 건 코드로 못 만듭니다.
  기존 잎 파이프라인(원화 → Meshy → 잎자루 접합) 그대로 씁니다.
- 씨앗·새순은 **전 작물 공용**입니다. 작물별 차이는 소형 단계부터 시작합니다.
