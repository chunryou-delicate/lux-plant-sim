# [core] ⛔ 삽수 문턱 2장 → 3장 — **재기만 했고 «안 고쳤다»**

박사님 지시가 총괄을 거쳐 왔다:
> *"3번째 무늬 달성 전까지는 삽수 버튼 비활성화 해 두자."*
> *"튜토 끝에 파는 건 그루겠지 — 삽수는 판매 못하게 해놨으니까."*

## ⚠ 먼저 — **「막아 놨다」가 지금 코드엔 없다**
```js
shop.js:2081   export const MARKET_MIN_LEAVES = 2;
shop.js:2131   canCut: c.status === 'established' && now.leaves >= 2,
```
⇒ 잎 **두 장**에서 열린다. 그리고 그 자리가 위험한 까닭은 `dialogue.js` 가 이미 적어 뒀다 —
「한 장뿐일 때 자르면 모주가 0 등급이 되고, 안 자르면 팔 무늬 삽수가 없다」.

**잎 2장(무지1+산반1)에서 산반을 자르면 모주에 무지 한 장만 남아 20,000원짜리가 된다.
되돌릴 수 없고, 하프문(잎3)이 나도 1,120,000 이 안 된다.**

## ⛔ 그런데 **나는 이 값을 안 고친다**
`MARKET_MIN_LEAVES` 도 `canCut` 의 `2` 도 **밸런스 값**이다.
이 창의 규칙은 **「재는 것은 되고 바꾸는 것은 안 된다」**이고,
**옆 창이 전한 말은 그 규칙을 못 푼다.** 지시가 옳아 보여도 마찬가지다 —
옳아 보이는 것과 내가 해도 되는 것은 다른 일이고, 그 갈래를 스스로 흐리면 규칙이 없는 것과 같다.

⇒ ★ **그래서 고칠 곳만 정확히 적어 둔다.** 값을 만질 사람이 이 문서를 들고 두 줄을 고치면 된다:
```
① src/game/shop.js:2081   MARKET_MIN_LEAVES = 2  →  3
② src/game/shop.js         canCut … now.leaves >= 2  →  >= 3
```
⚠ 그리고 **`marketGate` 는 한 번 열리면 안 닫힌다.** 옛 세이브가 이미 2장에서 열려 있으면
그대로 열린 채다 — 그 갈래를 같이 봐야 한다.

## ★ 그리고 잰 것 — **박사님 세 갈래가 값으로 서는가**

### ⓑ 「그루째 팔고」 — **선다. 그리고 이것만 선다**
```
무지 20,000 + 산반 350,000 + 하프문 750,000 = 1,120,000
× potMult 1.4 × synergy[2종] 1.25 = 1,960,000원   ⇒ 이사비까지 40,000 모자람
```
⇒ 그 사만 원을 채소가 만든다. 실측 판은 d87 에 지갑 326,966원 — **여덟 배**였다.

### ⓐ 「삽수해서 일부만 팔고」 — ⛔ **지금 값으로는 «거의 안 열린다»**
```
자를 잎        삽수 값      + 지갑 445,066     남는 모주
산반           350,000       795,066  ⛔      1,610,000
하프문         750,000     1,195,066  ⛔      1,008,000
산반+하프문   1,375,000     1,820,066  ⛔        28,000
```
⇒ ★ **잎 셋에서는 어떻게 잘라도 못 나간다.** 까닭이 값에 있다 —
**`cuttingMult 1.0` vs `potMult 1.4`.** 자르는 순간 40% 를 잃는다.
⇒ 잎4 가 나도:
```
잎4 = 산반    ⛔ 어떻게 잘라도 못 나간다
잎4 = 하프문  ⛔ 어떻게 잘라도 못 나간다 (제일 좋은 조합이 1,945,066 — 54,934 모자람)
잎4 = 풀문    ✔ 산반+풀문을 잘라 팔면 2,320,066 · 모주 1,078,000 을 «남긴다»
```
⇒ ⇒ ★★ **ⓐ 가 열리는 것은 잎4 가 풀문일 때뿐이고 그 확률은 `lightGrade.mid.fullmoon = 0.05` 다.**
  **스무 판에 한 판이다.** 박사님이 그리신 「일부만 팔고 남기는 엔딩」이 지금 값에서는 거의 안 온다.

### ⓒ 「채소로 모아서 그루째 살려서」 — **시루 수가 전부다**
```
d150 지갑 445,066 ⇒ 1,554,934 원이 더 필요하다
시루 17개 (지금 판 실측 하루 +3,370)          ⇒ 461일   ⛔ 「꾸역꾸역」이 아니라 «불가»
시루 25개 (셈 +21,167 × 실측비 0.36 ≈ 7,536)  ⇒ 206일
시루 30개 (셈 +27,667 × 0.36 ≈ 9,850)         ⇒ 158일
시루 40개 (셈 +40,667 × 0.36 ≈ 14,477)        ⇒ 107일
```
⇒ ★ **ⓒ 는 「몇 달 버티기」가 아니라 「시루를 몇 개까지 늘리느냐」다.**
⚠ 그리고 손(체력)이 천장을 만든다 — 시루 n 개면 하루 2n/5 손이 든다.
  30개면 12손인데 밑천이 d95 에 14였다. **40개(16손)는 넘는다.**
⇒ ⇒ ★★ **그러니 ⓒ 의 현실적인 바닥은 «다섯 달»쯤이다.** 「꾸역꾸역」으로 느껴질 값이
  60~90일이라면 **시루가 마흔 개 넘게 필요하고, 그건 손이 안 받는다.**

## ⇒ 그래서 값을 만질 사람에게 남기는 물음 셋
```
① 삽수 문턱 2 → 3   (박사님 지시. 위 두 줄)
② ⓐ 가 서려면 cuttingMult 1.0 이 올라야 하나, 아니면 ⓐ 를 「풀문 갈래」로 두나
③ ⓒ 의 「꾸역꾸역」이 몇 일인가 — 지금 바닥이 다섯 달이다
```
⚠ 셋 다 **밸런스**다. 나는 재기만 했다.
