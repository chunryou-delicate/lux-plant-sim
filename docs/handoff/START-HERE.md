## 2. ★ 이 저장소에서 제일 자주 나는 사고 — 열 번 났다

**숫자나 문구가 이상하면 코드가 아니라 「재는 자」를 먼저 의심하라.**

2026-08-09~11 사이에 측정이 **열 번** 틀렸는데 **열 번 다 「무엇을 재는지」**가 문제였다.
서버 없이 돌린 것 · 분모가 후보마다 다른 것 · 「분배」가 분배가 아니었던 것 ·
「체력 5로 쟀다」는데 실제로는 8~9였던 것 · 「세 층」이라 해 놓고 한 층만 켠 것 ·
하네스가 모주를 말려 죽인 것 · 검사가 옛 상수를 박아 둔 것 ·
**고장난 상태를 검사가 정상으로 못 박아 둔 것**(제일 위험하다 — 고치는 쪽이 검사를 깨게 된다).

그래서 이 셋을 지킨다:

1. **모든 표 머리에 「무엇을 켜고 무엇을 껐는지」를 적는다**
2. **「지금 그렇다」와 「그렇게 하기로 했다」를 갈라서 적는다**
3. **모르면 모른다고 적는다. 짐작으로 원인을 쓰지 않는다**

★ 그리고 **「고쳤다」를 화면 확인 없이 쓰지 않는다.** 그것 때문에 두 번 되돌아갔다.
   코드가 바뀐 것과 화면이 바뀐 것은 다른 말이다.

## 8. 창을 어떻게 굴리나

**VS Code 의 옛 여섯 창(growth·leaf·char·house·plan·core)은 깨우지 않는다.**
그 구조는 조각을 따로 만들던 때의 것이고, 지금은 조각들이 서로 물려 있어 나눌 금이 없다.
게다가 08-01~04 에 멈춰 있어 깨우면 **낡은 믿음으로 판단한다.**

**마스터 창 하나 + 워커**로 간다. 워커 규칙 넷:

1. **보고를 짧게 받는다** — 상세는 인계 문서, 나에게는 「바뀐 것 · 실측 · 판단필요 · 못 한 것」만
2. **동시에 둘까지** — 합치는 건 어차피 직렬이다
3. **마스터는 큰 파일을 안 든다** — 작은 수술은 직접, 파일 하나를 통째로 뜯는 일은 워커
4. **차기 전에 넘긴다** — 꽉 차서 급히 넘기지 말고 이 파일을 갱신해 두고 넘긴다
