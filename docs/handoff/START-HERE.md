## 2. ★ 이 저장소에서 제일 자주 나는 사고 — 열 번 났다

**숫자나 문구가 이상하면 코드가 아니라 「재는 자」를 먼저 의심하라.**

2026-08-09~11 사이에 측정이 **열 번** 틀렸는데 **열 번 다 「무엇을 재는지」**가 문제였다.
서버 없이 돌린 것 · 분모가 후보마다 다른 것 · 「분배」가 분배가 아니었던 것 ·
「체력 5로 쟀다」는데 실제로는 8~9였던 것 · 「세 층」이라 해 놓고 한 층만 켠 것 ·
하네스가 모주를 말려 죽인 것 · 검사가 옛 상수를 박아 둔 것 ·
**고장난 상태를 검사가 정상으로 못 박아 둔 것**(제일 위험하다 — 고치는 쪽이 검사를 깨게 된다).

그래서 이 셋을 지킨다:

1. **모든 표 머리에 「무엇을 켜고 무엇을 껐는지」를 적는다**
2. **「지금 그렇다」와 「그렇게 하기로 했다」를 갈라서 적는다**
3. **모르면 모른다고 적는다. 짐작으로 원인을 쓰지 않는다**

★ 그리고 **「고쳤다」를 화면 확인 없이 쓰지 않는다.** 그것 때문에 두 번 되돌아갔다.
   코드가 바뀐 것과 화면이 바뀐 것은 다른 말이다.

★★ **넷째 규칙 (2026-08-15 신설 · §2.8 을 겪고 나서)** —
   **낡은 숫자를 고칠 때는 「고친 값」도 재라.** 고치는 사람은 이미 「원래 값이 틀렸다」를
   알고 있어서, 대신 넣을 값은 안 재고 문서에서 집어 온다. 그 문서가 더 낡은 것이면
   **틀린 값을 틀린 값으로 바꾸고 「고쳤다」고 적게 된다.** 실제로 그랬다.

## 2.9 ★ 재는 자가 거짓말하는 **열두** 가지 방식
(넷은 2026-08-15 · 다섯째~여덟째 08-16 · 아홉째 08-17 · **열째~열둘째 08-18**)

**① 목록이 잘려 있다.** `test_multisiru` 는 어긋난 것을 **`slice(0, 4)` 로 넷만** 찍는다.
그걸 모르고 「넷만 어긋났다 = 나머지는 멀쩡하다」로 읽었다. 앞 넷을 고치자 **뒤 넷이
새로 나타났다** — 여덟 줄 다 움직여 있었다. ⇒ **안 나온 것을 「없다」로 읽지 마라.**

**② `readPixels` 는 그린 뒤에 까맣게 나온다.** WebGL 기본 프레임버퍼는 화면에 내보낸
뒤 비워진다(`preserveDrawingBuffer:false`). 「방이 새까맣게 렌더된다」고 결론 낼 뻔했는데,
**멀쩡히 도는 데모에서도 똑같이 `[0,0,0,255]`** 가 나왔다. ⇒ **화소를 재려면 사진을 찍어라.**

**③ 사진도 타이밍을 탄다.** 같은 순서로 찍은 사진이 한 번은 새까맣고 한 번은 멀쩡했다.
(어젯밤 다른 창은 재질이 덜 얹힌 한 프레임을 찍고 "색이 살아났다"고 쓸 뻔했다.)
⇒ **사진이 이상하면 코드보다 사진을 먼저 의심하고, 대기를 넣어 다시 찍어라.**
   ★ **색 가짓수를 세라** — 까만 사진은 3색, 멀쩡한 사진은 3,000색이 넘는다. 이게 제일 빠른 자다.

**④ 자가 딴 세상 것이었다.** 원룸 대사를 고치며 `avg7 = peak × weatherE('summer') 0.643` 으로
쟀는데, 그 계수는 **날씨가 굴러가는 `real` 모드의 자**다. 게임은 `novice` 로만 켜지고
(`game.html` 의 `newState` **세 곳 전부**), `novice` 는 맑음·여름에 못박혀 **peak 이 곧 실제값**이다

  ⇒ ★★ **문서에 적힌 숫자도 「재는 자」다.** 옮겨 적기 전에 한 번 계산해 봐라.

**⑩ ★★ 「재현이 안 된다」가 앞 조작이 남긴 찌꺼기였다** (2026-08-18 · 드래그 미리보기).
박사님이 두 번 짚으신 것을 앞 창이 *"내 화면에서는 정상"* 이라 적고 넘겼다. **찌꺼기 때문이었다** —
`#dragGhost` 의 `inroom` 클래스를 `drag.end()` 가 안 떼서, **가방에서 한 번 끌어 본 판에서는**
2D 사진이 저절로 감춰지고 **안 끌어 본 판에서는** 안 감춰졌다. 같은 코드가 판마다 다르게 보인다.
자에서 그 클래스를 걷어 내자마자 그 자리에서 났다.
⇒ ★ **「재현이 안 된다」를 만나면 「내가 재기 전에 무엇을 했나」를 먼저 물어라.**
  앞 조작이 남긴 상태가 병을 가린다. 자를 쓸 때는 **그 상태를 명시적으로 되돌리고** 재라.

**⑪ ★★ 재는 자가 값을 「다시 계산」하면 고쳐도 안 고쳐진 것처럼 보인다** (2026-08-18 · 바닥 격자).
바닥 격자 원점을 고쳤는데 자가 **그대로 6칸**이라 답했다. 코드는 맞았다 —
**자가 원점을 엔진에 안 묻고 제 안에서 옛 식으로 다시 계산**하고 있었다.
⇒ ★ **자는 재라. 짓지 마라.** 엔진이 안 내주는 값이면 **내주게 창구를 내는 것**이 먼저다
  (그래서 `rv.grid().room.origin` 을 냈다). 밖에서 베낀 식은 반드시 낡는다.

**⑫ ★ 삼항으로 갈래를 이으면 「앞 갈래가 빈손」일 때 뒷길을 안 본다** (2026-08-18 · 유령).
`a != null ? f(a) : b != null ? g(b) : h(c)` — `a` 가 실려 있기만 하면 `f(a)` 가 **빈손이어도**
`g`·`h` 를 아예 안 본다. 그래서 새로 낸 세 번째 길이 **영영 안 쓰였다.**
⇒ ★ 「갈래를 고르는 조건」과 「그 갈래가 값을 냈나」는 **다른 물음**이다.
  「찾을 때까지 내려간다」는 `||` 로 짓는다.

⚠ THREE 의 `Raycaster` 는 `visible` 을 **안 본다**(숨은 것도 맞았다고 나온다).
⚠ `screenPosOf` 는 **캔버스 기준**이라 `#roomCanvas` rect 를 더해야 화면 좌표다.
⚠ `localStorage.clear()` 는 **`goto` 뒤에** 불러라(빈 문서에서 부르면 SecurityError).
⚠ **`#next` 는 시루를 놓기 전엔 안 열린다** — 안 놓고 누르면 날짜가 0에 머무는데

## 8. 창을 어떻게 굴리나

**VS Code 의 옛 여섯 창(growth·leaf·char·house·plan·core)은 깨우지 않는다.**
그 구조는 조각을 따로 만들던 때의 것이고, 지금은 조각들이 서로 물려 있어 나눌 금이 없다.
게다가 08-01~04 에 멈춰 있어 깨우면 **낡은 믿음으로 판단한다.**

**마스터 창 하나 + 워커**로 간다. 워커 규칙 넷:

1. **보고를 짧게 받는다** — 상세는 인계 문서, 나에게는 「바뀐 것 · 실측 · 판단필요 · 못 한 것」만
2. **동시에 둘까지** — 합치는 건 어차피 직렬이다
3. **마스터는 큰 파일을 안 든다** — 작은 수술은 직접, 파일 하나를 통째로 뜯는 일은 워커
4. **차기 전에 넘긴다** — 꽉 차서 급히 넘기지 말고 이 파일을 갱신해 두고 넘긴다
