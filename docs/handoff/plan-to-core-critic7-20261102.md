## §1 7P7-① 주문 창 «모자란 만큼» (7C1)

### 지금

- 주문 창 줄은 `[−][N개][＋][전부]` 다(game.html:2468). [전부] = `buyMaxQty` = 소지금으로 살 수 있는 최대다(10097).
- 비판 A Day 13 `d13_seed_all`: «2324개 · 1,162,000원 · 주문하면 333원이 남습니다». 손가락은 그대로 [2324개 주문]을 짚는다(«개수를 정하고 [주문] — 내일 옵니다» · 6801 · 7391).
- 창 기본 개수는 그 품목을 지난번에 시킨 수다(`lastOrderQtyOf` · 10176).

### 새 글 (씨앗 두 품목 · 콩 씨앗 · 무 씨앗)

| 자리 | 지금 | 새 글 |
|---|---|---|
| 넷째 단추(`#buyAll`) | `전부` | `모자란 만큼` |
| 개수 줄(새 줄 · `#buyHave` 밑) | 없음 | `오늘 · 내일 심을 {box} {w}개 — ` + 갈래 |
| 　갈래 ㉮ need > 0 | | `씨앗 {need}개가 모자랍니다` |
| 　갈래 ㉯ need = 0 | | `씨앗은 모자라지 않습니다` |
| 손가락(개수 > need > 0) | [주문] «개수를 정하고 [주문] — 내일 옵니다» | [모자란 만큼] `모자란 만큼으로 맞춥니다` |
| 손가락(need = 0) | [주문] 같은 말 | [그만두기] `닫아도 됩니다` |

- `{box}`: 콩 씨앗 → `시루` · 무 씨앗 → `재배판`(§drawSow `BOX_KO` 와 같은 낱말).
- 단추 동작: `buyQty = min(need, buyMaxQty)`. need = 0 이면 회색이다. 까닭은 바로 위 개수 줄 ㉯ 가 말한다.
- 기본 개수: need > 0 이면 need, need = 0 이면 1 이다(총괄 가름 «지난 주문 수 대신»).
- 손가락이 개수 ≤ need 일 때만 [주문]을 짚는다. 그때 말은 지금 그대로 `개수를 정하고 [주문] — 내일 옵니다` 다.
- 값 줄(`#buyQuote`)은 그대로다. need 가 소지금보다 크면 [모자란 만큼]은 살 수 있는 데까지 맞추고, 값 줄이 지금처럼 «소지금으로는 N개까지입니다»를 말한다.

### 참인 조건

- w = 그 씨앗 작물(콩나물 · 무순)의 **놓인** 줄 가운데 ① 안 심은 줄(needsSow) ② 거둔 줄(harvested) ③ 익은 줄(ready) ④ 내일 익을 줄(growing ∧ daysLeft ≤ 1)의 수다.
  - ①②는 오늘 심고, ③은 오늘 거둬 다시 심고, ④는 내일 거둬 다시 심는다. 그래서 «오늘 · 내일 심을»이 참이다.
- have = 가방 씨앗 + 오는 중 씨앗(§seedTomorrowOf 의 have 와 같다). need = max(0, w − have).
- ⚠ ① 안 심은 줄을 꼭 센다. §seedTomorrowOf(11136)의 want 는 ①을 안 센다.
  - 이 창은 바닥 🛒 지름길(§drawSow `buyIt` — 안 심은 줄이 있고 씨앗 0 · 오는 중 없음)로 열린다. 그 판에서 ①을 빼면 w 가 0 이 되어 ㉯ «씨앗은 모자라지 않습니다»가 선다. 거짓이다.
  - §seedTomorrowOf 를 고칠지, 이 창만 따로 셀지는 core 가 가른다. 고치면 바닥 🛒 미리 단추와 «씨앗을 사러 갑니다» 손가락도 움직인다(같은 자).
- «모자란 만큼»과 «모자랍니다»는 같은 낱말이다. 바닥 단추 «(내일 심을 씨앗이 모자랍니다)»와도 같다.
- 손가락 «닫아도 됩니다»: need = 0 이면 이 창에서 할 일이 없다. 손가락이 이 창으로 이끄는 길(씨앗을 사러 · 🛒 지름길)은 need > 0 일 때뿐이다. 그래서 need = 0 창은 사람이 스스로 연 창이다.

### 후보 · 고른 것 · 까닭

- ㉠ `모자란 만큼` (택함). 까닭: 개수 줄 «씨앗 N개가 모자랍니다» · 바닥 단추 «내일 심을 씨앗이 모자랍니다»와 같은 낱말이다. 누르면 무엇이 되는지가 바로 위 줄에 수로 서 있다.
- ㉡ `필요한 만큼`(총괄 가름 글). 버린 까닭: 뜻은 같다. 하지만 화면 다른 곳은 «모자랍니다»를 쓴다. 한 뜻을 두 낱말로 쓰지 않는다.
- ㉢ `내일 몫`. 버린 까닭: ①② 오늘 심을 줄도 센다. «내일»만 말하면 좁다.
- 폭: 넷째 칸은 360 에서 64px · 390 에서 70px 이고 글은 13.5px 굵게다. `모자란 만큼`(약 66 css)은 칸 안폭을 넘어 `모자란` / `만큼` 두 줄로 접힌다. 단추 높이(44px)에 두 줄이 든다. 낱말 안에서 안 꺾이게 keep-all 을 건다(재 주십시오).

### 씨앗 아닌 품목 (총괄 가름)

- 시루 · 재배판 · 화분 · 가구 · 등은 «모자란 만큼»을 셀 자가 없다. 할 일 «시루 16개까지»에서 셀 수는 있으나 이번 글이 아니다.
- 그 품목의 [전부]를 그대로 둘지, 칸을 숨길지 총괄이 가른다. plan 은 숨김을 권한다(같은 덫이 시루 5,000원 × 수백 개로도 난다).

### 잴 차례

- ㉮ 비판 7판 A Day 13 꼴(거둔 시루가 있고 씨앗 0) · 390: 바닥 🛒 → 창 기본 개수 = need · 개수 줄 ㉮ · 손가락 [주문].
- ㉯ 같은 판에서 [＋] 로 need 를 넘기면 손가락이 [모자란 만큼]으로 가고, 누르면 need 로 돌아온다.

### 참인 조건

- W = 지금 물을 기다리는 작물 줄 수다(needsWater · 바닥 [💧 물 주기]가 물을 줄 줄과 같은 목록). wc = 물 체력(1).
- 회색 = W ≥ 1 ∧ 남은 체력에서 W·wc 를 먼저 뺀 값으로 §sowMixReach 를 셌을 때 m = 0 ∧ one = false 다.
  - 곧 «다음 하나를 심으면 이미 심은 줄의 물 몫을 쓴다»이다.
  - 새 빈 시루(첫 심기 · 체력 0)는 물 몫을 안 쓴다. 그래서 지금처럼 «(1개 · 물은 내일)»이 선다(one = true · 회색 아님).
- «남은 체력은 물 줄 몫»: 체력이 다 1 이라(data/balance/stamina.json `cost`) 위 회색 조건 ⇔ 남은 체력 ≤ W 다. 남은 체력이 다 물 몫이므로 참이다. 체력 값이 바뀌면 다시 잰다.
- «물을 받아야 자랍니다»: needsWater 는 «심고 아직 한 번도 물을 안 받은 판»이다. 물을 받아야 바퀴가 돈다(game.html §updateHint D100 #8 주석). 참이다.
- 회색이 아닐 때 단추 글도 같은 셈을 쓴다. 남은 체력에서 W·wc 를 먼저 빼고 m 을 센다. 그러면 꼬리 «물 줄 체력 N 남김»의 N 은 (W + m)·wc 여야 참이다(이미 심은 줄 몫 + 이번에 심을 줄 몫).

### 후보 · 고른 것 · 까닭

- ㉠ `(남은 체력은 물 줄 몫 — 💧 먼저)` (택함). 까닭: 왜 회색인지(물 몫)와 무엇을 먼저 할지(💧)를 둘 다 말한다. «물 줄 체력»은 지금 꼬리 «물 줄 체력 N 남김»과 같은 낱말이다.

- 폭: 꼬리 11px 굵게 · 한글 한 자 약 10 css(사진 `d24_p3` «(3개 — 물 줄 체력 3 남김)» 120 css 로 맞춤). ㉠ 꼬리는 약 152 css 라 360(181) · 390(198) 안이다.

## §4 7P1 «다음 기회» · 두 문

### 정본에서 «다음 기회»가 세는 것

- §cutWaitTail(10471): 무늬 잎이 «다 자랄» 굴림까지의 날 d 와 한 번 확률 q 다.
  - plant_grow §stepMaturation: 잎이 중간잎(stageMid)에 닿으면 게이지가 하루 `matGaugeStep` 씩 찬다. 차면 그 자리에서 `calcMatureProb` 로 굴린다. 성공하면 다 자란 잎, 실패하면 게이지 0.5(fail_reset)로 돌아가 다시 찬다.
  - q 는 dli7 이 fenestrate(6.0) 밑이면 roll_lo **10%** 이고, 6.0 ~ best_hi(11) 사이에서 10% → 90% 로 오른다(plant_grow §calcMatureProb · growth_tuning `mature`).
  - 게이지는 dli7 ≥ best_lo(5) 면 하루 (1/12)×1.4 ≈ 0.117 이라 실패 뒤 다음 굴림까지 **약 5일**이다. 5 밑이면 하루 0.05 라 **약 10일**이다.
  - 반지하 창턱에 등 하나를 단 판은 dli 6.0 언저리다(비판 7판 범례 «아주 밝음 6.02» · d45 «창턱 밝기 3.7 → 6.0»). 그래서 q 는 거의 10% 이고 굴림은 약 5일마다다.
  - 자르기 문은 다 자란 무늬 잎 **2장**이다. 굴림 하나는 잎 한 장 몫이다.
- 그래서 A Day 70 «약 5일 뒤» → Day 100 «약 3일 뒤» 사이 30일은 굴리는 잎마다 다섯 번 안팎 실패한 셈이다(셈으로 본 것 · 판의 굴림 기록은 안 봄). 글은 «날짜»가 아니라 «한 장의 한 번 기회»를 말한 것이다.
- 비판이 본 것은 [식물] 카드의 짧은 꼬리다(`A_d100_plant` · `chanceShort` « · 다음 기회 약 {d}일 뒤»). 짧은 꼬리에는 «한 번에 q%»가 없어 «3일 뒤 열린다»로 읽혔다. 확대 창(긴 꼬리)은 «한 번에 q%»가 있다.

## §11 7P8 늘리는 할 일 앞 — 알맞은 칸이 모자랄 때 (MINOR #10)

- 늘리는 할 일: siru8 · siru16 `콩나물 시루를 {n}개까지 늘리세요` · radish5 `무순 재배판을 {n}개까지 늘리세요`(quest.js).

- 무엇을 셀지 · 어디에 띄울지(할 일 열린 날 배너 한 번 · 할 일 탭 카드 줄)는 core 와 같이 정한다(총괄 가름). plan 은 글과 참인 조건만 낸다.
  - **[11-02 총괄 가름]** 띄울 자리는 시루 · 재배판을 늘리는 할 일의 카드 몸(할 일 창 · 탭 줄)이다. 새 배너는 안 만든다. 그래서 아래 표의 «제목»은 카드 줄 첫 줄로 읽는다.

| 갈래 | 제목(또는 카드 줄) | 둘째 줄 |
|---|---|---|
| ㉮ 빈칸은 넉넉(f ≥ r) · 알맞은 칸이 모자람(g < r) | `{crop}에 알맞은 빈칸은 {g}칸입니다` (g = 0 이면 `{crop}에 알맞은 빈칸이 없습니다`) | `나머지는 그럭저럭이거나 안 맞는 칸에 섭니다{tail}` |
| ㉯ 빈칸이 모자람(f < r) | `{box}을 놓을 빈칸이 {f}칸뿐입니다` | `그 가운데 {crop}에 알맞은 칸은 {g}칸입니다{tail}` (g = 0 이면 `… 알맞은 칸은 없습니다`) |
| `{tail}` | | ` — 선반 같은 가구를 들이면 칸이 늘어납니다` |

- `{crop}` 콩나물 · 무순 / `{box}` 시루 · 재배판(을 붙임: «시루를» · «재배판을»).
- 참인 조건
  - r = need − 놓인 수(그 작물 · quest done 과 같은 셈 «놓인 것만»). r ≤ 0 이면 줄 없음.
  - f = 그 용기가 들어가는 · 닿는 빈칸 수(자동 자리가 고르는 목록과 같은 거르기).
  - g = f 가운데 그 작물에 «알맞음»인 칸이다(§placeFitLine crop3 과 같은 자 · 같은 dli). 놓기 확인 바 «{word} — {crop}에 알맞음»과 같은 말이다.
  - «나머지는 그럭저럭이거나 안 맞는 칸에 섭니다»: f ≥ r 이고 g < r 이면, 자동 자리가 알맞은 칸을 다 채운 뒤 남은 것은 알맞음 아닌 칸에 선다. 참이다.
  - `{tail}`: 상점 가구 목록(§furnitureCatalogList)에 칸이 있는 가구가 지금 살 수 있게 서 있을 때만 붙인다. 없으면 뺀다. «늘어납니다»는 칸 수이고 «알맞음»을 약속하지 않는다.
- 몬이 «무순이 파래지는 자리는 몇 개 없어»는 그대로 둔다. 이 줄이 그 앞에 수로 말한다(몬이는 수를 안 말함).
- 후보 · 고른 것 · 까닭
  - ㉠ 칸 수로 말하고 가구는 «칸이 늘어납니다»까지만 (택함). 까닭: 셀 수 있는 것만 말한다. 가구가 알맞은 칸을 낼지는 놓기 전엔 모른다.
  - ㉡ «가구를 먼저 들이세요»(할 일로). 버린 까닭: 알맞은 칸을 내는 가구인지 모르는 채로 사라고 한다. 할 일 사슬에 새 줄이 든다(박사님 Q16 할 일 규모와 닿음).
  - ㉢ 몬이 대사를 앞당김. 버린 까닭: 몬이는 수를 말하지 않는다. 몇 칸인지가 이 줄의 뜻이다.
