## 1. 바뀐 것

### 1-1. 확정문 §1 의 표 — 그대로 옮겼다

| | 콩나물 | 무순 |
|---|---|---|
| 수확량 | 400/300/200g (5일) — **안 건드렸다** | ★ **300/200/100g** (7일 · 그램 표 신설) |
| 빛 경계 | `<0.3` / `<1.0` — **안 건드렸다** | ★ **`≥0.35` 최상 · `≥0.15` 중간** |
| 몫당 필요량 | **300g** (`mealPortionGrams`) | ★ **200g** |
| 파는 값 | **7원/g** (`sellWonPerGram`) | ★ **8원/g** |
| 회전분(중간 품질) | 3,000원 — 안 움직였다 | ★ **2,800 → 2,000원** |

⚠ 무순 회전분이 2,800 → 2,000 으로 **내려 보이지만 실제로는 올랐다.** 2,800 은 「질림이 붙기
전의 기본값」이라 곳간에 들던 것은 1,867원이었다. 질림이 걷힌 지금 이 칸이 곧 곳간 값이다.

### 1-2. ★★ 「몫」이라는 셈을 새로 세웠다 (`first_play.js §몫`)

지시서가 *"「몫」이라는 셈이 지금 없다"* 라 지목한 자리다. 새 계통 하나를 지었다.

```
cropMealPlan(fp, {grams?})   → { portions[], savedWon(밥값), usedGrams, usedWon(물건 값) }
consumePlan(fp, plan)        → 짠 대로 곳간을 앞(FIFO)에서부터 덜어 낸다
```

몫을 고르는 규칙 넷:

| | |
|---|---|
| ① | 몫 수 = `cropMealCapWon ÷ mealWon` = **2**. ★ **새 상한을 안 만들었다** — 하루 최대 5,000원은 끼니 상한 그 값이다 |
| ② | 값 = 첫 몫이거나 **앞 몫과 다른 작물**이면 2,500 · 같은 작물이면 **1,200** |
| ③ | ★ **못 채운 몫은 비례**(`round(값 × g / 몫당필요량)`) — 150g 이면 1,250원. **절벽을 안 만들었다** |
| ④ | ★★ **그 g 을 팔면 받을 돈보다 못 벌 몫은 안 먹는다** |

★★★ **④ 가 이 규칙의 핵심이다.** 확정문 §3 이 *"콩나물은 첫 300g만 먹고 나머지는 판다 …
**억지로 시키지 않아도 그게 최선이라 그렇게 된다** … 「한 가지를 600g까지 우겨 먹기」는
손해가 되어 **저절로 사라진다**"* 라고 적었다. ④ 를 안 넣으면 그 말이 안 일어난다 —
엔진이 300g 을 1,200원에 먹어 치우고, 팔았으면 2,100원이었을 것을 버린다.
확정문 §3 의 위끝·아래끝이 그대로 ④ 의 판정식이다:

```
콩나물 첫 몫     2,500/300g = 8.33원/g  >  7원/g  ⇒ 먹는다
콩나물 둘째(같은)  1,200/300g = 4.00원/g  <  7원/g  ⇒ 안 먹고 판다
무순  첫 몫     2,500/200g = 12.50원/g >  8원/g  ⇒ 먹는다
```

⚠ ④ 는 **「팔 수 있다」를 전제로 한다.** 상점에 한 번도 안 들르면 그 g 이 밥도 돈도 안 된다.
⇒ 판단필요 §3-1.

### 1-3. ★ 판매율을 갈랐다 — **작물 표가 갖는다** (지시서 ⚠ 1)

지시서: *"값을 두 곳에 적지 마라 — 작물 표(`CROP_KINDS`)가 갖는 것이 맞아 보인다.
재서 정하고 까닭을 적어라."* **작물 표로 정했다.** 까닭 셋:

| | |
|---|---|
| ㉠ | **그 표가 이미 작물마다 다른 값을 다 갖고 있다** — 주기·씨앗값·품질표·회전분·그램 표. 파는 값만 딴 데 두면 「무순 값을 고치려면 두 파일을 연다」가 된다 |
| ㉡ | **값을 두 곳에 안 적는다.** 전역 칸은 숫자를 안 갖고 `CROP_KINDS[0].sellWonPerGram / 10` 을 **가리킨다** — 이 파일이 `harvestDays`·`seedWonPerSiru`·`quality` 에 이미 쓰는 손버릇 그대로다 |
| ㉢ | **원/g 으로 적는다. 비율(%)이 아니다.** 확정문이 원/g 으로 정했고, 비율로 적으면 「무엇의 몇 %인가」에 물건 값(10원/g)이 다시 끼어들어 세 값이 한 줄에 얽힌다 |

⚠⚠ **`characters.json._meta.cropSurplusSaleRate`(0.85)를 지웠다.** 값만 고치지 않고 칸을
없앤 까닭: `firstPlayRulesFromBalance` 가 그 칸을 **먼저 읽어 작물 표를 통째로 덮어쓴다.**
0.85 를 남겨 두면 「작물을 모르는 꾸러미」가 8.5원/g 에 팔려 콩나물 밥 효율(8.33)보다 비싸지고,
**확정문 §3 의 위끝이 뒤집힌다.** 코드는 그 칸이 없어도 그대로 돈다(`rateFromMeta ?? 폴백`).
자리와 되살릴 방법은 그 파일의 `_cropSurplusSaleRate` 주석에 적어 뒀다.

★ **섞인 판은 꾸러미마다 따로 셈해 더한다** — 총액에 한 비율을 곱하지 않는다.
곱하면 콩나물·무순이 섞인 판에서 줄마다 적힌 값의 합과 총액이 안 맞는다(§그램 ⚠와 같은 규칙).

### 1-4. ★ 질림 vs 둘째 몫 — **질림을 걷었다** (지시서 ⚠ 3)

지시서: *"어느 쪽을 남길지 재서 정하고 까닭을 적어라."*

**둘째 몫을 남기고 질림을 걷었다.** 까닭 둘 — 하나는 확정문이 정했고, 하나는 재서 나왔다:

1. **확정문 §6 이 그렇게 정했다** — *"질림은 위 「둘째 몫」 규칙이 **대신한다.** 두 벌로 두지 마라."*
2. ★ **그리고 질림을 남기면 확정문 §1·§2 가 성립하지 않는다.** 질림은 무순 **수확량 자체**를
   ×2/3 로 깎으므로 무순 최상이 300g 이 아니라 200g 이 된다. 확정문 §2 의 본전선 셈
   (*"무순 300g / 7일 = 42.9 g/일 = 콩나물의 0.71배"*)이 그 자리에서 무너진다.
   ⇒ **재서 확인했다**: 질림을 그대로 두고 §1 표만 붙이면 무순 최상이 **133g** 이 된다.

**뜻이 어디로 갔나** — 「같은 것만 먹으면 물린다」는 **밭에서 밥상으로** 옮겼다.
㉠ 질림은 「무순을 두 번째로 들였으니 무가 덜 자란다」인데 현실로 읽으면 말이 안 된다.
㉡ 둘째 몫은 「같은 것만 두 끼 먹으면 덜 든든하다」라 그 자리가 맞다.

**⚠ 파장 — 재서 적는다** (지시서가 물은 그것):

| | 옛 | 새 |
|---|---|---|
| 무순 최상 한 회전 | 1,867원(187g) | **3,000원(300g)** |
| 무순 중간 한 회전 | 1,244원 | **2,000원(200g)** |
| `cropKindSavedWon` | [3,000 · 1,867 · 933] | **[3,000 · 2,000 · 2,000]** |
| 무순 손익분기 | 32.1% | **20.0%** |
| 하루 몫 합(`cropSavedWonPerCycle`) | 4,867원 | **5,000원** |

★ **표는 안 지웠다.** `CROP_TIRED_MULTIPLIER` 는 그대로 있고 `cropOverlapTiredEnabled`(겹침 벌을
되살리는 문 · 2026-08-17 아침)가 아직 읽는다. 지우면 「옛 셈과 나란히 재기」가 없어진다.
⇒ 지금 그 표를 읽는 곳은 **그 문 하나뿐**이고, 게임은 어디에서도 안 읽는다.

### 1-5. ⚠ 옛 이름 둘의 **뜻이 바뀌었다** (지시서 ⚠ 4 · 「10원=1g 은 물건 값」)

| 이름 | 옛 뜻 | 새 뜻 |

**지갑에서 뺄 값**으로 읽는다. 그 자리에 물건 값을 넣으면 살림이 조용히 틀어진다.
그래서 **밥값 쪽이 옛 이름을 가져가고 물건 값이 새 이름을 받았다.**

★ **하루 최대 5,000원은 새 상한이 아니다** — `cropMealCapWon` 그대로다(지시서 ⚠).
몫 수도 그 값에서 나눠 낸다(`floor(cropMealCapWon / mealWon)` = 2). 상한을 두 벌로 안 뒀다.

```js
     `useWon` 은 이제 **곳간에서 빠지는 물건 값**(g × 10원)이고, 아끼는 밥값은 `savedWon` 이다.
     둘이 갈린 까닭 — 확정문이 밥을 「몫」으로 정했다: 콩나물 한 몫은 **300g 에 2,500원**이라
     곳간은 3,000원이 빠지는데 밥값은 2,500원만 준다.
     ⚠ 옛 줄을 그대로 두면 화면이 **자기 모순**을 말한다(7,500 − 3,000 = 4,500 인데 5,000).
     ★ 숫자를 여기 손으로 적지 않는다 — 몫 값도 몫 수도 전부 `ms` 에서 읽는다. */
  if (ms.savedWon <= 0) {
    /* ★ 0g 은 고를 수 있어야 한다(모아서 파는 길). 다만 **밥값이 그대로 나간다**는 것을
       그 자리에서 말한다 — 안 말하면 「아꼈다」로 오해한다. */
    say.textContent = `오늘은 곳간을 안 씁니다 — 식비 ${ms.dailyFoodWon.toLocaleString()}원이 ` +
                      `그대로 나갑니다. ${formatGram(ms.restGrams)}이 곳간에 그대로 쌓입니다.`;
    say.className = 'pquote warn';
  } else {
    /* ★★ **몫 내역을 먼저 말한다.** 「왜 400g 을 다 안 먹나」가 여기서만 설명된다 —
       한 몫은 콩나물 300g · 무순 200g 이고, 같은 것으로 둘째 몫을 채우면 값이 절반 밑이라
       팔아 버리는 편이 낫다(확정문 §3). 그 사실을 화면이 말하지 않으면 「덜 먹는다」로 읽힌다. */
    const parts = (ms.portions || []).map(p =>
      `${p.kindKo} ${formatGram(p.grams)}` +
      (p.fill < 0.999 ? ` (몫의 ${Math.round(p.fill * 100)}%)` : '') +
      ` → ${p.won.toLocaleString()}원` + (p.same ? ' (같은 것이라 덜 칩니다)' : ''));
    say.textContent =
      (parts.length ? parts.join(' + ') + ' = ' : '') +
      `식비 ${ms.savedWon.toLocaleString()}원을 아낍니다 ` +
      `(오늘 지갑에서 ${ms.cashFoodWon.toLocaleString()}원)` +
      (ms.restGrams > 0
        ? ` · 남는 ${formatGram(ms.restGrams)}은 곳간에 그대로 쌓입니다 (팔 수 있습니다)`
        : '') +
      (ms.savedWon < ms.capWon
        ? ` · 하루에 ${ms.capWon.toLocaleString()}원까지 아낄 수 있는데 곳간이 그만큼 없습니다`
        : '');
    say.className = 'pquote';
  }
```

⚠ **머리글 한 줄도 같이 고쳐야 한다** (같은 함수 위쪽):

```js
  /* ⚠ 2026-08-17 — `capGrams` 는 이제 **「오늘 최선껏 먹으면 쓰는 g」**이다(몫 규칙이 정한다).
     「하루에 300g까지」라는 고정된 수가 아니다 — 콩나물만 있으면 300g, 무순까지 있으면 500g 이다. */
  $('mealTitle').textContent =
```

### 4-2. ⚠ 살림 표(`#ledger`)의 「한 번 거두면」이 **콩나물만 말한다**

`drawLedger` 의 `const cycleWon = R.cropKindSavedWon[0]` 은 콩나물 회전분이다. 무순 재배판을
세운 판에서도 콩나물 값만 적는다. **거짓은 아니지만 반쪽**이다.
⇒ 무순이 섰으면 두 줄로 적는 것이 맞다. ☐ 화면 판단이라 코드를 안 적었다.

### 4-3. 상점의 무순 설명 주석이 낡았다

`game.html §drawShop`(3781줄 언저리)의 주석이 *"무순의 값어치는 **하루 저감 상한을 올리는
것**이다 … 지금은 콩나물 3,000 + 무순 1,867 = 4,867원이다"* 라 적고 있다. 붙일 문장:

```js
       ⚠⚠ 2026-08-17 밤 — **또 바뀌었다.** 밥이 「몫」이 됐다(first_play §몫 · 확정문 §1).
         무순의 값어치는 이제 **「둘째 몫을 다른 작물로 채우는 것」**이다 —
         콩나물만으로는 하루 한 몫(2,500원)이 천장이고, 무순을 들이면 5,000원까지 열린다.
         (실측: 시루 9개만이면 200일 밥값 487,500원 · 재배판 4개를 더하면 868,750원)
       ★ 숫자를 다시 적지 마라 — `mealPlanStatus(S).capWon` 으로 **읽어라.**
```

### 4-4. 무순으로 한 판을 화면에서 안 밟았다

무순은 **코어·프로브로만** 확인했다(`test_econ §E·§G` · `probe_crop_balance` §①).
화면으로는 콩나물 판만 밟았다 — 무순 문이 몬스테라 도착 뒤에 열려서 판이 길다.
`overlap-to-plan §4-4` 가 올린 그 자리가 그대로 남아 있다.

### 4-5. 조도 엔진으로 14칸 DLI 를 안 뽑았다

§3-6. 확정문 §4 의 사이 값이 지어낸 값인 채로 남아 있다.
