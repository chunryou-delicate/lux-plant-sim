## 0. 제일 먼저 — **파일이 아니라 「책임」으로 가른다**

[core] 창의 제안을 채택했다. 원문:

> *"파일로 가르기보다 **「판정·계약」과 「화면·연출」로 가르고, 화면은 `turn.*` 이 준 값만 그리고
> 판정 숫자를 다시 만들지 않는다**를 경계로 두는 편이 이 저장소가 앓아 온 병에 맞아 보입니다."*

**왜 이것이 맞나** — 이 저장소가 반복해서 앓은 병이 정확히 그 경계에서 났다:

| 사고 | 무엇이었나 |
|---|---|
| 선물 몬스테라(08-21) | **코어는 맞았는데 화면이 안 따라와** 선물이 화면 어디에도 없었다 |
| 상판 칸 두 개씩 실종(08-18) | 링 쪽 결정과 칸 쪽 결정이 어긋나 **아무도 안 그리는 칸**이 생겼다 |
| 하루 몫 4,867원(§2.8) | 같은 값을 두 곳에서 세다가 한쪽만 낡았다 |
| 바닥 격자 반 칸(08-18) | 그리는 눈금과 앉는 눈금이 갈렸다 |

⇒ **경계 규칙 하나**:

> **화면은 `turn.*` 이 준 값을 그린다. 판정 숫자를 화면이 다시 만들지 않는다.**
> 다시 만들면 반드시 두 벌이 되고, 두 벌은 반드시 어긋난다(START-HERE §2.8).

## 3. ★ 싱크 — **일을 시작하기 전에 반드시**

박사님 지시: *"싹 다 싱크로시키고 그때부터 일 시작한다."*

### 3-1 창이 할 것 (다섯 걸음 · 10분 안에 끝난다)

```
1  git pull                                  ← 남이 민 것을 받는다
2  git log --oneline -20                     ← 내가 자리를 비운 사이 무슨 일이 있었나
3  git status --short                        ← 내 미커밋이 있나 (남의 것은 손대지 않는다)
4  docs/handoff/START-HERE.md 맨 위 5개 절    ← 계율과 최근 결정
   docs/handoff/team-map.md (이 문서)         ← 내 영역
5  내 소관 인계 문서 docs/handoff/{내창}-to-plan.md
```

**그 다음 총괄에게 한 줄로 보고한다:**
```
[싱크 완료] <창이름> · 마지막 앎 <날짜> → 지금 <HEAD 해시>
  내가 모르던 것 중 내 영역에 닿는 것: <목록 또는 "없음">
  내 미커밋: <목록 또는 0건>
```

### 3-2 ⚠ 싱크에서 반드시 걸러야 하는 것

| 증상 | 뜻 | 조치 |
|---|---|---|
| 「완료」라 했는데 저장소에 없다 | **미커밋으로 날아갔다** | 다시 해야 한다 |
| 「아직 남았다」인데 저장소에 이미 있다 | **다른 창이 했다** | 중복 착수 금지 |
| 문서와 코드가 다르다 | 한쪽만 갱신됨 | **코드가 사실.** 문서를 고친다 |
| 내 자(도구)가 이상한 값을 낸다 | **자가 낡았다** | 코드보다 자를 먼저 의심(§2.9) |

★ **오늘 실제로 넷 다 나왔다.** [growth] 는 「남았다」던 둘이 이미 처리돼 있었고,
[core] 는 자기 재현 도구가 낡아 「계약이 무너졌다」로 보였다.

## 4. 보고 체계 — **언제 · 무엇을 · 어떻게**

### 4-1 창 → 총괄

| 언제 | 무엇을 |
|---|---|
| **싱크 끝난 즉시** | §3-1 의 한 줄 |
| **결론이 날 때마다** | 문서 완성을 기다리지 않는다. **짧게** |
| **막히면 즉시** | 「막혔다」 한 줄이라도. 조용히 멈춰 있는 것이 제일 나쁘다 |
| **오래 걸릴 것 같으면 먼저** | 「얼마나 걸린다」 |
| **값이 어긋났을 때** | **고치지 말고 보고 먼저.** 확정 수치는 사용자 판단이다 |

**형식** — 근거 등급을 반드시 붙인다.

```
[실측] 직접 돌려서 재었다        ← 제일 세다
[문서] 원문을 직접 읽었다
[추론] 계산·유추. 확인 안 했다   ← 이 표시 없이 숫자를 주지 않는다
모름   모르면 "모른다"고 쓴다
```

⚠ **자기 창에 적은 것은 아무에게도 안 간다.** 반드시 `SendMessage`.

### 4-2 총괄 → 사용자

- **결론 먼저**, 근거는 그 다음
- 안건마다 **[창이름]** 표기
- 말미에 **표** — 대기목록·창 현황. 각 줄에 한 줄 설명을 붙여 **되묻지 않고 판단**할 수 있게
- 사용자는 비전공자다. **전문용어를 풀어 쓰고 비유를 쓴다**
- **세션 보고를 그대로 옮기지 않는다.** 중요한 것은 총괄이 파일로 검증한 뒤 올린다

### 4-3 승인 경계

| 누가 정하나 | 무엇 |
|---|---|
| **창이 스스로** | 자기 영역 안 · 되돌리기 쉬움 · 값이 안 움직임 |
| **총괄이 승인** | 영역이 걸치는 것 · 주인 없는 칸 · 읽기 전용 측정 · 문서 정정 |
| **사용자만** | **게임 값이 움직이는 것** · 비용(Meshy·Higgsfield·KLING) · 외부 발송 · 되돌리기 어려운 것 |

★ **총괄의 말은 사용자 승인을 대신하지 못한다.** 창에 사용자가 직접 내린 금지 지시가 있으면
  총괄이 「승인받았다」고 해도 **거부하고 되묻는 것이 맞다.**
★ 총괄이 승인을 전할 때는 **사용자 원문을 그대로 인용**한다. 요약만으로는 상대가 검증할 수 없다.

## 7. 오늘 배운 것 — 규칙의 근거

싱크 하루 만에 창들이 **스스로** 잡은 것들. 전부 *"맞다고 믿었는데 실제로는 달랐다"* 다.

- **[growth]** — 옛 축과 새 축을 견주려 설정에서 표를 지웠는데 **코드 안에 같은 표가
  기본값으로 또 있어** 세상이 안 바뀌었다. 같은 것을 두 번 재 놓고 *"둘이 같다"* 고 쓸 뻔했다.
  **두 출력이 한 글자도 안 달랐던 것**이 유일한 단서였다.
  ⇒ ★ **폴백이 있는 값은 「입력을 지우는 것」으로 못 끈다.**
    그리고 **두 조건의 출력이 완전히 같으면 「조건이 안 걸렸다」를 먼저 의심하라.**
- **[core]** — 헤드리스 재현 도구가 `<script>` 를 정규식으로 잡는데 인라인 스크립트가
  하나 늘면서 두 블록을 붙여 잡아 **"계약이 무너졌다"처럼 보였다.** 제품은 멀쩡했고 자가 낡았다.
- **[Asset]** — 총괄이 커밋해 놓고 **밀지 않은 것**을 잡아 줬다. 그리고 총괄 문서의
  **낡은 숫자**(도착 대사 2줄 → 실제 10줄)를 짚었다.
- **[Plan]** — 총괄 문서가 자기를 **offline 이라 적어 둔 것**을 짚었다. 문서가 틀렸다.
- **[Char]** — 「표정이 모자라다」던 총괄 판단을 뒤집었다. **그림은 이미 있고 매핑만 없었다.**

⇒ **총괄도 틀린다.** 그래서 창이 근거를 대고 반대하는 것이 규칙이다.

[Plan] · [core] · [House] · [growth] 넷이 답했고, **아래는 그 의견으로 고친 것**이다.
★ 넷 다 근거를 파일로 대고 답했고, **셋이 총괄 판단을 뒤집었다.** 그것이 이 체계가 도는 증거다.

### 8-1 ★ 세션 간 직통이 열렸다 (사용자 지시)

> **"필요시 세션끼리도 소통하라고 해. 대신 너한테 시작승인 및 결과보고 하면서."**

```
필요하면 다른 창과 직접 이야기해도 된다. 단 두 가지를 지킨다.
  ① 시작 전에 총괄에게 「누구와 무엇을 이야기하겠다」고 알리고 승인을 받는다
  ② 끝나면 총괄에게 결과를 보고한다
```
⇒ 총괄이 병목이 되는 것을 막되, **총괄이 그림을 놓치지 않게** 한다.
⚠ 승인·결과 보고를 건너뛰면 총괄이 사용자께 **잘못된 그림**을 올리게 된다. 그것이 이 규칙의 전부다.
⚠ **권한 세탁 금지는 그대로다.** 한 창에서 막힌 일을 다른 창에 시키지 않는다.

### 8-3 ★★ 새 규칙 — **복제된 값에는 짝을 지키는 검사가 있어야 한다**

### 8-4 ★★ 층 경계를 **검사 한 줄로** 지킨다 ([core] 가 재 왔다)

### 8-6 ★★★ **[QA] — 창이 아니라 「자리」다** (네 창이 다 찬성 · 셋이 같은 단서)

**왜 필요한가** [실측]:
- 순수 모듈 검사 51개 중 **14개 FAIL**([Plan] 실측). 표본 둘을 끝까지 팠는데 **둘 다 코드가 맞고 자가 낡았다**
- `acceptance.json`(7.4KB) — 합격 기준이 적혀 있는데 **읽는 코드가 0건.** 이름은 주석에만 나온다
- `tools/` 에 `test_*` 36개 + `probe_*` 20여 개인데 **일괄 러너도, 「어느 것이 유효한가」를 아는 사람도 없다**
- **오늘만 자가 낡아 거짓말한 것이 셋** — [growth] 의 `LEAF_DAYS`, [core] 의 정규식, `test_elec`

⇒ ★ **이 저장소의 병은 코드가 틀리는 것이 아니라 자가 낡는 것이다.**
  오늘 낡은 것을 넷 찾았는데 **넷 다 재는 자**였고, 그중 둘은
  **「재는 자가 거짓말한다」를 가르치려고 쓴 절**이었다([Plan] 관찰).

**★ 셋이 독립적으로 같은 단서를 붙였다 — 그것이 이 자리의 모양을 정한다:**

| 창 | 단서 |
|---|---|
| [Plan] | *"QA 는 심판이지 선수가 아니다. 지금은 심판이 없어서 **선수끼리 서로의 자를 들고 있다**"* |
| [House] | *"검사를 고칠 권한을 주면 **「통과시키려고 검사를 고치는」 길**이 열린다"* |
| [growth] | *"QA 는 `tools/` 만 쓴다. **제품 코드는 안 고친다**"* |

**⇒ 확정 — QA 는 「가르는 자리」다:**
```
① QA 는 돌리고 · 갈라서 · 보고한다. 제품 코드는 한 줄도 안 고친다
② 빨간 검사는 세 갈래로 가른다
     ㉠ 자가 낡음      → 그 자를 만든 창
     ㉡ 진짜 회귀      → 그 계통 소유 창
     ㉢ 자가 못 갖춤   → 하네스(조도 창·픽스처 없음 등)
③ ★ 「검사가 틀렸다」는 판정을 QA 혼자 하지 않는다. 소유 창과 맞댄다
   — 안 그러면 통과시키려고 자를 고치게 된다
④ QA 는 층이 아니다. ①②③ 을 **가로지르는 줄**이고 총괄 옆에 선다
⑤ acceptance.json 이 이 자리의 정본이다. 값은 [Plan] · 재는 것은 QA · 고치는 것은 소유 창
```

**첫 일감 셋** (세 창 제안이 겹치는 것):

2. **`acceptance.json` 을 실제로 읽는 검사 하나** — 빛 두 줄은 `sim.fenestrationContrast()` 가 이미 낸다
3. **`tools/` 떠돌이 20건을 `_` 규칙으로 정리**

### 8-7 ⚠ **검사가 못박는 것은 「숫자」가 아니라 「규칙」이어야 한다** ([growth] 제안)

`test_growth_speed E` 와 `test_maturation G` 가 **`117 → 3걸음 → 120` 을 숫자로 박아** 뒀다.

그 주석에 *"143·146 이 117·120 으로 움직였다"* 고 적힌 것이 **이미 한 번 손으로 고친 자국**이다.

★ **옆 칸에 모범이 있다** — 같은 파일 `E2` 는 `TUNING.leaf_interval.days` 를 읽어 누적을 만든다.
  표를 고치면 **검사가 저절로 따라간다.**

⇒ E·G 도 그렇게 바꾸면 검사가 못박는 것이 **규칙**이 된다:
> *"새순 나기 `SPEAR_READY_DAYS` 걸음 전부터 `spear_ready` 이고, 마지막 걸음에 `spear_furled 0.000` 이 된다"*

표가 바뀌어도 안 낡고, **기계가 깨지면 그때는 진짜로 빨개진다.**
