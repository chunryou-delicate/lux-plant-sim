## 1. ★ 먼저 — 가구 옮기기가 아예 안 되고 있었다

박사님 말씀은 "PC 에선"이었지만, 재 보니 **폰에서도 안 됐다.** 원인이 둘이었고 이게 큰 쪽이다.

`furnPicked.beginMove()` 첫 줄이 이랬다(2026-08-06 등 옮히기가 들어오면서).

```
const why = roomView.lampImmovableReason(this.uid);
if (why) { 이유를 적고 되돌아 나간다 }
```

그런데 `lampImmovableReason` 은 **등이 아닌 uid 에도 이유를 돌려준다** —
`room_view.js` 3607줄이 `모르는 등입니다: ${uid}` 를 낸다.
가구 탭으로 고를 수 있는 것은 `pickFurnitureAt` → `furnNodes()` 뿐이고 거기엔 집게등이 없다.
⇒ **[옮기기]를 누르면 침대·책상·서랍장 전부가 "모르는 등입니다: banjiha-bed (방 banjiha)" 로 막혔다.**

헤드리스 크롬으로 게임을 실제로 띄워 재서 확인했다. 고친 뒤 같은 침대가 옮겨진다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| [옮기기] 안내 | `모르는 등입니다: banjiha-bed (방 banjiha)` | `가구를 잡고 끌어 놓으세요` |
| 잡이판(`#moveCatcher`) | `display:none` — 아예 안 뜬다 | `display:block` |
| 끌고 놓은 결과 | 안 움직인다 | `x −1.55 → −1.20` · `z −0.50 → −0.125` |

고친 방식: **먼저 가구인가**를 묻고(`roomView.furniture()` 에 그 uid 가 있나),
가구가 아닐 때만 등의 길로 간다. 바닥에 선 스탠드등은 `furniture()` 에 들어 있으므로
예전대로 가구 길로 간다(`lampmove-to-plan` §0 이 그렇게 정해 두었다).
바 등·천장등은 여전히 등의 길에서 **왜 못 옮기는지** 이유가 나온다.

## 2. PC 에서 옮기기가 어색하던 이유 — 짐작이 아니라 코드가 말한다

`#moveCatcher` 는 [옮기기]를 누르면 화면을 덮는 투명 판이다. 폰에서 손가락이 가구를 가리니
"화면 아무 데나 잡고 끌면 그만큼 움직인다"로 만들어 둔 것이고, 그 발상 자체는 맞다.

문제는 그 판에 **눌림 판정이 없었다**는 것이다.

```
c.addEventListener('pointermove', e => who().move(e));   // ← 예전
```

손가락은 닿아야만 `pointermove` 가 온다. 그래서 폰에서는 티가 안 났다.
**마우스는 스치기만 해도 온다.** 그래서 PC 에서는

1. [옮기기]를 누른다
2. 마우스를 아직 안 눌렀는데 유령이 커서를 따라다닌다
3. 놓을 자리에서 누른다 → `down` 이 `x0·y0` 를 그 자리로 잡고 `dragTo(0,0)` 을 돈다
   → **유령이 원점(고를 때 눌렀던 자리)으로 되돌아간다**
4. 손을 뗀다 → 원점에 그대로 놓인다. 끌던 게 통째로 사라진다

"뭔가 잘 안 되네"의 정체가 이것이다. 4번에서 조용히 제자리에 놓이니 고장으로도 안 읽힌다.

## 3. 무엇을 어떻게 고쳤나

### ① 눌린 동안만 움직인다 (`held`)

`game.html` `bindPicked()`. 마우스·터치 구분 없이 같은 규칙이다 —
터치는 원래 눌린 동안만 `pointermove` 가 오므로 **폰 동작은 한 톨도 안 달라진다.**

⚠ 창이 흐려지면(`blur`·`visibilitychange`) `held` 를 같이 푼다. 창 밖에서 손을 떼면
`pointerup` 이 안 오는데, 그때 켜진 채로 남으면 **다음 옮기기에서 이 버그가 되살아난다.**
놓지는 않는다 — 어디에 놓을지 모르는 채로 놓는 것이 더 나쁘다(다른 창이 같은 판단으로
`cancelAnyDrag` 를 넣어 두었다. 그쪽은 `mode` 를, 이쪽은 `held` 를 푼다).

### ② 마우스면 가구 위에서만 잡힌다 (`grabbable`)

포인터 종류로 가른다.

| | 무엇으로 재나 | 어떻게 잡나 |
|---|---|---|
| 마우스 | `e.pointerType === 'mouse'` | 커서가 **그 가구 위**일 때만 잡힌다 |
| 손가락 | 그 밖 전부 | **화면 아무 데나** — 예전 그대로 |

버튼([옮기기])을 누른 뒤처럼 손댄 자국이 없는 자리에서는 **직전에 방을 만진 것**(`lastPointerType`)으로 본다.
`matchMedia('(pointer:fine)')` 만 보면 터치 노트북에서 늘 마우스로 읽힌다 — 그건 화면의 *능력*이지
*지금 무엇으로 만지고 있나*가 아니다. 실제로 폰 크기로 재 보니 안내 문구가 마우스 쪽으로 나왔고,
이 한 줄로 바로잡았다.

가구 위인지는 화면 거리가 아니라 **3D 히트테스트**로 본다 — 이미 있는
`roomView.pickFurnitureAt(x, y)` 를 그대로 쓴다(탭으로 가구를 고를 때 쓰는 그 함수다).
돌려준 `uid` 가 지금 고른 가구와 같아야 잡힌다.

잡을 수 있는 동안 커서가 `grab`, 끄는 동안 `grabbing` 이다. 히트테스트는 광선이라
안 눌린 동안에는 **60ms 마다 한 번만** 돌린다(눈에는 즉시고 매 픽셀 쏘지 않는다).

`#moveCatcher` 는 **그대로 둔다.** 마우스에서도 카메라 회전을 막아야 하고,
히트테스트는 캔버스 좌표로 직접 쏘므로(`ndcOf`) 판이 덮여 있어도 아무 상관이 없다.

**가르지 않은 것 두 가지 — 이유가 있다.**

- **돌리기·겨누기**는 잡는 자리가 없는 조작이다(좌우로 끄는 것뿐). 예전대로 아무 데나 잡는다
- **등 옮기기(`lampmove`)** 도 뺐다. 등은 상판에 *얹힌* 것이라 `pickFurnitureAt` 이 애초에
  못 집는다(`furnNodes()` 에 없다). 여기서 막으면 등을 **영영 못 옮긴다**
- **화분(`picked`)** 도 예전대로 아무 데나다. 화분은 슬롯이 작아 "멀리서 잡아도 된다"가
  애초에 이 조작의 설계였다. 다만 ① 눌림 판정은 화분에도 그대로 먹으므로 PC 에서 화분이
  제자리로 되돌아가던 것도 같이 낫는다

## 4. 격자 걸음 — 실제 수치

값을 새로 짓지 않았다. **이 저장소가 이미 쓰는 격자**(`src/game/place.js` 머리말 ·
`docs/handoff/roomview-grid.md`)를 나눠 쓴다.

| 이름 | 값[m] | 무엇인가 |
|---|---|---|
| `place.GRID_UNIT` | **0.05** | 크기를 세는 최소 칸. 안 건드렸다 |
| `place.GRID_CELL` | **0.25** | 바닥에 실제로 그리는 칸. 플레이어 눈에 보이는 그 줄 |
| `room_view.SNAP_DIV` | **2** | 그 칸을 몇으로 나눌지. 유일한 손잡이 |
| `room_view.MOVE_STEP` | **0.125** | = `GRID_CELL / SNAP_DIV`. **옮길 때의 한 걸음** |

- `SNAP_DIV = 1` → 한 칸 **0.25m**
- `SNAP_DIV = 2` → 반 칸 **0.125m** ← 기본

### 어디에 먹나

| 무엇 | 걸음이 먹나 | 어느 길로 |
|---|---|---|
| 가구 옮기기 · 돌리기 | ○ | `previewFurnitureAt`/`commitFurnitureAt` → `snapFurniture(pos.step)` |
| 화분 옮기기 | ○ | `surfaceAt(px, py, { step })` |
| 가방에서 새로 놓기(`drag`) | ✕ | 예전 0.05 그대로 — 지시는 "**이동**"이었다 |
| 등 옮기기(`lampmove`) | ✕ | 등은 상판 자리(슬롯)에 물린다. 좌표가 아니라 자리가 정본이다 |

### 안 깨뜨린 것

- **슬롯이 격자를 이긴다.** `surfaceAt` 은 자리(slotId)가 지배하는 점이면 격자보다 먼저
  자리 중심으로 보낸다. 그 갈래가 걸음보다 위에 있으므로 창턱·선반 자리는 그대로다
  (`test_roomview_place` Z-6 이 못 박고 있고, 지금도 통과한다)
- **벽 안쪽 범위는 스냅 뒤에 다시 본다.** `previewFurnitureAt` 은 앉힌 좌표로
  `furnitureFit` 을 부르고, 거기 벽 판정은 실수 좌표(`rectCorners`)라 걸음과 무관하게 정확하다.
  화분도 같다 — `surfaceAt` 의 `inRoom`·`nav.blocked` 는 전부 앉힌 뒤에 돈다
- **예전 길은 값이 한 자리도 안 변한다.** 걸음을 안 주면 `snapSpanStep` 은
  `place.snapSpan` 과 **같은 값**을 낸다(`test_snap` A-1·A-2). 그래서 기존 검사가 다 그대로다

### 두 번 앉히지 않는다

가구를 끌 때 바닥 점을 `surfaceAt` 이 0.05 로 앉히고 `snapFurniture` 가 다시 0.125 로 앉히면,
두 번째가 첫 번째의 반올림 위에 얹혀 **걸음이 반 칸씩 밀린다.**
그래서 가구 길은 `surfaceAt(..., { grid: false })` 로 날 좌표를 받고,
앉히는 곳은 `snapFurniture` **한 곳뿐**이다.

### ⚠ 반 칸(0.125m)의 대가 — 알고 쓴다

`0.125` 는 `0.05` 의 배수가 아니다. `place.cellBox` 는 좌표를 0.05 칸으로 **반올림**해
겹침을 정수로 보므로, 반 칸에 선 물건은 **겹침 판정이 최대 0.025m 어긋난다.**

- 벽 밖 판정은 영향 없다(실수 좌표로 본다)
- 칸 정수를 한 치도 안 틀리게 하려면 **`SNAP_DIV = 1`** 로 두면 된다. 0.25 는 0.05 의 배수다
- `tools/test_snap.mjs` D-3·D-4 가 이 둘을 각각 못 박아 둔다 — 나중에 누가 봐도 사고가 아니라
  고른 것임을 알 수 있게

## 6. plan 창이 알아야 할 것

- **걸음을 바꾸고 싶으면 `src/game/room_view.js` 의 `SNAP_DIV` 하나만 고치면 된다.**
  게임 쪽은 `roomView.moveStep()` 으로 물어보므로 `game.html` 은 안 건드려도 된다
- 가방에서 새로 놓을 때는 아직 0.05 다. "놓을 때도 같은 걸음"으로 하려면
  `game.html` `drag.move` 의 `freePlace.surfaceAt(...)` 에 `{ step: moveStep() }` 만 더하면 된다
- 마우스/터치를 가르는 판정은 `game.html` 의 `isMousePointer(e)` 하나다.
  펜(`pointerType === 'pen'`)은 지금 **손가락 쪽**으로 떨어진다 — 태블릿 펜을 지원할 일이 생기면
  거기 한 줄이다
- ★ **`lampImmovableReason` 은 등이 아닌 uid 에도 문장을 돌려준다.** 지금은 게임 쪽에서
  "가구가 아닐 때만 묻는" 것으로 막아 뒀지만, 등 창이 그 함수를 손볼 일이 있으면
  `null`(모르는 uid) 과 `이유`(아는 등인데 못 옮김)를 갈라 주는 편이 낫다.
  §1 은 화면 한 곳에서 막았을 뿐 함수 자체는 그대로다
- 가구 옮기기에는 아직 **자동 검사가 없다.** `test_roomview_place` 는 방 뷰 API 만 본다.
  §1 을 다시 겪지 않으려면 `game.html` 의 [옮기기]까지 밟는 검사가 하나 필요하다 —
  이 창이 쓴 임시 계측이 그 뼈대다(커밋하지는 않았다)
