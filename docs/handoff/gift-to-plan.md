## 0. 한 줄

**코어는 2026-08-17 에 이미 「선물은 가방으로」로 고쳐져 있었다. 화면이 안 따라왔다.**
그래서 선물이 **화면 어디에도 없었다** — 지적보다 나쁜 상태였다.

## 1. ① 가방으로 온다 · 놓아야 식물탭에 선다

### 1-1 먼저 잰 것 — **선물이 어디에도 없었다**

`tools/probe_giftflow.mjs` 로 2바퀴까지 실제로 굴려서 잰 값(고치기 전):

```
도착한 순간   그루  { slotId: null, at: null, placedOnce: false }   ← 상태는 「가방에 있다」가 맞다
              가방칸 ["콩나물"]                                     ← 몬스테라 칸이 **없다**
              몬스테라 카드  [식물]탭 안 · display:none             ← 있는데 **안 보인다**
```

- 코어(`loop.js`)는 2026-08-17 에 `slotId: null` 로 만들어 「아직 아무 데도 안 놓은」 상태로
  보내게 고쳤다. **상태는 그때부터 맞았다.**
- 그런데 **가방에 그 칸을 그리는 자리를 아무도 안 만들었다.**
- `#plantCard` 는 `arrived && S.pots.length === 0` 일 때만 뜬다. 선물이 오면서
  `S.pots.length` 가 1이 되어 **그 자리에서 숨었다.**
- 남은 것은 [식물] 탭의 **몬스테라 목록 줄 하나**뿐 — 그것이 박사님이 보신 것이다.

⇒ **두 결정이 어긋난 그 병이다.** 코어를 고칠 때 화면의 카드 자리를 같이 안 옮겼다.
  주석도 낡아 있었다 — `drawBag` 이 *"몬스테라는 늘 방에 온다(가방을 거치지 않는다)"* 라고
  적어 두고 있었다.

### 1-2 고친 것

| 어디 | 무엇 |
|---|---|
| `game.html §bagPots` | **「가방에 있는 그루」의 정본을 하나로.** `placedOnce === false && !at && !slotId` |
| `game.html §drawBag` | 그 그루마다 **가방 칸**을 세운다(식물등이 쓰는 그 자리). 칸이 **그루 이름을 들고 있다**(`data-potbag`) |
| `game.html §drawPlantMore` | [식물] 목록이 **가방 것을 뺀다.** 판정은 `bagPots()` **같은 자** |
| `game.html §startPhonePlacePotBag` | **눌러서** 놓는 길(끌기와 같은 일) |

★ **셋이 한 함수를 부른다.** 각자 판정하면 「가방에도 있고 목록에도 있는」 판이 난다.

**실측(고친 뒤)**

| | 놓기 전 | 놓은 뒤 |
|---|---|---|
| 가방 칸 | **`["몬스테라","콩나물"]`** | `["콩나물"]` |
| [식물] 목록 | **`{보이나:false, 줄수:0}`** | **`{보이나:true, 줄수:1}`** |
| 그루 | `slotId:null · placedOnce:false` | `banjiha-sill:0 · placedOnce:true` |

### 1-3 ★ 끌기가 **어느 그루인지**를 나른다 (덤으로 풀린 것)

가방 칸은 그루마다 서므로 「어느 그루를 끄는가」를 나르지 않으면 `commitPlace` 가
`pot0(S)`(첫 그루)로 떨어져 **남의 화분이 놓인다.**

⇒ `bindDrag(el, what, onTap, potId)` → `drag.begin(..., potId)` → `drag.end` → `commitPlace(what, hit, {potId})`
  까지 **끝까지** 나르게 했다. `bindDrag` 는 이제 **요소도 받는다**(가방 칸은 id 가 없다 — 그루마다 생긴다).

★ 이것이 `gridmove-to-plan §5-2` 가 *"둘째 그루에 끌기를 붙이는 날 이 줄이 그대로면
  그 순간 「집은 것 ≠ 붙든 것」이 된다"* 라고 적어 둔 그 자리다 —
  **「모르는 것이면 몬스테라」의 마지막 한 마리**를 여기서 잡았다.

### 1-4 ⚠ 재다가 잡은 것 — **칸이 혼자 네 배로 컸다**

붙이고 나서 사진을 보니 몬스테라 칸만 유난히 컸다. 눈으로는 그날 떠 있던
「첫 달 가계부」 모달과 상세 카드에 가려 **안 갈렸다.** 재서 잡았다:

```
내 칸 98×290   ·   다른 칸 98×76
```

까닭은 껍질이다. 칸 모양의 정본(`§bagSlotHTML`)은 `<span class="art"><img></span><span class="nm">` 인데
나는 맨 `<img>` + `<small>` 로 썼다 — `.bagslot .art img{width:100%;height:100%}` 가 안 걸려
그림이 **원본 크기**로 섰다. 껍질을 맞추니 **셋 다 98×76** 이 됐다.

⇒ ★ **모양을 새로 짓지 말고 있는 껍질을 쓴다.** 그리고 **눈으로 확인한 뒤에도 재라** —
  모달 하나가 그 위에 떠 있으면 눈은 못 가른다.

## 2. ② 식물신 멘트 — **주는 까닭을 말하게**

### 2-1 차례는 이미 맞았다

`dialogue.js §EVENT_ORDER` 가 **수확 → 배움 → 식물신 → 도착** 이고,
`god1` 은 `monsteraArrived` **바로 앞**에 꽂힌다(`storyteller` 1590행).
도착 조건도 이미 **2바퀴**다(`MONSTERA_ARRIVAL_RULE.harvestCount: 2`).
⇒ 고칠 것은 **차례가 아니라 멘트**였다.

### 2-2 무엇이 부족했나

```
(전) god1 — 한 줄
  식물신: 콩나물을 잘 키웠구나. 작은 걸 하나 줄 테니 키워 봐라.
```

**왜 지금인지도, 왜 하필 그것인지도** 말하지 않아서 「그냥 주는 물건」이었다.

### 2-3 고친 것 — 세 가지를 말하게 했다

```
(후) god1 — 네 줄
  식물신: 한 바퀴는 운이다. 두 바퀴는 손이지.              ← ① 왜 지금인가(도착이 실제로 2바퀴다)
  식물신: 너는 어두운 데서 먹을 것을 얻었다. 이제 **반대**를 해 보아라.   ← ② 왜 하필 이것인가
  식물신: 이건 못 먹는다. 대신 **잘 둔 만큼** 값이 된다.
  식물신: 가방에 넣어 두었다.                              ← ③ 어디에 있나
```

이어지는 `monsteraArrived` 는 **둘 → 열 줄**로 늘렸다. 마지막 줄이 **손짓 하나**로 끝난다:

```
  나  : 가방에… 화분이 하나 들어와 있어.
  몬이: 몬스테라야. 나도 오랜만에 보네.
  나  : 줄기가 하나뿐인데.
  몬이: 작은 걸 줬네. 대신 얘는 콩나물이랑 **반대**야.
  몬이: 콩나물은 어두울수록 하얗게 잘 됐잖아. 얘는 어두운 데 두면 **아무 일도 안 일어나.**
  나  : 먹지도 못하는 걸 왜…
  몬이: 잘 키우면 새 잎에 **흰 무늬**가 나. 그게 값이 돼.
  나  : …값이 된다고?
  몬이: 응. **이 방을 나가는 돈**, 거기서 나와.
  몬이: 가방에서 꺼내서 **밝은 데** 놓아 봐.
```

★ 「이 방을 나가는 돈」은 **지어낸 말이 아니다** — `quest §sell_varie` 의
  *탈출 = 돈 + 무늬 삽수를 판 적* 그대로다. 규칙이 바뀌면 이 줄도 같이 고쳐야 한다.
⚠ 값·날짜는 대사가 말하지 않는다. 그건 화면이 세는 것이고 대사가 세면 두 벌이 된다(§2.8).
⚠ `jachwi` 에 `curious` 표정은 **없다**(`§FACE_FILE`) — 처음에 썼다가 `surprise` 로 고쳤다.
  없는 표정은 조용히 `neutral` 로 떨어지므로 **오류 없이 틀린다.**

**실측** — `window.__dlgOpen('god1')` / `('monsteraArrived')` 로 직접 열어 글자와 굵게를 읽었다:
god1 **4줄** · monsteraArrived **10줄** · 굵게 여섯 군데가 다 걸렸다. 사진 `img/gift/dlg_monsteraArrived.png`.

★ 새 손잡이 **`window.__dlgOpen(id)`** — 도착 대사는 2바퀴를 굴려야 나오는데 글자·초상화만
  보려고 매번 그 길을 걸을 수는 없다. `__detailOpen`·`__lampTap` 과 같은 결이다.
  ⚠ 읽기용이 아니라 **진짜로 큐에 넣는다** — 그래서 재는 것이 실제로 뜨는 그 대사다.

## 3. ③ 손가락 — 가방에서 꺼내는 걸음

`updateHint` 에 **세 걸음**을 넣었다. 시루가 쓰는 그 결 그대로다:

| 언제 | 어디를 | 무엇이라 |
|---|---|---|
| 가방 칸이 보인다 | 그 칸 | 「끌거나 눌러서 방 안 밝은 자리에」 |
| 시트는 열렸는데 다른 탭 | `#tabBag` | 「가방에 몬스테라가 있습니다」 |
| 시트가 닫혔다 | `[가방]` | 「가방에 몬스테라가 있습니다 — 꺼내서 놓아 보세요」 |

⚠⚠ **가운데 걸음을 처음에 빼먹었다.** 그러면 다른 탭이 열려 있을 때 손가락이 통째로 사라진다 —
  칸이 가방 탭 안에 있어 `onScreen` 이 거짓이기 때문이다. **실측에서 `손가락: null` 로 잡혔다.**
⚠ 자리는 **도착 자리 안내보다 앞**이다. 뒤에 두면 아직 방에 없는 그루를 가리키는 줄이 먼저 걸려
  손가락이 허공을 짚는다.
⚠ `hintAt` 은 `textContent` 라 **굵게(`**`)가 안 먹는다** — 대사(`innerHTML`)와 다르다.

**실측**: 가방을 연 판 → 「끌거나 눌러서 방 안 밝은 자리에」 · 다른 탭 → 「가방에 몬스테라가 있습니다」 ·
놓은 뒤 → `null`(할 일이 없다). 사진 `img/gift/bag_hint.png`.

## 5. 남은 것

1. **원화 세 장면이 아직 안 붙었다** — `assets/illust/ev_monstera_arrive_*` 가 바로 이 장면 것이다.
   대사가 열 줄로 늘어난 지금이 붙이기 제일 좋은 자리다(`guide-event-quest-map.md §7`).
2. **가방 칸의 그림** — 선물이 신고 오는 화분은 `monstera/pot.glb` 라 썸네일이 없어
   `item_monstera.png`(기본 그림)로 떨어진다. GLB 를 찍으면(`tools/glb_thumb.mjs`) 제 그림이 된다.
   ⚠ 남의 그림을 되쓰지 않았다 — `§BAG_LETTER` 의 그 규율이다.
3. ⚠ **`#plantCard` 는 이제 영영 안 뜬다.** 조건이 `arrived && S.pots.length === 0` 인데
   도착이 곧 화분 생성이라 그 둘이 **같이 참일 수가 없다.** 내 변경 전부터 그랬다
   (실측: 놓기 전에도 놓은 뒤에도 `display:none`). 지금은 가방 칸과 `#plantBox` 가 그 일을
   나눠 하므로 **화면에 빈 데는 없다.** 죽은 카드를 걷을지는 따로 볼 일이다.
4. **회수한 그루도 같은 길로 온다** — `[📦 가방으로]` 로 걷은 그루는 `placedOnce` 가 이미 참이라
   가방 칸에 **안 선다.** 지금은 그 길이 「자리만 지운다」라 뜻이 다르지만,
   박사님이 「회수한 것도 가방 칸으로」를 원하시면 `bagPots` 의 판정 한 줄이다.
