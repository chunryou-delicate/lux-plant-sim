## 1. ② 를 다시 읽었다 — "스냅이 없다"가 아니었다

인계 지시에는 *"② 는 「스냅이 너무 곱다」가 아니라 「스냅이 아예 없다」로 읽는다"* 고 적혀
있었다. **재서 확인한 결과 그건 틀렸다.** 반박한다.

가방에서 끌어 놓는 길은 **예전부터 격자에 앉고 있었다.** `surfaceAt` 안에 격자 코드가
2026-08-03 부터 있었고(`snapOnSurface`), 화면이 `opt.step` 을 안 주면 `stepOf` 가
**`GRID_UNIT` 0.05 m** 를 넣었다.

잰 값 — 화면 한 줄을 **1 px 씩** 훑어 나온 좌표들의 간격이다:

| | 서로 다른 좌표가 갈리는 최소 간격 |
|---|---|
| 예전 | **0.05 m** |
| 지금 | **0.125 m** |

0.05 m 는 5 m 방에서 폰 화면 **2 px** 다. 손가락으로는 연속과 구별이 안 된다 —
그게 「촘촘하다」의 정체다. 「없다」가 아니라 **「너무 곱다」가 맞았고, 박사님 말씀 그대로였다.**

한편 **옮기는 길**(가구 끌기·화분 옮기기)은 이미 반 칸 0.125 m 였다(`MOVE_STEP`).
즉 **같은 손짓인데 걸음이 두 벌**이었다. 새 상수를 만들지 않고 놓는 길의 기본값을
`MOVE_STEP` 으로 맞춘 이유가 이것이다.

```js
// src/game/room_view.js
const stepOf      = v => (Number.isFinite(v) && v > 0 ? v : GRID_UNIT);   // 가구 — 그대로 0.05
const placeStepOf = v => (Number.isFinite(v) && v > 0 ? v : MOVE_STEP);   // 화분 — 반 칸 0.125
```

⚠ **가구 쪽 기본값은 일부러 안 건드렸다.** `snapFurniture` 를 `step` 없이 부르는 옛 길이
남아 있어(검사 Z-7 포함) 기본값을 같이 옮기면 가구가 조용히 반 칸으로 넘어간다.
가구는 놓는 길에서 화면이 늘 `step` 을 넘겨 주므로 실제 조작은 이미 0.125 다.

## 2. 걸음을 굵게 하면서 **눈금의 원점**도 바꿨다

0.05 → 0.125 로만 바꾸면 새 문제가 하나 생긴다. 예전 바닥 규약이
「**발자국 앞 모서리**를 걸음 선에 맞춘다」였기 때문이다(`snapSpanStep`).
그러면 앉는 자리가 **화분 크기마다 달라진다**:

| 화분 | 칸 수 | 반 발자국 | 앉는 자리 | 보이는 칸(0.25)과 |
|---|---|---|---|---|
| 몬스테라 0.202 m | 5칸 | 0.125 | `0.125 k` | 칸선·칸 한가운데에 딱 |
| 콩나물 시루 0.18 m | 4칸 | 0.100 | `0.125 k + 0.10` | **어긋난다** |
| 큰 화분 0.30 m | 6칸 | 0.150 | `0.125 k + 0.025` | **어긋난다** |

"밑에 그리드의 절반"이라는 지시는 **보이는 칸과 같은 눈금**을 뜻한다. 그래서 화분은
방 원점 기준 **걸음 배수**에 앉힌다. 방 치수가 전부 정수 m 이라 0.125 배수는 언제나
보이는 칸선 위이거나 그 한가운데다 — 어느 화분이든, 어느 방이든 그렇다.

⚠ 이 규약은 **화분·시루 것**이다. 가구는 예전 그대로 발자국 모서리를 맞춘다.
가구는 「칸 수 정수 점유」가 겹침 판정(`place.cellBox`)의 근거이기 때문이다.

검사 `test_roomview_place` **Z-5** 를 그래서 고쳤다. 예전 자는 「0.05 선에 발자국 모서리」를
쟀는데 그 규약이 없어졌다. 새 자는 「걸음 배수 · 화분 크기 0.202·0.18 둘 다」를 잰다 —
**느슨해진 게 아니라 재는 대상이 바뀌었고, 화분 크기를 하나 더 늘렸다.**

## 3. ③ 가구 상판 — 격자를 **가구에 맞춰** 깐다

예전에는 상판에서도 바닥과 같은 규약을 썼다. 그 선은 면 한가운데에서 시작하지 않아서
① 면 한가운데가 자리가 아닐 때가 있고 ② 마지막 칸이 상판 밖으로 넘어갔다.
상판은 좁다 — 선반 단 깊이가 0.28 m 다. 반 칸만 넘겨도 화분이 모서리에 걸친다.

지금 상판 격자는 이렇다.

| | |
|---|---|
| 원점 | **면 한가운데** (`u=v=0` 이 늘 자리다) |
| 걸음 | 바닥과 같은 값 (0.125 m) |
| 범위 | 면 한가운데에서 **면 반폭 − 화분 반지름** 안까지 ← 박사님 *"가구 크기만큼 또는 살짝 더 작게"* |

범위 밖으로는 **자리를 아예 안 낸다.** 그래서 격자에 물린 뒤에 삐져나오는 일이 없다.
한 칸도 안 들어갈 만큼 좁은 면이면 면 한가운데 하나만 남고, **그래도 안 들어가면
그건 격자가 아니라 판정(`potFits`)이 거절할 일이다** — 여기서 봐 주지 않았다.

### 잰 값 — 반지하, 지름 0.202 m 화분, **같은 화면 점 1445개**를 두 판이 똑같이 쏨

상판은 가구마다 여러 판이다(침대는 매트리스·프레임·베개까지 셋). 광선이 맞은 **그 판**으로
나눠 적는다 — 뭉쳐 적으면 판마다 다른 격자를 한 줄에 섞게 된다.

| 상판 | 크기[m] | 자유 자리 예전→지금 | 이론값 | 삐져나온 자리 예전→지금 | 제일 많이 나간 양[m] |
|---|---|---|---|---|---|
| 책상 | 1.20×0.60 | 139 → **21** | 21 | 62 → **0** | 0.026 → **0.000** |
| 서랍장 | 0.90×0.45 | 50 → **5** | 5 | 34 → **0** | 0.001 → **0.000** |
| 선반 한 단 | 0.72×0.28 | 47 → **5** | 5 | 89 → **0** | 0.036 → **0.000** |
| 의자 앉는 판 | 0.44×0.44 | 3 → **1** | 1 | 12 → **0** | 0.006 → **0.000** |
| 침대 매트리스 | 1.04×1.24 | 88 → **48** | 63 | 8 → **0** | 0.006 → **0.000** |
| 침대 프레임 | 1.02×1.92 | 22 → **13** | 91 | 4 → **0** | 0.016 → **0.000** |
| 침대 베개 | 0.68×0.34 | 18 → **3** | 3 | 11 → **0** | 0.035 → **0.000** |
| **합계** | | **367 → 96** | | **220 → 0** | |

- 이론값 = `(2·floor((폭/2 − 0.101)/0.125)+1) × (2·floor((깊이/2 − 0.101)/0.125)+1)`.
  **책상·서랍장·선반·의자·베개는 잰 값이 이론값과 정확히 같다.**
- 침대 매트리스(48/63)·프레임(13/91)만 잰 값이 모자란다 — 화면에서 쏜 점이 거기까지
  안 닿았고 위 판에 가린 곳도 있다. **그 둘은 이론값이 맞는지 못 쟀다.**
- **숫자가 줄어든 것이 ② 다.** 예전 367곳은 걸음이 0.05 라 나온 수고, 그중 **220곳이
  상판 밖으로 삐져나온 자리**였다. 지금 96곳은 **전부 상판 안**이다.

박사님이 견주실 것은 예전 자유 좌표가 아니라 **추천 자리 칸 수**다. 그쪽과 견주면 이렇다.

| 가구 | 추천 자리(원래 놓으라고 낸 칸) | 지금 격자 자리 |
|---|---|---|
| 책상 | 2칸 | **21칸** (가로 7 × 세로 3) |
| 서랍장 | 2칸 | **5칸** (가로 5 × 세로 1) |
| 선반 한 단 | 3칸 | **5칸** (가로 5 × 세로 1) |
| 침대 | **0칸** (자리가 아예 없었다) | **63칸**(매트리스 · 이론값) |

서랍장·선반이 **세로 1줄**인 것은 깊이(0.45·0.28 m)에서 화분 지름 0.202 를 빼면
한 걸음이 안 남기 때문이다. 그게 *"살짝 더 작게"* 의 실제 모습이다.

### 격자가 자리를 얼마나 끌어당기나 (R-2)

같은 화면 점을 `grid:false`(광선 날것)와 그냥, 두 번 쏴서 쟀다.
한 축이 끌리는 양은 **화분 반지름 + 한 걸음 = 0.226 m** 를 넘지 않는다 (880점 전수).

⚠ 처음에 「가구 옆 허공을 쏘면 거절해야 한다」로 재려다 헛짚었다 — 원근 때문에 가구
바깥 월드 좌표를 투영한 화면 점이 **여전히 그 상판을 맞는다**. 그건 격자 탓이 아니다.

### 시루 무리

지름 **0.97 m**(12개 무리)로 쏘았을 때 놓을 자리 **14곳 → 18곳**. 못 놓게 되지 않았다.
상판에는 한 칸도 안 나서 **상판 한가운데 하나**로 앉는다(그리고 대개 판정이 거절한다) —
회전무관 지름 규약 그대로다.

| banjiha-desk:0 | 0.000000 | 0.61 → **0.61** |
| banjiha-desk:1 | 0.000000 | 0.17 → **0.17** |

얼마나 달라지는지는 **안 쟀다** — 자리마다 다르고, 대푯값을 내면 그게 거짓말이 된다.

`dliOfSlot(slotId)` 와 `dliAt(surfaceAt 이 낸 좌표)` 가 **정확히 같은 값**이어야 통과한다

## 5. `game.html` 이 붙일 코드

### 5-0. 필수는 **없다**

②③ 은 방뷰 안에서 끝났다. 가방 끌기(`drag.move`)는 `opt` 를 안 넘기므로 새 기본값
0.125 를 그대로 받는다. 화분 옮기기(`plantSel.dragTo`)는 이미 `{ step: moveStep() }` 를
넘기고 있고 값이 같다. **아무것도 안 고쳐도 지시대로 돈다.**

### 5-1. 권함 — 등 옮기기는 격자를 끄는 게 낫다 (한 줄)

`beginLampMove` 의 끌기는 화분이 아니라 **등**인데 화분 격자를 타고 있었다. 예전에는
걸음이 0.05 라 티가 안 났지만 지금은 0.125 로 움직인다. 등이 상판에 물리는 자리는
`lampFit` 이 따로 정하므로(방뷰 몫), 여기서는 **날것 좌표를 주는 편이 맞다.**
가구 끌기(`dragTo`)가 이미 같은 이유로 `grid:false` 를 쓰고 있다 — 손버릇을 맞춘다.

```js
  lampDragTo(dx, dy) {
    /* ★ 여기서는 바닥·상판 점을 **안 앉힌다**(grid:false). 물리는 자리는 lampFit 이 정한다 —
       화분 격자(0.125m)에 먼저 앉히면 그 반올림 위에 lampFit 이 또 앉아 자리가 밀린다.
       가구 끌기(furnSel.dragTo)와 같은 이유다. */
    const hit = freePlace.surfaceAt(this.originX + dx, this.originY + dy, 0.2, { grid: false });
```

(바꾸는 것은 `freePlace.surfaceAt(...)` 인자 끝에 `, { grid: false }` 하나뿐이다.)

### 5-2. 권함 — 주석 한 줄이 이제 사실과 다르다

```js
/* ★옮길 때의 걸음[m] — 값도 근거도 room_view 가 갖는다(SNAP_DIV). 여기서 지어내지 않는다.
   방 뷰가 아직 없으면 undefined 를 주고, 그러면 room_view 가 예전 눈금(0.05m)을 쓴다. */
const moveStep = () => { try { return roomView.moveStep(); } catch { return undefined; } };
```

`surfaceAt` 은 이제 `undefined` 를 받으면 **0.125** 를 쓴다(0.05 는 `previewFurnitureAt`
쪽에만 남았다). 뒷줄을 이렇게 고치는 편이 정확하다:

```js
   방 뷰가 아직 없으면 undefined 를 준다 — 화분은 room_view 기본값(반 칸 0.125m)으로,
   가구는 옛 눈금(0.05m)으로 앉는다. */
```

### 5-3. 새로 읽을 수 있게 된 값

```js
roomView.grid()      // { unit:0.05, cell:0.25, step:0.125, room:{…}, visible, free, blocked }
hit.cells            // { i, j, unit:0.05, step:0.125 }   ← 그 자리를 낸 격자
hit.surface          // { x, z, w, d, rot } 상판 격자의 원점·크기 (바닥이면 null)
```

`hit.surface` 를 쓰면 화면이 **겨냥한 상판에 격자를 그릴** 수 있다(§6 참고).

## 6. 못 한 것 · 박사님 판단이 필요한 것

1. **보이는 격자는 여전히 0.25 선만 그린다.** 실제로 앉는 자리는 그 절반 눈금이다
   (칸선 위 **또는** 칸 한가운데). 반 칸 선을 옅게 더 그릴지는 안 했다 —
   5 m 방에서 41+33 줄이라 폰에서 잡음이 될 수 있어 **눈으로 보고 정하실 일**로 남긴다.
2. **가구 상판에는 격자를 안 그린다.** "선반마다 격자를 얹으면 방이 안 보인다"는 예전
   결정을 그대로 뒀다. 지금은 `hit.surface` 가 나오므로 **겨냥한 상판 한 개**에만
   격자를 비추는 것이 가능하다. 할지 말지 지시 주시면 방뷰 쪽에서 한다.
3. **자리가 예전보다 성글어졌다** (상판 367→96곳). 이게 지시 ② 자체지만, 막상 만져 보시고
   너무 성글면 `SNAP_DIV = 4`(0.0625 m) 한 줄이면 다시 촘촘해진다. 그 한 줄로 바닥·상판·
   가구가 **같이** 움직인다.
4. **0.125 는 0.05 의 배수가 아니다.** `place.cellBox` 는 좌표를 0.05 칸으로 반올림해
   겹침을 정수로 보므로 반 칸에 선 물건은 칸 판정이 최대 0.025 m 어긋난다. 화분은 겹침을
   **원 거리**로 보므로 지금은 영향이 없다(가구만 cellBox 를 탄다). 나중에 화분을 칸 판정에
   넣게 되면 그때 다시 봐야 한다 — 이미 `SNAP_DIV` 머리말에 적혀 있던 빚이다.
5. **상판 격자의 원점은 「광선이 맞은 그 메시」의 사각형이다.** 3단 선반은 단마다 제
   격자를 갖는다. 그게 맞다고 봤지만(단마다 크기가 다르다) 다른 뜻이셨으면 말씀해 주시라.
6. **반지하 한 방에서만 쟀다.** 다른 다섯 방은 **못 쟀다.** `test_place_grid` 는 지금
   `banjiha` 로 못 박혀 있다(자리 수 14칸 같은 문턱이 그 방 것이라서다).
   방을 늘리려면 문턱을 방마다 따로 적어야 한다 — 그건 안 했다.
