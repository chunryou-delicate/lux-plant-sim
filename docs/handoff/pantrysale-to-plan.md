# 2026-08-15 · pantrysale → plan (곳간 채소를 상점에서 판다 · 몇 판 팔지 고른다)

박사님 확정: *"채소는 상점에서 판매 가능하게 해줘. 누르면 몇개팔지 나오게도 해주고."*
그리고 ㉯(곳간 것도 팔게)를 고르시며 *"어차피 체력이 막고있어서 괜찮을거랴"*.

## 먼저 네 줄

1. **된다. 화면에서 밟았다.** 상점 탭에 [곳간 채소 팔기]가 생겼고, 누르면 **몇 판 팔지 고르는
   자리**가 뜬다(− / 판 수 / ＋ / 전부). 받을 돈과 **손해**가 같이 뜨고, 팔면 지갑에 들어가고
   곳간이 그만큼 준다. 새 판을 처음부터 돌려 **진짜 수확**으로도 확인했다(§2-A).
2. **㉮(꾸러미 목록)를 골랐다. 다만 「총액이 정본」인 꼴로 만들었다** — 곳간의 정본은 여전히
   `pantryWon`(원)이고, 꾸러미 목록은 **그 총액이 무엇으로 이루어졌나**를 적는 칸이다.
   그래서 먹기·한도·쉬기의 셈이 **한 글자도 안 움직였다**(§1).
3. **새 값을 하나도 안 만들었다.** 판매가는 잉여와 **같은** `cropSurplusSaleRate`(0.85)를 쓴다.
   `dailyCropSaveWon` 은 안 건드렸다.
4. **잉여 단추는 지금처럼 숨긴 채로 뒀다** — 대신 **곳간 단추가 늘 보인다**(비면 회색 + 까닭 한 줄).
   판단 근거는 §4.

## 1. ★ 제일 큰 판단 — ㉮ 를 골랐고, **총액을 정본으로 남겼다**

지시서가 준 두 길이었다.

| | 무엇 | 걸림돌 |
|---|---|---|
| ㉮ | 곳간을 **꾸러미 목록**으로 바꾼다 | 세이브 스키마가 바뀐다 |
| ㉯ | 원 그대로 두고 **한 판 단위로 환산**해 센다 | 정수로 안 떨어져 「약 N판」이 된다 |

### ㉯ 를 안 쓴 이유 — 재 보니 **정말로 안 떨어진다**

곳간에 들어가는 값은 3,000원짜리만이 아니다. 같은 날 겹쳐 거두면 **3,000 → 2,000 → 1,000**
으로 깎여 들어가고, 품질이 낮으면 2끼·1끼 값이 들어간다. 게다가 하루에 먹는 몫이
**4,867원**(콩나물 3,000 + 무순 1,867)이라 꾸러미 경계에 안 맞게 잘린다.
⇒ 6,000원을 「약 2판」이라 적으면 **실제로는 3판(3,000+2,000+1,000)이다.** 거짓말이 된다.

### ㉮ 를 그대로 안 쓴 이유 — **블라스트 반경**

`pantryWon` 은 이 저장소에서 **검사·프로브 12곳이 직접 읽고 쓰는 값**이다
(`test_cropsale:262` 는 `fp.food.pantryWon = pantryCapWon(fp)` 로 곳간을 한도까지 채운다).
목록을 정본으로 삼으면 그 줄들이 **조용히 거짓**이 된다 — START-HERE §2 가 열 번 겪었다는
바로 그 사고("고장난 상태를 검사가 정상으로 못 박아 둔 것")의 반대 방향이다.

### ⇒ 실제로 만든 것 — **총액이 정본, 목록은 그 총액의 구성**

```js
fp.food.pantryWon  = 6000                                    // ★ 정본
fp.food.pantryLots = [ {kind:'beansprout', day:7, won:3000, meals:3},
                       {kind:'beansprout', day:7, won:2000, meals:3},
                       {kind:'beansprout', day:7, won:1000, meals:3} ]
```

`pantryLotsOf(fp)` 가 **읽을 때마다 목록을 총액에 맞춘다.**

- 목록 합이 총액보다 **많으면** → **앞(먼저 거둔 것)부터** 깎는다 = 먹는 순서(FIFO)
- 목록 합이 총액보다 **적으면** → 모자란 만큼을 **하루치씩 쪼개 뒤에 붙인다** = 옛 세이브가 열리는 길

이렇게 두어 얻은 것 셋:

| | |
|---|---|
| ① | **경제 셈이 한 글자도 안 움직인다.** `eatFromPantry`·`pantryCapWon`·`spoiledWon` 의 산수가 그대로다 — 경제 표를 다시 안 재도 된다 |
| ② | **옛 세이브가 저절로 열린다.** `pantryLots` 가 없는 판은 총액에서 다시 세워진다 |
| ③ | **검사가 안 거짓말한다.** `pantryWon` 에 직접 값을 넣는 줄들이 그대로 산다 |

⚠ 대가 하나 — **하루 몫이 판 경계에 안 맞으면 판이 잘린다.** 2,000원짜리 둘에서 3,000원을
먹으면 앞이 사라지고 뒤가 1,000원으로 남는다. 그건 「반 판」이 아니라 **먹다 남은 판**이고,
화면은 **판마다 제 값을 적으므로**(`콩나물 1,000원`) 속이지 않는다. 검사 D-2 가 못 박는다.

## 4. ★ 판단 — 잉여 단추를 회색으로 남길지 (지시서 4번)

**남기지 않았다. 지금처럼 잉여가 있을 때만 뜬다.** 대신 **곳간 단추를 늘 보이게** 했다.

| | 왜 |
|---|---|
| 원래 걱정(`game.html` 옛 주석) | *"늘 띄우면 「왜 회색이지」가 된다"* |
| 감사(`guideaudit §1-8 ②`) | *"통째로 사라져 「그런 것이 있다」를 배울 자리가 아예 없다"* |
| **⇒ 판단** | **둘 다 맞다. 그래서 「왜 회색인지」를 바로 밑에 적는 단추 하나만 늘 띄운다** |

곳간 단추는 곳간이 비어도 회색으로 남고, 바로 밑에 이렇게 적는다 —
`곳간이 비어 있습니다 — 거둔 채소가 쌓이면 여기서 팔 수 있습니다 (밥으로 먹는 편이 이득입니다)`
⇒ 「파는 길이 있다」와 「왜 지금은 안 되나」와 「그래도 안 파는 게 낫다」를 한 줄이 다 말한다.

잉여까지 늘 회색으로 두지 **않은** 이유 둘:

1. 상점에 회색 단추가 **둘**이 되면 「왜 회색이지」가 둘로 는다 — 원래 걱정이 그대로 살아난다
2. 잉여는 **겹쳐 거뒀을 때만 생기는 예외 몫**이다. 늘 보이면 정상적인 길처럼 읽히는데,
   이 게임에서 잉여가 생기는 것은 **잘못 굴린 결과**다(겹침 벌)

## 5. ★ 지킬 것을 어떻게 지켰나 — **구조가 하던 일을 값과 말이 이어받았다**

`first_play §잉여 판매` 는 이렇게 적어 두었다:

> 파는 함수는 곳간을 **한 번도 안 만진다.** 그래서 "끼니로 쓸 수 있는 것은 안 팔린다"가
> 검사로 지키는 약속이 아니라 **구조**다.

**이번에 그 구조가 깨졌다.** `takePantryCrop` 은 곳간을 만진다. 대신 이 셋이 받는다.

| | 무엇이 지키나 |
|---|---|
| **값** | 곳간 1원 = 밥값 1원인데 팔면 **0.85원**. **팔면 늘 손해**라 이득을 보려고 파는 길이 없다. 코드가 적어 둔 위끝(*"1.00 을 넘기면 뼈대가 뒤집힌다"*) **아래**다 |
| **화면** | 고르개가 손해를 **문장 한가운데**에 적는다 — `2,550원에 넘깁니다 — 450원 손해입니다` |
| **검사** | `test_pantrysale §B` 가 `won < pendingWon` 과 `rate < 1` 을 못 박는다 |

★ 그리고 **잉여 창구는 예전 그대로다.** `sellCropSurplus` 는 여전히 곳간을 한 푼도 안 만진다 —
검사 §F 가 한 판 안에서 둘을 나란히 굴려 못 박는다.

### 검사가 못 박던 것 중 이번에 바뀌는 약속

| 어디 | 무엇을 지키던 줄인가 | 지금 |

## 7. ☐ 판단 필요 (박사님·plan 몫)

1. **파는 데 체력을 물릴 것인가.** 지금은 **안 문다** — `sellPot`·`sellCutting`·잉여 넘기기가
   다 안 물어 왔고, 그 줄에 맞췄다. 박사님 말씀(*"어차피 체력이 막고있어서"*)은 **채소를
   만드는 쪽**의 체력으로 읽었다. 파는 손에 물리면 「콩나물 15시루가 삽수를 영영 못 자른다」
   (econgap §A-3)가 한 칸 더 나빠진다.
2. **팔 때 되묻지 않는다.** 고르개 자체가 되묻기이고 그 자리가 손해를 이미 말한다고 봤다.
   한 번 더 물으면 손해를 적은 문장을 지나쳐 [예]만 누르게 된다 — 그런데 이건 판단이다.
3. **곳간을 상점 밖에서도 보여 줄지.** 지금 곳간이 화면에 뜨는 곳은 **상점 탭**과
   (첫 플레이가 끝난 뒤의) 살림 장부뿐이다. guideaudit §3-3 이 지적한 「곳간이 조용하다」는
   상점 탭에서만 풀렸다.
4. **잉여를 알리는 일은 안 했다** (guideaudit §5-2). `loop.js` 소유라 안 건드렸다.

## 8. ✗ 못 한 것

1. **`spoiledWon`(쉰 몫)이 실제로 나는 판을 못 만들었다.** guideaudit §6-1 이 적은 그대로
   — 시루가 늘면 한도도 같이 늘어 몰아 거두기만으로는 한도에 안 닿는다. 코드로는 그 몫이
   꾸러미에서 빠지게 해 뒀지만(`savedWon - spoiledWon`), **화면으로 확인한 것은 아니다.**
2. **무순으로 진짜 한 판을 안 돌렸다.** 세이브 왕복에서 무순 꾸러미가 이름까지 살아 넘어오는
   것은 봤지만(§2-C), 그건 손으로 세운 꾸러미다.
3. **여러 시루를 진짜로 사서 세 판을 거둔 판은 못 밟았다** — ± 와 [전부]는 지름길로 세운
   곳간에서만 봤다(§2-B). 걸음 자체는 §2-A 에서 지름길 없이 확인했다.
4. **살림 장부(`#ledger`)에 「채소를 팔아 번 돈」을 안 붙였다.** `totalPantrySoldWon` 은
   쌓이고 저장도 되는데 **읽는 데가 없다.** 붙일 자리는 `drawLedger` 다.
5. ★ **하루 몫이 3,000원이 아니라 4,867원이었다** — 이건 이 작업 중에 검사가 넘어져서 알았다.
   코드를 읽으면 이렇다(`first_play.js:482`):
   ```
   dailyCropSaveWon = min(cropSavedWonPerCycle, 끼니상한)
                    = min(3,000 + 1,867, 5,000) = 4,867
   ```
   `cropSavedWonPerCycle` 은 **가진 작물이 아니라 작물 표 전체의 합**이다. 무순을 사지
   않아도 표에 있으므로 **새 판에서도 4,867원**이다.
   ⚠ 그런데 **어제 기획서(`plan-2026-08-14-pantry-shelflife.md §3`)가 「하루에 먹을 수 있는
     양 3,000원」이라 적고 그 위에 유통기한 셈을 얹었다.** 지시서도 그렇게 적혀 있다.
   ⇒ **어느 쪽이 맞는 설계인지는 이 창이 못 정한다.** 값을 안 건드렸고(지시대로), 다만
     **「3,000원」이라 적힌 문서들이 지금 코드와 다르다**는 것만 적어 둔다.
