## 0. 어떻게 갈랐나 — 짐작을 안 쓰려고 재는 도구부터 만들었다

`tools/probe_siru_tap.mjs` — 헤드리스 크롬 **폰 390×844**, CDP 로 **진짜 터치**를 넣는다.
방에 몬스테라 1(책상) + 시루 3(바닥 자유 좌표)을 세우고, 각 그루의 화면 좌표를
`screenPosOf` 로 물어 그 둘레를 눌러 본다. 무엇이 골라졌는지는 `window.__picked.slotId` 로 읽는다.

⚠ **이 도구가 한 번 스스로 속았다.** 처음에는 누르기 전에 고르기를 안 풀었다.
그랬더니 시루를 눌러도 「몬스테라」가 찍혔는데, 그건 시루가 몬스테라로 잡힌 게 아니라
**아무것도 안 잡혀서 직전 선택이 남은 것**이었다. 두 그림이 똑같이 보인다.
⇒ 누르기 전에 `__picked.clear()` 를 넣고서야 갈렸다. 검사에도 같은 줄을 넣어 뒀다.

## 1. ① 의 원인 — **두 개**다

### 1-a. 자유 좌표로 선 것은 퍼지 그물에 없었다 (`room_view.js`)

`resolveTap` 의 차례는 캐릭터픽 → **화분(광선)** → 등 → 캐릭터(퍼지) → **자리(퍼지 30px)** 다.
그런데 퍼지 그물(`pickSlotFuzzy`)의 후보가 `slotById` 뿐이었다.
시루는 「각개」 뒤로 **자유 좌표**(`free:crop_01_02`)로 서므로 `slotById` 에 **없다** —
즉 **정확한 광선 한 발**로만 잡혔다.

재서 나온 표적 크기(폰 390px · 바닥의 24cm 시루):

| 발밑에서 | 결과 |
|---|---|
| (0, 0) | 잡힌다 |
| (0, −6px) | 잡힌다 |
| (0, −10px) | **안 잡힌다** |
| (±8px, −6px) | **안 잡힌다** |

즉 표적이 사실상 **±6px** 이다. 손가락은 40px 을 덮는다.

그리고 **못 잡은 탭은 아무 신호도 안 낸다** — `resolveTap` 이 `null` 이면
`onPlantTap` 이 안 불리고, 화면의 고르기는 **그대로 남는다**.
⇒ 그래서 시루를 아무리 눌러도 **직전에 고른 몬스테라가 계속 붙어 있었다.**

**고침** — 자유 좌표 그루도 퍼지 그물에 넣는다(슬롯과 같은 30px).
정확히 짚은 것이 먼저라는 원칙은 안 건드렸다: 광선이 앞, 그물이 뒤다.

```js
const pool = highlighted.size ? [...highlighted]
           : [...slotById.keys(), ...plants.keys()];
```

### 1-b. 제대로 잡아도 이름이 「몬스테라」였다 (`game.html` · `slotLabel`)

```js
// 예전
if (isFreeSlotId(slotId)) {
  const id = String(slotId).slice(5);
  return id === BEANSPROUT_ID ? '열린 시루' : '몬스테라';   // ← 여기
}
```

`BEANSPROUT_ID` 는 **자리 사본** `crop_01` 이다. 그런데 「각개」(2026-08-09) 뒤로
방에 서는 것은 **시루 개체** `crop_01_01`·`crop_01_02`… 라 저 비교에서 전부 떨어지고
**else 로 굴러떨어져 "몬스테라"** 가 됐다.

재서 확인한 그림 — 시루 셋을 정확히 짚었을 때:

```
free:crop_01_01 → 고름 free:crop_01_01  이름 "몬스테라"
free:crop_01_02 → 고름 free:crop_01_02  이름 "몬스테라"
free:crop_01_03 → 고름 free:crop_01_03  이름 "몬스테라"
```

**★ 박사님이 보신 사진이 바로 이것일 가능성이 높다.** 메뉴에 「몬스테라」가 떠 있었지만
실제로 골라져 있던 것은 **바닥의 시루**다. 그 상태에서 [옮기기]를 하면 움직이는 것도 시루다.

**고침** — 이름은 코어 목록(`cropPotList`)에서 가져온다. 이제 「시루 / 시루 2 / 시루 3」.

## 2. ② 의 원인 — **옮기기는 멀쩡하다.** 안내가 거짓말이었다

재서 확인한 것(같은 프로브 ⓓ · [자리] 목록에서 창턱을 고른 뒤):

| | 옮기기 전 | 옮긴 뒤 |
|---|---|---|
| 상태 `slotId` | `banjiha-desk:0` | `banjiha-sill:0` |
| 상태 `at` | null | `(0, 1.585, −1.95)` = 창턱 점 |
| **오늘 DLI** | **0.61** | **4.80** |
| 방뷰 열쇠 | `banjiha-desk:0` | `free:pot_01` |
| **방뷰 3D 좌표** | (0.79, 0.74, −1.41) | **(0, 1.585, −1.95)** = 창턱 점 |
| 첫플레이 `slotId` | `banjiha-desk:0` | `banjiha-sill:0` |

**상태 · 3D · 조도가 전부 같은 자리를 가리킨다.** 「옮겼다고 말만 하고 안 옮겨진다」는
**재현되지 않았다.**

그러면 「7일평균 0.61 < 최소 3」은 무엇이었나 — **판정값이 7일 평균이라서** 그렇다.
자리를 옮겨도 판정값은 그 날 안 바뀐다. 책상(0.61) → 창턱(4.80) 이면

```
0.61 → 1.21 → 1.81 → 2.41 → 3.01     (문턱 3 을 넘는 것은 나흘째)
```

`first_play.js §MONSTERA_LAMP_HINT_DAYS` 가 같은 값을 실측해 이미 적어 뒀다
("7일평균이 새 자리 값으로 차오르는 데 나흘쯤 걸린다").

그런데 화면 안내는 이렇게 말하고 있었다:

> 창턱 화분받침(으)로 옮겼습니다. **[다음 날]을 눌러 새순이 오르는지 보세요.**

그리고 그 사흘 동안 다른 줄은 「⏸ 오늘은 자라지 않았습니다 — 빛 부족」을 계속 띄운다.
**두 줄이 다른 말을 한다.** 플레이어는 옮긴 것이 안 먹혔다고 읽는다 —
박사님이 실제로 그렇게 읽으셨다.

**고침** — 날짜를 화면이 새로 세지 않는다. **판정이 평균이라는 사실**만 말한다.

> 창턱 화분받침(으)로 옮겼습니다. 빛 판정은 7일 평균이라 나흘쯤 지나야 새 자리 값이 됩니다 — 하루씩 넘겨 보세요.

## 3. 아닌 것으로 밝혀진 것 (다음 사람이 또 의심하지 않게)

| 의심 | 결과 |
|---|---|
| 「옮기기 모드에 갇혀서 다른 걸 못 고른다」 | **아니다.** `#stage.moving` 이면 `#plantActions` 는 `display:none` 이라 **메뉴가 아예 안 보인다.** 사진에 메뉴가 보였으므로 옮기기 모드가 아니었다. [옮기기]가 초록인 것은 `class="primary"` 라서다 |

| 「시루 그룹이 `plantSlotId` 를 못 받아 부모로 올라가다 몬스테라를 만난다」 | **아니다.** 정확히 짚으면 자기 열쇠가 나왔다 |
| 「화면이 라벨·메뉴를 몬스테라로 고정한다」 | **반은 맞다** — 고정은 아니고 `slotLabel` 이 못 읽은 것이다(§1-b) |

## 4. ★ 다른 창이 알아야 할 것

- **`pickSlotFuzzy` 의 후보가 늘었다** — 이제 자유 좌표 그루도 30px 안에서 잡힌다.
  「빈 자리를 눌러 놓기」를 하는 쪽은, 근처에 그루가 있으면 그루가 이길 수 있다.
  놓기 모드에서는 `highlightSlots` 로 후보를 좁히므로 예전과 **한 톨도 안 다르다**.
- **`slotLabel(free:…)` 가 이제 「시루 2」처럼 순번을 낸다.** 이름을 문자열로 비교하던
  곳이 있으면 어긋난다(저장소 안에서는 없었다).
- **`arrivalSlotId` 는 세이브에 안 실린다** — `game.html` 의 모듈 변수다. 앱을 껐다 켜면
  null 이라 「옮겼습니다」 안내가 안 뜨고 「옮겨 보세요」로 돌아간다. 이번엔 안 고쳤다.

## 5. ★ 판단이 필요한 것 (plan)

1. **빈 데를 눌렀을 때 고르기가 풀려야 하나.** 지금은 안 풀린다 —
   `resolveTap` 이 null 이면 방뷰가 호스트에 아무 말도 안 한다. 그래서 메뉴가 계속 떠 있다.
   [×]가 있으니 막다른 길은 아니다. 풀려면 방뷰에 `onEmptyTap` 창구가 하나 는다.
   ⚠ 폰 배치의 [확인] 바가 열려 있을 때 같이 닫히면 안 되므로, 넣는다면 그 예외가 필요하다.
2. **「나흘쯤」을 문구에 박을까, 실제로 셀까.** 지금은 실측값을 문구에 박았다(값이 자리·계절마다
   다르다). 정확히 세려면 「지금 이력 + 새 자리 값으로 며칠 뒤 문턱을 넘나」를 세는 규칙이
   필요한데, 그건 화면이 아니라 코어(또는 growth)에 있어야 한다.
3. **몬스테라 유도가 여름에는 창턱만으로 끝난다** — `first_play.js §1895` 가 이미 적어 둔
   미해결이다. 이번 건과는 별개지만, ② 를 파다 다시 마주쳤다.
