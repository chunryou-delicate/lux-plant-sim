## 0. 설명 먼저 — 두 줄이 각각 무슨 이야기인가

### G-17 「중간잎은 하프문 하나로. 성숙 때 확률로 분류」

몬스테라 무늬 잎은 그림이 **두 벌**이다. 잎이 어릴 때(중간잎) 한 벌, 다 자란 뒤(성숙잎) 한 벌.
어제 다른 창이 중간잎 42장을 재서 산반·하프문·풀문 셋으로 묶었는데, 그러고 나니
**중간잎 그림이 그 잎의 등급을 미리 말해 버리게** 됐다 — 풀문이 될 잎은 중간부터 전백으로 뜨고,
하프문이 될 잎은 (그 갈래가 하나뿐이라) 늘 같은 그림 하나로 뜬다.

박사님이 그것을 **그냥 받아들이자**고 하셨다: *"중간잎은 하프문만 있는 걸로 그냥 ㄱ,
성숙 때 확률적으로 분류되는 걸로."*

⇒ 그래서 **중간 시절에는 모두 같은 얼굴**로 두고, **다 자랄 때 비로소 갈리게** 했다.

### G-16 「식물등 최초 위치를 몬스테라 위쪽으로」

첫 등을 사면 켜지는 것은 **선반 밑에 붙어 있는 바 등**인데, 그 발광점이 y 1.066 이다.
몬스테라가 앉는 창턱은 y 1.585 다 — **등이 식물보다 0.52m 아래**에 있었다.
아래에서 비추니 창턱은 4.80 → 5.15 밖에 안 올랐고, 정작 12.31 로 밝아지는 것은
아무도 안 쓰는 선반 맨 윗칸이었다. **이만오천 원을 낸 사람이 제 그루에서 아무 변화를 못 봤다.**

⇒ 등을 **창 위 벽**으로 올렸다. 이제 첫 등이 창턱을 **7.07** 로 만든다 — 갈라짐 문턱 6.0 을
처음으로 넘는다. 즉 **등을 사면 잎이 갈라지는 것이 눈에 보인다.**

## 1. G-17 — 무엇을 옮겼고 **무엇을 안 옮겼나**

지시가 *"정하는 시점을 성숙 때로 옮길지, 중간잎 그림만 한 갈래로 둘지 — 재서 판단하고 근거를 적어라"*
였다. **재서 갈랐다. 둘 다 했되 서로 다른 것을 했다.**

| | 언제 | 무엇이 |
|---|---|---|
| **정하기** (장부 `pot.leafGrades`) | **잎이 날 때** — 안 옮겼다 | 값이 여기 선다 |
| **드러내기** (중간잎 그림 · 배너) | **잎이 성숙할 때** — 옮겼다 | 플레이어가 여기서 안다 |

### ⚠⚠ 왜 정하는 시점을 안 옮겼나 — **재서 정했다**

장부 쓰기까지 성숙 때로 미루면 **프롤로그 그루가 196만 → 100.8만**이 된다.
`tools/probe_midreveal.mjs` 가 그 표를 낸다:

```
㉯ 지금 코드 — 장부는 잎이 날 때 · 드러내기만 성숙 때
  성숙한 잎 0/1/2/3 → 그루값 1,960,000원 (네 경우 다 ✔)

㉮ 안 고른 길 — 장부 쓰기까지 성숙 때로 미뤘다면
  성숙한 잎 0 → 1,960,000원 ✔
  성숙한 잎 1 → 1,960,000원 ✔
  성숙한 잎 2 → 1,008,000원 ✘  (−952,000원)
  성숙한 잎 3 → 1,960,000원 ✔
```

까닭: **잎2 만 성숙하고 잎3 이 아직이면** 장부에 칸이 하나 생긴다. 그러면
`prologueLeafGradeListOf` 다리가 꺼지고(그 다리는 **장부가 완전히 비었을 때만** 산다),
등급 없는 잎3 이 `legacyGradeId`(산반)로 떨어져 **하프문 750,000원이 통째로 사라진다.**
확정문 §2 의 「196만 · 이사비에 4만 모자란다」가 그 자리에서 깨진다.

⇒ **값은 잎이 날 때 조용히 정하고, 드러나는 것만 성숙 때로 미룬다.**
  박사님 말씀의 요점(「중간에 미리 티 나지 않게」)은 이것으로 온전히 선다 —
  중간에는 그림도 같고 알림도 안 나간다.

### ㉠ 중간잎은 한 갈래 — `data/balance/varie_grades.json §midCommon`

```json
"midCommon": { "enabled": true, "fromGrade": "halfmoon" }
```

무늬 잎은 등급과 상관없이 **하프문 갈래**(`heart_halfmoon_v2_stem` · `leaf_mid_albo29·30·31`
세 판)에서 중간잎을 뽑는다. **브라우저에서 재서 확인했다**(`tools/probe_midcommon_browser.mjs`):

| 등급 | 중간잎 | 성숙잎 가짓수 |
|---|---|---|
| 산반 | `leaf_mid_albo29 30 31` | 23 |
| 하프문 | `leaf_mid_albo29 30 31` | 15 |
| 풀문 | `leaf_mid_albo29 30 31` | 18 |

⇒ 세 등급이 **같은 칸**을 쓴다. 그림으로 등급을 못 알아본다. 성숙잎에서만 갈린다.

⚠ **42갈래 표는 한 줄도 안 지웠다.** `enabled` 를 false 로 하면 그 자리에서 예전 동작으로
  돌아간다(검사 `G-mid-4b` 가 그것을 잰다). 다른 갈래로 바꾸려면 `fromGrade` 만 고친다 —
  **코드는 안 고쳐도 된다.**

### ㉡ 드러내기는 성숙 때 — `assignPotLeafGrades` 가 둘로 갈렸다

```js
{ graded:   [...],   // 이번에 **장부에 적힌** 잎 — 조용하다. 값이 여기서 선다
  assigned: [...],   // 이번에 **화면에 드러난** 잎 — 성숙했고 아직 안 알린 잎
  revealed: assigned, seen, grades, pending, step, events }
```

★★ **`assigned` 의 뜻을 바꾼 것이 이 배선의 핵심이다.** `game.html §noteLeafGrades` 가
이미 `r.assigned` 를 돌며 배너를 띄우고 있다 — 그래서 **그 파일을 한 글자도 안 고치고**
배너가 성숙 때로 미뤄진다. `game.html` 은 이번 창의 ⛔ 목록이라 그 모양을 골랐다.

「이미 알렸다」는 **`pot.leafGradesSeen`** 에 적는다(`{ [leafBirth]: true }`).
`save.js §화분 한 칸` 에 같이 넣었다 — 안 적으면 저장 한 번에 **본 알림이 다시 뜬다.**

⚠ `leafState` 줄에 `matured` 가 없으면(옛 접근자) **아무것도 안 드러난다.** 지어내지 않는다.
⚠ 배너 문구도 바꿨다: 「3번째 잎의 무늬는 **하프문**입니다」 → 「3번째 잎이 **다 자랐습니다** —
  무늬는 **하프문**, 잎 한 장 750,000원」. 「자라 봐야 안다」가 글에서도 서야 한다.
⚠ `gradeOfMidNum(n)` 은 이제 **「그 잎의 등급」이 아니다** — 표 검사용이다. 주석에 못 박았다.

## 5. ★ 판단필요 — 박사님

**① 3단 선반 grow rack 을 잃었다 — 그대로 둘까**
첫 등이 창턱을 맡으면서 선반 맨 윗칸이 12.31 → 0.89 가 됐다(등1 자람칸 4 → 1).
반지하에서 삽수·모주를 여러 개 굴리던 유일한 자리였다.
⇒ ㉠ **그대로 둔다** — 둘째 등(집게)을 선반에 물리면 되살아난다. 「등보다 자리」를 한 번 더 가르친다.
  ㉡ **등 순서를 바꾼다** — 집게등을 첫째로 올리고 그 집을 창턱 위에 둔다. 그러면 첫 등이
     몬스테라를 밝히고 **둘째 등(바)이 선반을 되살린다**. ⚠ 다만 「첫 등은 못 옮긴다」는
     튜토의 긴장이 사라지고, 원룸도 같은 순서라 원룸 값이 같이 움직인다(180 → 120 ppfd).
  ㉢ 등을 하나 더 준다 — 값이 크게 흔들린다.
지금은 **㉠** 으로 두었다. 순서를 바꾸는 것은 지시에 없어서 안 했다.

**② `real` 모드를 켤 계획이 있나**
지금(`novice`)은 7.07 이 문턱 6.0 을 넘지만, 날씨·계절을 굴리면 7일평균이 4.55 로 내려앉아
**안 넘는다.** 옛 자리는 두 모드에서 다 넘었다. real 을 켤 생각이면 등 높이를 다시 잡아야 한다
(0.42m 쯤이면 두 모드에서 다 넘지만 그루가 등을 뚫는다 — 그때는 다른 기구가 필요하다).

**③ 중간잎 세 판을 그대로 쓸까**
지금 중간잎은 하프문-크림민트 **한 갈래 세 판**(기본·쨍·차분)이다. 잎마다 그중 하나가
결정적으로 뽑히므로 잎끼리는 조금씩 달라 보인다. 「완전히 똑같이」를 원하시면
`midCommon.fromGrade` 대신 판 하나만 남기면 된다(표에서 번호를 빼면 된다 · 코드 안 고침).
