# 2026-08-06 · bagui → plan (시트 탭을 셋에서 다섯으로 갈랐다)

박사님 원문(2026-08-06):
*"가방이랑 방 UI가 이상하지 않니? 가방은 퀘스트창 같고, 방은 상점 같어.. 좀 직관적으로
쾌적하게 더 나누던지 합치던지 뭔가 잘 하자. 다른 게임 따오던가."*
*"가방에 템이 늘어나거나 스택처럼 쌓여서 분명하게 표현되었으면 좋겠어. 특히 시루 용기는
따로 표기되게.. 그리고 탭을 늘려서 배치된 식물 리스트들 나오게 하던지 하자."*

고친 것은 `game.html` 의 시트(`#sheet`) 구역과 그 CSS·그리기 함수뿐이다.
**규칙 모듈(`src/game/*.js`)은 한 줄도 안 건드렸다.** 새 숫자도, 새 상태 칸도 안 만들었다 —
화면이 이미 있던 값(`shopStatus(S).stock` · `.orders` · `CATALOG`)을 읽기만 한다.

## 결론 네 줄

1. 탭은 **[가방] [식물] [상점] [방] [검수]** 다섯이다. 가르는 자는 **그 물건이 지금 어디 있나** 하나다.
2. [가방]은 이제 **격자 인벤토리**다 — 칸마다 그림·이름·개수 배지(`×3`), 용기와 씨앗을 줄로 갈랐고
   배송 중인 것은 같은 격자에 흐리게(점선) 놓고 「2일 뒤 도착」을 붙였다.
3. 시루 카드는 **놓이면 [가방]에서 [식물]로 노드째 옮겨간다**(`holdCard`). 두 벌을 안 만들었으므로
   끌기(`bindDrag`)·상세창(`bindDetail`)·손가락 안내(`updateHint`) 배선이 그대로 산다.
4. 덤으로 **조용한 고장 하나를 잡았다** — `__byeotSheet.tab('room')` 이 표에 없는 이름이라
   **모든 탭이 꺼진 빈 시트**가 열리고 있었다(§4).

# 1. 무엇이 문제였나 — 실제로 열어 보고 적는다

| 탭 | 그 안에 있던 것 | 그래서 무엇으로 읽혔나 |
|---|---|---|
| 가방 | 「첫 플레이 · 자리의 차이」 제목 + 진행 안내 + 카드 두 장 | **퀘스트 창**. 산 물건(재고)이 어디에도 없었다 |
| 방 | 「인터넷 주문」 목록(다섯 품목 + [주문]) + 삽수 + 「방 안에서 하기」 | **상점**. 주문 목록이 탭의 대부분을 먹었다 |

재고는 코어가 처음부터 갖고 있었다(`shop.js` 의 `stock`). **없던 것은 화면의 창구뿐이었다.**

# 2. 어떻게 갈랐나 — 자는 하나다

새 개념을 만들지 않았다. **그 물건이 지금 어디 있나**로만 가른다.

| 탭 | 무엇이 있나 | 무엇이 여기 없나 |
|---|---|---|
| **가방** `#pageBag` | 산 물건 격자(`#bagGrid`) + **아직 안 놓은** 용기 카드(`#bagHold`) | 퀘스트·안내·주문 |
| **식물** `#pagePlants` | 진행 안내 한 줄(`#sheetQuest`) · 방에 놓인 작물/몬스테라(`#plantsHold`) · 삽수(`#cutBox`) | 재고·주문 |
| **상점** `#pageShop` | 인터넷 주문(`#shopBox`) · 배송 중 · 몬스테라/잉여 팔기 | 방 설정 |
| **방** `#pageRoom` | 반지하 살림(`#tutBox`) · 집과 자리(`#ctl`: 방·자리·식물등·점등시간) | 상점·삽수 |
| **검수** `#pageDev` | 그대로. 여기에 `#firstRun`(첫 플레이 자동 시뮬)이 **가방에서 옮겨 왔다** | — |

**한 물건이 두 탭에 동시에 있지 않다.** 이 성질이 이 갈래를 고른 이유다 —
"어디서 봤더라"가 안 생긴다.

## 2-1. 기본안에서 바꾼 것 둘 (지시와 다르게 한 자리라 이유를 적는다)

- **삽수(`#cutBox`)를 [방]이 아니라 [식물]에 두었다.** 삽수는 병·포트에 담겨 **방에 서 있는 식물**이고,
  자르기·분갈이·팔기는 전부 그 그루에 하는 일이다. [방]에 두면 「집·자리에 관한 것만」이 깨진다.
- **아직 안 놓은 용기 카드를 [가방]에 둔다.** 지시는 카드를 [식물]로 보내라는 쪽이었는데, 그러면
  시루 카드가 「가방에 있음」이라고 적힌 채 **가방에 없는** 상태가 된다. 두 화면이 서로 다른 말을 한다.
  ⇒ 상태에 따라 자리를 옮긴다(§3). 첫 플레이의 손가락 안내(`updateHint` → `#cropThumb`)도
  이 편이라야 그대로 산다 — [가방]을 열면 시루가 거기 있다.

# 3. 가방 — 흔한 격자를 그대로 따왔다

박사님이 "다른 게임 따오던가"라고 했다. **스타듀밸리식 격자 + 탭**을 골랐다.
품목이 일곱이고 앞으로도 열 남짓이라, 목록(한 줄에 하나)이면 개수를 세로로 훑어야 하고
격자면 배지 하나로 읽힌다.

- 칸 하나 = **그림 + 이름 + 개수 배지 `×3`**. 0개이고 오지도 않는 품목은 안 보인다.
- **용기 / 씨앗**을 작은 제목으로 갈랐다(박사님 "특히 시루 용기는 따로 표기되게").
  가르는 자는 `CATALOG[*].kind` 라 화면이 품목을 하나하나 알 필요가 없다 — 품목이 늘어도 저절로 붙는다.
- **배송 중**도 같은 격자에 흐리게(점선 테두리) + 「1일 뒤 도착」. 재고가 있는데 더 오는 중이면
  「+2 · 2일 뒤 도착」으로 덧붙는다. 「없다」와 「오는 중」이 같아 보이면 시킨 것을 또 시킨다.
- 칸 폭은 `auto-fill minmax(72px,1fr)` 이라 **폰(390)에서 4열 · PC 패널(360)에서 3열**이 저절로 난다.

## 3-2. 카드가 오가는 방식 — 노드째 옮긴다

```
holdCard(card, inRoom)   // inRoom ? #plantsHold : #bagHold
```

`innerHTML` 로 다시 그리지 않는다. **같은 DOM 노드를 옮긴다** — 그래야
`#cropThumb` 하나를 붙잡고 있는 끌기·상세창·손가락 안내가 전부 따라온다.
카드마다 `data-ord`(1 시루 · 2 무순 · 3 몬스테라)를 두어 돌아올 때 순서가 안 뒤집힌다.

# 4. ★덤으로 잡은 고장 — 빈 시트가 열리고 있었다

`selectTab` 의 표에는 `tabBag`·`tabRoom`·`tabDev` 만 있었는데, 부르는 쪽은
`__byeotSheet.tab('room')` 을 쓰고 있었다(말풍선 [삽수 자르기]·[씨앗이 없습니다],
`tools/probe_cutting_ui.mjs`). 이름이 안 맞으면 `forEach` 가 **모든 페이지의 `.on` 을 떼어**
시트가 **빈 채로** 열린다. 고장이 조용해서 아무도 안 봤다.

⇒ 짧은 이름도 받게 했다(`bag`·`plants`·`shop`·`room`·`dev`). 모르는 이름이면 지금 탭을 그대로 둔다 —
빈 시트가 다시는 안 나온다. 바깥에서 부르는 이름을 화면 구조가 정해야 할 이유가 없다.

# 5. 그 밖에 옮긴 것

- **`#firstRun`(첫 플레이 자동 시뮬)을 [가방] → [검수]로.** QA 가 적어 둔 그 자리다
  (`docs/handoff/qa-to-plan.md`: "검수용인데 `#pageBag`(플레이어의 가방 탭) 안에 있다").
- **`#ctl` 의 개발자 설정을 접었다** — 모드·[30일 자동]·[초기화]·[방 프로파일]을 닫힌 `<details>` 안으로.
  지우지 않았다. 검수가 이 넷을 쓰고, `details` 안이라 닫혀 있어도 id 로 찾아 누르는 길은 그대로다.
  `#ctl` 제목도 「방 안에서 하기」 → **「집과 자리」**.
- **말풍선이 가리키는 탭**을 목록을 따라 옮겼다: [삽수 자르기] → `plants`, [씨앗이 없습니다] → `shop`
  (씨앗이 없으면 갈 곳은 상점이다. 예전에 [방]으로 보낸 건 주문 목록이 거기 있어서였다).
- **작물 탭 확대 진입**(`__byeotZoom.open`)도 `tabBag` → `tabPlants`.

# 6-1. ★cherry-pick 할 때 — 부딪히는 자리는 **한 줄뿐**이다

이 작업은 `d7f8665` 위에서 했는데 그 뒤 main 이 `2bb52d9`(「화면이 말을 가로막던 것 넷을 걷는다」)로
`game.html` 을 또 고쳤다. 실제로 얹어 보니 **14 덩이 중 13 덩이가 그냥 붙는다.**
부딪히는 곳은 `__byeotZoom.open` 안의 **한 줄**이다.

```
        var shown = false;
        try { shown = !!(window.__byeotCropDetail && window.__byeotCropDetail(slotId)); } catch (e) { }
-       if (!shown) openSheet('tabBag');
+       if (!shown) openSheet('tabPlants');   // 카드도 못 열면 [식물] 탭 — 놓인 작물이 거기 있다
```

main 쪽이 이 줄을 「상세 카드를 먼저 열고, 못 열면 가방」으로 바꿨고 이 작업은 같은 줄을
「[식물] 탭」으로 바꿨다. **둘 다 살린다** — 상세 카드가 먼저고, 못 열 때 가는 곳만 [식물]이다.

`draw()` 도 양쪽이 건드렸지만 겹치지 않는다(main 은 `drawMarks` 를 위로 올렸고 이쪽은
`drawBag` 을 `drawMusun` 뒤에 끼웠다). 얹은 결과로 `node --check`·id 중복·`<div>` 짝을 다시 쟀고
전부 통과했다.

# 7. plan 에게 — 남은 판단 셋

1. **[식물] 탭 줄에 「받은 빛」이 없다 — 일부러 뺐다.** 지시에는 "각 줄에 이름·자란 날·**받은 빛**·
   자리 이름·상태"라고 되어 있고 값도 이미 있다(`dliBySlotId()`). 그런데 `rankSlots` 머리말이
   **첫 플레이 동안은 DLI 를 숨긴다**고 이미 정해 놨다: *"놓기도 전에 초록이 켜지면 그 배움이
   색 읽기로 바뀐다"*. 카드에 DLI 를 적으면 그 판단을 **화면 반대편에서 뒤집는 셈**이라
   내가 혼자 정할 자리가 아니다.
   ⇒ 갈 길 둘. ㉮ 첫 플레이가 끝난 판에서만 적는다(지금 `rankSlots` 와 같은 문지기).
   ㉯ 숫자 대신 「밝음/보통/어두움」 세 마디로 적는다. 박사님 확정이 필요하다.
2. **삽수가 [식물] 탭에서 카드가 아니라 줄(`.cutRow`)이다.** 작물 카드와 골격이 다르다.
   같은 탭에 두 골격이 있는 것이 지금은 오히려 갈래를 말해 주는데, 통일할지는 판단이 필요하다.
3. **가방에 「쓰는 중」이 없다.** 방에 놓인 시루는 [식물]에 있고 가방에는 없다. 그게 이 갈래의 뜻이지만,
   "내가 시루를 몇 개 갖고 있나"를 한눈에 보려면 가방에 회색 칸으로 같이 세는 길도 있다.
   지금은 **한 물건이 한 탭에만** 쪽을 골랐다.
