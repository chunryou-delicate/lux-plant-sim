## 0. 무엇이 잘못돼 있었나

박사님 원문(2026-08-09, 폰 플레이 중 사진과 함께):

> 가방에 열린 콩나물 시루가 있으면 안 되지. 콩나물시루 아이템만 있어서 그걸 드래그 하면
> 하나씩 따로따로 설치되게 하고싶어. 지금 콩나물시루를 뭉태기로 설치가 되는데 내가 의도한건
> 콩나물시루 하나하나가 각개 움직이고 각개 물주고 햇으면 좋겠어.
> 그리고 식물마다 게이지가 나와서 자라는게 표현되면 좋겠어. 시간에 따라서 게이지가 차고,
> 하루 넘기면 뭉태기로 차있고

증상 넷은 **한 뿌리**였다: **자리가 작물마다 하나**였다(`site.slotId` / `site.at`).
시루 N개는 그 한 자리 위에 무리로 섰다(`site.pots[]`).

```
자리 1개  ─┬─ 시루 1   ← 좌표가 없다. 무리 안의 몇 번째일 뿐
           ├─ 시루 2
           └─ 시루 3
```

그래서:

| 증상 | 그 자리 |
|---|---|
| 가방에 「1/5일 자람」이 뜬다 | 카드 하나가 「가방의 시루」와 「방의 콩나물」을 겸했다 |
| 끌면 4개가 함께 선다 | `commitPlace` 가 `resowCrop({sirus: 지금+가방전부, at})` 을 불렀다 |
| 「물 주기 3개」 | 말풍선이 자리 하나에 하나였다 |
| 방에서 덩어리로 보인다 | 방뷰에 `count: N` 을 줘 무리 짓기를 시켰다(multisiru §1) |

`multisiru-to-plan.md §9 ㉰` 가 *"자리를 여러 개로 나눈다 — 자리 모델을 바꿔야 한다. **이 창 범위 밖**"*
이라고 남겨 둔 것이 정확히 이것이다. 이번에 그것을 했다.

## 1. 무엇이 바뀌었나 — 자리가 **시루로 내려왔다**

```
시루 1 ── slotId · at        ← 정본. 화분(S.pots[])과 같은 두 칸이다
시루 2 ── slotId · at
시루 3 ── slotId · at
자리   ── slotId · at        ← **읽기용 사본**(대표 시루의 것). syncCropLead 가 채운다
```

`first_play.js` 가 *"자리는 여전히 하나다"* 라고 적어 둔 근거 셋을 하나씩 다시 봤고, **셋 다 무너졌다.**
근거와 반박은 코드 주석(`makeCropPot` §자리는 시루마다 따로다)에 그대로 적어 뒀다. 요약:

| 옛 근거 | 왜 안 맞나 |
|---|---|
| "시차는 시간의 축이지 자리의 축이 아니다" | 맞다. 그런데 자리를 쪼개도 시차는 그대로다(`startedOnDay` 는 이미 시루마다였다). 자리를 하나로 둬서 **얻은 것이 없었고**, 잃은 것은 있었다 — 무리가 자리 한도에 맞춰 통째로 찌그러졌다 |
| "조도 계약·방뷰가 slotId 하나를 전제한다" | 계약은 `state.placedItems(S)` 가 내는 **목록**이고, 한 물건이 여러 줄인 것은 삽수가 이미 하고 있었다. 조도 엔진은 안 고쳤다 — 목록이 길어질 뿐이다 |
| "현실이 그렇다 — 시루 셋은 같은 선반에 둔다" | 그건 **놓는 사람의 선택**이지 규칙이 아니다. 나란히 두고 싶으면 나란히 놓으면 된다 |

### 「가방에 있다」는 무슨 뜻인가

**`slotId` 도 `at` 도 없는 시루 = 가방의 빈 용기.**
처음에 받는 시루 하나가 그 상태로 시작한다. 상점에서 산 시루(`shop.stock.siru`)와 **같은 것**으로 센다 —
화면은 둘을 더해서 「가방에 N개」라고 말한다(`spareContainerOf`).

가방의 시루는 **자라지 않고 · 물도 안 받고 · 계약에도 안 실린다.** 방에 없는 것은 방의 일이 아니다.

## 2. 인터페이스 — 늘어난 것

`potId` / `potIds` 를 **안 주면 예전과 한 톨도 안 다르다.** 옛 호출부·옛 검사가 그대로 돈다.

```js
/* ── first_play.js ── */
placeCrop(fp, kindId, target, { potId })      // potId 있으면 그 시루만 · 없으면 전부(옛 뜻)
addCropPot(fp, kindId, { day })               // 빈 시루 하나를 만든다(가방에 있는 채로)
waterBeansprout(fp, day, { potIds })          // 고른 시루만 시작
harvestBeansprout(fp, { day, potIds })        // 고른 시루만 거둔다
resowBeansprout(fp, { day, potIds })          // 고른 시루만 다시 심는다
advanceBeansproutDay(fp, dli, { dliBySlot })  // 자리마다의 DLI 표 { slotId: 값 }

cropPotList(fp, day)   // ★ 화면이 읽는 유일한 창구. 시루마다 한 줄
cropPotPlaced(p) · placedCropPots(site) · idleCropPots(site) · cropPotOf(site, id)

/* ── state.js ── */
placeSiru(S, at, opt)          // ★ 빈 시루 하나를 방에 세운다 (끌기·[하나 두기] 둘 다 이걸 탄다)
waterSiru(S, potId)            // 그 시루에만 물
setCropAt(S, at, { potId })    // 그 시루만 옮긴다

/* ── loop.js ── */
harvestCrop(S, io, { potIds }) // 고른 시루만 거둔다
```

### `cropPotList` 가 내는 한 줄

```js
{ id, kind, kindKo, containerKo, ord,          // ord = 그 자리 안의 순번 ("시루 2")
  slotId, at, placed, inBag,
  started, startedOnDay, idleSinceDay, idleDays,
  needsWater, growing, ready, harvested, needsResow,
  ageDays, harvestDays, daysLeft, progress01, cycle,
  quality, avgDli, dliSoFar }
```

**판정을 화면이 다시 만들지 않게** 하려고 뒀다. 「익었나·물이 필요한가·다시 심어야 하나」가
화면에 한 벌 더 생기면 두 벌은 반드시 어긋난다.

## 3. §게이지 — **생장 규칙은 한 톨도 안 바뀌었다**

박사님 지시의 *"시간에 따라서 게이지가 차고"* 를 **표시로만** 구현했다.

- 자라는 것은 여전히 하루 단위다(`advanceBeansproutDay` 가 하루에 `ageDays++`).
- 게이지의 **진한 몫** = `ageDays / harvestDays` (확정된 날).
- **연한 몫** = 그 하루가 흐른 만큼. 방의 해가 도는 속도와 **같은 자**를 쓴다
  (`DAY_SWEEP_MS × IDLE_SWEEP_MULT` = 144초 한 바퀴). 0.995 에서 멈춘다.
- [다음 날]을 누르면 연한 몫이 진한 몫으로 **뭉텅이로** 바뀐다.

시각은 `dliHist`·품질·수확 판정 어디에도 안 들어간다. 들어가면 빛(자리)·물(시작)에 이어
**세 번째 축**이 생겨 "왜 자랐는지"가 흐려진다.

## 4. 조도 — 엔진은 안 고쳤다 (계약에 줄이 늘었을 뿐)

고친 곳은 `state.placedItems(S)` 한 곳이다. 예전에는 자리마다 한 줄이었다:

```js
out.push({ id: 'crop_01', slotId: site.slotId, at: site.at, ... })   // 시루 12개 → 1줄
```

지금은 시루마다 한 줄이다:

```js
for (const p of site.pots) if (p.slotId || p.at)
  out.push({ id: p.id, slotId: p.slotId, at: p.at, ... })            // 시루 12개 → 12줄
```

⚠ **열쇠가 시루 id 여야 한다.** 자리 id 하나를 나눠 쓰면 자유 좌표 열쇠가 `free:crop_01` 로
겹쳐 `light_adapter.slotsFor` 의 Map 에서 **뒤엣것이 앞엣것을 덮는다** — 그러면 시루마다 다른
자리의 DLI 를 못 찾는다. 그래서 열쇠가 `free:crop_01_01` 로 바뀌었다(§6 참고).

`light_adapter.js` · `data/profiles/` · `daily_light.js` 는 **한 줄도 안 건드렸다.**
`loop.js` 는 그 계약에서 시루마다 값을 **꺼내 오기만** 한다:

```js
cropDliBySlot[p.slotId] = cropDliFromReport(report, p.slotId);
advanceBeansproutDay(S.firstPlay, cropDli, { dliBySlot: cropDliBySlot });
```

### ★ 그래서 생긴 것 — **같은 날 품질이 갈린다**

시루를 어두운 데와 밝은 데에 나눠 놓으면 같은 날 거둬도 품질이 다르다
(`test_siru_each` C-2: `crisp_white` / `green_bitter`). 예전에는 자리가 하나라 불가능했다.
**「자리가 결과를 바꾼다」가 콩나물에서도 손에 잡히게 됐다.**

## 5. 옛 세이브 — 무리로 저장된 판이 **각개로** 열린다

| 옛 판의 모양 | 열리는 모양 |
|---|---|
| `pots` 칸이 아예 없고 `sirus: 3` | 시루 3개로 펴지고, **셋 다 그때 서 있던 자리**를 그대로 갖는다 |
| `pots` 는 있고 자리는 사본 하나 | 자리 사본을 시루마다 베낀다 |

지어낸 값이 아니다 — **옛 판은 실제로 한 자리에 무리로 서 있었다.** 그것이 그때의 사실이다.
그래서 열면 겹쳐 서 있지만, 그 순간부터 **하나씩 집어 옮길 수 있다**(`test_siru_each` E-5).

세이브에 `pots[].slotId` · `pots[].at` 을 실었다(`save.js §packCropPot`).
⚠ 안 실으면 **저장 한 번에 시루들이 한 자리로 뭉친다** — 각개로 흩어 놓은 판이 통째로 되돌아간다.

## 6. ★ 다른 창이 알아야 할 것

### ㉠ 자유 좌표 열쇠가 바뀌었다: `free:crop_01` → `free:crop_01_01`

시루마다 열쇠가 있어야 계약이 안 겹친다(§4). 옛 세이브의 `free:crop_01` 은 그대로 살아 있다
(시루의 `slotId` 로 옮겨지고, `slotsFor` 가 자유 열쇠를 지어내지 않고 그대로 쓴다).
**새로 놓는 것만** 새 이름이다.

### ㉡ 방뷰의 `count` 는 이제 콩나물에서 안 쓰인다

`setPlantAt(시루 id, at, { count: 1 })` 을 시루마다 부른다. `room_view.js` 의 무리 짓기
(`clusterUnit`·`buildBeansprout`)는 **지우지 않았다** — 다른 호출부가 아직 쓸 수 있고,
`test_multisiru` 16항목이 그대로 통과한다.

### ㉢ `oneroom.js` 를 두 함수 고쳤다 (소유가 겹치는 파일이라 적어 둔다)

- `clearPlacements` — 시루마다 자리를 비운다. 안 고치면 이사한 판이 **떠나온 방의 좌표**를
  들고 와서 다음 하루에 `cropDliFromReport` 가 던진다. 게임이 통째로 멈춘다
  (`test_ending_flow` 가 실제로 거기서 섰다).
- `reseatCrops` — 자라는 중이던 시루만 새 방에 앉힌다. **가방의 빈 시루는 가방에 둔다.**

### ㉣ `data/balance/` 는 한 줄도 안 건드렸다

값을 바꾸고 싶은 것은 §7 판단표에 적었다.

## 7. ★ 판단이 필요한 것

### ① 각개 수확의 **체력값** — 지금은 누를 때마다 1이 나간다

`harvestCrop` 은 부를 때마다 `spendStamina(S, 'harvest')` 를 한 번 한다.

| | 예전 | 지금 |
|---|---|---|
| 익은 시루 5개를 거둔다 | [모두 거두기] 한 번 = **손 1** | 시루마다 한 번 = **손 5** |

하루 손이 10인 판에서(`stamina.js §STAMINA_MAX`) 이건 **살림이 바뀌는 값**이다.
시루 5개를 돌리면 거두는 데만 하루의 절반이 간다.

| 길 | 무엇 | 값 |
|---|---|---|
| ㉮ 지금대로 | 각개면 손도 각개다. "다섯 개를 놓으면 다섯 번 챙긴다"가 정직하다 | 시루를 늘릴수록 손이 없다 — 삽수·몬스테라를 못 챙긴다(econgap §A-3 이 한 칸 더 나빠진다) |
| ㉯ 거두기는 자리당 1 | 첫 수확에만 손을 물리고 같은 날 나머지는 공짜 | 셈이 하나 늘어난다 |
| ㉰ [모두 거두기] 를 남긴다 | 지금 그렇다 — 아래 버튼이 익은 것을 한 번에 거둔다(손 1) | 각개가 **손해**가 된다. 그러면 각개를 아무도 안 쓴다 |

**지금은 ㉰ 다** — 각개도 되고 일괄도 된다. 그런데 ㉰ 는 두 길의 값이 달라서 오래 두면 안 된다.
**박사님·plan 이 정해 주셔야 한다.**

### ② 「모두 거두기」 버튼을 남길까

브리핑은 *"일괄이 편해서 남기고 싶으면 따로 물어라. 기본은 각개다"* 였다. **묻는다.**
지금은 남겨 뒀고, 방 말풍선이 보일 때는 **안 뜬다**(말풍선이 시루마다 각개로 뜬다).
즉 일괄은 「방이 안 보일 때의 뒷길」이다. 없앨지, 이대로 둘지 정해 주십시오.

### ③ 물주기는 예전에도 각개였다 — 글자가 거짓말이었다

박사님이 보신 「물 주기 3개」는 **한꺼번에 주는 버튼이 아니었다.** `waterCrop` 은 예전부터
한 번에 하나만 시작했고, `(3개 대기)` 는 「아직 안 준 시루가 3개」라는 뜻이었다.
글자를 고쳤고(「한 시루에 물 주기 (3개 대기)」), 말풍선은 이제 시루마다 뜬다.

## 8. 못 한 것 — **폰 배치 방식** (코디네이터 지시 2026-08-09)

> 폰에서는 가방드래그가 좀 힘든거같어. (…) 템을 눌러서 배치하기 누르면 그냥 빈칸으로 임시로
> 가있고 (배치 말고 이동상태고 상대이동 드래그 배치 가능하게) 거기서 드래그해서 놓고,
> 놓으면 그 물품 옆으로 확인버튼이 떠서 그 확인을 누르면 거기로 일단 배치되는거고

**안 했다.** 시루 각개가 먼저라고 지시받았고, 각개가 이 방식의 **전제**이기도 하다
(무엇을 배치 상태로 띄울지 정하려면 개체가 있어야 한다).

### 설계 — 붙일 자리는 이미 다 있다

지금 코드에 **필요한 부품이 전부 있다.** 새로 만들 것은 [확인] 버튼 하나뿐이다.

| 필요한 것 | 이미 있는 것 |
|---|---|
| 임시로 세워 두기 | `placeSiru(S, at)` — 아무 데나 놓고 나중에 옮기면 된다 |
| 이동 상태 | `picked.beginMove()` — 고른 것을 화면 아무 데나 끌어 옮긴다 |
| 상대이동 | `applyPointerMode('relative')` — 이미 있고 `test_uiwire` P-1~P-6 이 지킨다 |
| 옆에 뜨는 버튼 | `placeFurnMenu(p)` — 가구 메뉴가 **이미 그 일을 한다**(화면 밖으로 안 나가게 접는 셈까지) |
| 그 시루만 옮기기 | `commitPlace(what, hit, { potId })` (이번에 넣었다) |

⇒ 순서는 이렇게 된다:

```
[가방] 시루 카드 → [배치하기]
  → 가방을 닫고 · placeSiru 로 방 가운데(또는 마지막 빈 자리)에 세우고
  → picked.select(그 시루) · picked.beginMove()   ← 여기서부터 「이동 상태」
  → 손을 떼면 picked.up() 이 commitPlace 를 부르는 대신 **[확인]을 띄운다**
  → [확인] → commitPlace(potId) 로 확정 · [취소] → 원래 자리로 되돌린다
```

### ⚠ 이 저장소가 이미 밟은 지뢰 (코디네이터 경고 + 코드에 남은 자국)

1. **전역 `#sheet .itemcard:active { transform: scale(.995) }`** — 자리를 `transform` 으로
   잡는 버튼은 누르는 순간 튄다. 가구 메뉴가 `left/top` 으로 자리를 잡는 이유가 그것이다.
   [확인] 버튼도 **`left/top`** 으로 잡아야 한다.
2. **꺼진 오버레이가 포인터를 먹는다** — 가구 메뉴는 `visibility:hidden` 으로 감춘다.
   `display:none` 이 아니면 크기를 잴 수 있으면서도 포인터를 안 먹는지 반드시 확인할 것.
3. **밑 캔버스가 눌림을 가져간다** — `test_uiwire` F-5·F-6 이 가구 메뉴에 대해 이미 그것을
   재고 있다. [확인] 버튼도 **같은 검사를 새로 써야 한다**(버튼 한가운데 · 상자 바깥 6px).
4. **화면 밖으로 나가는 자리** — `placeFurnMenu` 가 캔버스와 화면의 **겹치는 부분** 안으로
   접는 셈을 이미 갖고 있다. 베끼지 말고 그 함수를 **일반화해서 같이 쓰는 것**이 맞다.

## 12. ③ 놓은 것이 길을 막는다 — **경고만 한다**

박사님: *"막는거 경고는 해주되, 막히면 뭐 재배치하면 되지 그 식물을."*

### ⚠ 고친 것은 **한 줄짜리 사실**이다

그전까지 `nav.setWorld` 가 받는 것은 방을 지을 때 나온 벽·가구뿐이라,
**시루를 아무리 깔아도 캐릭터가 통과했다.** 그래서 「여기 놓으면 저기 못 간다」는
말할 근거 자체가 없었다 — 언제나 갈 수 있었기 때문이다.
이제 놓인 그루를 상자로 바꿔 같이 물린다(`room_view.navColliders` · `refreshNavObstacles`).

### 새 창구 (`room_view`)

```js
roomView.reach(key)      // → { ok, reason }         그 그루 곁으로 갈 수 있나
roomView.unreachable()   // → [{ key, potId, reason }]  지금 못 가는 그루 전부
```

재는 법은 `runAct` 가 **실제로 걷는 방식 그대로**다(`standNear` → `nav.path`).
새 규칙을 안 만들었다 — 만들면 화면이 말하는 것과 캐릭터가 걷는 길이 갈린다.

### 화면은 **말만 한다**

[확인] 바에 한 줄이 붙는다: 「여기 두면 시루 2에 못 갑니다 — 그래도 두시려면 [확인]」.
**[확인]은 잠기지 않는다.** 눌러 넘긴 경고도 기록에는 남는다.

### 잰 것 — 이것이 이 변경의 증거다

| | 놓기 전 | 놓은 뒤 |
|---|---|---|
| 그 **바닥** 점에 설 수 있나 | `ok: true` | `ok: false · 가구·벽에 걸립니다` |

⚠ **가구 위에서 재면 안 된다.** 가구 칸은 그 가구가 이미 막고 있고, 그 자리에서는
「화분끼리 겹침」 검사가 먼저 걸려 **길 판정을 안 거친다** — 그걸로 통과시키면 검사가
아무것도 안 재고 통과한다. 실제로 처음에 그렇게 썼다가 잡았다(`test_place_confirm` ③ 주석).

### 안 한 것

- **도달 범위 제한(4칸)** — 코디네이터 지시대로 **안 했다.** 지금 값으로는 체력이 8배 먼저 막는다.
- **캐릭터 반경**(0.38m)은 그대로 뒀다 — 박사님이 말씀하신 2칸보다 이미 넓다.

## 15. 체력·경험치 — 붙인 모양

### 숫자는 표가 갖는다 (`data/balance/stamina.json` · **새 파일**)

```
startMax 5 · maxCap null(상한 없음) · cost{water,harvest,sow,cut,repot} = 1 · xpPerStamina 1
levelUp.table { 5:10, 6:15, 7:20, 8:25, 9:30 } · beyondFrom 10 · beyondMult 10
quests { siru5_cycle5: 1 }
```

⚠ **곡선이 아직 최종이 아니라** 코드에 안 박았다. `staminaRulesFrom(json)` 하나가 읽어 꽂고,
파일이 없으면 `STAMINA_RULES` 밑값으로 돈다(밸런스 파일 하나 때문에 방이 안 열리면 안 된다).
`data/balance/**` 는 남의 것이라 **기존 파일은 한 글자도 안 건드렸다.**

### 규칙

- **레벨 = 최대체력 그 자체다.** 별도 레벨 숫자를 안 만들었다 — 두 숫자를 두면
  「레벨 7인데 체력 5」가 되어 무엇이 오른 것인지 흐려진다.
- **경험치 = 그날 쓴 체력.** `spend()` 안에서 같이 쌓인다. 따로 세는 축이 없다.
- **오른 그날 남은 손도 같이 는다** — 안 그러면 "올랐는데 오늘은 못 쓴다"가 되어 보상이 하루 밀린다.
- **안 내려간다.** 세이브에 `max`·`xp` 를 싣는다.
  ⚠ 옛 주석이 *"`max` 는 규칙이지 판의 상태가 아니다"* 였는데 **그때는 맞았다**(누구나 10이었다).
  이제 오르므로 `max` 는 **그 판이 쌓은 것**이다.
- **레벨업이 보인다.** `takeLevelUps(S)` 가 가져가며 비우고 화면이 배너로 띄운다(두 번 안 나온다).
  배너는 기존 `banners()` 상자 규칙(묶어서 세 줄까지·6초·누르면 닫힘)을 그대로 탄다.
- **★ 왜 못 하는지 말한다.** 체력이 모자라면 버튼 글자가
  「오늘 손이 다 떨어졌습니다 (0/5) — [다음 날]을 누르면 5만큼 다시 채워집니다」로 바뀐다.
  ⚠ `disabled` 는 **안 건드린다** — 잠긴 버튼은 말풍선의 `click()` 까지 삼킨다(2026-08-08 버그).

### 퀘스트는 **창구만** 열었다

`grantStaminaQuest(S, 'siru5_cycle5')` 가 있고 표에 +1 이 있다. **부르는 데가 없다** —
무엇을 「시루 5개 분배 5주기 완주」로 볼지는 분배 계통이 정해야 한다(§16).

### ⚠ 다른 워커 측정과 **안 맞는다** — 짐작 말고 그대로 적는다

| | 코디네이터가 전한 값 | 내가 잰 값 |
|---|---|---|
| 시루 6개 못 한 날 | 50일 중 **1일** | 50일 중 **11일** |
| 첫 레벨업 (2개 / 5개) | 13일 / 7일 | **10일 / 5일** |

**어느 쪽이 틀렸는지 나는 모른다.** 다만 내 쪽 전제는 적어 둘 수 있다:
① 매일 할 수 있는 것을 **다 한다**(부지런한 플레이) ② 몬스테라 선물을 **껐다**(하네스 우회,
아래 ⚠) ③ 물은 시루마다 하나씩 준다. 전제가 다르면 값이 다르다 — **같은 전제로 다시 재야 한다.**

### ⚠⚠ 이 측정에서 한 번 **틀린 값을 낼 뻔했다** — 적어 둔다

처음 잰 값은 「시루 1개인데 50일 중 **35일**을 못 했다」였다. 체력 탓인 줄 알았는데
**아니었다**: 세 번째 수확에 몬스테라 선물이 오는데 하네스의 생장 스텁이 `growthPhase()` 를
안 내서 **수확이 던지고 있었다.** 그 던짐을 「체력이 모자란 날」로 세고 있었다.
⇒ 막힌 **사유를 같이 찍게** 고쳐서 잡았다. 사유를 안 찍었으면 그대로 보고할 뻔했다.

## 19. ★★ 체력 상한을 없앴다 (2026-08-09 3차 중 재확정)

박사님: *"체력도 상한이 없이 계속 ×10 쓰면 1씩 오른다 치고"* — 앞서 「최대 20」이라 했던 것이 취소됐다.

| 구간 | 필요 경험치 |
|---|---|
| 5 → 10 | **10 · 15 · 20 · 25 · 30** (앞서 10·20·30·40·50 에서 완만하게 내려옴) |
| 10 위 | **최대체력 × 10** — 11→12 는 110, 30→31 은 300 … **끝이 없다** |

### ⚠ 「없음」을 큰 수로 흉내 내지 않았다

`maxCap: null` 이 **없다**는 뜻이다. 999 같은 값으로 두면 화면이 「최대 999」를 보여 주거나
진행바가 이상해진다. 코드는 `Number.isFinite(R.maxCap)` 일 때만 막는다 —
**나중에 상한을 두기로 하면 표에 숫자 한 개만 넣으면 그때부터 막힌다**(검사 A-8 이 그 길을 지킨다).

### ★ 화면이 큰 수를 못 견디던 자리 하나 — **재서 잡았다**

| 최대체력 | 점 줄(`#staDots`) | 자원칩 | 넘침 |
|---|---|---|---|
| 10 | 점 10개 | `0/10` | 없음 |
| **78** | **점 78개 → 한 줄이 통째로 무너짐** | `0/78` | 없음 |
| 999 | 점 999개(무너짐) | `123/999` (63.2px) | 없음 |

⇒ **12칸까지만 점**이고 그 위는 숫자(`0/78`)로 바꿨다. 점은 「한눈에 세어지는 것」이
값어치인데 스무 개를 넘으면 이미 못 센다. `test_place_confirm ④` 가 10 · 78 · 999 를
실제로 넣어 보고 지킨다(칩 넘침·진행바 0~100%까지 같이 본다).

경험치는 누적이 수만이 되어도 `title` 문구와 세이브(`needInt`)가 그대로 받는다 —
`9999/9990` 을 넣어 확인했다.

## 22. ★★★ 급한 버그 — 삽수가 식물등 빛을 **아예 못 받고 있었다** (2026-08-09)

### 무엇이 잘못돼 있었나 — 한 줄

`io.light.dliOfSlot(ref, opt)` 는 `opt` 에서 **날씨·계절·등 개수·켠 시간**을 받는다.

```js
화분:  dliOfSlot(p.at ? p : p.slotId, { weather, season, lampCount, litHours })   ← 넷을 다 넘김
삽수:  dliOfSlot(c, {})                                                          ← 하나도 안 넘김
```

⇒ **삽수와 그걸로 키운 새 모주는 식물등 빛을 한 톨도 못 받았다.**

### 잰 값 (반지하 · 등 1개 · 12시간 · 맑음/여름)

| 자리 | 빈 옵션 `{}` | 고친 뒤 | |
|---|---|---|---|
| `banjiha-etagere:7` | **0.48** | **12.31** | **25.6배** |
| `banjiha-etagere:6` | 0.51 | 5.98 | 자란다 |
| `banjiha-etagere:8` | 0.48 | 5.95 | 자란다 |
| `banjiha-sill:0` | 4.80 | 6.64 | 자란다 |
| 나머지 10칸 | 0.05~0.61 | 0.10~2.27 | 안 자란다 |

몬스테라 최소 DLI 는 **3**이다. ⇒ 고치기 전에는 **등 밑에 둬도 영영 안 자랐다.**
400일을 돌려도 새 모주 잎이 1장·0장이던 증상과 앞뒤가 맞는다.

**화분(몬스테라)의 DLI 는 한 자리도 안 움직였다** — 그쪽은 원래 넷을 다 넘기고 있었고,
이번에 바꾼 것은 **그 넷을 어디서 짓느냐**뿐이다(값은 같다. `J-1` 이 그 동일성을 잰다).

### 어떻게 고쳤나 — **베끼지 않았다**

두 부르는 데가 하는 일이 다르다: 하나는 「오늘」(`report.sky`), 하나는 「그 날씨라면」
(`expectedWeekStats` 의 what-if). 그래서 **함수를 통째로 묶을 수는 없다.**
⇒ **옵션을 짓는 일**만 한 곳으로 묶었다:

```js
export function lightOptsOf(S, sky) {
  return { weather: sky && sky.weather, season: sky && sky.season,
           lampCount: (S && S.lamps && S.lamps.count) || 0,
           litHours: (S && S.lamps && S.lamps.litHours) || 0 };
}
```

칸이 하나 더 늘어도 **여기만** 고치면 두 곳이 같이 따라온다. 이번 사고가 난 이유가
「같은 일을 두 곳에서 따로 적었기 때문」이라 그 자리를 없앴다.

### ★ 자리가 진짜 상한이다 — 확인했다

- **등 1개에서 몬스테라가 자라는 자리는 넷뿐이다**: `sill:0` · `etagere:6` · `7` · `8`.
  (코디네이터가 전한 값과 **일치한다.**)
- **등을 더 사도 안 풀린다**: `etagere:7` 이 등 1개 12.31 → 2개 **12.41** (**+0.8%**).
- ⇒ 모주를 늘리려면 **가구(선반)가 밝은 칸을 만들어야** 한다.

### 검사

`tools/test_cutting_wiring.mjs §J` 4항목 + 실측 두 줄을 새로 넣었다.
`J-1` 이 「삽수와 화분이 같은 칸을 넘기는가」를 지켜서, 앞으로 한쪽만 늘어나면 그 자리에서 걸린다.
