## 발견한 것 ★

### 1. 캐릭터 키가 1.50/1.70 → **1.40/1.50 으로 줄었습니다**

방이 좁아 보인다는 판단으로 낮췄습니다(2026-07-26). **키를 하드코딩한 곳이 있으면
어긋납니다.** 몬이는 **연동 안 합니다** — 0.375m 고정입니다.

```js
여 1.40 · 남 1.50 · 몬이 0.375  ← GLB에 이미 구워져 있음. 엔진에서 추가 스케일 금지
```

### 2. 색 커스터마이징은 **기술적으로 막힌 것**이지 안 한 게 아닙니다

머리·눈썹·피부·홍채 색을 바꾸려면 부위 마스크가 필요한데,
Meshy가 **아틀라스 한 장에 전신을 굽습니다.** 실측한 벽:

- 피부 R−G **24~48** vs 옷 **−20~+39** → **겹칩니다.** 전역 임계값이 존재하지 않음
- 남주부 셔츠는 그의 얼굴과 색도 거리 **0.0247** — 남연구원 **손(0.0374)보다 얼굴에 가깝습니다.**
  어떤 색공간을 써도 "셔츠 = 피부"로 분류됩니다
- 눈매는 여캐 3종에서 끝내 안정화 못 했습니다(눈꼬리가 눈썹 쪽으로 올라가는 형태)

**기획에 주는 의미** — "캐릭터 색 커스터마이징"을 기능 목록에 넣으실 거면
**모델 생성 단계에서 부위를 나눠 뽑아야 합니다.** 사후 마스크로는 안 됩니다.
재시도할 사람이 같은 데서 안 막히게 **함정 8개를 표로** `assets/characters/README.md` §5 에 남겼습니다.

### 3. 게임 화면은 반드시 `lq/` 를 쓰세요

원본은 방 전체와 같이 돌리면 눈에 띄게 버벅입니다. 클립은 **노드 이름 바인딩**이라
원본·경량본 **어느 쪽에도 그대로 붙습니다.**

### 4. 모션 클립 128개는 캐릭터에 종속되지 않습니다

Meshy 리깅이 24본 표준 골격에 **노드 이름이 8종 전부 동일**합니다.
→ 키를 다시 바꾸셔도 **클립은 손댈 필요 없습니다**(씬 최상단 래퍼에 스케일만 얹는 방식).
캐릭터를 추가해도 클립은 재생성 불필요합니다.

### ③ 은 Meshy 를 안 쓰고 끝났습니다

새 idle 3~4종을 뽑을 계획이었는데(12cr) **기존 16종으로 됩니다.**
`tools/char/check_idle_break.py` 로 전수 측정해 **10종**을 골랐습니다 —
서서 하고, 끝자세가 시작으로 돌아오는 것만.

| 판정 | 클립 |
|---|---|
| 변주 가능 10종 | `wave` `cheer` `listen` `heart` `happyjump` `harvest` `scratch` `opendoor` `pickup` `sleep` |
| 앉음·누움 | `sit`(Hips 72%) · `harvest_crouch`(68%) · `doze`(55%) |
| 끝자세 안 돌아옴 | `repot`(46도) · `inspect`(91도) |

**leaf 의 토마토·고추 90cr 과 경합하지 않습니다.** 잔액 22cr을 leaf 가 다 쓰셔도 됩니다.

배정표와 재생 코드는 `char-to-house.md` 에 올렸습니다 — 엔진이 house 소유라 제가 못 붙입니다.

> 못 잰 것: **그 동작이 그 성격으로 보이는가.** 배정은 클립 이름과 측정값으로 정했고
> 눈으로는 안 봤습니다. `motion_library.html` 로 확인하시면 되고,
> **바꾸실 게 있어도 배정만 고치면 됩니다. 에셋은 그대로입니다.**

## 판단이 필요한 것 ★ (지금은 없음)

3건 모두 답변받았습니다. 다음으로 판단이 필요한 시점은 **core 루프 재미 확인 후**입니다.
아래는 그때 참고하실 기록입니다.

### ① 표정 — 착수 시점만 정해 주시면 됩니다

박사님이 **"core 최소 루프가 재미 확인선을 넘은 뒤"** 로 정하셨습니다. 대기 중입니다.
방식은 확정돼 있습니다 — **B안(얼굴 텍스처 교체)**, 눈 4종 + 입 몇 종, **깜빡임 먼저.**

> 부위 마스크가 아니라 **얼굴 전체 텍스처를 통째로 교체**하는 쪽입니다.
> 위 §2에서 마스크가 실패한 게 근거입니다. 같은 함정을 안 밟습니다.

### ② 2D 초상화(대화용) — 아직 시작하면 안 된다고 봅니다

8종 × 7표정 = **56장**입니다. **대화 시스템 설계가 먼저**여야 낭비가 없습니다.
지금은 대화 UI도 없습니다. 기획에서 대화 형식(전신/흉상, 표정 종류)이 정해지면 그때.

### ③ 캐릭터별 성격 차이를 **에셋으로 표현할지**

지금 8종은 **외형만 다릅니다.** 모션 19종은 전원 공용입니다.
성격 차이를 주려면 두 갈래인데, 기획 결정이 필요합니다.

| 안 | 비용 | 효과 |
|---|---|---|
| **㉮ 기본 자세만 다르게** | 낮음 (idle 클립 3~4종 추가) | 서 있는 모습만으로 구분됨 |
| ㉯ 캐릭터별 전용 모션 | 높음 (Meshy 재생성 × 8) | 확실하지만 128 → 수백 파일 |

**㉮ 권고.** 게임 화면에서 캐릭터는 대부분 서 있거나 걷습니다.
