## 1. ★★★ 제일 먼저 — **크기의 정본이 프리셋 JSON 이 아니었다**

박사님이 짚어 주신 바로 그 자리다. 재서 확인한 것:

| | |
|---|---|
| `data/furniture_presets.json` 의 `w`·`d`·`h` | **빌더에 넘기는 밑값**이다. 117개 중 **28개는 셋 다 없다**(협탁이 그렇다) |
| 있어도 뜻이 다른 것 | **천장등 `h` 0.35 는 갓 높이**인데 실제 크기는 줄까지 **0.55** 다. 펜던트 둘도 같다 |
| 진짜 크기 | `src/render3d/furniture_pastel.js` 의 `g.userData.size` — **빌더가 정본이다** |

⇒ **부피로 값을 매기는데 그 부피를 JSON 의 `w·d·h` 로 재면 절반이 틀린다.**
협탁은 부피 0 이 되어 밑값(30,000원)으로 주저앉고, 천장등은 실제보다 36% 작게 잡힌다.

### 어떻게 풀었나 — ㉰ (정본을 한 곳으로) + **검사로 못 박기**

1. **빌더를 실제로 돌려**(`vendor/three/three.min.js` 를 node 에서 그대로 불러 쓴다 — 브라우저가 필요 없다)
   117개의 `userData.size` 를 받아 **프리셋 파일의 `size_m` 칸에 박았다.** 손으로 안 적었다.
2. 상점은 **`size_m` 하나만** 본다(`w·d·h` 는 한 번도 안 읽는다).
3. ⚠ **`w`·`d`·`h` 는 한 톨도 안 건드렸다.** 건드리면 빌더 입력이 바뀌어 가구가 실제로 변한다
   (천장등 `h` 를 0.55 로 「고쳤으면」 갓이 커졌을 것이다).
4. ★ **`tools/test_furnishop.mjs §A` 가 117개를 빌더로 다시 지어 `size_m` 과 대조한다.**
   한 톨이라도 다르면 빨개진다 — 값이 두 벌인 것을 **검사가 지킨다.**

⇒ 그리고 **크기가 정말로 없는 프리셋은 0개**다. 117개가 전부 값을 갖는다.

⚠ **방 정의가 프리셋을 덮어쓰는 것은 그대로 남아 있다**(창턱 깊이 0.24 → 0.30 이 그 예다).
  상점 값은 **프리셋 크기**로 매기고, 방이 덮어쓴 크기로 값을 물으려면
  `furnitureQuoteOf(preset, { sizeM })` 에 그 크기를 넘기면 된다. §C 의 반지하 합계가 그렇게 쟀다.

## 3. 값 — **부피 하나로 센다**

```
정가   = 100원올림( 30,000 + 140,000 × 부피[㎥] )
실구매 = 정가 × 1.4 → 100원 올림      (다른 품목과 **같은 규칙** · buyPriceOf)
되사기 = 정가 × 0.30 → 100원 내림
```

### 왜 갈래 계수를 안 뒀나
갈래마다 계수를 매기려면 **60여 개의 숫자를 지어내야** 한다. 지어낸 값은 근거가 없어
다음 사람이 못 고친다. 재 보니 **부피 하나로도 한국 실거래가 범위에 전부 들어왔다**:

| 가구 | 이 규칙 | 실제 시세 |
|---|--:|---|
| 협탁 | 56,300 | 5~8만 |
| 의자 | 85,700 | 5~10만 |
| 책상 | 132,800 | 10~20만 |
| 서랍장 | 120,400 | 10~20만 |
| 옷장 | 258,100 | 20~40만 |
| 2인 소파 | 325,000 | 30~60만 |
| 싱글 침대 | 410,500 | 20~40만 |

### ★★ 두 상수는 **이 게임의 돈에 맞춘 것이다** (「비싸게」가 얼마인가)

먼저 뽑아 놓은 돈 감각:

| | |
|---|--:|

그 사이에 이렇게 놓았다:

⇒ **제일 싼 것 러그(민트) 46,700원(월세 0.23달) ~ 제일 비싼 것 이층 침대 733,600원
   (월세 3.67달 · 시작돈의 49%)** 사이에 81개가 선다.

## 4. ★★★ 되사는 값 **정가의 30%** — 재서 정했다

이 저장소에 있던 되사기 규칙은 **잉여 채소 85%** 하나인데 **안 따랐다.**
채소는 오늘 거둔 상품이고 가구는 **중고**다. 그리고 결정적인 이유가 따로 있다.

**85% 로 두면 반지하 탈출이 깨진다.** 반지하에 팔 수 있는 가구가 여섯이다:

| uid | 가구 | 정가 | 실구매 | 되사는 값(30%) |
|---|---|--:|--:|--:|
| `banjiha-bed` | 싱글 침대 | 293,200 | 410,500 | 87,900 |
| `banjiha-desk` | 책상 | 94,800 | 132,800 | 28,400 |
| `banjiha-chair` | 의자 | 61,200 | 85,700 | 18,300 |
| `banjiha-dresser` | 서랍장 | 86,000 | 120,400 | 25,800 |
| `banjiha-etagere` | 선반-다단-3단 | 50,900 | 71,300 | 15,200 |
| `banjiha-nightstand` | 협탁 | 40,200 | 56,300 | 12,000 |
| | **합** | **626,300** | 877,000 | **187,600** |

- **85%면 532,000원**이 그냥 생긴다 — 이사비 200만의 **27%** 이고, 하프문 그루를 판 뒤 남는
  여유(21만원 · START-HERE §6)의 **2.5배**다. ⇒ **「침대를 팔아 이사 간다」가 열려
  하프문이 탈출의 축이 아니게 된다.**
- **30%면 187,600원** — **월세 한 달치(20만)의 94%** 이고 이사비의 **9.4%** 다.
  ⇒ 「가구를 팔면 한 달을 버틴다」는 되고 **「가구를 팔아 나간다」는 안 된다.**
- 되사려면 877,000원이라 **판 값의 4.7배** — 홧김에 못 판다.

⚠ 100원 단위 **내림**이다(사는 값은 올림). 중고를 넘기는 쪽이 손해를 본다.
★ `test_furnishop §C` 가 「반지하를 다 팔아도 이사비의 15% 미만」과 「월세 0.7달치 이상」을
  **양쪽에서** 못 박는다 — 값을 만지면 그 자리에서 빨개진다.

## 7. 세이브 — **자리표만으로는 못 적는다**

⚠⚠ **`S.home.furniture` 는 「방에 무엇이 있나」가 아니다.** 그 표는 **옮긴 자리**만 담고
(`{uid:{x,z,rot,y}}`), 방에 무엇이 서 있나는 `house_rooms.json` 이 갖는다. 조도 엔진은
조립 직전에 그 표를 **덮어쓰기로만** 얹는다(`light_adapter §defWithOverrides`).
⇒ **지우는 길도 더하는 길도 원래 없었다.** 자리표에서 지우는 것만으로는
  판 가구가 **다시 켤 때 되살아난다.** 그래서 칸을 둘 뒀다:

```
S.home.furnitureSold  = ['banjiha-chair', …]                  판아서 걷어낸 uid
S.home.furnitureAdded = [{uid, preset, x, z, rot, y?}, …]     사서 놓은 것
```

`save.js` 의 `packSoldFurniture` · `packAddedFurniture` 가 적는다.
★ `preset` 을 반드시 적는다 — 없으면 다시 켤 때 **무슨 가구인지 모른다**
  (자리표에는 프리셋이 안 실린다. 원래 방 정의가 갖고 있었으므로).
★ **옛 세이브는 두 칸이 없다 → 빈 목록으로 열린다 = 「아무것도 안 팔았고 안 놓았다」.**
  그 판의 방은 `house_rooms.json` 그대로이므로 **저장될 때와 똑같이 열린다.** 검사 G 가 못 박는다.

## 9. `src/game/light_adapter.js` 가 붙일 코드 (⚠ 이것도 내 쓰기 영역 밖이다)

**이것이 안 붙으면 상태·세이브는 맞는데 화면이 안 바뀐다.** 지금 `defWithOverrides` 는
**자리를 덮어쓰기만** 하고 더하거나 빼는 길이 없다.

```js
/* ① 상태 두 칸 — furnOverrides 와 같은 규약(플레이어가 실제로 한 것만 담는다) */
let furnSold = [], furnAdded = [];
function setFurnitureEdits(sold, added) {
  furnSold  = Array.isArray(sold)  ? [...sold] : [];
  furnAdded = Array.isArray(added) ? added.map(f => ({ ...f })) : [];
  return { sold: furnSold, added: furnAdded };
}

/* ② defWithOverrides 를 넓힌다 */
function defWithOverrides(def) {
  if (!Object.keys(furnOverrides).length && !furnSold.length && !furnAdded.length) return def;
  const lay = f => { const o = f.uid ? furnOverrides[f.uid] : null; return o ? { ...f, ...o } : f; };
  const base = (def.furniture || []).filter(f => !furnSold.includes(f.uid)).map(lay);  // 판 것을 걷는다
  return { ...def, furniture: [...base, ...furnAdded.map(lay)] };                      // 산 것을 더한다
}

/* ③ 창구로 낸다 (return 객체에 두 줄) */
setFurnitureEdits,
```

## 10. 못 한 것 — 있는 그대로

1. **화면이 아직 안 바뀐다.** §8·§9 가 붙기 전에는 가구 상점도 [팔기] 단추도 없다.
   ⇒ **「팔면 방에서 사라지고 다시 켜도 안 되살아난다」를 화면에서 못 쟀다.**
     상태·세이브 수준에서는 검사 F·G 가 못 박았다.
2. **사서 놓는 3D 길이 없다.** `roomView.furnitureFit`·`previewFurnitureAt` 은
   **방에 이미 있는 가구**만 안다(uid 로 노드를 찾는다). 새로 산 가구는 아직 방에 없어서
   그 창구를 그대로 못 쓴다 — `room_view` 가 「목록에 없는 프리셋으로 유령을 만드는」
   길을 열어야 한다. ⇒ 그때까지 **사면 재고까지만** 간다(박사님 지시도 그러하다).
   `placeBoughtFurniture` 는 그 길이 열렸을 때 부를 창구로 미리 뚫어 두었다.
3. **가구 색**(`colorways` 14색)은 안 건드렸다. 지금은 프리셋마다 색이 고정이다.
4. **배송이 전부 2일**이다 — 침대도 협탁도 같다(§② 「부피가 있는 것은 2일」 규칙 그대로).
   큰 가구를 더 늦게 오게 할지는 판단 필요.
