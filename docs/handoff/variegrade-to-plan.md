# 2026-08-09 · variegrade → plan (무늬 등급을 눈으로 매기는 도구)

## 무엇을 했나

**`tools/varie_grade.html`** 을 만들었다. 변이 원화를 격자로 늘어놓고 한 장씩
등급(무지 / 산반 / 섹터 / 하프문 / 고스트)을 고르는 페이지다.

```
python tools/serve.py 8963
http://localhost:8963/tools/varie_grade.html
```

- 고른 것은 `localStorage`(`byeot.varie_grade.v1`)에 남는다 — 새로고침해도 안 날아간다
- 썸네일을 누르면 **원본을 전체화면으로** 띄운다. 거기서도 등급을 고를 수 있다
- 다 고르면 **내보내기** → JSON / 마크다운 표를 복사할 수 있다
- 위쪽에 「이 등급이면 값이 얼마가 되나」 표가 있다. **숫자를 손으로 안 적었다** —
  `src/game/shop.js` 의 `priceOf` 를 직접 부르고, 이사비는 `data/balance/homes.json`
  에서 읽는다. 코드나 밸런스 값이 바뀌면 표가 따라 바뀐다

같이 만든 것:

| 파일 | 무엇 |
|---|---|
| `tools/make_thumbs.py` | 원화 → 썸네일. 원화가 늘면 다시 돌리면 된다 |
| `tools/probe_varie_grade.mjs` | 이 도구가 실제로 도는지 재는 검사(여섯 항목) |
| `assets/existing/thumbs/` | 썸네일 100장 + `index.json`(원본경로 → 썸네일 이름) |

**아무 등급도 미리 안 찍었다.** 이름에 「하프문」이 든 것조차 비워 두었다 —
그림이 이름과 다를 수 있고, 정하는 것은 박사님이다.

## 발견한 것

### ★ 41종이 아니라 **34종**이다

세어 보니 매니페스트에서 `name_ko` 가 `변이-` 로 시작하고 갈래가 「잎·몬스테라」인 것은
**34종**이다. `docs/asset_catalog.md` 의 변이 줄도 정확히 34줄이다.

| 갈래 | 종 |
|---|---|
| 몬스테라 모양 · 초기 | 1 |
| 몬스테라 모양 · 중간 | 1 |
| 몬스테라 모양 · 성숙 | 19 |
| **하트·포토스 모양 · 중간** | **13** |
| 합계 | **34** |

그 밖에 **색변형 66종**(`-쨍` / `-차분`)이 따로 있다. 원본에서 채도만 옮긴 판이라
*"모양·무늬 동일"* 이라고 매니페스트가 직접 적어 두었다. 그래서 **기본 34종만 먼저 보이고**,
[색변형도 보기] 를 누르면 66종이 더 나온다. 34 + 66 = 100 종이 전부다.

### ★★ 「잎·몬스테라」 갈래인데 **몬스테라 잎이 아닌 것이 13종** 있다

중간 단계 14종 중 **13종의 3D 판이 `pothos_*` · `heart_*`** 다.
갈래는 몬스테라인데 실제 그림은 하트(스킨답서스) 잎 모양이다.

```
변이-하프문-크림민트    heart_halfmoon_v2_stem.glb
변이-마블-그린옐로우     pothos_marble_greenyellow.glb
변이-스페클-실버점      heart_speckle_2657.glb        … 모두 13종
```

값 체계가 다를 수 있어(`shop.js` 의 `UNIT_WON` 은 `monstera` 와 `pothos` 를 갈라 둔다 —
성체 잎당 10,000 대 3,750) **화면에서 갈라 두었다.** 등급을 매기실 때 같은 잣대를 쓸지
갈래를 나눌지는 박사님·plan 판단이다.

⇒ 결과가 뜻하는 것: **몬스테라 중간 단계 무늬 잎이 사실상 1종뿐**이다
(`변이-알보-전체흰중기`). 초기도 1종이다. 잘 자란 그루의 무늬는 성숙 19종이 다 받쳐 주는데
그 앞 단계는 비어 있다.

### 값 표가 말하는 것 (잎 8장 · `priceOf` 가 낸 값)

| 등급 | 무늬 잎 | 잎당 배수 | 그루값 |
|---|---|---|---|
| 무지 | 0장 | ×1 | 80,000원 |
| 산반 | 1장 | ×8 | 150,000원 |
| 섹터 | 2장 | ×35.56 | 771,111원 |
| 하프문 | 3장 | ×71.11 | **2,183,333원** ★ |

★ = 원룸 이사비 2,000,000원을 넘긴다. 즉 **하프문 잎 3장이 이사 한 번**이다.

## ★ 다른 창이 알아야 할 것

- **`src/game/**` · `game.html` · `data/**` 를 하나도 안 고쳤다.** 이건 도구다.
  읽기만 한다 — `shop.js`(`priceOf`·`VARIE_GRADES`) · `assets/manifest.json` ·
  `data/balance/homes.json`
- `docs/asset_catalog.md` 도 안 고쳤다(자동생성 파일이다)
- `assets/existing/thumbs/` 폴더가 새로 생겼다. **원본은 안 건드렸다.**
  `tools/make_thumbs.py` 가 만든다 — 원화가 늘면 다시 돌리면 되고, 이미 있는 것은 건너뛴다
- 썸네일은 **긴 변 512px JPEG** 이다. `assets/crops/thumbs`·`assets/furniture/thumbs` 는
  PNG 인데, 저쪽은 알파가 있는 GLB 렌더고 여기는 흰 배경 그림이라 갈랐다
  (재서 골랐다 — 512px 기준 PNG 170KB 대 JPEG 36KB. 100장이면 17MB 대 3.6MB 다.
  **폰에서 격자로 펴는 것이 목적**이라 JPEG 여야 한다). 400 이 아니라 512 인 이유는
  **산반과 스페클을 갈라 봐야** 해서다 — 400 이면 잘게 흩뿌린 점이 뭉개진다

## ★ 판단이 필요한 것

1. **하트·포토스 모양 13종을 몬스테라와 같은 잣대로 매길 것인가.**
   `shop.js` 는 종별 단가를 이미 갈라 두었다(몬스테라 10,000 / 포토스 3,750).
   같은 잣대면 도감 갈래대로 가는 것이고, 가르면 매니페스트의 `category` 를 고쳐야 한다
   (그건 leaf 창 몫이다).
2. **중간 단계 무늬가 몬스테라 모양으로 1종뿐인 것을 그대로 둘 것인가.**
   성숙 19종에 견주면 눈에 띄게 비어 있다.
3. **등급이 정해진 뒤 값 공식에 어떻게 넣을 것인가.**
   지금 `priceOf` 는 「무늬 잎이 **몇 장**인가」만 보고 **어떤 변이인지는 안 본다**
   (`shop.js` §⑥ 에 그 사실이 적혀 있고, growth 에 잎별 무늬 종류를 내달라는 요청이
   `core-to-growth.md` 에 이미 있다). 등급표가 나오면 그 요청과 이어 붙는 자리가 된다.
   ⚠ 도구는 등급을 **적어 두기만** 한다. 코드에 넣는 것은 core 창 몫이다.
4. **색변형 66종도 따로 매길 것인가.** 무늬 모양이 같으니 원본 등급을 물려받는 것이
   자연스럽지만, 「채도가 값을 바꾸나」는 정해진 바가 없다.

## 눈으로 확인한 것 (`node tools/probe_varie_grade.mjs`)

```
① 34종이 격자에 다 뜬다 — 몬스테라 초기1·중간1·성숙19 / 하트·포토스 중간13
   [색변형도 보기] 를 누르면 100종 · 다시 누르면 34종
② 썸네일 34장 중 깨진 것 0장 · 512×512 (한 장만 512×279 — 원화가 가로로 길다)
③ 값 표가 priceOf 와 한 원도 안 다르다 — 80,000 / 150,000 / 771,111 / 2,183,333
④ 하프문을 찍고 새로고침 → 그대로 남는다 (localStorage)
⑤ 내보내기 JSON · 마크다운 표 둘 다 나온다
⑥ 폰 390px — 가로로 안 넘친다(390≤390) · 값 표도 안 잘린다(340≤340) · 2단 · 칸 178×337
   크게 보기 — 원본 600×600 을 전체화면으로 띄운다
```

⚠ 처음 판은 폰에서 **값 표의 그루값 칸이 잘렸다**(「80,0…」). 화면을 안 봤으면 못 잡았다.
좁은 폭에서 글자·여백을 줄이고, `←이사비를 넘긴다` 를 `★` 로 바꿔서 고쳤다.
검사 ⑥ 에 그 등식을 박아 두었다.
