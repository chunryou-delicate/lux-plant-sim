## 1. 무엇이 없었나

[주문]을 누르면 `confirmOnce('정말 주문?')` 가 돌았다 — **단추 글자가 바뀌고, 둘째 탭에
한 개**가 나갔다. 그래서:

| | 고치기 전 | 지금 |
|---|---|---|
| 씨앗 5시루분을 시키려면 | [주문]×2 를 **다섯 번** = **손 10번** | [주문] → [＋]×4 → [5개 주문] = **손 6번**. ★ 그 다음부터는 **손 2번**(디폴트가 5다) |
| 총액 | **화면 어디에도 없다** | 창 한가운데와 **단추 글자**에 |
| 언제 오나 | 목록 줄의 `1일 뒤 도착`(누르면 사라진다) | 창 안에 **계속** 떠 있다 |

누른 사람이 보는 것은 「눌러도 아무 일이 없다」다(`quiet-to-plan §1` *하는 중은 그 자리*).
그래서 `disabled` 를 걷고 **창 안에서 까닭을 말하게** 했다.

### 2-2. ★★★ 디폴트를 **어디에 기억하나** — 재서 골랐다

지시가 콕 집은 물음이다. 길이 셋이었다.

| | | 판정 |
|---|---|---|
| ㉮ **세이브**(`S.shop`) | 스키마가 바뀐다. `save.js` 는 **쓰기 영역 밖**이고 옛 판을 여는 길까지 건드려야 한다 | ⛔ |
| ㉯ **화면 변수만** | 새로고침 한 번에 사라진다. *"직전 주문량"* 이 그 판 안에서만 사는 값이 된다 | ⛔ |
| ㉰ **localStorage** (`byeot.lastOrderQty`) | **채택** | ★ |

★ **㉰ 를 고른 진짜 까닭은 「이게 살림이 아니라 손버릇」이라는 것이다.**
이 파일이 이미 같은 결의 값을 거기 두고 있고, 그 주석이 이유를 적어 두었다 —
`byeot.pointerMode`(§PTR_KEY): *"판을 지우거나 새로 시작해도 남아야 하는 **조작 취향**이지
게임 진행이 아니다"*. 음악 켜짐(`MUSIC_KEY`)·안내판 본 것(`GUIDE_SEEN`)도 같은 자리다.
**주문 개수가 정확히 그 줄에 선다** — 「나는 씨앗을 다섯 개씩 산다」는 지갑이 아니라 습관이다.

⚠⚠ **품목마다 따로 기억한다.** `{itemId: qty}` 표다. 한 칸에 담으면 씨앗(500원) 5개를
시킨 뒤 시루(5,000원)에 5가 떠서 **25,000원이 디폴트**가 된다 — 지시서가 못 박은 자리고
검사 §B-2 가 실제로 잰다.

⚠ **기억은 주문이 실제로 나간 뒤에** 적는다(`r.qty` — **코어가 받은 개수**로 적는다).
고르다 그만둔 값은 손버릇이 아니다.

⚠ **기억한 값이 지금 소지금으로 안 되면 살 수 있는 데까지 내려서 연다.** 그리고
**그 사실을 창이 말한다** — 조용히 줄이면 「5를 시켰는데 3이 나갔다」가 된다(실측 §3-4).

★ **알아 둘 것**: 이 기억은 [지금 판을 지웁니다]로 안 지워진다(그쪽은 세이브 키만 지운다).
지워지는 것은 [완전 초기화](`hardReset` · `localStorage.clear()`) 때다. **일부러 그렇다** —
새 판을 시작해도 손버릇은 그 사람 것이다. ⏸ 싫으시면 판 지우기에 한 줄 붙이면 된다(§5-3).

### 2-3. ★ 「돈이 모자란다」를 **그 자리에서** 말한다

`disabled` + `title` 을 걷고 창이 말하게 했다. 두 갈래다.

| 언제 | 화면이 하는 말 |
|---|---|
| **한 개도 못 살 때** | 창은 뜬다. `pquote.warn`(주황)으로 *"돈이 모자랍니다 — 한 개에 5,000원인데 소지금이 100원입니다 (4,900원 모자랍니다)"* · [주문]은 회색 |
| **더는 못 올릴 때** | *"— 소지금으로는 2개까지입니다 (더 시키려면 돈이 더 있어야 합니다)"* · [＋]와 [전부]가 회색 |

★ 회색이 남은 자리는 **[＋]·[전부]·[주문]** 셋인데, 셋 다 **바로 옆 한 줄이 까닭을
적고 있다**. 「회색인데 왜인지 모른다」가 안 생기는 것이 이 창의 값어치다.
⚠ 회색 [주문]을 눌러도 돈이 안 나가는 것을 실측으로 확인했다(§E).

### 2-4. ★ 되묻기가 없어진 것이 아니라 **더 무거워졌다**

`confirmOnce('정말 주문?')` 를 걷었다. 팔기 팝업이 이미 같은 판단을 했고(§pantryGo:
*"고르는 자리 자체가 되묻기"*), 여기서는 그것이 더 분명하다 — **총액과 도착일을 적어
놓은 창**이 뜨고, 화면이 어두워지고, [N개 주문]이라 적힌 단추를 눌러야 나간다.
⇒ `confirmOnce` 는 아직 산다. 남은 손님은 **[몬스테라 팔기]와 [지금 판을 지웁니다]** 둘이다.

## 5. ☐ 판단 필요 (박사님·plan 몫)

### 5-1. ★ ± 눈금이 **한 개씩**이다

시루·화분은 한두 개, 씨앗도 시루 수만큼이라 자릿수가 작아 한 개씩으로 뒀다.
[전부]가 위끝으로 한 번에 데려다 주므로 갇히지는 않는다.
⇒ 씨앗을 열 개씩 사는 판이 되면 **±5 나 ±10 이 필요**할 수 있다. 지금은 이르다고 봤다.

### 5-2. 개수를 **직접 쳐 넣는 칸**을 둘지

지시서가 *"개수 **입력창**"* 이라 하셨는데 **± 와 [전부]로 갔다.** 까닭 둘:
① 폰에서 숫자 자판이 올라오면 창의 절반이 가려진다 ② 이 게임의 다른 고르개(팔기·밥상)가
전부 ± 라 여기만 자판이면 손버릇이 갈린다. ⇒ **틀린 판단이면 `<input type=number>` 를
`pcount` 자리에 끼우면 된다** — 나머지(총액·한도·기억)는 그대로 돈다.

### 5-3. 「판 지우기」로 기억을 같이 지울지

[지금 판을 지웁니다](`firstRun`)는 세이브 키만 지우므로 **주문 개수 기억은 남는다.**
일부러 그렇게 뒀다(손버릇은 판이 아니라 사람 것이다 — 음악 켜짐과 같은 결).
⇒ 싫으시면 한 줄이다: `localStorage.removeItem('byeot.lastOrderQty')`.

### 5-4. 여러 품목을 **한 번에 담는 장바구니**

지금은 품목 하나씩이다. 시루 5 + 씨앗 5 를 시키려면 창을 두 번 연다.
⇒ 장바구니는 `orderItem` 을 여러 번 부르면 되지만 **주문이 여러 건으로 갈린다**
(배송일이 품목마다 달라 어차피 따로 온다). 지금 이 일의 범위 밖이라 안 건드렸다.

## M-3. ⚠⚠ 어디에 쌓나 — **재서 골랐다. localStorage 다**

`state.js`·`save.js` 는 이 창의 **쓰기 영역 밖**이고 세이브 스키마를 바꾸는 일이다.
⇒ **주문 개수와 같은 자리**에 뒀다: `byeot.month`(`byeot.lastOrderQty` 옆).

```
{ v:1, fromDay, snap:{cash,shopSpent,shopEarned,pantrySold,surplusSold,foodSaved},
  run:{days,out,power,rent,saved,income,harvests,ateG:{작물:g},gotG:{작물:g}}, prevNet }
```

- **월초 스냅샷**은 **부팅 때** 열린다(`monthEnsure`) — 하루가 가기 **전**이라야 첫날이 안 샌다.
- 하루가 갈 때 `run` 에 더하고(`monthNoteDay`), 수확할 때 `gotG` 에 더한다(`monthNoteHarvest` —
  ★ **수확은 턴 밖**이라 이 길로만 셀 수 있다).
- 월세를 낸 날 마감하고(`monthCloseNow`) **그 자리에서 새 달을 연다**.

⚠ **대가를 적어 둔다 — 세이브가 아니라 브라우저에 남는다.** 옛 세이브를 열면 스냅샷이
「앞날」을 가리킬 수 있어 이번 달이 음수가 된다 ⇒ **`fromDay > 지금`이면 버리고 새로 연다**
(그러면 첫 달처럼 군다. **거짓말을 하지 않는다**). ⏸ 코어에 칸을 내는 쪽이 맞다 — §M-6.

## M-4. ★ 언제 뜨나 — **재서 정했다. 하루의 맨 끝이다**

지시가 콕 집은 자리다(*"한 줄에 세 개가 겹치면 안 된다"*). 시간축으로 갈랐다:

| | 창 | 언제 |
|---|---|---|
| ① | **오늘 밥상**(`#mealPanel`) | 하루가 가기 **전** — 오늘 먹을 것을 정한다 |

| ④ | ★ **한 달 가계부** | 그 **뒤** — 지난 한 달이 어땠나 |

⇒ **넷이 시간축에서 안 겹친다.** ①과 ④는 뜻이 정반대라(정하는 창 / 끝난 것을 보는 창)

⚠⚠ **대사보다 뒤다.** 월세 낸 날은 대사가 반드시 하나 뜬다(`rentFirst`/`rentAgain`).
겹치면 표가 몬이를 덮는다. ⇒ **대사 줄이 비는 순간**(`dlgPaint` 의 `!line` 갈래)에 연다.
대사가 아예 없으면 `commitNextDay` 끝에서 바로 연다. **검사가 「뜬 순간 `#stage.talking` 이
아니다」를 실제로 잰다**(§G).

⚠ **닫아도 하루는 그대로다.** 이미 끝난 일을 보는 창이라 되돌릴 것이 없다 —
닫는 길 셋([알겠습니다]·뒤 누르기·`Esc`) 다 확인했고, 닫은 뒤 `S.day`·지갑·살림 날짜가

## M-6. ☐ 코어에 붙일 것 — **내가 안 고쳤다. 코드째로 적는다**

지금 화면이 **못 말하는 것**이 셋이고, 셋 다 코어에 칸이 없어서다.
⚠ 아래는 **내가 안 붙였다**(`tutorial.js`·`state.js`·`save.js` 는 쓰기 영역 밖).

### ㉮ 식물등 사기·이사비가 **어느 장부에도 안 적힌다**

지금 화면은 그 몫을 **「장부에 안 잡힌 것」**으로 적어 대차를 맞춘다. 제대로 하려면:

```js
/* src/game/tutorial.js §buyLamp — `ts.cashWon -= …` 바로 뒤에 */
  ts.spent = ts.spent || { lampWon: 0, moveWon: 0, rentWon: 0 };
  ts.spent.lampWon += ts.rules.lampPriceWon;

/* src/game/tutorial.js §moveOut — 이사비를 뺀 자리 뒤에 */
  ts.spent = ts.spent || { lampWon: 0, moveWon: 0, rentWon: 0 };
  ts.spent.moveWon += cost;

/* src/game/tutorial.js §tutorialDay 월세 블록 — `ts.rent.paidCount += 1;` 뒤에 */
  ts.spent = ts.spent || { lampWon: 0, moveWon: 0, rentWon: 0 };
  ts.spent.rentWon += rentPaid;
```
```js
/* src/game/save.js §packTutorial — rent 옆에 한 칸 */
  spent: {
    lampWon: needNum((t.spent || {}).lampWon ?? 0, 'tutorial.spent.lampWon', { min: 0 }),
    moveWon: needNum((t.spent || {}).moveWon ?? 0, 'tutorial.spent.moveWon', { min: 0 }),
    rentWon: needNum((t.spent || {}).rentWon ?? 0, 'tutorial.spent.rentWon', { min: 0 })
  },
/* 되세우는 쪽도 같은 모양으로(없으면 0 셋) */
```

### ㉯ 「한 달」을 자를 **스냅샷 칸**이 없다 — 그래서 지금은 브라우저에 산다

가장 작은 해법은 **월세를 낸 그 순간에 누적값을 한 번 찍어 두는 것**이다:

```js
/* src/game/tutorial.js §tutorialDay 월세 블록 안 — `ts.rent.nextDueDay += …` 뒤에
   ⚠ 누적값은 tutorial 이 안 갖는 것도 있어(shop·firstPlay) 부르는 쪽이 넘겨야 한다.
     그래서 `loop.stepTutorial` 이 opt 로 넣어 주는 편이 맞다. */
  ts.rent.close = {
    day: ts.day, cashWon: ts.cashWon,
    shopSpentWon: opt.shopSpentWon ?? null, shopEarnedWon: opt.shopEarnedWon ?? null,
    foodSavedWon: opt.foodSavedWon ?? null,
    prevNet: ts.rent.close ? ts.cashWon - ts.rent.close.cashWon : null
  };
```
⇒ 그러면 「이번 달 = 지금 누적 − `rent.close`」가 **세이브 안에서** 나오고, 판을 옮겨도 살아남는다.
지금 화면 코드(`monthSnapNow`/`monthCloseNow`)는 **그대로 그 칸을 읽게만** 고치면 된다.

### ㉰ 공과(2,500원/일)가 식비와 **안 갈린다**

`TUTORIAL_RULES.dailySpendWon` 이 「월세몫 + 공과·전기 + 식비」를 **한 수로** 갖는다.
⇒ 화면도 「식비 · 공과」로 묶어서 적는다. 가르려면 규칙에 `utilityWon` 을 따로 둬야 한다
(`data/balance/homes.json` 에 `utility 75,000` 이 이미 있다 — 읽는 데만 없다).

## M-7. ☐ 판단 필요 (박사님·plan 몫)

### M-7-1. ★ 지난 장부를 **다시 볼 길이 없다**

닫으면 다음 달까지 못 본다. 창구(`window.__byeotMonthShow`)는 냈는데 **단추가 없다** —
붙일 자리는 [살림] 탭의 살림 장부(`#ledger`) 밑이 자연스럽다.
⏸ 「매달 한 번 뜨는 창을 다시 볼 일이 있나」가 판단이라 안 붙였다.

### M-7-2. 30일에 한 번이면 **너무 뜸한가**

지금은 월세 주기(30일)에 묶여 있다. 반지하 한 판이 대략 100일 안팎이라 **서너 번** 뜬다.
⇒ 주마다 뜨게 하려면 주기를 따로 정해야 하는데, 그건 **월세와 무관한 새 눈금**이라 안 지었다.

### M-7-3. 「식물 판 것」이 **뺄셈으로만** 나온다

`shop.earnedWon` 이 판매 넷을 한 칸에 담아서다(§M-2 ⚠). 지금은 맞지만 **판매 갈래가
하나만 늘어도 조용히 틀린다.** ⇒ `credit()` 이 갈래별로 쌓으면 그 자리가 없어진다.

### M-7-4. 첫 달이 **첫 플레이 16일을 품는다**

살림 시계로는 1일차이지만, 그 앞의 첫 플레이 동안 거두고 먹은 것은 **「첫 달」에 잡힌다**
(스냅샷이 부팅 때 열려서다). 돈 줄은 안 그렇다(살림이 안 돌아 지갑이 안 움직인다).
⇒ 「첫 달은 배우는 기간까지 포함」이 맞다고 보고 그렇게 뒀는데, **판단이다.**

## M-8. ✗ 못 한 것
