## 무엇을 하나

Higgsfield 안에 3D 가 있다. Meshy 7(38) 말고도 **Tripo H3.1**(9 · 텍스처 detailed 12)이 있다. Tripo 가 Meshy(30~38)만 하면 같은 크레딧으로 3D 를 세 배 넘게 뽑는다.
그래서 **먼저 견준다**(T). 이미 Meshy 로 뽑은 원화 둘을 Tripo 에 그대로 넣고, 결과를 같은 카메라·같은 자로 잰다. 엔진은 그 결과로 house 가 정해 알린다.

이어서 넷이다.

1. **C→M 가구** — 원화(nano_banana_2_1 2k · 셋씩)를 고른 뒤 3D. 가게 진열대 · 주문판 · 간판 둘(하나만 3D) · 협탁 r2 · 벤치.
   - 진열대는 코드 몸이 없어 house 가 **새 빌더**를 먼저 세웠다(앞 낮고 뒤 높은 세 단 · 자리 9 · 1.25×0.75×0.815). 그 찰흙 그림이 원화 참조다(회색 상자 길 — 단 수·자리가 맞는다).
   - 간판은 단골 10명 보상이다(plan D59). 매다는 간판·입간판 둘 다 원화를 뽑아 하나를 고른다. **판 앞면은 그림만이고 글자는 비운다**(가게 이름은 게임이 캔버스로 얹을 수 있게).
2. **U 유니티 · 겉감 4k** 여덟 — 반지하 벽지·장판 · 콘크리트 벽·천장 · 원룸 벽지·마루 · 빌라 벽돌 · 계단 인조석. 웹은 앞 주문 ③의 2k 를 쓰고, 유니티는 이 4k 를 그대로 쓴다. 다섯은 ③에서 고른 2k 를 첫 참조로 같은 무늬를 4k 로 뽑는다.
3. **U 유니티 · 방 키트** 여덟 — 기준 그림의 생활감 소품이다(벽 배관 · 계량함 · 창 우물 덮개 · 벽 선반 · 벽걸이 옷걸이 봉 · 현관 매트 · 펜던트 등 · 작은 신발장). 웹 판에도 소품으로 쓸 수 있다.
4. **크레딧 없이 house 가 할 것** — 유니티 «모듈 벽·바닥·창·문 조각». 생성 모델은 치수가 안 맞아 조각을 짜 맞출 수 없다. 그래서 코드 판(house.js)에서 치수 그대로 GLB 로 낸다(GLTFExporter). 창·문 GLB 는 이미 있다.

## T 견줌 결과(10-10 · 총괄 1553714f · 사진 `img/house_20261009/tripo_vs_meshy_stool_etagere.webp`)

같은 원화 · 같은 카메라(probe_dress_fit · 옷 층만 바꿔 끼운 사본 DRESS_MOD) · 텍스처는 둘 다 webp 1024 로 줄여 쟀다.

| | Meshy(30) | Tripo detailed(12) | Tripo standard(9) | Tripo std + pbr |
|---|---|---|---|---|
| 스툴 부품(판 · 다리 넷) | ✔ | ✔ | ✔ | ✔ |
| 스툴 윗면 오차 | 0 | 0 | 0 | 0 |
| 스툴 비율(세로/가로 · 1 이면 원화 그대로) | 0.99 | 0.91 | 0.91 | 0.91 |
| 면 수 · 받은 텍스처 | 5,746 · 2k | 7,166 · 4k | 7,652 · 2k | 5,762 · 2k×3 |
| 다단 선반(기둥 넷 · 판 셋) | ✔ · 오차 0 | ✔ · 오차 ≤ 7mm | — | — |

- **Tripo 도 쓸 만하다.** 부품 수가 맞고, 윗면도 자리에 1cm 안으로 맞는다. 다리·판 결이 조금 울퉁불퉁하고(손으로 깎은 결), 비율이 원화에서 조금 벗어난다(스툴 9% 좁음 · 선반 좁고 깊음). 옷 층이 발자국에 맞춰 늘이니 화면에서는 거의 안 갈린다.
- detailed 와 standard 의 차이는 **텍스처 크기(4k↔2k)뿐**이다. 웹은 어차피 1024 로 줄이니 standard(9)로 넉넉하다. 유니티는 4k 가 쓸모 있으니 detailed(12)를 쓴다.
- ⚠ 앞 방향이 엔진마다 다르다. 다단 선반이 Meshy 는 Z 로 길었고(yaw 90), Tripo 는 X 로 길다(yaw 0). Tripo 는 키를 1.0 으로 맞춰 낸다. **yaw 는 GLB 마다 재서 정한다.**
- ⇒ **정함**: 웹 가구 = Tripo standard(9 · pbr 끔). 유니티 방 키트 = Tripo detailed(12 · pbr 켬 — 유니티는 노멀·거칠기를 쓴다). 진열대처럼 단이 중요한 것도 tiers 꺾은 선으로 맞추니 Tripo 로 된다. 원화가 어려운 꼴(가는 살대 · 투명)만 Meshy 7 을 예비로 둔다.
- 크레딧: M 다섯 60 → 45 · U 키트 128 그대로(detailed).
- **다시 뜨는 차례(박사님 10-10 «Meshy 가 잘 안 되면 Tripo 로» · 총괄)**: 웹 = Tripo standard → 틀리면 Tripo detailed. 어려운 꼴의 예비 Meshy 7 로 뜬 것이 틀리면 → **Tripo detailed** 로 다시 뜬다(Meshy 를 거듭 돌리지 않는다).
- 받은 다섯(10-10 · 9b226b17): 진열대 yaw −90(+90 이면 앞뒤가 뒤집혀 앞단 +0.49m) · 협탁 r2 yaw −90(서랍이 +X 로 나옴) · 벤치 yaw 0 — 셋 다 윗면 오차 ≤ 2mm. 주문판(얇은 축 X → 벽 걸이면 yaw 90)·입간판은 webp 로만 두고, 벽 걸기·간판 자리를 세운 뒤 잇는다.
