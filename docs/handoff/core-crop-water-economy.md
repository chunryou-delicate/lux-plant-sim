## ① 물주기

### 축을 겹치지 않는다

| 축 | 무엇이 정하나 | 결과 |
|---|---|---|
| **자리(빛)** | 어디에 두었나 | **품질** — 하얗고 아삭 / 살짝 초록 / 초록·쓴맛 |
| **물** | 오늘 줬나 | **속도** — 준 날만 자란다 |

이 게임이 가르치는 것은 빛이다. 물이 품질을 건드리면 두 축이 같은 것을 말하게 된다.

**구현에서 그것이 한 줄로 나타난다: 물을 안 준 날은 `dliHist` 에도 안 쌓는다.**
안 쌓아야 "물을 안 준 것"이 품질 평균을 못 건드린다. 쌓으면 어두운 방에서 물을 빼먹을수록
평균이 더 어두워져 **물이 품질을 올리는** 규칙이 된다. 이력은 "이 콩나물이 자란 날에 받은 빛"이고,
안 자란 날은 그 콩나물의 하루가 아니다.

### 안 준 날 · 연속으로 안 준 경우

**속도만 멈춘다. 품질은 안 떨어뜨린다. 죽지 않는다.**

박사님 확정 원칙("초보는 안 죽는다")을 그대로 지킨다. 열흘을 내리 빼먹어도 시들지 않고
늦어질 뿐이다. **벌은 시간이고, 시간이 곧 돈이다** — 5일 회전이 7일이 되면 하루평균 절감이
600원에서 429원으로 스스로 내려간다. 따로 벌점을 만들지 않았다: 만들면 그것이 두 번째 벌이 되고
"안 죽는다"가 흔들린다. 실측은 아래 §③ 표 ③.

### 하루 한 번

현실은 하루 3~4번 헹궈 줘야 한다(집에서 시루로 기르는 실제 방식). 그래도 하루 한 번으로 둔다 —
**게임에서 하루에 여러 번 누르게 하면 재미가 아니라 노동이다.** 누르는 횟수가 아니라
**잊지 않는 것**이 이 행위의 내용이고, 하루 한 번이면 그 내용이 다 담긴다.
같은 날 두 번 눌러도 안전하다(`already: true` 로 조용히 지난다 — 던지면 화면이 붉어진다).

### 대상은 작물뿐이다 — 몬스테라에는 안 건다

1. **현실이 다르다.** 시루는 하루 3~4번, 관엽은 주 1회다. 매일 축이 아니다.
2. **몬스테라의 속도 축은 이미 빛이다**(저광 정지). 물을 얹으면 정지 사유가 둘이 되어
   "왜 안 자라지"의 처방이 흐려진다 — `loop.js` 가 머리공간 정지를 빛 정지와 다른 칸에 두는 것과
   같은 이유다.
3. 몬스테라의 하루 진행은 **growth 창 소유**(`advanceTo`)다. 코어가 물로 그걸 막으면
   남의 창 규칙을 코어가 갖게 된다.

### ★ 빨리감기와 어떻게 맞물리나

빨리감기 중에 매일 [물 주기]를 누를 수는 없다. **두 모드가 답을 달리 낸다** — 두 모드가 이미
다른 것을 하고 있기 때문이고, 새 모드를 만들지 않았다.

| 모드 | 언제 | 물 | 기본값 |
|---|---|---|---|
| `jump` | 반지하 튜토 = 첫 플레이 진행 중 | 마른 날에 **선다** | `stopOnDry` |
| `fast` | 그 뒤 · 본편 | 물을 **같이 준다** | `autoWater` |

**왜 점핑은 서나** — 점핑이 도는 구간이 곧 **물주기를 배우는 구간**이다. 첫 플레이는
"행위가 있어야 재미있다"는 그 행위를 처음 만나는 자리다. 여기서 코어가 대신 주면 플레이어는
물주기를 한 번도 안 하고 튜토를 끝낸다. 그리고 점핑은 "다음 이벤트까지"인데 물을 안 주면
수확 이벤트가 영영 안 온다 — 안 서면 60일 한도까지 헛돌고 화면은 이유를 말할 창구가 없다.
서면 정지 사유가 곧 답이다.

**왜 배속은 주나** — 배속에서 서면 배속이 하루짜리가 되어 기능이 사라진다. 콩나물 회전은
튜토 내내(50일 넘게) 계속 돌기 때문이다. 그리고 이것은 **지름길이 아니다**:
물은 공짜라 자동으로 줘서 버는 것이 없고, 회전 속도도 손으로 매일 준 것과 한 글자도 다르지 않다
(`test_fastforward.mjs` ★물주기-b 가 배속판과 손으로 밟은 판을 대조해 등식을 고정한다).
건너뛰는 것이 아니라 **같은 길을 빠르게 밟는 것**이고, 어두운 자리에 두면 여전히 안 자란다.
배속은 튜토 이후 전용이라(`timeModeOf`) 배우는 구간으로는 새지 않는다.

시루를 아직 안 놓았거나 이미 거뒀으면 **마를 것이 없다** — 두 규칙 다 아무 일도 안 한다.
그래서 몬스테라만 기다리는 긴 구간은 그대로 길게 간다.

## ② "5일 주기 3,000원"을 어떻게 읽었나

**자라는 날이 4일 → 5일로 바뀐다는 뜻으로 읽었다.** 양쪽을 다 계산해 봤다.

| 읽는 법 | 하루평균 | 판정 |
|---|---|---|
| (가) 재배 기간이 5일 · 한 회전이 3,000원 | 600원 | **채택** |
| (나) 재배 기간은 4일 · 절감이 5일마다 3,000원 | 600원 | 기각 |

하루평균은 **둘 다 600원으로 같다.** 갈리는 것은 셋이다.

1. **"주기에 따라"가 일을 하나.** 그 말이 2종·3종에도 붙었다 — 절감이 **그 작물의 한 주기가
   내는 값**이라는 뜻이다. (나)로 읽으면 주기가 무엇이든 5일마다 들어오므로 그 말이 아무 일도 안 한다.
2. **시계가 하나인가.** (나)는 회전 4일 · 절감 5일이라 두 박자가 어긋난다. 곳간·상한이
   어느 쪽에 맞물리는지 코드에 두 개의 시계를 만들어야 한다.
3. **★ 물주기와 맞물리나.** (가)는 물을 빼먹으면 회전이 6일·7일로 늘어 하루평균이 저절로
   내려간다. (나)는 물을 안 줘도 5일마다 3,000원이 들어와 **물주기가 경제에 전혀 안 걸린다.**
   같은 날 넣는 두 규칙이 서로를 무력화하면 안 된다.

현실이 4~7일(보통 5일)이라 5 자체도 타당하다. ⇒ `harvestDays: 4 → 5`.
**그리고 그 5일은 달력 5일이 아니라 물을 준 날 5일이다.**

### 같은 시루를 여러 개 사는 것

**남기되, 절감은 안 늘어난다.** 시루 수를 곱하지 않는다.

근거가 문서에 이미 있다. `docs/food_economy.md` §4 는 끼니 상한의 이유를 *"질림·영양"* 이라고
적어 뒀는데, **질리는 것은 같은 것을 계속 먹는 것**이다. 그러니 콩나물 시루를 열 개 놓는 것이 아니라
다른 작물을 들이는 것에만 값이 붙어야 그 이유와 셈이 같은 말을 한다.

| | 예전 | 지금 |
|---|---|---|
| 같은 종류 시루를 늘린다 | 상한까지 절감이 는다 | **안 는다** (씨앗값만 더 나간다) |
| 다른 종류를 들인다 | 없던 개념 | 3,000 → +2,000 → +1,000 (순번마다 체감) |

**완전히 없애지 않은 이유** — 시루는 여전히 (ㄱ) 자리를 차지하고 씨앗을 먹으며
(ㄴ) 작물 종류가 늘면 종류마다 하나씩 필요하다. 즉 시루는 "많이 먹는 장치"에서
**"한 종류를 담는 그릇"** 으로 뜻이 바뀌었다. 상점 품목·`resowCrop(opt.sirus)`·세이브 칸은
그대로 두고, 늘리면 **로그가 손해라는 사실을 말한다**(막지는 않는다 — 막으면 규칙이 아니라 벽이 된다).

**2종·3종은 자리만 만들어 뒀다.** `CROP_KINDS` 에 지금은 콩나물 한 줄뿐이고,
`cropKindSavedWon: [3000, 2000, 1000]` 의 2·3번째 값은 **합계에 안 들어간다**
(`firstPlayRulesFromBalance` 가 `CROP_KINDS.length` 만큼만 자른다). 작물이 생기면 한 줄 붙이면 흐른다.

### ⚠ 판단이 필요한 것 — 씨앗값이 절감의 70%를 먹는다

```
절감      600원/일  (3,000원 ÷ 5일)
씨앗     −420원/일  (2,100원 ÷ 5일 · 정가 1,500 × 상점 마진 1.4)
────────────────────
순액      180원/일  = 하루 지출 20,000원의 0.9%
                     (예전: 2,175원/일 = 10.9%)
```

**콩나물의 순액이 12분의 1로 줄었다.** 이사는 여전히 성립하지만(§④ — 이사 자금은 확정 무늬
잭팟이 만든다) "콩나물을 돌릴 이유"는 얇아졌다: 재현에서 **본전을 뽑는 날이 튜토 27일**이고,
이사(중앙값 57일)까지 다 돌려야 5,700원 더 남는다.

**수치를 고치지 않았다.** 대신 셋 중 하나를 plan 이 골라 주시면 그대로 흐른다.

| 안 | 내용 | 순액 |
|---|---|---|
| (ㄱ) 그대로 둔다 | 콩나물은 "거의 본전"인 버티기 수단 | 180원/일 |
| (ㄴ) 씨앗값을 내린다 | 1,500 → **1,000원**. 지시서의 실제 시세 "나물콩 1시루분 700~1,200원"에 오히려 더 맞는다 | 320원/일 |
| (ㄷ) 3,000원을 **순액**으로 읽는다 | 회전 총액을 3,000 + 씨앗값으로 잡는다 | 600원/일 |

내 판단은 **(ㄴ)** 이다. 현실 근거가 있고, 확정 수치(월세·하루 지출·이사비·식물등·여름 45일차)를
하나도 안 건드리며, `docs/food_economy.md` §3 의 1,500원만 고치면 된다.
⚠ 다만 그 값은 `first_play.js`(`seedWonPerSiru`)와 `shop.js`(`CATALOG.bean_seed.listWon`) 두 곳에
있으므로 plan 이 `characters.json._meta` 로 옮겨 주시는 편이 낫다(아래 §요청).

## ⑤ game.html 이 부를 API

`game.html` 은 **손대지 않았다.** [물 주기] 버튼이 부를 것은 이것뿐이다.

```js
import { waterCrop, cropWaterStatus } from './src/game/state.js';

waterCrop(S)
//   → { watered, already, day, dryRun, events:[{id:'crop_watered', ko:'콩나물에 물을 주었습니다'}] }
//   · 하루 한 번. 같은 날 두 번 부르면 { watered:false, already:true } — 던지지 않는다
//   · 이미 거둔 시루면 { watered:false, harvested:true } — 역시 안 던진다
//   · 시루를 아직 안 놓았으면 throw (err.tutorialInput === true — isRecoverable 이 보는 표식)
//   · 돈이 안 든다

cropWaterStatus(S)
//   → { needsWater, wateredToday, placed, harvested, wateredOnDay, dryRun, dryDays,
//       ageDays, harvestDays }
//   · 버튼을 켤지 흐리게 할지의 근거. 상태를 안 바꾼다
```

턴 결과에도 실린다 — `turn.cropWatered` · `turn.cropDry` · `turn.cropWater`(위와 같은 모양).
**`growthBlocked`(빛 부족)·`headroomBlocked`(머리공간)와 다른 칸이다** — 셋을 한 칸에 섞으면
처방이 뒤섞인다(등을 켜라 / 자리를 옮겨라 / 물을 줘라).

빨리감기는 `startFastForward(S, io, { stopOnDry, autoWater })` 로 뒤집을 수 있다.
**기본값은 모드가 정하므로 평소에는 안 넘겨도 된다.** 마름으로 서면 `onStop` 의 reason 이 `'dry'` 다.
