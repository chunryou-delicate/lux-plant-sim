# 1. ★★ 먼저 정정할 것 — 「clamp 는 이미 고쳐져 있다」가 아니다

지시문 ①은 이렇게 적혀 있었다:

> ① **clamp 는 이미 고쳐져 있다.** 예전 인계 문서에 「0원인 날의 지출을 clamp 가 삼킨다」고
>    적혀 있는데 **그건 낡은 기록이다.** … `const out = Math.max(0, base - saved) + power;`
>    … **STATUS.md 의 그 줄도 네가 정정해 두어라.**

**정정하지 않았다. 그 기록은 낡지 않았고, 지금도 맞다.** 근거 둘:

## ① clamp 가 **둘**이고, 문제가 된 것은 다른 쪽이다

| | 어디 | 무엇을 자르나 |
|---|---|---|
| ㉮ | `const out = Math.max(0, base - saved) + power` | 절감이 지출보다 클 때 **지출을 0 밑으로 안 내린다** |
| ㉯ | `if (ts.cashWon < 0) { ts.cashWon = 0; … }` | **잔액을 0 밑으로 안 내린다**(초보 모드) |

`lampecon-to-plan.md §4` 가 말한 것은 **㉯** 다 — 그 문서가 인용한 코드도 ㉯ 그대로다.
㉮ 는 애초에 문제였던 적이 없다. `git log -L 261,261:src/game/tutorial.js` 로 확인했는데
**`power` 는 파일이 생긴 날부터 clamp 밖에 있었다.** 고쳐진 적이 없으므로 「이미 고쳐져 있다」도 아니다.

## ② 그리고 ㉯ 는 지금도 전기세의 80%를 삼킨다 — 실측

`tools/probe_elec.mjs` 가 후보마다 **명목 전기세**(매긴 값의 합)와 **실제로 낸 것**(잔액이 실제로 준 몫)을
따로 센다. 등 2개·24시간·이사까지 완주한 판(중앙값 12판):

| 후보 | 명목 전기세 | 실제로 낸 것 | **삼켜진 몫** |
|---|---|---|---|
| E0 지금 | 14,222원 | 2,906원 | **80%** |
| E2 단가 ×10 | 142,103원 | 25,348원 | **82%** |
| E5 실와트×2 + 누진 | 115,747원 | 21,653원 | **81%** |

⇒ ★ **STATUS.md 의 그 줄은 그대로 두었다.** 지우면 다음 사람이 같은 것을 다시 재게 된다.
  (STATUS.md 에는 대신 **와트를 고쳤다는 것**과 **실측 80%** 를 덧붙였다.)

# 2. 와트가 두 벌이었다 — 고친 내용

| | 예전 | 지금 |
|---|---|---|
| `TUTORIAL_RULES` | `lampWatt: 12` (등이 몇 개든 개당 12W) | `lampWattsByOrder: [20, 12]` |
| 기구 프리셋 `lighting_presets.json` | 바 20W · 집게 12W | 그대로 |
| 방 프로파일 `room_profile.banjiha.json` | `lampWatts [0, 20, 32]` | 그대로 |
| **등 2개 24시간 요금** | 지갑 **92원** · 화면 123원 | **둘 다 123원** |

셋 중 **하나만 달랐다.** 그래서 화면에 뜨는 전기세와 지갑에서 빠지는 전기세가 갈려 있었다.

`tools/test_elec.mjs §B·§B-2` 가 이 등식을 고정한다 — 기구 프리셋·방 프로파일·지갑이
같은 와트와 같은 단가를 보는지 매번 확인한다. 셋 중 하나가 움직이면 검사가 깨진다.

⚠ 이 때문에 `tools/test_tutorial.mjs` 의 골든값이 **23원 → 38원**으로 움직였다.
  12 → 20 은 ×1.667 이고 23 × 1.667 = 38 이다. 검사가 물러선 것이 아니라 와트가 정정된 것이다.
  같은 파일의 「등 2개 = 1개의 두 배」 단언도 **일부러 뺐다** — 등마다 와트가 다르므로
  두 배가 되면 그건 다시 한 벌로 뭉갠 것이다. 지금은 `base < two < base × 2` 를 확인한다.

# 5. 이 창이 못 정하는 것 — 박사님이 고르실 것

## ★ 하나만 고르시면 됩니다

**후보 여섯 중 무엇을 골라도 이사일은 안 바뀝니다.** 그러니 고르실 것은 「얼마나 아프게」가 아니라
**「전기세를 무엇으로 쓸 것인가」** 입니다. 셋으로 갈립니다.

| | 무엇 | 무엇을 얻나 | 무엇을 잃나 |
|---|---|---|---|
| **㉠** | **E0 그대로 둔다**(와트 정정만) | 「등을 켜면 요금이 나온다」를 **배움**으로 남긴다. 실비 근거(160원/kWh)가 유지된다 | 밸런스 손잡이는 아니다 |
| **㉡** | **E4**(실제 식물등 와트 + 누진) | 하루 살림의 **4.9%**. 「많이 켜면 비싸진다」가 규칙으로 선다. **실제 LED 식물등이 20~100W** 라 근거도 산다 | 프리셋 와트(바 20W)를 바꿔야 한다 — `data/lighting_presets.json` 은 **house 소유** |
| **㉢** | **E2**(단가 ×10) | 하루 살림의 **12.3%** — 가장 세다 | 「가정용 평균 단가」라는 근거가 통째로 없어진다. 이 게임에 근거 있는 숫자는 드물다 |

⇒ 이 창이 권하는 것은 **㉡** 입니다. 이유는 「세서」가 아니라 **거짓말을 안 해서**입니다 —
  실제 식물등이 45W 라면 45W 로 세는 것이 맞고, 한국 주택용이 누진이라면 누진이 맞습니다.
  다만 **그래도 이사일은 안 움직입니다.** 그걸 움직이려면 §3 의 세 겹 중 1·2 를 먼저 풀어야 합니다.

## 그리고 이건 박사님만 정하실 수 있습니다

**0원 clamp 를 어떻게 하시겠습니까.** 지금은 「초보 모드라 안 죽는다」(story_arc §0)는 규칙이고,
그것 때문에 **하루 지출로 밸런스를 잡는 길이 통째로 막혀 있습니다.** 후보 셋:

| | 무엇 | 대가 |
|---|---|---|
| ㉮ | 그대로 둔다 | 하루 지출은 영영 손잡이가 아니다. 전기세는 **배움 전용** |
| ㉯ | 0원 밑으로 **빚**을 진다(음수 허용) | 「안 죽는다」는 살지만 지출이 계속 아프다. 다만 빚이 얼마까지인지 새 규칙이 필요 |
| ㉰ | 0원이면 **못 하는 일**이 생긴다(씨앗을 못 산다 — 지금도 그렇다) | 이미 그렇다. 다만 확정 무늬가 막다른 길을 막고 있어 압박이 안 된다 |
