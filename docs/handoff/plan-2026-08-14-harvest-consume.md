## ★ 먼저 — 「아이템으로 쌓인다」는 **이미 반쯤 있다**

박사님 제안을 읽고 지금 구조를 뜯어보니, 없는 줄 알았던 것이 이미 있었다.

| 지금 실제로 도는 것 | 근거 |
|---|---|
| 수확하면 **곳간에 쌓인다** | `loop.js:1173` — *"예전 증거(`foodSavedWon` = 그날 곳간에서 꺼낸 돈)는 이제 수확과 **다른 날**에 난다"* |
| 하루가 갈 때 **곳간에서 자동으로 꺼내** 식비를 던다 | `foodSavedWon` |
| 하루에 꺼낼 수 있는 **상한이 있다** | 5,000원 = 2끼 × 2,500원 |
| **질림**으로 깎인다 | 첫째 1 · 둘째 **2/3** · 셋째 1/3 · 넷째부터 0 (`first_play.js §질림`) |
| 남는 것은 **85%** 에 팔린다 | START-HERE §6 |

즉 **「쌓였다가 나중에 소비」는 이미 그렇게 돈다.** 없는 것은 저장이 아니라 **둘**이다:

1. **화면에 안 보인다** — 곳간에 뭐가 얼마나 있는지, 오늘 뭘 먹었는지 플레이어가 모른다
2. **손이 안 간다** — 무엇을 먼저 먹을지, 먹을지 팔지를 못 고른다

⇒ 그러니 이 일은 **「새 계통을 만드는 일」이 아니라 「있는 것을 보이게 하고 손을 붙이는 일」**이다.
훨씬 작고, 밸런스 표(`econ-to-plan` §7.5~7.14)를 다시 안 재도 된다 — 값이 아니라 **표시와 조작**만 바뀐다.

## A. 수확 뒤 안내 — *"콩나물 시루 1번 수확하고나서 주기 설명하고 구매 및 재배치 가이드"*

### 지금 무엇이 비어 있나
`guide-to-plan.md` **P-06** 이 같은 것을 이미 짚어 두었다:
> **씨앗 사서 다시 심는 회전을 아래 한 줄이 한 번도 안 말한다.**

그리고 오늘 박사님이 폰에서 겪으신 것이 정확히 그 자리다 — 거두고 나니 씨앗이 없고,
씨앗이 없으니 다시 못 심고, 무엇을 해야 하는지 화면이 말을 안 했다.

### 제안 — **첫 수확 직후 세 걸음**을 순서대로 말한다
한꺼번에 다 말하면 안 읽는다. **한 번에 하나씩**, 아래 한 줄(`#quest`)로.

| 언제 | 말 | 왜 이때 |
|---|---|---|
| 거둔 **그 순간** | `5일이면 한 판입니다 · 식비 3,000원을 아꼈습니다` | **주기와 값**을 처음으로 말한다. 지금은 아낀 게 얼마인지도 안 보인다 |
| 그 다음 | `씨앗을 주문하세요 · [상점]에서 하루 뒤에 옵니다` | 회전이 씨앗에서 막힌다는 걸 **막히기 전에** 알린다 |
| 씨앗이 온 뒤 | `시루에 다시 심으세요` | |
| 다시 심은 뒤 | `자리를 옮겨도 됩니다 — 어두울수록 잘 큽니다` | ★ 재배치를 **여기서** 처음 말한다. 첫 판은 튜토가 자리를 정해 주지만, 둘째 판부터는 **자리가 플레이어의 선택**이다 |

★ **마지막 줄이 이 게임의 핵심**이다. 「자리마다 밝기가 다르다」를 대놓고 말하는 화면이
지금 축하 배너 한 장뿐이다(`guide-to-plan` P-03). 회전이 두 번째로 돌 때가 그 말을 할 제일 좋은 때다.

⚠ 문구 길이는 **한 줄 28자 · 두 줄 60자** 안이다(실측값, `player_guide.md`).

## B. 수확물 소비 — **자동인가 수동인가** (검토 요청분)

### 결론부터 — **반자동을 권한다.** 완전 수동은 권하지 않는다

| | 완전 자동 (지금) | **반자동 (권함)** | 완전 수동 (제안하신 것) |
|---|---|---|---|
| 손이 얼마나 드나 | 0 | **[다음 날] 누를 때 한 번** | 매일 여러 번 |
| 곳간이 보이나 | ✗ | ✓ | ✓ |
| 질림이 체감되나 | ✗ | ✓ | ✓ |
| 먹을지 팔지 고르나 | ✗ | ✓ | ✓ |
| 120일 동안 누르는 횟수 | 0 | 120 | **360+** |

### 완전 수동을 안 권하는 이유 — **손이 하루 다섯 개뿐이다**

이 게임의 하루는 **체력 5**다. 한 행동이 손 하나고, 경험치도 「그날 쓴 체력의 총량」이다
(START-HERE §6). 밥 먹는 데 손을 쓰면 **식물에 쓸 손이 준다.**
그런데 이 게임이 재려는 것은 「빛과 자리」지 「끼니 관리」가 아니다. 축이 하나 더 생기면
「왜 자랐는지」가 흐려진다 — 이 저장소가 여러 번 경계해 온 그것이다.

그리고 **선택이 매일 바뀌지 않으면 클릭은 그냥 손이다.** 콩나물 5일 회전에서
「오늘 뭘 먹지」의 답은 대개 어제와 같다. 120일이면 의미 없는 클릭 360번이 된다.

### 반자동은 이렇게 — **[다음 날]에 「오늘 밥상」을 얹는다**

```
 [다음 날 ▸] 을 누르면
 ┌─────────────────────────────┐
 │ 오늘 밥상                    │
 │  🥣 콩나물   ×2   -3,000원   │   ← 기본으로 골라져 있다
 │  🌱 무순     ×1   -1,867원   │   ← 질림 2/3 라고 여기 적힌다
 │  ─────────────────────────  │
 │  아낀 식비  4,867 / 5,000원  │   ← 상한이 여기서 보인다
 │  남는 것 3개는 팔면 2,550원   │   ← 85%
 │           [이대로]  [바꾸기]  │
 └─────────────────────────────┘
```

- **기본값이 지금과 똑같다.** 그냥 [이대로]를 누르면 오늘까지의 게임과 한 톨도 안 다르다
- 손은 **[다음 날] 하나에 붙는다.** 새 손이 안 는다
- **질림이 화면에 처음으로 보인다** — 지금은 무순이 2/3로 깎이는데 플레이어가 그 이유를 모른다
- **「먹을까 팔까」가 실제 선택이 된다** — 지금은 자동이 먼저 먹고 남는 것만 판다.
  돈이 급하면 덜 먹고 더 파는 선택이 생긴다. ★ **이사비 200만을 모으는 게임에서 이건 실한 선택이다**

### ⚠ 정하기 전에 재야 할 것
- **[이대로]를 누르는 비율.** 늘 그것만 누르면 창을 띄우는 값이 없다 — 그때는 자동으로 되돌린다
- **초반 빈 날**(시루 1~3개 구간이 39~77% 빈다 · START-HERE §4-2)에 이 창이 **더 허전해 보이지 않는지**
- 밸런스는 **안 바뀐다** — 기본값이 지금과 같으므로 `econ` 표를 다시 안 재도 된다

## C. 곁들여 — 상시 메뉴 (*"가방/식물/상점/방/메뉴 를 밑이나 좌우에"*)

박사님이 주신 참고 그림처럼 **탭이 늘 보이는** 형태다. 지금은 [가방]을 눌러 시트를 연 뒤에야
탭이 나온다 — **한 번 더 눌러야** 상점에 간다.

### 제안 — **아래 띠를 탭 다섯으로 바꾼다**
지금 아래 띠는 `[다음 날 ▸] [가방] [♪]` 셋이다. 여기를 이렇게 나눈다:

```
┌──────────────────────────────────────────┐
│           [ 다음 날 ▸ ]                   │  ← 크게 · 그대로 둔다(제일 많이 누른다)
├────┬────┬────┬────┬────────────────────┤
│가방│식물│상점│ 방 │ ♪ │                  │  ← 늘 보이는 탭
└────┴────┴────┴────┴───┘
```

- 누르면 **그 탭이 바로 열린다.** 한 번에 간다
- 지금 것을 안 버린다 — 시트와 탭은 이미 있다(`__byeotSheet.tab('shop')`). **여는 손잡이만 늘리는 일**이다
- ⚠ 폰 세로 390px 에서 다섯 칸이면 한 칸 **70px 남짓**이다. 손가락 최소(`--tap`)를 넘는지 **재야 한다**
- ⚠ [다음 날]을 작게 만들면 안 된다 — 제일 많이 누르는 단추다

★ **좌우보다 아래를 권한다.** 방을 세로로 길게 보는 화면이라 좌우에 띠를 세우면
방이 좁아진다. 그리고 엄지가 닿는 곳은 아래다.
