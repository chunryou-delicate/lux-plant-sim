## ★★ 2026-08-15 — **판매를 연다. 접었던 것이 되살아난다**

> 박사님: *"채소는 상점에서 판매 가능하게 해줘. 누르면 몇개팔지 나오게도 해주고."*
> 이어서 ㉯(곳간 채소도 팔 수 있게)를 고르시며: *"어차피 체력이 막고있어서 괜찮을거랴"*

**연다.** 어제 §0 에서 「되살아나는 조건」이라 적어 둔 그 문이 열렸다.

### 왜 안 무너지나 — 체력보다 **0.85 가 문지기다**

박사님 말씀(체력이 막는다)도 맞지만, 더 단단한 이유가 있다.
**곳간 1원 = 밥값 1원**인데 팔면 **0.85원**이다. 즉 **팔면 늘 손해**다.
이득을 보려고 파는 길이 애초에 없으므로, 잘 노는 사람은 계속 먹는다.
파는 것은 **급전이 필요할 때 손해를 감수하는 선택**이 된다 — 이사비 200만을 모으는
게임에서 그건 실한 긴장이다.
★ 코드 주석이 이미 그 위끝을 이렇게 적어 두었다: *"1.00 을 넘기면 「밥으로 먹는 것보다
파는 게 낫다」가 되어 이 게임의 뼈대가 뒤집힌다."* **0.85 는 그 아래**라 뼈대가 안 뒤집힌다.

### ★ 진짜 효과 — **상해서 버려지던 것이 돈이 된다**

지금 곳간에 한도(`pantryCapWon`)가 있고 넘치면 그 자리에서 버려진다(`spoiledWon`).
팔 수 있게 되면 그 몫을 **버리기 전에 넘길** 수 있다. 없던 벌을 만드는 게 아니라
**이미 있던 벌에 빠져나갈 길을 내는 것**이다.

### 그래서 되살아나는 것

| | 왜 |
|---|---|
| **꾸러미 목록** | *"누르면 **몇 개** 팔지"* — 개수가 있으려면 물건이 있어야 한다. 지금 곳간은 원이라 개수가 없다 |
| **먼저 것부터(FIFO)** | 팔 때 **어느 꾸러미가 나가는지**가 결과를 바꾼다(꾸러미마다 값이 다르다). 어제는 먹기만 해서 순서가 뜻이 없었는데, **팔기가 생기면 뜻이 생긴다** |
| **밥상 창** | 「먹을까 팔까」가 실제 선택이 되므로 [이대로]만 누르는 창이 아니게 된다 |

⚠ 유통기한은 여전히 **안 넣는다**(박사님 확정). 위 셋은 판매만으로 되살아난다.

### ⚠ 지킬 것

1. **파는 값은 `cropSurplusSaleRate`(0.85) 하나를 쓴다.** 새 값을 만들지 마라 —
   `characters.json` 이 정본이고 2026-08-09 박사님 확정값이다
2. **하루 몫(`dailyCropSaveWon`)은 안 건드린다.** 파는 길이 생겼다고 먹는 양을 늘리면
   경제 표를 전부 다시 재야 한다
3. **화면이 손해를 말해야 한다** — 「3,000원어치를 2,550원에 넘깁니다」처럼.
   안 말하면 모르고 팔고 나서 손해를 뒤늦게 안다
4. ⚠ **화면 문구가 지금 틀렸다** — 「값은 아직 미확정, 70%」라고 적혀 있는데 정본은 0.85 다.

## 0. 결론 — ★ **유통기한도, 꾸러미도, 밥상 창도 접는다** (2026-08-14 박사님 확정)

> 박사님: *"아니다 유통기한 그냥 없는걸로 하면 어떨지 싶다."*
> 이어서: *"유통기한이 없으면 먼저 것부터는 의미가 없어지지"*

**두 번째 말씀이 맞고, 그 한마디가 연쇄를 일으킨다.** 내가 앞서 *"꾸러미마다 품질이
달라서 먼저 것부터가 뜻이 산다"*고 적은 것은 **틀렸다.** 바로잡는다.

### 왜 연쇄가 일어나나

곳간에서 하루에 **3,000원어치**를 꺼내 먹는다. 꺼내는 **순서는 총합을 안 바꾼다** —
오늘 3,000원을 어느 꾸러미에서 꺼내든 내일 남는 돈은 같다.
순서가 뜻을 가지려면 **무언가가 없어져야** 하는데, 없애는 것은 유통기한뿐이었다.
(지금 있는 `spoiledWon` 은 **수확하는 순간** 상한을 넘긴 만큼을 버리는 것이라 소비 순서와 무관하다.)

```
유통기한 없음
   └→ 먼저 것부터(FIFO)가 결과를 안 바꾼다     ← 박사님 지적
        └→ 꾸러미 목록으로 바꿀 이유가 없다    (개수는 원 ÷ 회전분으로 근사하면 된다)
             └→ 반자동 밥상에 **고를 것이 없다**  ← 여기가 제일 중요하다
```

★ **밥상 창의 값어치는 「선택」에 있었다.** 그런데 유통기한이 없고 곳간을 팔 수도 없으면
(지금 주석: *"남는 것은 버려진다. **팔지 않는다**"*), 창은 **[이대로]만 누르는 창**이 된다.
손만 늘고 고르는 것은 없다. **그러면 안 만드는 게 맞다.**

### ⇒ 그래서 남는 것은 **둘뿐**이다

| | 왜 여전히 유효한가 |
|---|---|
| ① **곳간을 화면에 보이게** | 지금 곳간에 얼마가 쌓였는지, 오늘 얼마를 아꼈는지, **상해서 버려진 것이 있는지** 화면이 한 글자도 안 말한다. 고르게 하지 않아도 **보여는 줘야** 한다 |
| ② **낡은 주석 셋 고치기** | 아래 §3 에서 찾았다. 값을 안 바꾸는 일이라 언제 해도 안전하다 |

⇒ **꾸러미 구조 · FIFO · 유통기한 · 반자동 밥상 창은 전부 접는다.**
   §1~§7 은 지우지 않고 **기록으로 남긴다** — 나중에 판매를 열기로 하면 그때 다시 살아난다.

### ⚠ 되살아나는 조건 하나

**잉여를 팔 수 있게 열면** 밥상 창이 다시 뜻을 갖는다 — 「먹을까 팔까」가 생기기 때문이다.
그건 `food_economy` 의 설계 결정(곳간은 지출 방어이지 수입이 아니다)을 뒤집는 일이라
**따로 정하실 일**이고, 이 문서에서 혼자 정하지 않는다.

## 3. 제안 — 곳간을 **꾸러미 목록**으로

```js
// 지금:  food.pantryWon = 12000
// 바꿈:  food.pantry = [
//   { kind:'beansprout', day: 8, won: 3000, meals: 3 },   // 8일차에 거둔 것
//   { kind:'beansprout', day:11, won: 3000, meals: 3 },
//   { kind:'musun',      day:12, won: 1867, meals: 2 },
// ]
```

한 꾸러미 = **한 번의 수확**이다. 시루 하나를 거두면 하나가 생긴다.

이렇게 하면 세 요구가 **따로 만들 것 없이** 나온다:

- **개수** — `pantry.length`. 「콩나물 3판 · 무순 1판」
- **먼저 것부터** — `day` 오름차순으로 꺼낸다. 그게 곧 FIFO다
- **유통기한** — `day + 기한 < 오늘` 이면 상한다

### ⚠ 검토하다 찾은 것 — **주석 두 개가 낡아서 서로 반대말을 한다**

박사님이 *"3~4일 말고 좀 늘려"* 하셔서 값을 다시 재다가 걸렸다. 셈의 바닥이 되는 숫자부터 틀려 있었다.

| 어디 | 뭐라고 적혀 있나 | 실제 |
|---|---|---|
| `first_play.js:1763` | *"하루 상한 **600원**이 그 나눗셈이다"* | ✗ 틀렸다 — 아래 정정을 보라 |
| `first_play.js:1771` | *"상한은 **시루 수에 비례한다**"* | ✗ 안 비례한다 |
| `first_play.js:1752` | *"시루 수에 **안** 비례하는 이유"* | ✓ 이쪽이 맞다 |

> ### ⚠⚠ 2026-08-15 — **고친다면서 또 틀렸다. 이 문서 아래쪽의 「3,000원」은 전부 거짓이다**
>
> 위 표에서 600원을 **「3,000원이다」로 고쳤는데 그것도 틀렸다.** 실측은 **4,867원**이다.
>
> 3,000원은 **작물이 콩나물 하나뿐이던 때**의 값이다. 무순이 둘째로 들어오면서
> 한 회전분이 `3,000 + 1,867`(무순 2,800 × 질림 2/3) = **4,867원**이 됐고,
> 하루 몫은 그것과 끼니 상한 5,000원 중 작은 쪽이라 **4,867원**이다.
> 이 문서 §「그래서 실제 셈은 이렇다」 아래로 **3,000원 위에 얹은 셈은 전부 다시 세야 한다.**
>
> ★ **이 사고의 결이 다르다.** 값이 낡은 게 아니라, **낡은 값을 고치면서 또 낡은 값을 적었다.**
> 「600 → 3,000」이 맞다고 믿은 근거가 콩나물 한 종류짜리 옛 문서였다.
> ⇒ **숫자를 문서에 적지 마라. `dailyCropSaveWonOf(fp)` 를 읽어라.** 코드 주석은 고쳐 놨다.
>
> 다행히 결론은 안 뒤집힌다 — 유통기한은 박사님이 **없애기로** 하셨고,
> 판매 창구도 하루 몫을 **안 건드린다**. 그래서 이 정정이 오늘 만든 것을 무르지 않는다.
> ⚠ 다만 **여유가 133원뿐이다**: 셋째 작물이 들어오는 순간 끼니 상한이 이기고,
>   그때부터 「작물을 늘려도 하루 저감이 안 는다」가 된다.

**정본은 `dailyCropSaveWon = min(한 회전분, 끼니 상한)`** 이다(`:482`). **여기에 값을 안 적는다.**
2026-08-04 에 「회전분을 일수로 나눠 먹기」에서 **「하루에 한 회전분」**으로 바꿨는데,
그때 이 주석들이 안 따라왔다. 오늘만 세 번째로 겪는 사고다(`START-HERE §2.6`).
⇒ **이 셋은 고쳐야 한다.** 값을 안 바꾸는 일이니 언제 해도 안전하다.

### 그래서 실제 셈은 이렇다

| | |
|---|---|
| 하루에 먹을 수 있는 양 | **3,000원** (콩나물 한 회전분) |
| 시루 n개의 하루 평균 유입 | n × 600원 (5일에 3,000원) |
| ⇒ **균형점** | **시루 5개** — 매일 하나씩 거두면 유입 3,000 = 소비 3,000 |
| 6개째부터 | 반드시 같은 날과 겹쳐 **2,000 → 1,000 → 0** 으로 깎인다(겹침) |

★ 이 게임은 **시루 5개를 균형점으로 설계돼 있다.** 코드 주석 ①이 그렇게 적어 뒀다.

### ⇒ 유통기한이 실제로 무엇을 정하나 — **「몰아 거두기」를 얼마나 봐주느냐**

- **시루 1개**: 거둔 날 3,000원을 그날 다 먹는다 → 곳간이 안 남는다. **기한이 아예 안 물린다**
- **시루 5개를 하루씩 어긋나게**: 매일 1판 들어오고 매일 1판 먹는다 → 큐가 1판. **안 물린다**
- **시루 5개를 같은 날 몰아**: 15,000원이 한꺼번에 들어오고 하루 3,000원씩 먹는다 →
  **5일에 걸쳐 먹는다.** 여기서 비로소 기한이 물린다

⇒ **기한은 「얼마나 상하나」가 아니라 「몰아 거둬도 되나」를 정하는 값이다.**

### 값 — **콩나물 7일**이었다 · ⛔ **안 쓴다**(§0 에서 접음 · 기록용)

| | |
|---|---|
| 3~4일 | ✗ **너무 짧다.** 시루 5개를 몰아 거두면 뒤 두 판이 그냥 상한다. 그런데 몰아 거두기는 **겹침(2,000→1,000→0)이 이미 벌하고 있다** — 기한까지 짧으면 **같은 잘못에 벌이 둘**이다 |
| 5일 | 회전과 같아서 「다음 판 나올 때 딱 떨어진다」. 깔끔하지만 여유가 0이라 물 하루 늦게 준 판이 바로 아프다 |
| **7일** | **권함.** 몰아 거둔 5판을 5일에 걸쳐 다 먹고도 **이틀 여유**가 남는다. 잘 굴리는 사람은 절대 안 상하고, 시루를 6개 이상으로 늘린 사람만 물린다 — 그게 이 규칙이 물려야 할 자리다 |
| 10일 이상 | 사실상 안 물린다. 규칙만 늘고 체감이 없다 |

**무순은 회전이 7일이니 같은 비율로 10일**을 권한다(회전 × 1.4).

⚠ 이 값은 **`data/balance/` 로 뺀다.** 코드에 박지 않는다 — 이 저장소 규약이다.

## 5. ⚠ 그래도 같이 봐야 하는 것

§3 에서 셈을 바로잡고 나니 처음에 걱정했던 것(「시루를 늘리면 대부분 상한다」)은 **안 일어난다.**
하루에 3,000원까지 먹으므로 **시루 5개까지는 유입과 소비가 맞물린다.** 그래도 남는 물음 셋:

1. **시루 6개 이상이면 어떻게 되나.** 지금은 겹침이 2,000 → 1,000 → 0 으로 깎는다.
   여기에 기한이 얹히면 **같은 잘못에 벌이 둘**이 된다. §4 대로 상한을 걷으면 하나로 준다
2. **잉여를 팔 수 있게 열 것인가.** 지금 주석은 *"남는 것은 버려진다. **팔지 않는다**"* 다.
   ★ 기한이 생기면 「상하기 전에 팔자」가 실한 선택이 된다 — 축이 느는 게 아니라
   **이미 있는 축(85% 판매)에 힘이 붙는 것**이다. 이사비 200만을 모으는 게임이라 값이 있다
3. **초반은 안 다친다** — 시루 1~3개 구간은 거둔 날 다 먹으므로 곳간이 안 남는다.
   기한이 아예 안 물린다. 확인만 하면 된다

⚠ **하루 몫(3,000원)은 건드리지 마라.** 그 값은 끼니 상한·질림·겹침과 물려 있고,
건드리면 경제 표(`econ-to-plan §7.5~7.14`)를 전부 다시 재야 한다.

## 6. 화면 — 반자동 밥상에 이렇게 적는다 (박사님 요청분 포함)

```
 ┌──────────────────────────────────┐
 │ 오늘 밥상                          │
 │  🥣 콩나물  3판   (8일차 · 11일차 · 13일차)  │  ← ★ 잔여 개수
 │  ⚠ 8일차 것은 내일 상합니다(7일)      │  ← ★ 유통기한 경고
 │  ─────────────────────────────  │
 │  오늘 먹을 것  8일차 콩나물  −3,000원 │  ← 먼저 것부터 (FIFO)
 │  아낀 식비  3,000 / 3,000원          │
 │  상하기 전에 팔면  2,550원           │  ← 85%
 │              [이대로]  [바꾸기]      │
 └──────────────────────────────────┘
```

★ **상하는 순간을 반드시 말한다.** 지금은 상해도 아무 말이 없다.
   ⇒ 상한 날 배너: `콩나물 1판이 쉬었습니다 — 3,000원` 처럼.
