# 빛식물 — 보이는 층 다시 짜기 (기획안)

2026-09-24 · 총괄(claude-a3) · 박사님 지시: *「이 영상은 저 퀄리티를 금방 만들던데, 이건 왜 이렇게 오래 걸리고 퀄이 이런지 모르겠다. 기획안부터 다시 짜 보라」*
참고 영상: https://www.youtube.com/watch?v=WKjCEMnScf8 (스마트대디 · 「GPT-6 Sol vs 클로드 Opus 5.5 비교」 · 12분 · 2026-09-23)

전제: **게임 규칙·밸런스·생장 캐논(확정값)은 그대로 둔다.** 반지하→몬스테라→하프문→이사의 고리는 실제로 돈다.
다시 짜는 것은 **「무엇을 보여 주나」와 「어떻게 만드나」**다.

---

## 1. 영상은 실제로 무엇을 했나

영상을 5초 간격으로 145장 찍고 자막 전체를 읽었다. 여섯 시험 중 3D 게임 둘(대항해시대·다크소울)이 우리와 가장 가깝다.

**요청은 한두 줄이었다.** 화면에 보이는 프롬프트 원문:
- 「대항의 시대 스타일의 3d 항해 시뮬레이션 게임 만들어줘. 3d에셋은 힉스필드 mcp …」
- 「브라우저에서 직접 조작 하는 3d 트랜스포머 로봇 변신 시뮬레이터를 만들어줘. … blender 이용해서 구현해줘」
- 모드는 Claude Code **Ultracode**(여러 에이전트가 나눠 만들고 서로 검사하는 모드)였다.

**에셋은 「좋은 그림 한 장 → 3D 변환」이었다.** 힉스필드 화면(4:30, 6:10)을 보면
1. 이미지 모델(GPT Image 2.5)로 **흰 바탕에 물체 하나씩** 개념 그림을 뽑고
2. 그것을 이미지→3D로 바꿨다. 힉스필드의 3D 메뉴를 열어 보니 **속은 Meshy다**(image_to_3d · 리깅 · 678가지 동작 클립).
3. 캐릭터는 **옷까지 입은 한 벌 통째**로 뽑고, 리깅과 걷기·공격 동작을 **변환할 때 같이** 받았다.
⇒ 도구는 우리가 이미 쓰던 Meshy와 같다. **쓰는 법이 달랐다.**

**화면의 품질은 대부분 에셋 밖에서 나왔다.** 다크소울 판(7:15~8:40)에서 눈에 띄는 것은 횃불 빛·안개·빛줄기·먼지·타격 이펙트·카메라가 스스로 도는 연출이다. 트랜스포머·롤러코스터·강아지 애니는 **에셋 없이 코드만으로** 그 수준이 나왔다. 롤러코스터는 소리(바람·바퀴)가 속도에 따라 바뀌는 것이 몰입의 절반이었다.

**「금방」은 사람 손이 안 들었다는 뜻이지 빨랐다는 뜻이 아니다.** 영상 11:10 기준:

| | 여섯 시험 합계 |
|---|---|
| Opus 5.5 작업 시간 | 14시간 30분 (한 개 평균 약 2시간 25분) |
| API 비용 환산 | $529 (한 개 평균 약 $88) |

그리고 결과물은 **한 판짜리 데모**다. 저장·경제·며칠에 걸친 성장 같은 것은 없다. 우리 게임이 가진 규칙 층은 영상에 없다.

## 2. 우리는 왜 느리고 화면은 왜 이런가

지금 게임을 1280×720으로 사흘 눌러 찍었다(`tools/_out/playshot/plan0924/`). 방은 **회색 상자 가구에 평평한 빛**이고, 2D 초상화(웹툰풍)만 완성도가 높다. 이유는 다섯이다.

**① 힘을 «안 보이는 층»에 썼다.**
2026-07-11부터 커밋 1,942개 중 **1,195개(61%)가 문서**다. 인계 문서 289개, 검사·탐침 스크립트 303개, START-HERE 1,953줄, 「재는 자가 거짓말하는 방식」 69조. 방 렌더러(`src/render3d`) 커밋은 79개다.
규칙 층이 정확해진 것은 그 덕이지만, **박사님이 보는 화면에는 그 61%가 하나도 안 보인다.**

**② 방 화면에 «분위기를 만드는 장치»가 하나도 없다.**
렌더러를 훑으면 후처리(블룸·SSAO·색보정)가 0, 빛줄기·먼지·안개 0, 환경음 0이다. 가구는 코드로 쌓은 상자(`furniture.js`)이고 텍스처를 쓰는 곳은 천 하나(`fabricTex`)다. 영상의 품질을 만든 바로 그 층이 비어 있다.

**③ 캐릭터는 제일 어려운 문제부터 풀려고 했다.**
옷을 부품으로 갈아입히는 체계(Meshy가 구운 몸에서 옷을 색으로 떼어 우리 뼈대에 다시 붙이기)는 3D에서 가장 어려운 축에 든다. 거기에 두 달, 커밋 148개, 자체 파이썬 도구 59개를 썼고 결론은 **「옷 입은 몸 통째」**로 돌아왔다. 영상은 처음부터 통째로 뽑고 리깅·동작을 변환할 때 같이 받았다. 그리고 **게임 안의 캐릭터는 아직 옛 치비 그대로**다.

**④ 게임 화면이 아니라 «내 렌더러»로 판정했다.**
캐릭터 결과를 직접 짠 렌더러로 찍어 판정했는데, 그 렌더러가 구멍 점을 만들고 밝기를 1.25배 올려 결함을 가렸다. 박사님이 「스샷 중 정상인 게 없다」고 짚으실 때까지 못 봤다. 영상은 **게임을 실제로 해 보며** 판정했다.

**⑤ 창이 여섯이라 한 사람이 「한 장면」을 끝까지 책임지지 않았다.**
영상은 한 요청을 한 세션이 처음부터 끝까지 만들었다(Ultracode 안에서 에이전트를 나눴을 뿐). 우리는 조명·가구·캐릭터·식물이 창마다 갈라져 있어 **한 화면을 누구도 끝까지 다듬지 않았다.**

## 3. 새 기획 — 「첫 5분」 한 장면을 영상 수준으로

목표를 좁힌다. **반지하 방 한 칸, 첫날 아침부터 첫 수확까지의 5분**을 박사님이 영상과 나란히 놓고 봐도 밀리지 않게 만든다. 이것이 되면 원룸·밤·계절은 같은 방법으로 넓힌다.

### 3-1. 아트 방향 하나 (박사님 결정)

| | 무엇 | 장점 | 걸리는 것 |
|---|---|---|---|
| **A. 따뜻한 디오라마 (추천)** | 손그림 느낌 재질 · 부드러운 창빛 · 작고 꽉 찬 소품. 「Unpacking」「A Little to the Left」 결 | 지금 웹툰 초상화·치비 캐릭터와 맞는다. 반지하의 «좁고 어두운데 아늑한» 정서와 맞는다 | 생성기 그림을 한 톤으로 묶는 스타일 지시가 필요하다 |
| B. 사실풍 | 영상 다크소울·대항해처럼 PBR 재질·실사 가구 | 생성기가 가장 잘 뽑는 결이다 | 초상화·캐릭터와 안 맞아 캐릭터도 다시 뽑아야 한다 |
| C. 로우폴리 파스텔 | 지금 `furniture_pastel.js` 방향을 다듬기 | 가장 싸고 빠르다 | 영상 수준의 «와»가 안 나온다 |

### 3-2. 단계

**0단계 · 브리프 한 장 (반나절 · 크레딧 0)**
영상의 한 줄 프롬프트에 해당하는 것을 우리 게임용으로 쓴다. 방향 그림(무드보드) 세 장, 반지하 첫 5분의 장면 목록, 소품 목록, 동작 목록. 박사님이 이 한 장으로 방향을 고른다.

**1단계 · 코드만으로 분위기 (1~2일 · 크레딧 0)**
영상의 절반은 에셋 없이 나왔다. 먼저 이것부터 한다.
- 빛: 반지하 창에서 드는 **빛줄기와 떠다니는 먼지**, 스탠드의 따뜻한 빛, 시간대별 색(새벽 푸름 → 낮 → 저녁 주황). 이미 있는 조도 시뮬레이션 값을 화면 빛에 잇는다
- 후처리: 그늘 모서리(SSAO), 빛 번짐(블룸), 색보정, 비네트
- 재질: 벽지·장판·시멘트 얼룩을 코드로 그린 텍스처
- 카메라: 대사할 때 인물 쪽으로 살짝 다가가기, 수확 때 시루 쪽으로
- 소리: 반지하 환경음(냉장고 윙·밖의 발소리·빗소리), 물 주기·거두기 효과음

**2단계 · 가구와 소품 (2~3일 · 크레딧 필요)**
개념 그림 → 이미지→3D. 반지하 가구 10점, 소품 15점(라면 봉지·빨래 건조대·전기장판·곰팡이 핀 모서리 같은 «반지하다운 것»). 한 톤 지시를 모든 그림에 똑같이 건다. **생성기가 못 하는 것은 기획에서 뺀다.**

**3단계 · 캐릭터 교체 (1~2일 · 크레딧 필요)**
주인공 한 명을 개념 그림 → 이미지→3D + 리깅 + 동작 클립으로 새로 뽑는다. 옷은 **통째로 네 벌**(잠옷·집옷·외출·작업복). 동작은 서기·걷기·앉기·눕기·물 주기·쪼그려 앉기. 몬이도 같은 길로. 자체 GLB 수술은 쓰지 않는다.

**4단계 · 판정 (반나절)**
첫 5분을 실제 게임에서 녹화해 영상 장면과 나란히 놓는다. 판정은 박사님 눈 하나다. 통과하면 원룸으로 넓힌다.

### 3-3. 크레딧 어림

| 항목 | 개수 | 어림 |
|---|---|---|
| 가구·소품 개념 그림 | 25장 | 그림 1장 약 9 |
| 가구·소품 이미지→3D (텍스처) | 25점 | 1점 약 30 |
| 캐릭터 옷 네 벌 · 몬이 | 5벌 | 그림 9 + 3D 30 + 리깅 5 + 동작 6개 × 3 |
| 다시 뽑기 여유 | 30% | |
| **합계** | | **약 1,600 크레딧** |

지금 잔액은 Meshy 36, 힉스필드 0이다. **충전이 있어야 2·3단계가 시작된다.** 1단계는 크레딧 없이 바로 할 수 있다.

### 3-4. 운영을 이렇게 바꾼다

- **한 장면은 한 세션이 끝까지 만든다.** 이번 일은 총괄 한 창이 맡는다. 나머지 여섯 창은 대기(점호 결과 모두 대기 중이라 비용이 안 든다).
- **판정은 게임 화면으로만** 한다. 자체 렌더러로 찍은 그림은 판정에 쓰지 않는다.
- **문서는 결과 한 장.** 이 기획안이 이번 일의 정본이고, 단계마다 게임 화면 캡처 한 장과 몇 줄로 보고한다. 새 측정 규칙은 늘리지 않는다.
- 박사님이 원하시면 영상처럼 **Ultracode**로 돌릴 수 있다. 여러 에이전트가 나눠 만들어 빠르지만 토큰이 많이 든다(영상은 한 개에 평균 약 $88 환산).

### 3-5. 하지 않을 것

- 옷을 부품 단위로 갈아입히기(벌 단위만 한다)
- Meshy 결과물을 파이썬으로 뜯어고치는 일
- 규칙 층(경제·생장 수식) 손대기 — 이번 일의 범위가 아니다

## 4. 박사님이 정하실 것

1. **아트 방향** — A 따뜻한 디오라마(추천) · B 사실풍 · C 로우폴리 파스텔
2. **크레딧 충전** — Meshy 또는 힉스필드에 약 1,600 크레딧. 1단계는 충전 없이 먼저 시작할 수 있다
3. **옷 범위** — 부품 갈아입히기를 접고 「통째 네 벌」로 가도 되는지
4. **Ultracode 사용 여부** — 빠르지만 비싸다
