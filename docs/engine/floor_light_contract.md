# 바닥 조도 계약 — 「바닥 수치로 그냥 재기」가 어디까지 되나

갱신: 2026-08-24 · [House]·[growth] 가 **같은 날 각각** 쟀다 (그래서 답이 두 번 나왔다)
잰 자: `tools/test_coord_matches_slot.mjs` ([growth]) · `tools/probe_floor_contract.mjs` ([House])

## 먼저 — 이게 무슨 이야기인가

방에는 **이름 붙은 자리**가 있다. 창턱, 책상 위, 선반 셋째 칸 같은 것이다.
반지하는 그런 자리가 **열다섯 개**고, 그 열다섯의 밝기는 표로 얼려 두었다.

그런데 **바닥은 자리가 아니다.** 바닥은 넓고, 이름이 없고, 아무 데나 놓을 수 있다.
콩나물 시루는 바로 그 바닥에 놓인다.

⇒ 그러면 **바닥에 놓은 시루의 밝기를 무엇으로 재나?**
  이름이 없으니 표에서 못 찾는다. 남은 길은 **좌표로 직접 묻는 것**뿐이다.

박사님이 정하신 것이 그것이다 — *"★ 바닥 수치로 그냥 재기로 했잖아."*

## ⇒ 답: **게임에서는 이미 그렇게 하고 있다. 안 되는 것은 「우리가 재는 자」다**

계약에는 자리를 부르는 길이 둘이고, **둘 다 있다**:

```
① 이름으로   io.light.dliOfSlot('banjiha-sill:0', 옵션)
② 좌표로     io.light.dliAt({x,y,z}, {occIdx, ...옵션})
```

★ 그리고 **둘은 같은 점에서 같은 값을 낸다.** 반지하 15칸 + 바닥 4점, **소수 넷째 자리까지 같다.**
⇒ 자가 둘이 아니다. 이건 확인된 것이고, 이 저장소에서 그렇게 말할 수 있는 것이 드물다.

⚠ **[House]·[growth] 가 서로 모르고 같은 날 같은 것을 쟀다.** 답이 두 번 나왔고 둘이 맞았다.
  ⇒ ★ 그래서 **한 벌을 지웠다** — 15칸 대조는 `test_coord_matches_slot.mjs` 가 갖고,
    `probe_floor_contract.mjs` 는 **바닥 쪽만** 남겼다. **두 벌이면 갈리고, 갈리면 어느 쪽이
    맞는지 아무도 모른다.** (`test_lampmove ①-0` 에서 같은 판단을 한 적이 있다.)
  ⇒ ⇒ 그리고 `light_adapter §dliAt` 주석이 *"슬롯 판정과 «같은 함수»를 탄다"* 고 **적어만 두고
    아무도 안 재고 있었다.** 이제 잰다.

```
자리                    ①이름     ②좌표
banjiha-sill:0          3.6800   3.6800   같다
banjiha-nightstand:0    0.4400   0.4400   같다
… 15칸 전부 같다

바닥 ( 0.0, 0.0)        0.2700   0.2700   같다     ← 이름 없는 화분도 두 길이 만난다
바닥 ( 0.3, 0.6)        0.1800   0.1800   같다
바닥 ( 1.8, 1.8)        0.0600   0.0600   같다
바닥 (-1.5,-1.5)        0.0000   0.0000   같다
```

★ 그리고 **바닥 네 점이 서로 다른 네 값이다.** 좌표를 실제로 보고 있다는 뜻이다.
★ 바닥 좌표가 내는 것은 값 하나가 아니라 **계약 한 칸 통째**다 —
  `dli` · `dli_daylight` · `dli_lamp` · `peak_lx` · `band` · `fenestrating` · `overlight` · `ko`.
  **슬롯이 내는 것과 같은 모양**이라 갖다 쓰면 된다([growth] 가 열쇠까지 셌다).

# ⛔ 그런데 헤드리스는 못 잰다. 그리고 **못 잰다고 말하지 않는다**

정적 프로필(`data/profiles/*` · `room_profile.createProfileLight`)에는 **좌표 표가 없다.**
이름 붙은 열다섯 칸뿐이다. 바닥 점은 그 표에 없다.

```
                       브라우저(라이브)   헤드리스(정적 프로필)
이름으로 sill:0            3.68              3.68        ✅ 만난다
바닥 ( 0.0, 0.0)           0.27            ★ 0           ⛔ 갈린다
바닥 ( 0.3, 0.6)           0.18            ★ 0           ⛔ 갈린다
바닥 ( 1.8, 1.8)           0.06            ★ 0           ⛔ 갈린다
바닥 (-1.5,-1.5)           0.00              0             (우연히 같다)
dliAt 이 있나              있다            ★ 없다
```

## ★★★ 그 `0` 은 「어둡다」가 아니라 **「모른다」**다

`room_profile.js:165` 이 그렇게 적혀 있다 — *"자유 좌표 화분을 이 경로로 돌리면
그 화분의 slotId(`free:…`)가 표에 없어 0 이 나온다."*

⇒ ⇒ ★ 그리고 **콩나물 최상 대역은 상한만 있고 하한이 없다**(`maxDli 0.3`).
> ## ⛔ 그래서 **「몰라서 나온 0」이 「최상 등급」으로 읽힌다.**
> ## ⇒ 헤드리스로 바닥 작물을 재면 **소리 없이 초록이 된다.**

## ⚠ 그리고 이 거짓말은 **어느 점을 찍느냐에 달려 있다**
위 표의 `(-1.5,-1.5)` 를 보라. 브라우저도 0, 헤드리스도 0 — **우연히 맞았다.**
⇒ ★ 어두운 구석을 찍은 검사는 **통과한다.** 밝은 데를 찍어야 갈린다.
⇒ ⇒ **「검사가 초록이니 됐다」가 여기서는 안 통한다.** 표본이 답을 정한다.

## ⚠ 어느 쪽으로 틀리는지 — 「최하가 된다」가 아니다
[growth] 가 재 뒀다(`night-20260823.md §10.9`):
- **반지하에서는 티가 안 난다.** 바닥 최댓값이 0.32 라 0.30 을 넘는 점이 221 중 다섯뿐이다.
- ★ **터지는 데는 바닥 최댓값이 0.3 을 넘는 방이다.** 거기서는 어두운 구석까지 최상으로 읽혀
  **콩나물을 잘 놓고도 초록·쓴맛**이 된다 — 지금 병의 **정반대**이고, **잘 한 것을 벌하므로 더 나쁘다.**

# ✅ 결정됐다 — **D** (박사님 2026-08-30 · 총괄 전달)

> ## **「헤드리스는 «모른다고 던진다». 바닥 표가 필요하면 «브라우저 자로만» 낸다.」**
```
① 게임(라이브)        이미 좌표를 잰다. ★ 손댈 것 «없음»
② 헤드리스 dliOfSlot  ✅ «던진다» — [core] 3b3177f. `at` 가 있거나 `free:` 면, 그리고 표에 없는 slotId 도
                      「[정적 프로필] 자유 좌표 자리 … 의 조도는 모른다 — 바닥 표는 브라우저 자로만 낸다(계약 D)」
③ 바닥 표             `tools/probe_floor_dli.mjs` (라이브) «로만» 낸다 — [growth] 가 이미 그렇게 한다
④ 파수꾼              `tools/probe_floor_contract.mjs` — ✅ [잰 것] 네 점 «전부» 「던짐 … 계약 D」
                      ⇒ 이제 이 자는 「0」이 하나라도 나오면 «붉어진다» — D 가 빠진 것이다
```
⚠ **값은 하나도 안 바뀐다.** 이 결정은 「게임을 고치는 것」이 아니라 «우리가 재는 법»을 «정한» 것이다.

# ⏸ (옛 절 — 결정 «전»의 갈래. 기록으로 남긴다) 남은 결정 — 박사님 몫이다

`docs/handoff/night-20260823.md §좌표 조도 계약` 에 A·B·C 가 있다.
**이 문서는 그 셋 중 하나를 고르지 않는다.** 여기서 새로 보탠 것은 하나다:

> ## ★ **A·B·C 는 「게임을 고치는 안」이 아니다. 게임 쪽은 이미 된다.**
> ## ⇒ 셋은 전부 **「우리가 바닥을 어떻게 잴 것인가」**에 대한 안이다.

⇒ 그러니 결정이 늦어도 **플레이어가 보는 값은 안 틀린다.** 늦어서 위험한 것은
  **밸런스 표**다 — 헤드리스로 뽑은 바닥 작물 수치는 그때까지 **믿으면 안 된다.**

## ⇒ 그때까지 지킬 것 하나
```
바닥이 밝나          tools/probe_floor_dli.mjs         (라이브 · 브라우저) [growth]
좌표 = 슬롯 인가     tools/test_coord_matches_slot.mjs (라이브 · 브라우저) [growth]
바닥에서 갈리나      tools/probe_floor_contract.mjs    (라이브 + 헤드리스) [House]
⛔ 정적 프로필로 바닥을 묻지 마라 — 0 이 돌아오고, 그 0 이 초록으로 읽힌다
```

■ 곁의 것: [core] 가 본 「바닥 시루가 **대표값**으로 떨어진다」는 **이것과 다른 병**이다.
  그건 `loop.js:996` 의 `cropDli`(작물 종류마다 «한 값»)와 `dliBySlot`(시루마다) 사이의 일이고
  **`src/game/` 마당**이다. 여기서 잰 것으로는 **라이브 엔진은 결백하다** — 좌표를 물으면 좌표를 준다.
