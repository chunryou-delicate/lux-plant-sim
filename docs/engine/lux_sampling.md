# 창 적분 샘플링 — 정확도 기준선

`src/engine/daylight_lux.js` · `daylightAt(p, n, wins, { samples })`

---

## 문제

창을 조각으로 쪼개 각 조각을 **점광원**으로 취급해 적분한다.

```
E = Σ L·cosWin·cosP·dA / d²        L = Ev·τ/π
```

조각이 거리에 비해 크면 `1/d²` 근사가 깨진다.
고정 `[4,3]`은 작은 창에선 괜찮았지만 **큰 창·근거리에서 무너진다.**

---

## ★ 옛 회귀 기준선(426/104/559)이 검증하지 못한 것

tool.html의 기본 장면은 `windows:[]` — **창이 하나도 없다.**
그래서 이관 당시 확인한 `hAvg 426 / mMin 104 / mMax 559`는
`candela`·`axialIntensity`·`pointIllum`·`isShadowedEx`(인공광 경로)만 검증했고
**`daylightAt`(자연광 경로)은 한 번도 실행되지 않았다.**

"회귀 불변"은 그 세 숫자에 한해 사실이고, 자연광에 대해선 **아무 말도 하지 않았다.**
아래가 자연광 경로의 실제 기준선이다.

---

## 정확도 측정

기준(참값) = 고정 `[128,128]` 수렴값.

### 엔진 일반 (천공 25,000 lx)

| 창 | 거리 | 고정 [4,3] 오차 | **auto 오차** |
|---|---|---|---|
| 1.2×1.4 | 0.4m | −27.7% | **−1.6%** |
| 1.2×1.4 | 1.5m | −9.6% | −9.3% → **수정 후 ±2.5%** |
| 4.9×2.7 | 0.4m | **−56.7%** | **−1.2%** |
| 4.9×2.7 | 0.8m | −26.9% | **−1.5%** |

고정 샘플링은 **양방향으로** 틀린다. 근거리에선 과소평가하고,
최댓값을 탐색하면 조각 중심이 측정점에 붙는 자리를 골라 **과대평가**한다
(온실에서 106,540 lx = 물리 상한 21,250의 5배가 나온 경위).

### 파라미터 결정

창 3종 × 거리 6종(0.3~5.0m) 전 조합의 **최대 오차**:

| 최소분할 | 조각크기 | 최대오차 | 평균 샘플수 |
|---|---|---|---|
| 2 | d/3 | 9.6% | 132 |
| 3 | d/3 | 10.8% | 133 |
| **4** | **d/4** | **±2.5%** | **182** |
| 6 | d/6 | 1.1% | 261 |

**채택: 최소 4분할 · 조각 한 변 ≤ d/4 · 짝수 강제.**

> **분할수는 짝수여야 한다.** 홀수면 창 정중앙에 샘플이 놓여 계통 편향이 생긴다 —
> 최소 3이 최소 2보다 **오히려 나빴다**(10.8% vs 9.6%).

## ★ tool.html 새 기준선 (자연광, 천공 8,000 lx, 작업면 y=0.75)

`samples:'auto'`를 tool.html에도 켰다. **이건 회귀가 아니라 버그 수정이다.**

| 창 | 지점 | 옛값 [4,3] | **새값 auto** | 변화 | 참값 대비 |
|---|---|---|---|---|---|
| 일반창 1.5×1.4 | 창가 0.5m | 1685.3 | **1630.0** | −3.3% | +1.3% |
| 일반창 1.5×1.4 | 중앙 | 472.9 | **469.0** | −0.8% | +1.6% |
| 일반창 1.5×1.4 | 안쪽 | 134.3 | **133.7** | −0.4% | +0.8% |
| 큰창 2.6×2.0 | 창가 0.5m | 2322.0 | **2142.2** | −7.7% | +0.3% |
| 큰창 2.6×2.0 | 중앙 | 833.3 | **809.2** | −2.9% | −0.6% |
| 벽 전체 4.0×2.4 | 창가 0.5m | 1618.0 | **2311.5** | **+42.9%** | +0.3% |
| 벽 전체 4.0×2.4 | 중앙 | 1008.4 | **1051.5** | +4.3% | +1.0% |
| 벽 전체 4.0×2.4 | 안쪽 | 398.8 | **408.9** | +2.5% | +0.8% |

- 일반창은 사실상 그대로(−3% 이내). **기존 툴 사용 결과는 대체로 유효하다.**
- 벽 전체 창은 **창가에서 +42.9%** — 옛 값이 크게 과소평가였다.
- 새 값은 전부 참값의 **±1.6%** 안이다.

**UI 표시값(hAvg/mMin/mMax)은 안 바뀐다** — 기본 장면에 창이 없어서 자연광이 0이기 때문.
창을 추가한 순간부터 위 표대로 달라진다.

## 사용

```js
daylightAt(p, n, wins, { samples: 'auto' })   // 게임 · 측정 · tool.html — 전부 이것
daylightAt(p, n, wins, { samples: [8, 6] })   // 고정하고 싶을 때만
```

기본값은 여전히 `[4,3]`이다(인자 없이 호출하는 코드 보호용).
**새로 쓰는 코드는 항상 `'auto'`를 넘긴다.**
