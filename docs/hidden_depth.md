# 숨겨진 공략 — 물리에서 나온 것만 숨긴다

**2026-08-01 신설.** 개발하면서 우리가 발견한 것들이 그대로 좋은 공략이다.
게임에 숨겨두면 플레이어가 **찾는 재미**가 생긴다.

> 정본은 `GAME_PLAN.md`. 이 문서는 **발견 목록과 그 판정**을 관리한다.
> **새 발견이 나올 때마다 여기 추가한다** — 각 창 STATUS의 "발견" 항목이 그대로 재료다.

---

# 0. 원칙 — 물리에서 나온 것만

| | |
|---|---|
| ✅ **좋은 비밀** | **물리 결과.** 관찰·실험으로 찾을 수 있고, 일관되고, 설명이 된다 |
| ❌ **나쁜 비밀** | 임의 규칙(*"3번 클릭하면 2배"*). 알 방법이 없어 **위키 없으면 못 하는 게임**이 된다 |

**새 비밀을 만들지 않는다. 이미 물리에 있는 걸 발굴해서 목록화한다.**
그래서 플레이어가 발견하면 *"내가 알아냈다"* 가 된다 — 우리가 실제로 그렇게 알아냈으니까.

## ★ "알면 좋은 것"과 "몰라도 되는 것"을 가른다

```
알면 좋음    효율 2배. 몰라도 느리게 갈 수 있다     ← 이게 비밀
모르면 막힘  ← 비밀이 아니라 벽. 튜토에서 가르치거나 난이도를 낮춘다
```

**★ 자취생이 위험하다.** 경제가 빠듯해서 벽 선반 트릭을 모르면 진짜 못 간다.
그럼 그건 비밀이 아니라 **필수 지식**이다. 아래 표의 「몰라도 되나」 열이 그 판정이다.

## 발견 경로 3단계 — 이게 없으면 아무도 못 찾는다

| 단계 | 무엇 | 우리 게임에서 |
|---|---|---|
| 1. **관찰 가능** | 조도맵 · 잎 상태 변화 | 정보 축(초보 숫자 / 표준 막대) |
| 2. **실험 가능** | 옮겨보기 · 등 켜보기 — **되돌릴 수 있어야** | 가구 0.25m 그리드 · 튜토 되돌리기 |
| 3. **결과 명확** | 162배면 한 번에 보인다 | 밴드 라벨 · 말 피드백 |

**정보 축(초보 숫자 / 표준 막대 / 고수 없음)이 정확히 이 장치다.**
초보는 숫자로 배우고, 고수는 그 지식으로 숫자 없이 한다. **이미 있는 축이라 새로 안 만들어도 된다.**

# 2. 아직 못 찾은 것 — 검토 결과

박사님 질문 셋을 물리로 확인했다.

## ① 계절별 최적 배치가 다른가 → **지금은 다르지 않다**

**엔진의 천공이 방향과 무관한 균일 휘도**다(`daylight_lux.js`).
계절은 **세기(`k`)와 낮 길이(`hours`)만** 바꾸고 **기하는 그대로**다.
→ **모든 자리가 같은 비율로 어두워진다. 순위가 안 바뀐다.**

```
겨울 = 여름 × 0.372   (모든 슬롯에 같은 계수)
→ 1등 자리는 겨울에도 1등이다
```

**⚠ 단 온도가 들어오면 바뀐다.** 창가는 겨울에 춥다 —
*"여름엔 창가가 명당인데 겨울엔 냉해"* 가 생기면 **계절별 배치가 진짜 비밀이 된다.**
지금은 없고, 온도 축을 넣을 때 **의도적으로 만들 값어치가 있다.**

## ② 차광 걷는 타이밍 → **★ 있다. 이미 물리에 있다** (위 표 #8)

`greenhouse_plan.md` 실측: 온실에 여름 차광막 50%를 걸면 6.7(최적)인데,
**그대로 겨울까지 두면 2.48로 몬스테라 `min` 3.0 미달 = 성장 정지.**

→ **계절 교체가 필수 행동**이고, 이걸 모르면 겨울에 통째로 멈춘다.

## ③ 물주기와 빛의 상호작용 → **★ 설계돼 있다. 미구현**

`env_difficulty_axis.md`:
```
마름속도 = f(빛, 온도, 습도)
→ 어두우면 증산이 적고 → 흙이 안 마르고 → 평소 간격으로 주면 과습
```

**"어두운 방에선 물을 덜 줘야 한다"가 규칙이 아니라 결과로 나온다.**
실내식물 사망 원인 1위가 과습이라 **현실과도 맞는다.**

→ 물(로드맵 2단계)이 들어오면 **자동으로 좋은 비밀이 하나 생긴다.** 설계를 더 할 필요가 없다.

## ④ 내가 추가로 발굴한 것

- **#6 등 높이 조절** — `lighting_sim.js` 주석이 이미 *"높이 조절이 스킬이 됨"* 이라 적어뒀는데
  목록에 없었다. **역제곱이라 30cm가 크다.** 게다가 **공짜 행동**이다(#1과 같은 뿌리)
- **#7 광주기** — 24h 켜면 DLI는 2배인데 **판정이 나빠지고 요금도 2배**다.
  *"많이 켜면 좋겠지"* 가 **세 방향으로 동시에 배신**당한다 — 배우는 함정으로 좋다
- **#12 반지하 계절 변동 3%** — #11과 같은 뿌리인데 **다른 얼굴**이다.
  *"겨울 대비를 안 해도 되는 유일한 방"*

# 3. 위키·커뮤니티가 생기면 — **오히려 재료다**

**값어치가 있다.** 세 가지 이유다.

**① 우리 비밀은 "숫자를 아는 것"이 아니라 "읽는 법을 익히는 것"이다.**
*"벽 선반은 1.6m"* 를 위키에서 봐도, **방마다 창 높이가 다르면 다시 재야 한다.**
집짓기가 들어오면 **플레이어마다 방이 달라져** 정답이 하나가 아니다.

**② 물리 기반이라 커뮤니티가 검증·확장한다.**
임의 규칙이면 위키 하나로 끝나지만, 물리면 *"우리 집에서도 되나"* 를 해보게 된다.
`tool.html`(조도 진단)이 그 놀이터다 — **실제 우리집 빛을 재는 도구가 이미 있다.**

**③ 첫 발견 경험은 한 번뿐이다 — 그래서 게임 안에 발견 경로가 있어야 한다.**
위키를 볼지 말지는 플레이어가 정하지만, **게임이 스스로 가르칠 수 있어야** 한다.

```
정보 축   초보 숫자 → 표준 막대 → 고수 없음
말 피드백  "왜 안 자라는지"를 짚어준다
되돌리기   실험이 안전하다
```

이 셋이 **위키 없이도 찾을 수 있게** 만든다. 위키는 **지름길**이지 필수가 아니어야 한다.

> **역으로 위험한 것**: 발견 경로가 부실하면 *"위키 안 보면 못 하는 게임"* 이 된다.
> 그때는 비밀이 깊이가 아니라 **진입 장벽**이 된다. §0의 ❌ 판정이 그걸 막는 장치다.

# 4. 규칙 — 새 발견이 나올 때마다

```
1. 각 창 STATUS의 "발견" 항목이 재료다
2. 물리에서 나온 것인지 확인한다 (임의 규칙이면 목록에 넣지 않는다)
3. 표에 한 줄 추가 — 효율 · 근거 · 발견 경로 · 몰라도 되나 · 난이도
4. 「몰라도 되나」가 ❌면 acceptance.json에 통과 조건을 넣고 튜토·피드백을 설계한다
```
