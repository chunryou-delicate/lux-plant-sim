## 0. 공통 원칙 — 켜둔 시간만 간다

**세 모드 전부** 게임 시계는 **실행 중일 때만** 흐른다.

- 접속 안 하면 게임 시간도 안 간다. **오프라인 성장 없음**
- 창을 닫거나 백그라운드로 내리면 정지

이 원칙 하나가 앞서 걱정하던 문제를 통째로 없앤다:

| 걱정 | 해소 |
|---|---|
| 여행 갔다 오면 다 죽어 있음 | 시간이 안 갔으니 그대로 |
| 서버 시각 대조·치트 방지 | 실제로 켜둬야 시간이 가니 **조작할 게 없다** |
| 오프라인 처리 로직 | 불필요 |

## 1. 세 모드

| 모드 | 시간 | 정체 |
|---|---|---|
| **배속** | ⏸ / 1x / 4x / 최고속 | 훅훅 넘기며 최적화 — **관리 게임** |
| **실시간** | 배속 고정·스킵 없음. 게임 1일 = **30분** | 빛이 방을 가로지르는 걸 지켜봄 — **관찰 게임** |
| **1:1** | 게임 1일 = 실제 24시간(켜둔 시간 기준) | 몇 달에 잎 하나 — **사육** |

### 실시간 모드의 의미 — "정직한 관찰"

배속으로 넘기면 아침 빛이 어디 드는지, 오후에 어느 선반이 밝아지는지 **못 본다.**
실시간이면 **관찰이 곧 플레이**다. "빛이 진짜다"를 제대로 경험하는 방식이고,
그래서 보상이 납득된다 — 강해지는 게 아니라 **제대로 본 사람에게 주는 표식**.

### 1:1의 960시간은 버그가 아니라 의도다

실제 식물이 그렇다. 몇 달에 잎 하나, 매일 별일 없다가 어느 날 새순이 돋아 있는.
**그 느림 자체가 경험**이다. 게임이라기보다 사육에 가깝다.

1:1에서만 가능한 것:
- **계절이 진짜 계절이 된다.** 12월에 시작하면 정말 겨울을 나야 하고 봄이 오면 진짜 봄.
  배속으로 3분 지나가는 겨울과 완전히 다른 경험
- **"내가 키웠다"가 진짜가 된다.** 960시간을 스킵 없이 지켜본 개체

## 2. ★ 결정 — 실시간 모드 = 게임 1일 **30분**

### 체감 계산 (`GMAX=1095` · `timeCurve=0.72` · `spawnStep=40` 기준)

`plant_grow.html:1466`의 `ageOf(d) = 1095 × (d/1095)^0.72` 때문에 **초반이 빠르다.**
단순 나눗셈으로 계산하면 틀린다.

| 마일스톤 | 생장나이 | 게임일 | **30분** | 60분 | 1:1 |
|---|---|---|---|---|---|
| 씨앗 끝 | 20 | 4.2 | **2.1시간** | 4.2시간 | 4.2일 |
| **첫 마디·첫 잎** | 40 | 11.0 | **5.5시간** | 11.0시간 | 11.0일 |
| 새싹 끝 | 45 | 13.0 | **6.5시간** | 13.0시간 | 13.0일 |
| 2번째 잎 | 80 | 28.9 | **14.5시간** | 28.9시간 | 28.9일 |
| 잎 1장 성숙 | 120 | 50.8 | **25.4시간** | 2.1일 | 50.8일 |
| 잎 6장 | 240 | 133.0 | **2.8일** | 5.5일 | 133일 |
| 최대 마디(12) | 480 | 348.3 | **7.3일** | 14.5일 | 348일 |
| 완성(3년) | 1095 | 1095 | **22.8일** | 45.6일 | 1095일 |

### 세션당 진행

| 누적 플레이 | 30분 모드 | 60분 모드 |
|---|---|---|
| 1시간 | 2.0 게임일 (나이 12) | 1.0일 (나이 7) |
| **2시간(한 세션)** | **4.0 게임일 (나이 19)** | 2.0일 (나이 12) |
| 8시간 | 16일 (나이 52) | 8일 (나이 32) |
| 40시간 | 80일 (나이 166) | 40일 (나이 101) |

### 왜 30분인가 — 세 가지 다 30분을 가리킨다

**① 한 세션에 "며칠이 지났다"가 느껴져야 한다**
2시간 세션에 30분 모드는 **4일**, 60분 모드는 **2일**이다.
하루가 두 번 넘어가는 걸로는 변화가 안 읽힌다.

**② 첫 잎까지 5.5시간(3세션) vs 11시간(6세션)**
60분은 첫 보상까지 너무 멀다. 관찰 게임이라도 첫 마디는 봐야 계속한다.

**③ 밤 시간이 지루함의 한계 안에 있다**

| 계절 | 30분 모드 | 60분 모드 |
|---|---|---|
| 여름 | 낮 18.1분 / **밤 11.9분** | 낮 36.3분 / 밤 23.8분 |
| 봄 | 낮 15.6분 / **밤 14.4분** | 낮 31.3분 / 밤 28.8분 |
| 겨울 | 낮 12.3분 / **밤 17.8분** | 낮 24.5분 / **밤 35.5분** |

60분 모드의 겨울 밤 **35.5분**은 빈 화면이다. 30분이면 17.8분으로 견딜 만하다.

> **겨울 밤이 낮보다 긴 게 오히려 좋다.** 그 시간에 할 게 있다 — 식물등이다.
> `light_thresholds.json`의 광주기 밴드(12h 정상 / 22h~ 연속점등 장해)와 전기요금이
> 이미 있으므로 **겨울 = 등 관리의 계절**이 물리에서 그대로 나온다.

### ⚠ 실시간 모드는 씨앗부터 시작하면 안 될 수도 있다

첫 5.5시간(3세션) 동안 화면에 **씨앗과 떡잎뿐**이다. 관찰 게임인데 볼 게 없다.
→ 실시간 모드는 **모종(새싹 이후) 또는 이미 자란 개체를 옮겨 심는 것**으로 시작하는
쪽이 맞을 수 있다. 배속 모드에서 키운 개체를 실시간으로 데려오는 것도 방법이다.
**미확정** — 실시간 모드 착수 때 정한다.

### 배속 모드 계수 (실시간 1일=30분을 1x로 잡는다)

| | 게임 1일 | 3년 완주 |
|---|---|---|
| 1x | 30분 | 22.8일 |
| 4x | 7.5분 | 5.7일 |
| 최고속 | 30초 | 9.1시간 |
| **하루 넘기기 버튼** | 즉시 | — (배속 모드 전용) |

## 3. ★ 모드 전환 — 자유. 대신 자격은 **개체**가 들고 있다

전환 규칙을 복잡하게 짤 필요가 없다. **보상 자격을 모드가 아니라 개체에 붙이면** 된다.

```jsonc
plant: {
  observed: { realtime_ticks: 0, oneone_ticks: 0 },   // 이 개체가 각 모드로 관찰된 시간
  born_mode: "realtime"
}
```

- 모드는 **언제든 바꿀 수 있다**
- 배속으로 300일 키운 개체를 실시간으로 옮겨도 `realtime_ticks`가 0이라 **자격이 없다**
- 실시간으로 키우다 배속으로 넘기면, 넘긴 뒤 자란 부분은 카운트가 안 붙는다

→ 전환 제한·잠금·경고창이 전부 필요 없어진다. **규칙 하나로 줄어든다.**

## 4. 치트 방지 — 온라인 불필요

**로컬만으로 성립한다.**

| 공격 | 왜 안 통하나 |
|---|---|
| 시스템 시계 조작 | 켜둔 시간만 세므로 **얻을 게 없다** |
| 창 닫고 기다리기 | 시간이 안 간다 |
| 배속으로 키우고 모드 전환 | 개체의 `observed` 카운트가 0 (§3) |

남는 건 **세이브 파일 직접 편집**뿐인데, 싱글플레이에서 자기 세이브를 고치는 건
막을 이유가 없다. 보상이 성능이 아니라 자랑거리라 남에게 피해가 없다.

**온라인이 필요해지는 유일한 조건**: 도감·칭호를 **남과 공유·비교**할 때.
그때만 서버 검증을 붙이면 되고, 그 전까지는 접속 요구가 순손해다.
→ **지금은 로컬. 온라인은 공유 기능이 생길 때 다시 판단.**

## 5. AFK 방지 — ★ 넣지 말 것

**넣지 않기를 권한다.** 두 가지 이유다.

**① 은유를 깬다.** 실시간·1:1 모드는 "식물을 책상에 두는 것"의 은유다.
화분은 내가 안 볼 때도 거기 있다. AFK 페널티는 "계속 쳐다보고 있어라"가 되어
**느긋함이라는 이 모드의 본질을 정확히 반대로 만든다.**

**② 보상 설계로 이미 해결된다.** 보상을 두 층으로 나누면 별도 시스템이 필요 없다:

| 층 | 획득 조건 | AFK로 되나 |
|---|---|---|
| **기록** — 도감 타임스탬프, 개체 나이 | 켜둔 시간 | **된다** (그래도 된다. "지켜봤다"의 최소 증명) |
| **순간** — 개엽 관찰, 일출 스탬프 | 그 순간에 **반응**해야 함 | **안 된다** |

자랑거리가 되는 건 아래층이다. AFK로는 못 딴다. **금지하지 않아도 갈린다.**

## 6. 보상 — "강해짐"이 아니라 "다르게 가짐"

> ❌ 성장속도 +50% · 희귀확률 2배 → 실시간이 사실상 강제가 된다
> ✅ 배속 모드가 열등해지지 않을 것. 실시간은 **느긋하게 진짜로 보는 사람의 선택**

### 실시간 모드

| 보상 | 내용 | AFK |
|---|---|---|
| **관찰 기록** | 도감에 잎이 펴진 **시각**까지 남는다. 배속은 날짜만 | 자동 |
| **개엽 관찰 스탬프** | 새순이 펴지는 건 실제로 이른 아침. **그 순간 접속해 반응**해야 찍힌다 | ✕ |
| **빛 스냅샷 갤러리** | 특정 시각 빛이 개체에 닿는 순간 촬영. 계절·시각별로 다른 그림 | ✕ |
| **칭호** | "새벽 5시의 관찰자" · "겨울을 난 사람" | 일부 ✕ |
| **계절 한정 무늬** | 그 계절을 실제로 관찰하며 넘긴 개체만 발현 | 자동 |

### 1:1 전용

| 보상 | 내용 |
|---|---|
| **도감 별도 칸** | 1:1로 키운 개체만 등록되는 칸. 채우는 데 몇 달 |
| **"3개월 넘긴 개체"** | 개체 나이 표시. 960시간 스킵 없이 지켜본 증명 |
| **진짜 계절 무늬** | 12월에 시작해 **실제 겨울을 난** 개체에만 |

## 7. 엔진과의 관계 — 구조는 이미 맞다

**좋은 소식**: 실시간 렌더에 필요한 게 이미 다 있다.

| 필요한 것 | 있나 |
|---|---|
| 시각별 순간 조도 | ✅ `daylightAt()` · `pointIllum()` (기하학적, 시간 무관 → 매 프레임 싸다) |
| 하루 총량 | ✅ `daylightDLI()` — 하루 끝에 계약 객체 1개 생성 |
| 계절별 낮 길이 | ✅ `dayLengthHours()` (하지 14.5 / 동지 9.8) |

`daylightRatio`가 **시간과 무관한 기하 값**이라 매 프레임 다시 안 재도 된다.
천공 조도만 시각에 따라 바꿔 곱하면 실시간 렌더가 된다. **엔진 변경 없음.**

### ⚠ 1:1 모드에서 `fStable`이 오래 중립이다

`plant_grow.html`의 `dliCV()`는 **기록 7일 미만이면 `null`(모름) → 중립 1.0**이다.
1:1에서 7 게임일 = **168 실시간 시간**, 14일 = 336시간.
즉 1:1 플레이어는 초반 168시간 동안 안정 보너스를 못 받는다.

이건 1:1의 본질(느림)이라 그대로 두는 게 맞다고 본다.
다만 **모른다는 걸 UI로 보여줘야 한다** — "관찰 기록 3/7일"처럼.
안 그러면 "왜 아무 일도 안 일어나지"가 된다.

## 8. 구현 순서 — ★ 1:1은 마지막

기능적으론 제일 쉽다(배속 계수를 1/24로 고정하면 끝). 그런데 **이 모드가 재밌으려면
나머지가 다 완성돼 있어야 한다.** 960시간 켜둘 사람이면 그동안 볼 게 있어야 한다 —
하루 안 빛 변화, 계절 전환, 개체 성장, 이벤트. 지금처럼 뼈대만 있으면
**960시간은 그냥 빈 화면**이다.

```
지금        모드 구조만 잡는다 — 배속 계수를 파라미터로.
            timeScale: { minutesPerGameDay: 30 }  하나로 세 모드가 다 표현된다
              배속 최고속 0.5 / 배속 1x·실시간 30 / 1:1 1440

다음        배속 모드로 게임 완성 (지출 루프 → 재미 확인)

나중        실시간 모드 튜닝 + 보상
마지막      1:1 모드
```

**세 모드가 `minutesPerGameDay` 숫자 하나로 갈린다.** 지금 할 일은 그 파라미터를
하드코딩하지 않는 것뿐이다.
