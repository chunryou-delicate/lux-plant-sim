# 온실·학원교실 채우기 — 방안 (구현 전 검토용)

---

## 0. 지금 상태

| | 온실 | 학원교실 |
|---|---|---|
| 겉모습 | **이미 됨** — `glassWalls:["back","left","right"]` + `ceiling:"glass"` | 됨 (창 3개) |
| 조도 엔진이 보는 창 | **0개** | 3개 |
| 식물 슬롯 | **0개** | **0개** |
| 가구 | **0개** | 0개 |
| DLI | **0.00** | 측정 불가(슬롯 없음) |

온실은 **화면엔 유리로 보이는데 조도 엔진에는 창이 하나도 없다.**
`house.js`가 `glassWalls`를 *렌더용 유리판*으로만 만들고, `windows[]`에는 아무것도 안 넣기 때문이다.
지금 온실에 식물을 두면 DLI 0 = 즉사한다. **겉과 속이 어긋난 상태.**

---

## ★ 핵심 제약 — 엔진은 수직 창만 표현한다

`daylight_lux.js:106`
```js
const cosWin = (rx * w.nx + rz * w.nz) / d;   // ← ny 가 없다
```
창 법선이 **수평 2D**로 고정돼 있고, 창면 세로축도 항상 월드 Y다(`wy = w.cy + sv`).

→ **지붕 천창은 지금 구조로 표현할 수 없다.**

그리고 온실에서 천창은 곁가지가 아니다. 수평 유리는 하늘 반구를 **통째로** 보므로
보통 벽면 유리보다 훨씬 세다. 천창 없는 온실은 "온실"이 아니라 그냥 창 큰 방이다.

---

## 방안 3가지

### A. 커튼월 창 프리셋으로 벽을 채운다
`greenhouse.windows[]`에 `win_curtainwall_full` 같은 걸 벽마다 하나씩 넣는다.

- ✅ 엔진 수정 **0**. 오늘 바로 됨
- ✅ `win_greenhouse_full`·`win_curtainwall_full` 등 프리셋이 이미 있음
- ❌ `glassWalls`와 **데이터 이중 관리** — 하나만 고치면 겉과 속이 또 어긋남
- ❌ **천창 여전히 불가**

### B. `glassWalls` → 창을 자동 생성
`house.js`가 유리벽을 만들 때 그 벽 크기 그대로 `winFromHouse`용 창을 하나 뱉는다.
데이터는 `glassWalls` 한 곳만 유지.

- ✅ 이중 관리 없음. **겉과 속이 구조적으로 일치**
- ✅ house.js 20줄 남짓. 엔진은 안 건드림 → **tool.html 무관**
- ❌ **천창 여전히 불가**

### C. 엔진에 3D 창 법선 추가 (천창)
`win`에 `ny`와 창면 세로축 벡터를 넣어 임의 방향 개구부를 지원.

```js
// 지금            → 바뀐 뒤
w.nx, w.nz         → w.nx, w.ny, w.nz
wy = w.cy + sv     → w.cx + ux*su + vx*sv  (세로축도 벡터)
cosWin = rx*nx + rz*nz  →  + ry*ny
```

- ✅ 천창·경사 지붕·다락 창까지 전부 열림
- ⚠️ **공용 엔진 변경** → tool.html 회귀 재검증 필수
  (기존 수직창은 `ny=0`, 세로축=(0,1,0)이라 **수치가 바뀌면 안 된다** — 0.000000 확인)
- ⚠️ 온실 DLI가 20~40까지 치솟을 것. `over`(과광) 밴드에 걸릴 수 있어 밸런싱 필요

---

## 권고: **B + C**

| 단계 | 내용 | 위험 |
|---|---|---|
| 1 | **B** — `glassWalls` 자동 창 생성 | 없음 (house.js만) |
| 2 | **C** — 엔진 3D 법선 + `ceiling:"glass"` → 천창 | 회귀 검증으로 통제 |
| 3 | 온실 가구·슬롯 (재배대·모종판·행잉) | 없음 |
| 4 | 학원교실 가구·슬롯 (책상·의자·칠판·창가 화분단) | 없음 |

**A는 권하지 않는다.** 오늘 빠른 대신 이중 관리가 남고, 어차피 천창 때문에 C를 하게 된다.

**C의 안전장치** — tool.html 이관 때와 같게:
1. 작업 전 `tool.html`·`daylight_lux.js` 백업
2. 변경 후 수직창만 있는 방으로 회귀 — **오차 0.000000** 확인
3. `_dli_probe.html`로 4개 방 DLI 재측정 — 값이 **하나도 안 변해야** 함
4. 어긋나면 즉시 롤백

## 온실을 게임에서 뭘로 쓸 것인가 (밸런싱)

천창이 들어가면 온실 DLI는 20~40이 나온다. 이건 몬스테라 `max`(16)를 넘는 **과광**이다.
그래서 온실은 "제일 좋은 방"이 아니라 **성격이 다른 방**이 되는 게 맞다.

- 빛은 남아돈다 → **차광이 관리 변수**가 됨 (커튼·차광막)
- 대신 겨울 난방비 폭발 · 여름 과열 (→ `temp` 축이 들어오면 자동으로 트레이드오프)
- 고광 요구 식물(다육·허브·채소)엔 최적, 몬스테라엔 오히려 잎이 탐

즉 온실은 **엔드게임 보상이 아니라 다른 플레이**로 두는 걸 권한다.

## 학원교실 (간단)

빛은 이미 있다(창 3개). 필요한 건 가구뿐.
`desk`·`chair`·`blackboard`·`shelf` 계열로 채우고, **창가 쪽에만 식물 슬롯**을 둔다.
→ "교실 뒤편은 어둡다"가 자연스럽게 나오고, 자리 선택이 곧 난이도가 된다.
