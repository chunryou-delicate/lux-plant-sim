# 하루치 빛 계약 — 조도 창 → 생장 창

`src/engine/daily_light.js` · `data/light_thresholds.json`

---

## 0. 책임 경계 (제일 중요)

| | 조도 창 (이 문서) | 생장 창 |
|---|---|---|
| 만드는 것 | 그날 하루의 **물리량** | 식물의 **상태 변화** |
| 상태 | **없음** — 순수 함수 | 있음 (세이브/로드 포함) |
| 판정 | 밴드 **이름만** 붙임 | 며칠 연속 부족 → 시듦/고사, 황변 누적 |

조도 창은 "식물이 어떻게 됐는지"를 **절대 결정하지 않는다.**
`buildDailyLight()`를 **하루 1회** 호출해 객체 하나를 넘기면 끝이다.

```js
const report = buildDailyLight(day, slots, wins, {
  weather:'cloudy', season:'winter', region:'default',
  occluders, lums, litHours:12, lampWatts:12, tariffWonPerKwh:160,
  thresholds: light_thresholds.json
});
```

### 왜 필드를 쪼개 놨나
`dli_daylight` / `dli_lamp`이 나뉘어 있어야 생장 창이
**"오늘 안 자란 게 날씨 탓인지 등을 안 켠 탓인지"** 를 플레이어에게 설명할 수 있다.

## 2. 천공 조도

```
evMax = 25,000 × weather × season × region
```

| | 계수 | 근거 |
|---|---|---|
| `CLEAR_SKY_MAX` | 25,000 lx | **★ 캘리브레이션값** — 아래 참고 |
| 맑음/흐림/비 | 1.00 / 0.25 / 0.12 | |
| 여름/봄/가을/겨울 | 1.00 / 0.85 / 0.80 / 0.55 | 태양 고도·대기 경로 |
| 지역 | 전부 1.00 (자리만) | 국내 연간 일조시간 차 최대 37%, 서울 ±5% — 계절(45%)·날씨(75%)보다 작음 |

### ★ 25,000은 캘리브레이션값이지 이론 물리값이 아니다
문헌의 **"밝은 실내 창가 DLI 3~8"에 실내 결과가 맞도록 역산해서** 고른 값이다.
이론적으로는 맑은 날 수직면 확산광 대역(10,000~25,000)의 **상단이라 낙관적인 편**이다.
게임이 문헌 실측에 맞는 게 목적이므로 실용적으론 맞는 선택이지만, "왜 25,000이지?" 할 때
물리적 근거로 오해하지 말 것.

**재조정하면 방별 DLI 실측표 전체를 다시 검증해야 한다** — `_dli_probe.html` 사용.
(12,000이던 시절엔 최고 DLI가 2.8로 문헌 대역 아래여서 모든 방이 재배 불가였다)

> `tool.html`은 이 값을 **쓰지 않는다**. 자기 UI 입력(`S.sky`, 기본 8,000)을 직접 넘긴다.
> 두 도구가 같은 모듈을 쓰지만 천공값은 각자 정한다.

### 낮 길이 — 겨울의 두 번째 효과
겨울은 **어둡고(×0.55) + 짧다(9.8h vs 14.5h)**. 둘을 곱해야 실제가 나온다 → 겨울 총량 ≈ 여름의 **37%**.

렌더용 sun 슬라이더(`skyEv`의 t=12~88 = 18.2h)는 "보기 좋은 하루"라 실제보다 길다.
**DLI는 슬라이더가 아니라 계절별 실제 낮 길이로 적분한다.** (`daylightDLI`)

## 3. DLI 밴드 — `data/light_thresholds.json`

임계값은 전부 **"이 값 이상이어야 그 상태"인 하한**이다.

| 밴드 | 구간 | 뜻 |
|---|---|---|
| `die` | die 미만 | 고사 |
| `weak` | die~survive | 쇠약 — 버티지만 서서히 상함 |
| `survive` | survive~min | **정체 — 죽진 않는데 새 잎이 안 남** |
| `slow` | min~best_lo | 느린 성장 |
| `best` | best_lo~best_hi | 최적 |
| `good` | best_hi~max | 성장 |
| `over` | max 초과 | 과광 — 잎 탐·황변 |

| 식물 | die | survive | min | fenestrate | best | max |
|---|---|---|---|---|---|---|
| 산세베리아 | **0.15** | 0.5 | 1.5 | — | 3~6 | 12 |
| 몬스테라 델리시오사 | 0.5 | 1.2 | 3.0 | **6.0** | 5~11 | 16 |
| 몬스테라 아단소니 | 0.6 | 1.2 | 2.5 | 5.0 | 4~9 | 14 |

`fenestrate`는 **best와 별개**다. 몬스테라는 5.0이면 잘 크지만 **6.0을 넘어야 잎이 갈라진다** —
"살아는 있는데 그 잎이 안 나온다"가 목표 동기가 된다.

> `data/plants.json`(출처 기반 79종 DB)은 **건드리지 않는다.** 이 파일은 그 위에 얹는 게임 규칙 레이어다.
> 충돌하면 plants.json이 사실이고 여기는 그걸 놀이로 번역한 것.

### ★★ 생장 창 필수 요구사항 — 하루치로 생사 판정하지 말 것
날씨가 매일 굴러가면 반지하 산세는 **맑은 날 0.54(정체) ↔ 흐린 날 0.14(고사 밴드)** 를 오간다.
하루 값으로 죽이면 **운으로 죽는다.**

**요구사항: `die` 판정은 최소 5~7일 이동평균으로 할 것.**
`band`는 그날의 라벨일 뿐이다. 누적은 전적으로 생장 창 몫이다.

산세 `die`를 0.3 → **0.15**로 낮춰둔 것도 같은 이유다. 실제 산세는 아주 어두운 곳에서도
몇 달 버틴다. 이동평균과 함께 쓰면 반지하 산세는 **정체 ↔ 쇠약을 오가되 죽지 않는다** —
이게 튜토리얼이 성립하는 조건이다.

## 4. 광주기 — 연속점등 페널티

24시간 점등은 DLI만 보면 유리해 보이지만 실제로는 해롭다.
암기(暗期)에 당 전류·호흡·조직 복구가 일어나고, 일주기가 깨지면 성장률이 떨어진다.
(*"암반응"은 어둠에서 도는 게 아니라 낮에도 돈다 — 밤에 켜두면 더 자란다는 건 오해*)

| 점등 | 밴드 | 성장 배율 | 비고 |
|---|---|---|---|
| ~14h | `photo12` | 1.00 | 정상 |
| 14~18h | `photo16` | 0.92 | 수확체감 |
| 18~22h | `photo20` | 0.80 | 과다 |
| 22h~ | `always` | **0.65** | ★ `continuous_injury` 발동 |

```jsonc
"continuous_injury": {
  "growth_mult": 0.65,
  "chlorosis_per_day": 0.04,   // 하루당 잎 황변 진행도(0~1). 생장 창이 누적
  "energy_mult": 2.0,
  "reason": "연속점등 — 암기 부족(당 전류·호흡·조직 복구 저해, 일주기 교란)",
  "fix": "타이머로 점등시간 12~16h로"
}
```

### ★ `overlight` ≠ `continuous_injury` — 절대 합치지 말 것
둘 다 "빛 때문에 나빠짐"이지만 **원인도 해법도 다르다.**

| | `overlight` (슬롯 필드) | `continuous_injury` (최상위 필드) |
|---|---|---|
| 조건 | `dli > 식물.max` | 점등 22h 이상 |
| 원인 | **광량 초과** | **암기 없음** (일주기 교란) |
| 증상 | 잎 탐·백화 | 황변·성장 둔화 |
| 해법 | **차광**·거리 띄우기 | **타이머** |

광량이 적정이어도 24h 켜면 `continuous_injury`가 걸리고,
12h만 켜도 너무 세면 `overlight`가 걸린다. **둘은 독립적으로 동시에 발생할 수 있다.**

### 함정이 성립하는지 실측
반지하 · 흐림 겨울 · 클립등 12W:

| 점등 | DLI | 판정 | 전기 | 원인 |
|---|---|---|---|---|
| 12h | 6.55 | **성장** | 23원 | — |
| 24h | 13.03 | **과광** + **연속광 장해** | 46원 | 산세 max 12 초과 **동시에** 암기 0h |

24시간 켜면 **DLI는 2배인데 판정은 나빠지고 요금은 2배**다.
"많이 켜면 좋겠지"가 세 방향으로 동시에 배신당한다 → 배우는 함정.

이 사례는 `overlight`와 `continuous_injury`가 **둘 다** 걸린 경우다.
플레이어가 등을 약한 걸로 바꾸면 `overlight`만 풀리고 장해는 남는다 — 타이머를 걸어야 풀린다.
그래서 필드를 나눠야 한다.
