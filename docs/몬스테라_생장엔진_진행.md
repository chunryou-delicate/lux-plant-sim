## 생장 로직 (순서도 캐논 그대로)

순서도 원본의 `up` 포인터를 읽어 구조를 확정했다. 요약:

1. **생장점(TIP)은 고정된 하나**이고 **잎도 그 자리에 하나**. 그 잎이 새순 → 반잎 → 어린 → 중간 → (확률)성숙으로 자란다.
2. **새 마디는 TIP "아래"에 삽입**된다(growUp). 줄기가 밑에서 길어지고 생장점이 위로 밀려 올라간다.
3. 마디는 삽입 후 시간이 지나면 **아래(오래된 것)부터** 줄기_초기 → 줄기_중기.
4. **혹은 무조건 1개씩.** "어떤 생장점의 잎이 **중간잎이 되는 순간**"에만, 예비혹(중기) 중 **순수 랜덤 1개**가 혹이 된다.
5. 그 혹에서 난 가지의 새순이 **다시 중간잎이 되어야** 그 다음 혹이 발생. (다발성 아님)

데이터 근거 — 순서도에서 그대로 읽힌 순서:

```
step6  잎 어린잎    → step7,8,10  줄기가 아래부터 중기로 하나씩
step9  잎 중간잎    → step12      중기 중 딱 1개가 혹
step14 혹에서 가지  → step15      그 가지에 새순
step26 가지 잎 중간잎 → step26    두 번째 혹
```

### 변이(무늬종)
- **잎(생장점)마다 독립 판정** = "중간에 발현". 그루 단위 아님. 기본 **20%**(난이도별로 달라질 예정).
- 어린잎에서 결정되면 중간 단계도 알보로 유지.
- 무늬 텍스처는 **절대 단색 틴트 금지**(무늬가 곧 텍스처).
- 향후: 가지를 잘라 **수경재배**로 번식 시, 모주가 무늬면 삽수는 **80% 수준**을 물려받는다.

## 이번에 해결한 것

### 1. 줄기를 이음새 없는 튜브로

마디마다 GLB를 늘려 이어붙이니 경계 링이 필연적이었다. 마디 점들을 CatmullRom 곡선으로 잇고 **가변 반지름 튜브를 직접 생성**(`makeStemTube`)해서 경계 자체를 없앴다. 혹/쌍혹 GLB만 그 위에 얹는다. 양 끝은 뚜껑으로 막았다.

### 2. 줄기가 너무 직선이던 문제

- 원인 ①: `stemStraight 0.30`이 휘려는 걸 매 마디 30%씩 펴버림
- 원인 ②: `spread`는 매 마디 독립 랜덤(백색잡음)이라 서로 상쇄 — 곡선이 안 생기고 떨리기만 함

**축마다 고정된 아치 방향**(`curveDir`/`curveAmt`)을 부여해 일관된 곡선이 누적되게 했다.

| | 이전 | 지금 |
|---|---|---|
| 밑동→끝 총 휨각 | 8.6° | **26~29°** |
| 마디당 최대 꺾임 | 5.8° | 11.5° |

### 3. 잎이 줄기를 관통

세 개의 독립된 버그였다.

**(a) 잎을 "선"으로 판정** — 축 위 3점만 검사해 실제 잎몸 폭의 1/4~1/5만 봤다. 성숙잎 기준 실제 반폭 0.29 vs 판정여유 0.058 = **5배 과소평가**. → 잎몸을 실측 폭의 구, 잎자루를 캡슐로 판정.

**(b) 검사한 자리 ≠ 실제 자리** — `freeAim`이 잎 위치를 어림잡는데 실제 잎은 그 뒤에 ADJ 회전이 적용된다. 조절기 회전이 큰 값(회전Y 2.05rad=117°)이라 실제 잎몸은 **최대 22° 벗어난 곳**에 놓였다. → `leafBladeCenter()`로 `addLeaf`의 변환을 그대로 재현해 실제 좌표로 검사.

**(c) 자기 줄기를 제외 안 함** — 어느 방향으로 돌려도 자기 줄기와 겹침으로 계산돼 **모든 후보 점수가 똑같이 나빠지고 변별력이 사라졌다**. → 자기 축의 끝 두 마디는 검사 제외.

추가로 **생장 시 조향**(접촉굴성)을 넣어 줄기가 자라며 다른 줄기를 피해 휘게 했다.

> 3년치(잎 14 / 줄기 110) 기준 관통 잎 **3.5장 → 1.4장**

### 4. 잎·엽초 일체화

엽초를 월드 기준으로 그렸는데 `setFromUnitVectors`는 **축 둘레 회전(roll)이 정의되지 않는다.** 줄기 방향이 바뀌면(=시드가 바뀌면) roll 기준이 달라져 맞춰둔 각도가 틀어졌다.

→ 잎과 엽초를 **같은 holder(줄기축 관통선 프레임)** 안에 담아 세트로 회전·이동하게 했다.

> 검증: 방위 0~315° 회전에도 잎-줄기축 각도 편차 **8.5e-14°**

### 5. 비균등 스케일 전단(shear)

회전된 자식에 부모의 비균등 스케일(XZ ≈0.05 vs Y ≈0.02~0.2)이 걸려 **Z회전 시 형상이 어그러졌다**. 계층을 `[방향] → [ADJ회전] → [비균등스케일]` 순으로 재배치해 회전을 강체로 만들었다.

### 6. 혹 돌기가 판때기로 뭉개지던 것

혹 에셋은 돌기 때문에 **바운딩박스(0.56)가 몸통(0.42)보다 넓다.** bbox 기준으로 굵기를 맞추다 XZ가 Y의 55%로 눌려 둥근 혹이 납작해졌다. → 정점에서 실측한 **몸통 폭 기준**(`STEM_CORE`)으로 환산. 왜곡비 **0.55 → 0.87**.

### 7. 전체 성장 게이지

줄기 굵기·마디 길이·잎 크기·엽초에 **동일 배율**을 적용해 맞춰둔 비율이 그대로 유지되며 함께 커진다.

```
  0일 ×1.00  →  365일 ×1.30  →  730일 ×1.60  →  이후 고정(상한)
```

**주의(실제 발생한 버그)**: 이 배율을 `axBase()`(가지 시작점)에 빠뜨려 가지가 혹이 아니라 **37% 아래**에서 났다. 길이를 계산하는 곳은 **전부** 배율을 곱해야 한다. 현재 3곳(`axBase` 누적/혹 오프셋, 렌더 누적) 모두 적용됨.

## 파이프라인 규칙 (에셋창 참고)

- 로드 시 `normalizeAsset`이 **높이 1로 정규화**하고 밑면을 y=0에 맞춘다 → **GLB 절대 크기는 무시된다.** 실제 미터 스케일을 부여해도 무방.
- 비율(길이 대비 굵기)이 바뀌면 충돌 판정과 잎몸 반폭은 **자동으로 따라간다**(로드 때마다 재계산).
- **파일명 변경 시에는 반드시 알려야 한다** — `ASSET_FILES`가 404.
- 잎이 거꾸로면 **에셋에서 고쳐야 한다.** `ANCHORB`가 "가장 낮은 정점"을 잎자루 끝으로 보므로, 회전으로 덮을 수 없다.
- 무늬종은 텍스처를 지우면 안 되므로 `KEEP_TEX`에 등록한다.
