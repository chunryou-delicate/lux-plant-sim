# 연구자 트랙 — 대학원생·논문·재현성 (설계 기록, 2026-07-26)

> ⚠ **→ [GAME_PLAN.md](GAME_PLAN.md)로 통합됨 (2026-07-26).**
> 정본은 GAME_PLAN.md다. 이 문서는 근거·유도 과정 보관용이며 **여기서 기획을 고치지 말 것.**


> ⚠ **이 문서는 설계 기록이다. 구현은 1단계(대학원생)만 한다.**

>
> `game_design_core.md`의 연구자 항목(「고정월급·희귀종·명성·쉬움~보통」)을
> **이 문서가 갱신한다.** 충돌하면 여기가 최신이다.

## 1. 연구자 = 대학원생. 목표는 논문·졸업·교수

기존 설계에선 연구자가 "고정월급 있고 압박 없는 쉬운 캐릭터"였다.
**대학원생으로 다시 잡으면 성격이 완전히 달라진다.**

| 캐릭터 | 돈 | 환경 | 난이도 |
|---|---|---|---|
| 자취생 | 없음 | 최악(반지하) | 헬 |
| 가장 | 있는데 지출 큼 | 중간(학원교실) | 어려움 |
| **연구자** | **없음(대학원생)** | **최고(온실)** | **중간 — 환경이 상쇄** |
| 주부 | 있음 | 좋음(아파트) | 쉬움 |

### 온실이 "보상"이 아니라 "주어진 것"이 된다

이게 이 재정의의 핵심 소득이다. 기존 구조에선 온실이 최종 보상이라
연구자가 처음부터 온실에서 시작하는 게 설명되지 않았다.

**대학원생이면 설명된다 — 남의 연구실 설비를 공짜로 쓰는 것이다.**
`greenhouse_plan.md`가 이미 "온실은 최고의 방이 아니라 성격이 다른 방"이라고
정리해뒀다(빛 남아돎 → 차광 관리 / 난방비 폭발 / 고광종). 여기에 얹으면
연구자는 **쉬워서 온실에 있는 게 아니라 다른 게임을 하는 것**이 된다.

## 2. ★ 논문 = 재현성. 이게 연구자의 고유 메커니즘

**한 번 나온 건 논문이 안 된다.** 실제 과학처럼 재현돼야 한다.

```
갤럭시 무늬 1개 발현        → "우연" (표본 1)
같은 조건으로 3개 발현      → "재현 성공" → 논문 등록
```

→ 연구자는 "어쩌다 예쁜 거 하나"가 아니라 **의도적 반복 생산**을 해야 한다.
→ 무늬 발현 확률을 빛으로 밀어올리는 관리와 직결된다. **운이 아니라 확률 관리다.**
→ 자취생·가장(많이 팔기)과 **완전히 다른 플레이(정확히 반복하기)**.

### 결정 — 재현 기준 = **3개**. 단, 등급을 나눈다

| 같은 무늬 발현 수 | 결과 | 보상 |
|---|---|---|
| 1개 | **관찰 기록** | 도감 등재만 |
| 2개 | **학회 포스터** | 소액 명예 + 소액 연구비 |
| **3개** | **논문** | 명예 大 · 졸업 카운트 +1 |

**왜 3인가**
- `n=3`은 실제 과학의 최소 반복 관례다. 설명이 필요 없다
- 현재 상수 기준 희귀 무늬 확률이 **잎당 2%** (`varieProb 0.20 × matRare 0.10`)라
  3개를 모으는 게 "확률 관리"로 성립한다
- 5개는 같은 짓 반복이라 지루하다

**왜 등급을 나누나**: 3개 미만이 전부 0이면 실패가 너무 쓰다.
1·2개에도 뭔가 남아야 "다음 번엔 조건을 바꿔보자"가 나온다.

### 재현 판정 규칙 (초안)

- **같은 무늬 ID**여야 한다 (`MAT_TREE`의 계보 번호 기준, `plant_grow.html:895` 부근)
- **같은 조건**이어야 한다 — 판정 시점의 DLI 대역 + 광주기 밴드가 같을 것.
  느슨하게: 7일 평균 DLI가 **±20% 이내**면 같은 조건으로 친다
- 표본 3주는 **판매 잠금** (논문 근거물이라 처분 불가)

## 3. ★ 진행 = U자 곡선. 연구자만 방향이 다르다

```
자취생: 반지하 → 원룸 → 아파트          (계속 좋아짐)
가장:   학원교실 → 온실                  (좋아짐)
연구자: 온실(공짜) → ★졸업 = 연구실 상실 → 교수(자기 연구실)
```

**졸업하면 온실을 잃는다.** 남의 설비를 공짜로 쓰던 거라 나가야 한다.

- 졸업 **전에** 준비해둬야 한다 (자기 장비·종자·자금)
- **졸업 직후가 가장 힘든 시기**
- 교수가 되면 자기 연구실

"성공했는데 오히려 힘들어지는" 구간. **다른 캐릭터에 없는 구조다.**

> 이 U자는 `game_design_core.md`의 "이사 = 항상 업그레이드" 전제를 깬다.
> 깨는 게 의도다. 다만 **구현은 1단계 확인 후**.

## 4. 전기요금 비대칭 — 연구자만의 규칙

대학원생은 **연구실 전기를 학교가 낸다** → 식물등 펑펑, 겨울에도 DLI 확보.
반면 좋은 화분·비료·희귀 씨앗은 못 산다. **"빛은 풍족한데 나머지가 빈곤"**.

```jsonc
// characters.json — 연구자 1단계
{
  "id": "researcher",
  "stage": "grad",
  "monthlyIncome": 600000,      // 조교 월급 (원)
  "rent": 0,                    // 연구실 거주
  "electricityWaived": true,    // ★ 이 플래그 하나
  "startHome": "greenhouse",
  "goalType": "papers",
  "goalValue": 3
}
```

**`electricityWaived: true` 하나로 끝난다.** 지출 루프에서 `energy.won`을 빼지 않으면 된다.
(`food_economy.md` §1 — 전기요금은 이미 하루치 계약에 실려 온다)

### 조교 월급 60만원/월인 이유

월세 0 + 전기 0이므로 **식비(월 22.5만)는 충분히 덮는다.** 살 수는 있다.
남는 37.5만원으로 씨앗·화분·비료를 사야 하는데, 희귀 씨앗 하나가 그 몇 배다.
→ **"굶지는 않는데 아무것도 못 산다"**가 이 숫자 하나로 성립한다.

### 결정 — 식물을 팔 수 있나?

**팔 수 있다. 단 두 가지 제약을 건다.**

1. **재현 등록에 쓴 표본 3주는 판매 잠금** (논문 근거물)
2. 그 외는 팔리되 **명예가 오르지 않는다** — 연구자의 승리 조건은 돈이 아니다

→ 자취생과 같은 행동(판다)을 해도 **점수가 안 오르므로 자연히 다른 플레이를 하게 된다.**
막지 않고 유인만 바꾸는 쪽이 규칙이 적다.

## 5. ★ 확률 = 빛의 함수 — **구현 완료 (2026-07-26)**

> ⚠ **이건 연구자 전용 기능이 아니다. 게임 전체의 핵심 연결이다.**
> 여기가 없으면 지금까지 한 조도 작업(DLI 적분·차광·창 향·천창·근거리 샘플링 버그 수정)이
> **전부 장식**이다. 계산해서 계약 객체까지 만들어 놓고 **받는 쪽이 없었다.**

### 무엇이 비어 있었나

`plant_grow.html:877~895`에 **연결부는 이미 만들어져 있었다.** 그런데 내용이 비어 있었다:

```js
function calcVarieProb(dli){  return P.varieProb;  }   // ← dli를 받아놓고 안 쓴다
function calcMatureProb(dli){ return P.matureProb; }   // ← 갈라짐도 상수였다
function calcMatRare(dli){    return P.matRare;    }
function calcMatSub(dli){     return P.matSub;     }
```

**`matureProb`(갈라짐)도 상수였다.** 이게 더 큰 문제다 —
`light_thresholds.json`에 `fenestrate: 6.0`이 있고, `daily_light.js`가 `fenestrating`을
계약 객체에 실어 보내고, `balance_decisions.md` §②가 "자연광만으로는 아파트에 가야
갈라진 잎을 본다"를 실측표까지 만들어 근거를 대 놨는데, **정작 잎을 만드는 쪽이 그걸
읽지 않았다.** 이사의 보상이 문서에만 있고 화면엔 없었다.

### 구현

`PLANT_DLI`(스칼라 하나)만으로는 이동평균·안정성을 못 구하므로 **생장 창이 이력을 갖게**
했다(`DLI_LOG`, 30일). `light_contract.md` §0의 책임 경계 그대로 — 조도 창은 무상태,
누적은 생장 창 몫이다. `setDailyLight()` 시그니처는 안 바뀌었다.

- `dli7()` — 7일 이동평균. **하루 값으로 판정하지 않는다.** 날씨가 매일 굴러가면 운으로 갈린다
- `dliCV()` — 최근 14일 변동계수. 기록 7일 미만이면 `null`(모름)
- `PLANT_DLI === null`이면 **상수 폴백** — 이 파일 단독 튜닝 모드가 그대로 살아 있다

### 확률식 (★ 대충 정한 값. 나중에 정밀화)

```
varieProb = 0.20 × fLight(DLI7) × fStable(CV14)
```

`DLI7` = 7일 이동평균 (하루 값으로 판정하지 않는다 — `light_contract.md` §3의 원칙)

**fLight — 무늬 최적 대역은 일반보다 높다**

| DLI7 | ×배 | 근거 |
|---|---|---|
| < 3.0 (`min` 미만) | **0** | 정체 구간. 새 잎 자체가 안 나므로 발현 기회 없음 |
| 3.0 ~ 7.0 | 0.5 | 자라긴 하는데 무늬가 잘 안 나옴 |
| **7.0 ~ 15.4** | **1.5** | ★ 무늬 최적 대역 = 일반 `best`(5~11) × 1.4 |
| 15.4 ~ 16.0 (`max`) | 1.0 | |
| > 16.0 (과광) | 0.3 | 흰 부분이 먼저 탄다 |

경계값을 손으로 적지 않고 **`best_lo × 1.4` / `best_hi × 1.4`로 계산**한다.
무늬종은 흰 부분이 광합성을 안 하니 더 많은 빛이 필요하다는 원예 상식이고,
`daily_light.js`의 무늬종 임계값과 **같은 계수 하나(1.4)를 공유**하므로 두 곳이 어긋나지 않는다.
(1.3~1.5 중 가운데값. **이 1.4가 임시값의 핵심이고 나중에 재조정 대상**)

**fStable — 재현성의 핵심. 흔들리면 재현이 안 된다**

| 최근 14일 DLI 변동계수(표준편차/평균) | ×배 |
|---|---|
| ≤ 0.15 (안정) | **1.3** |
| ≤ 0.30 | 1.0 |
| > 0.30 (들쭉날쭉) | 0.7 |

→ **"같은 조건을 정확히 유지하는 것" 자체가 확률로 보상된다.** 재현성 게임의 심장.

**★ 갈래 비율(`matRare`·`matSub`)에는 배율을 태우지 않는다.**
빛은 "무늬가 나오느냐"(`varieProb`)를 결정하고, 나온 무늬가 어느 갈래로 정착하는지는
계보(`MAT_TREE`)가 결정한다. 같은 배율을 두 번 곱하면 관리 보상이 5.6배가 아니라
**30배**가 되어 다른 캐릭터의 플레이가 무의미해진다.

| | 잎당 희귀 무늬 확률 |
|---|---|
| 최적 관리 (1.5 × 1.3) | **3.9%** |
| 방치 (0.5 × 0.7) | **0.7%** |

→ **5.6배 차이.** 관리하면 5배 빨라진다. 운이 아니라 관리라는 게 숫자로 나온다.

### `matureProb` — 갈라짐은 문턱값에서 '켜진다'

```
DLI7 < fenestrate(6.0)  →  0            ← 못 본다. 식물등을 사거나 이사해야 한다
6.0 ~ best_hi(11)       →  0.5 → 1.0 선형
best_hi ~ max           →  1.0
> max(16)               →  0.6          ← 과광. 잎이 상해 성숙이 더디다
```

6.0에서 **절반부터 시작**하는 게 의도다. 문턱을 넘는 순간 눈에 띄게 켜져야
"이사했더니 잎이 갈라지기 시작했다"가 읽힌다.

### 실측 — 방별로 재보면 (`P.matureProb=0.22` 기준)

| 방 | DLI | 무늬 발현/잎 | 희귀 무늬/잎 | **갈라짐/잎** |
|---|---|---|---|---|
| 반지하 | 0.55 | **0%** | 0% | **0%** |
| 원룸 | 4.77 | 13.0% | 1.30% | **0%** |
| 학원교실 | 5.49 | 13.0% | 1.30% | **0%** |
| **아파트** | **6.26** | 13.0% | 1.30% | **11.6%** ← 첫 갈라짐 |
| **온실** | **13.01** | **39.0%** | **3.90%** | **22.0%** (최대) |
| 온실·불안정 관리 | 변동 큼 | 21.0% | 0.70% | — |
| 과광 | 18 | 7.8% | 0.78% | 13.2% |

**설계 의도가 그대로 나왔다**:
- 반지하는 무늬도 갈라짐도 **0** — 자연광만으론 아무것도 안 된다(식물등을 사야 한다)
- 아파트가 **갈라짐이 처음 켜지는 방** — `balance_decisions.md` §②가 코드로 성립했다
- 온실은 무늬 3배 · 갈라짐 2배 — **연구자가 온실을 필요로 하는 이유가 숫자다**
- 같은 온실이라도 관리가 흔들리면 희귀 무늬가 **3.90% → 0.70%** (5.6배 손해)

### 무늬종 광량 계수 — `daily_light.js`에도 실제 구현

`light_thresholds.json`에 `variegated` 블록(`need_mult: 1.4`)을 넣고,
`thresholdsFor()`가 무늬종이면 임계값을 통째로 밀어 올린다.
**`max`(과광 한계)에는 곱하지 않는다** — 흰 조직은 보호 색소가 없어 오히려 더 잘 탄다.

| 몬스테라 | die | survive | min | fenestrate | best | max |
|---|---|---|---|---|---|---|
| 일반 | 0.5 | 1.2 | 3.0 | 6.0 | 5.0~11.0 | 16 |
| **무늬종** | 0.7 | 1.68 | 4.2 | **8.4** | **7.0~15.4** | 16 |

같은 자리·같은 DLI인데 판정이 갈린다:

| DLI | 일반 | 무늬종 |
|---|---|---|
| 4.77 (원룸) | 느림 | **정체** |
| 6.26 (아파트) | **최적 · 갈라짐** | 느림 · 갈라짐✕ |
| 13.01 (온실) | 성장 · 갈라짐 | **최적 · 갈라짐** |

→ **아파트에서 일반 몬스테라는 갈라지는데 무늬종은 안 갈라진다.**
무늬종을 제대로 키우려면 온실이 필요하다는 게 규칙이 아니라 **판정의 결과**로 나온다.

### 확인 방법 — `plant_grow.html`에 DLI 슬라이더를 넣었다

「🔆 DLI(조도엔진 연동 테스트)」 슬라이더. `−1`이면 끔(상수 그대로라 기존 튜닝이
평소대로 먹는다), 0~20이면 **"이 자리에 계속 뒀다면"**으로 이력을 채워 실제 확률을
적용하고 옆에 `갈라짐○/✕ · 무늬 ×배`를 표시한다. 눈으로 확인할 수 있다.

### 이 식이 온실 실측과 맞물리는 지점 ★

`greenhouse_plan.md`의 온실 차광 실측에 위 대역(7~14)을 겹치면:

| 차광 | 여름 맑음 | 무늬 판정 | 겨울 맑음 | 무늬 판정 |
|---|---|---|---|---|
| 없음 | 13.3 | **1.5 최적** | 5.0 | 0.5 |
| 차광막 30% | 9.3 | **1.5 최적** | 3.5 | 0.5 |
| 대나무 발 | 7.3 | **1.5 최적** | 2.7 | **0 (정체)** |
| 차광막 50% | 6.7 | 0.5 | 2.5 | **0 (정체)** |

→ **여름엔 차광을 걸지 않거나 30%까지만.** (관엽 최적을 노리는 다른 캐릭터와 반대!
  일반 몬스테라는 차광막 30~50%가 최적인데, 무늬를 노리면 더 밝게 둔다 — 선택이 갈린다)
→ **겨울엔 자연광만으로 5.0. 무늬 대역 7에 못 미친다. 반드시 식물등으로 밀어올려야 한다.**
→ **그리고 연구자는 전기가 공짜다.** 전기요금 비대칭이 여기서 정확히 작동한다.

이게 "온실 + 전기 면제 + 무늬 확률"이 한 점에서 만나는 지점이다. 물리에서 자연히 나왔다.

## 6. 결정 — 졸업 = 논문 **3편**

| | 값 |
|---|---|
| 재현 표본 | 3개 → 논문 1편 |
| 졸업 | **논문 3편** |
| 예상 소요 | 1편당 30~45턴 → **1단계 100~150턴** |

**왜 3편**: 실제 박사 졸업요건(주저자 논문 편수)과 겹쳐 설명이 필요 없다.
분량으로도 콩나물 1단계(75턴)의 약 2배라 캐릭터 간 차이가 적당하다.

### 소요 턴 추정 근거 (거칠다)

```
온실 슬롯 64개 중 DLI≥6 자리 45개 → 45그루 병렬
몬스테라 새 잎 = 40턴/그루 → 하루 약 1.1장 발현 기회
잎당 희귀 3.9% → 표본 3개까지 평균 77장 ≈ 68턴
```

68턴은 목표 30~45턴보다 길다. 다만 실제로는 **여러 무늬 계열을 동시에 노리므로**
"뭐라도 3개 모이는" 속도는 더 빠르다. **정밀화 시 재계산 대상.**

## 7. 스코프 — 1단계만 구현한다

```
✅ 완료 (07-26)  varieProb·matureProb = f(빛, 안정성)   ← 게임 전체의 연결. 연구자 전용 아님
                무늬종 광량 계수 1.4 (daily_light.js)
                화폐 원 통일 · characters/homes.json 개정

⬜ 다음          온실 + 전기 면제(electricityWaived) + 식비 압박  ← 지출 루프가 없어 대기
                무늬 발현 → 재현(3개) → 논문 등록

⏸ 기록만        졸업(온실 상실) · 교수(자기 연구실) · U자 곡선
```

**지출 루프가 병목이다.** `electricityWaived` 플래그도, 식비도, 재현 판정도 전부
"하루가 지나면 무슨 일이 일어나는가"를 도는 코드가 있어야 붙는다. 지금 `src/`에 그게 없다.

연구자 하나에 3단계 진행 + 논문 + 재현성 판정이면 다른 캐릭터보다 훨씬 무겁다.
**대학원생 단계가 재밌는지 확인한 뒤에 나머지를 붙인다.** (헌법: 한 번에 하나씩)
